# 🧱 4. Core Phase 3 Components

---

## 4.1 SemanticDescriptor (NEW CORE VO)

```php
final readonly class SemanticDescriptor
{
    public function __construct(
        public string $semanticCode,     // e.g. "QUORUM_PASSED"
        public string $meaning,          // human/constitutional interpretation
        public array  $tags,            // e.g. ["voting", "valid", "threshold_met"]
        public string $doctrineVersion  // important: semantic evolution tracking
    ) {}
}
```

### Key rule:

> SemanticDescriptor NEVER affects computation

It only annotates results.

---

## 4.2 GovernanceSemanticClassifier (NEW ENGINE)

```text
INPUT:
  CompositeQuorumEvaluationResult (Phase 2)

OUTPUT:
  SemanticDescriptor
```

### Responsibility:

* interpret quorum result
* apply doctrine rules
* assign meaning labels
* DO NOT recompute logic

---

## 4.3 SemanticCanonRegistry (IMMUTABLE KNOWLEDGE BASE)

```text
Purpose:
  maps result patterns → semantic meaning
```

Example:

```text
if quorumMet = true AND participation > 80%
  → HIGH_PARTICIPATION_VALID_DECISION

if quorumMet = false
  → QUORUM_REJECTED_DECISION
```

### Critical constraint:

> Registry is READ-ONLY in runtime

---

## 4.4 DoctrineSemanticMap (Versioned meaning system)

```text
Doctrine v1:

Doctrine v2:
```

### Key insight:

> SAME STRUCTURE, DIFFERENT MEANING OVER TIME

This is where Phase 3 becomes powerful.
