## 1. Scope & Method

- **Source examined:** `<sibling>/nrna/claude/.claude/.claude` — 346 files: 117 agents, 154 commands, 35 skills, 40 helpers, `settings.json`.
- **Comparison baseline:** this repository's `.claude/` (69 files, project-grown).
- **Method:** read-only. First-hand: full `settings.json`, complete file inventories, grep sweeps. Three independent deep-read analyses (agents/, commands/, skills+helpers/), ~60 files read in full across every category; duplication verified by `diff`; helper scripts assessed by tracing code, not comments.
- **Explicitly Unverified:** (a) behaviour of the external `claude-flow` runtime itself (only its scaffold was present); (b) the 10 declared daemon "workers" (resolve to the absent runtime); (c) whether the scaffold was ever operated (no `.claude-flow/` state found — leaning "never used").

## 2. Executive Summary

The source is an **unmodified vendor scaffold** generated by `claude-flow` v3.0.0 (commit attribution: `Co-Authored-By: claude-flow <ruv@ruv.net>`). Grep confirms **zero project-specific content** (the only "election/voting" hits are Raft *leader election* and the substring "selection").

Architecturally it is a **distribution surface for an external runtime**: a "hook-funnel plus external brain". All nine Claude Code lifecycle hooks funnel into one dispatcher (`hook-handler.cjs`) which delegates intelligence to the `claude-flow` npm CLI and affiliated MCP servers / SaaS products (`ruv-swarm`, `agentic-flow`, `agentdb`, Flow Nexus cloud, `sublinear`, `sona`, E2B). **~90% of files are inert without those runtimes** — documentation wrappers around `npx claude-flow …` / `mcp__claude-flow__*` calls.

Its implicit core domain is **swarm orchestration**. Its treatment of the concerns PublicDigit cares about is largely **theatrical**:

- `adr-compliance.sh` hardcodes 5 of its 10 ADR scores (`adr_004=50; …` with comment "assume partial compliance").
- `security-scanner.sh` hardcodes `CVE-1/2/3 remediated`, counts `exec(`/`eval(` occurrences as "vulnerabilities", and skips `npm audit` "for speed".
- The "intelligence layer" (`intelligence.cjs`) is a self-labeled stub: learning `feedback()` is a no-op, yet the hook layer prints "PageRank recomputed".
- The "truth score" verification metric (0.0–1.0, auto-rollback at 0.95) is never defined anywhere; its dashboards are hardcoded sample ASCII.

A minority (~10–15 files) is substantive, portable engineering content (see §7). The rest is duplication, vendor SaaS surface, marketing fiction, or claude-flow-internal tooling.

## 4. Entry Points & Runtime Flow (traced)

Single load-bearing entry point: **`settings.json`** (composition root). Hook registration: 9 lifecycle events → one dispatcher. Command/agent/skill registration: native filesystem convention (no loader). Plugin system: **none** — "plugins" are the external npm/MCP runtimes.

Flow: SessionStart → `session-restore` + memory import (no-ops without vendor package) · UserPromptSubmit → regex router · PreToolUse(Bash) → tiny hardcoded denylist · PostToolUse(Write/Edit) → counters + Jaccard keyword match (no-op learning). **Actual work never flows through the platform** — commands/agents are advice text telling the model to call an absent runtime; the model does the work with native tools while hooks count edits around it.

## 5. DDD Reading of the Source (context map)

- Implicit core domain: Swarm Orchestration; everything serves or advertises it.
- Every context is **Conformist** to a single upstream — the claude-flow MCP/CLI surface (its Published Language). No anticorruption layer anywhere; absent upstream ⇒ every downstream context dead. Total vendor capture.
- Memory/Learning is a **shared kernel** across all contexts — classic liability, amplified because the kernel is mostly a stub.
- Vendor SaaS contexts (Flow Nexus, sublinear, E2B) are Separate-Ways candidates bundled in anyway.
- **The inversion PublicDigit needs:** conform to the *native platform's* published language (Claude Code skills/hooks/subagents/settings) — unavoidable and cheap; never to a third-party runtime on top of it — avoidable and expensive.

## 6. Architectural Patterns Observed

Reusable: hook system (Observer) · single-dispatcher (Front Controller/Mediator — own the payloads) · registry-by-convention · command pattern · template method (with discipline). Anti-patterns for us: platform-as-vendor-adapter (facade over an external product = where lock-in lives) · blackboard shared memory · autonomous background daemons (contradicts confirm-before-state-change) · **zero tests for the platform's own 40 helper scripts** (the platform that preaches TDD ships none).

## 9. Risks Register

- **Governance:** fabricated-evidence pattern would poison an evidence-based culture; `adr.autoGenerate: true` violates the human-review rule; opaque metrics with authority (auto-rollback) are unaccountable actors.
- **Maintenance:** 346 unowned vendor files drifting with an alpha upstream; dead vocabularies (Roo/Cline) show the rot rate; internal duplication guarantees divergence (v1/v2 copies already differ).
- **Vendor lock-in / supply chain:** settings whitelist `Bash(npx claude-flow*)` pre-authorises executing whatever npm serves under that name — disqualifying for an election platform.
- **AI-specific:** capability roleplay (prompts asserting nonexistent powers induce confident fictional narration; hooks printing success for no-ops train false claims); context pollution (300+ files of orchestration vocabulary crowding out constitutional language); autonomous daemons contradicting confirm-before-state-change discipline.

## 10. Measurable Success Criteria for the Target Platform

1. ≤ ~80–100 governed files; every file traceable to exactly one capability.
2. Zero capabilities with two implementations.
3. Zero external runtimes; no pre-authorised third-party `npx` permissions.
4. **Honesty invariant:** every reported score/verdict derived from an executable check that exists in-repo (fitness-testable — no literal numbers in reporting scripts).
5. New architect operational from ≤3 documents within one session.
6. No model-specific behaviour tricks.
7. Platform-as-product: every capability has an owner, one-line responsibility, declared dependencies (lintable).
