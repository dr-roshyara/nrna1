### ⛔ Sequencing inference withdrawn — one of three blockers survives

**The Board declined to accept *“WP-4B is the last of four builds”* as established and commissioned a dependency verification. It was right to: two of the three prerequisites do not block WP-4B at all.**

**P1 — `Jurisdiction`: does not block.** What R-73 requires of WP-4B is that `receiveRulingDecision()` **accept** the value and the concluded state **retain** it — **a signature and a field, both inside `Adjudication/Application`, needing no port, no adapter and no crossing.** **Who calls the method in production is WP-4D's concern; what it accepts is not.** The roadmap does not make the intake port a prerequisite. *(One scope question flagged and not decided: is widening that signature WP-4B's work?)*

**P2 — `EvidenceEnvelopeRef`: does not block construction.** The value **already flows into the PM as a string** — `admitEvidence(ChallengeRef, string $reference)`, and the house test data is literally `'envelope-sha256…'`. **The admitted reference *is* the envelope hash**, and the concluded state retains them. **The gap is a producer, not a type.**

> ⭐ **And the deferral is neither new nor caused by R-74. EPIC-004K §8 — an accepted artifact — already says it:** *“Evidence admission arrivals — upstream satisfaction of demands **(transport counterpart deferred; see §14)**.”* **R-74 named the owner of an old dependency; it did not create a new one.** That gap bites at WP-8's full-loop proof, not at WP-4B's construction.

**P3 — `ContestedOutcomeRef`: this one blocks, and it is the only one.** Adjudication holds the type and nothing populates it · `ChallengeRouted`'s payload lacks it · `ChallengeRaised` is not published · `openFor(ChallengeRef)` takes identity alone · **no interim stand-in exists** — unlike P2, there is no field, admission path or string already flowing. **`IssueDeterminationCommand` cannot be constructed.**

**P3 is also the one place a roadmap/allocation question genuinely arises:** publishing `ChallengeRaised` is **Contestation-side work no current work package covers** — §WP-3's scope was publication of `ChallengeRouted`, a different event. **Whether it becomes a WP-3 slice, a WP-4 slice or its own package is the Board's allocation decision, and architecture proposes none of them.**

**The governance decisions stand unchanged. Only the sequencing inference drawn from them was wrong, and it was mine** — I turned three ownership decisions into a dependency graph without testing whether each dependency was real.
