## Decisions (PO, this session)

- **D1** Verification window: SetupAdministration → VotingActive.
- **D2** Authority: the Chief or Deputy Chief **of the election**. The intended concept is the Election Committee leadership; v1's technical source is election-scoped `election_officers` behind a port. It is not the acceptance Committee (EM-GOV-029). Formalisation is follow-up G10.
- **D3** Evidence fields.
- **D4** Policy lock from ReadyForVoting, enforced in both the application and the model.
- **D5** A confirmed suspension revokes the evidence's *current effect*.
- **D6** 1 story, 4 slices.
- **R3** Voter Admission card with a dedicated endpoint; transition-specific impact; additive UI keeping the legacy Verify; "Suspend Identity" = the existing two-person Propose; reinstatement **and** re-verification are both required.
- **"Admission" terminology:** keep the names and record the mapping (EM-ENT-003 "admission" = Registration). The rewording is PO terminology debt G11.
- **`show()` semantics:** `isEligible` = `standingOf()`, `canVote` = `decide()` ∧ ¬hasVoted. The lifecycle is used for display and logging only.

## Problems

- The first regression design (`git stash`) was blocked by permissions. The PO chose an isolated worktree.
- The shared `vendor/` autoloader and the PHPUnit binary resolved to the **main** tree, so the "before" run would have tested C1 code. This was caught by a probe and fixed (worktree-local `vendor/composer`, `autoload.php`, `phpunit` and `bin`) before any result was collected.
- **Deviation (C0):** the existing-story search for PBDIGIT-213 checked only `PBDIGIT-*.md` files and missed **`PBDIGIT-201`** (a README row: *"Starting the vote still hides a valid voter's membership behind the ambient tenant"*). C1's `start()` change resolves that defect (pinned by `VotingEntitlementUnificationTest::test_start_does_not_depend_on_the_ambient_tenant`). 201's status is **not** changed by engineering; it is recorded for PO acceptance.
- **Security observation, outside scope:** `.env.back_20260419_0138` and `.env.backup-laravel12` are **tracked in git** and may contain credentials (not opened). This needs a PO/ops decision.
- Pre-existing test-estate failures (fixture clusters A–D) are unchanged; they are not owned by PBDIGIT-213.
