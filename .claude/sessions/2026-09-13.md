# 2026-09-13 — Ballot Preview feature + two follow-on voting-flow fixes

## Summary

Implemented the Ballot Preview feature end-to-end via TDD (plan: `.claude/plans/encapsulated-hopping-hamster.md`), then two smaller fixes surfaced during the manual review of it. All three landed as separate, independently-reviewed commits, with a hand-constructed hunk-level staging process so each commit contains exactly its own topic and nothing from the other two.

## Completed

1. **`4865caf15` — Ballot Preview / BallotAssemblyService extraction.**
   - Extracted `VoteController::create()`'s real-election ballot query/mapping logic into `app/Services/BallotAssemblyService.php` (`buildNationalPosts`/`buildRegionalPosts`/`buildElectionProp`), verified behavior-preserving via a dedicated characterization test written before the extraction.
   - New read-only, interactive-but-non-submittable **Ballot Preview**: `Election::canBePreviewed()`, `OperationCapabilityMapper`'s `preview_ballot` capability, `BallotPreviewController`, route `organisations.elections.ballot-preview`, `Vote/BallotPreview.vue` wrapper, `CreateVotingPage.vue`'s new `previewMode` prop (single authoritative gate for submission/draft-autosave).
   - Voter Hub gets a "Preview Ballot" quick-action tile (`can_preview_ballot`).
   - Bundled prerequisite: `ElectionScenarioFactory::votingActive()`'s `voting_locked` fixture fix (previously separately approved as "Boundary B").
   - Tests: `BallotAssemblyServiceTest`, `BallotPreviewTest` (lifecycle reachability, full auth matrix, region data-shape, demo 404, side-effect/idempotency, direct-POST submission-impossibility), `VoteControllerBallotAssemblyRegressionTest`, plus two `OrganisationVoterHubTest` cases.
   - Developer guide: `developer_guide/ballot_preview/01_ballot_assembly_service_and_preview.md`.

2. **`81aa13b83` — national-only election: no false regional-candidates warning.**
   - Found during the manual walkthrough: a voter with a `region` set saw "no regional candidates available" even on a purely national-only election. Added `has_regional_posts` to `VoteController::create()`'s `$electionProp`; `CreateVotingPage.vue`'s `hasRegionButNoPosts` now requires it to be `true` before considering the voter's own region.
   - Test: new national-only-election case in `VoteControllerBallotAssemblyRegressionTest`, plus `has_regional_posts` assertions added to the two existing tests.
   - Developer guide: `developer_guide/ballot_preview/02_national_only_regional_warning_fix.md`.

3. **`57ac18eeb` — Receipt Codes made committee-only, removed from Voter Hub.**
   - Raised directly by the user: the Receipt Codes page (full randomized voter-code list) had no authorization beyond `results_published`, and Voter Hub linked to it for any org member. Added `$this->authorize('viewResults', $election)` to `VotingReceiptController::index()`; removed the Receipt Codes tile/CTAs from `VoterHub.vue` (it already has its own link in Voter Management); renamed "Verify Vote" → "See Your Vote".
   - Test: new negative-authorization test in `VoteReceiptVerificationTest`, plus a `results_published_at` field test in `OrganisationVoterHubTest`.
   - Developer guide: `developer_guide/ballot_preview/03_receipt_codes_committee_only.md`.

## Decisions

- **Strict TDD checkpoints throughout**: RED test written and shown before any production code, at every stage (BallotAssemblyService extraction, Ballot Preview feature, both follow-on fixes).
- **"No unintentional behavioral change"** as the governing principle for the extraction — any discovered improvement opportunity was reported separately (Current behavior / Proposed change / Why / Tests required / Impact) and only implemented after explicit approval, never silently bundled in.
- **Three separate commits, not one.** Even though all three landed in the same session, they are independently revertable topics. Where a single file mixed material from more than one commit (`VoteController.php`, `CreateVotingPage.vue`, `OrganisationController.php`, `VoterHub.vue`, two test files), staging was done via hand-constructed blob content (`git hash-object` + `git update-index --cacheinfo`) rather than `git add -p`, verified against HEAD with `git diff HEAD -- <file>` before every commit to guarantee no cross-topic leakage.
- **Build assets (`public/build/assets/*`, `manifest.json`) deliberately left uncommitted**, per this repo's existing convention of a separate `chore(build): npm run prod` commit.

# 2026-09-13 (continued) — Election lifecycle constitutional migration: Counting-derivation fix (Slice A) + `complete_nomination` migration (Slice B)

## Summary

User reported a real election (`testing-1-0c715071`, later also `onf-europe-test-7891ba99`) that jumped from `setup_nomination` straight to `voting_active`/`counting` after clicking "Nomination Complete," with voting dates already in the past and no way to revert. Investigated read-only first (no code/data changes) via `tinker`, producing two migration-conflict reports establishing that the codebase has two lifecycle authorities — the legacy, fact-derivation `ElectionLifecycleEngineImpl::getState()` and the constitutional `Election::transitionTo()`/`ElectionConstitution` mechanism — and that `complete_nomination` was the one remaining constitutional action still running the old, pre-constitutional code path with none of the Guard's protections. Two slices followed, both TDD-first, each characterized before any production change.

## Completed

### Slice A — Counting-derivation invariant (committed: `e023b6555`)
`ElectionLifecycleEngineImpl::getState()`'s Counting-derivation rule now also requires `voting_locked === true` (previously: `approved_at !== null && administration_completed && nomination_completed` alone was sufficient) — closing the path by which a stale/past voting window plus a legacy `completeNomination()` call could make the engine derive `Counting` even though `open_voting` was never invoked. Exactly one production line changed; two new characterization tests added to `ElectionLifecycleEngineTest.php`; `ElectionScenarioFactory::votingClosed()` and two inline test fixtures synchronized with the new fact.

### Slice B — `complete_nomination` → constitutional migration (uncommitted — see Status below)
Migrated `Election::completeNomination()` from an inline-guard legacy method to `transitionTo(Transition::manual('complete_nomination', ...))`, and added a parallel `auto_complete_nomination` constitutional action for the system/grace-period path (`ProcessElectionAutoTransitions::processAdminToNominationTransition()` now calls `transitionTo(Transition::automatic(...))` instead of the legacy method). New shared authority `app/Application/Election/Services/NominationCompletionPredicates.php` (`hasApprovedCandidates`/`hasNoPendingCandidacies`, both `withoutGlobalScopes()` for system/console execution) is the single source consumed by both `ConstitutionalTransitionGuard` (human path) and `Election::validateCompleteNomination()`/`validateAutoCompleteNomination()` (both paths, since `validateTransitionRules()` runs regardless of trigger). New `applySideEffectsForCompleteNomination()` shared by both actions; `NominationCompleted` wired into `transitionTo()`'s event-dispatch match — the invariant "completing nomination must never itself set `voting_locked`" is preserved exactly (open_voting remains the sole setter on the human path).

An investigation midway through implementation surfaced that this migration adds a genuine new authorization boundary (the Guard's chief/deputy role check, previously absent from the direct model method) to every direct/programmatic caller. A full architect-review (production call graph, comparison against every other already-migrated action, ADR-001 + the 2026-08-12 ARB-accepted rule-ownership map, actor-identity semantics) confirmed this is the intended, ADR-001-backed behavior, not an accidental leak — and, critically, established that only 4 of the 27 initially-failing pre-existing tests were actually caused by Slice B; the other 23 were pre-existing, unrelated staleness (a legacy raw `state`-string fixture pattern already broken for `complete_administration`/`open_voting`/`close_voting`/`approve`/`publish_results`, none of which this slice touched). Fixed exactly the 6 genuinely-affected tests (4 in `ElectionStateMachineTest.php`, 2 in `StateMachineTransitionAuditTest.php`) with mechanical fixture corrections (real derivation facts instead of a stale `state` string, `actingAs()` + an active chief `ElectionOfficer`, and one exception-type update where precondition failures now surface via the Guard) — no assertion was weakened.

## Decisions

- **TDD-first with characterization before migration** for both slices — `ElectionLifecycleEngineTest.php` (Slice A) and `CompleteNominationCharacterizationTest.php` (Slice B, 12 tests against the unmodified legacy method) were written and shown RED/GREEN before any production change.
- **Option A approved**: migrate both the human (`complete_nomination`) and system (`auto_complete_nomination`) paths coherently in the same slice, rather than leaving the system path as a non-constitutional "compatibility shim" (an earlier "Option 7a" proposal was explicitly rejected for creating a second business-rule authority).
- **Shared predicate authority approved**: `NominationCompletionPredicates`, consumed by both the Guard and the domain validate hooks — one definition, two consumers, `withoutGlobalScopes()` required (not decorative) for the console/no-tenant-context caller.
- **Role enforcement on `complete_nomination` accepted as intentional** (Option A of a second architect review): backed by ADR-001 (`docs/architecture/decisions/001-constitutional-capability-sovereignty.md`) and the ARB-accepted rule-ownership map (`docs/publicdigit/reviews/2026-08-12-election-constitution-authority-investigation.md`), which explicitly places "who may act" inside `ElectionConstitution`'s authority, not the HTTP boundary alone.
- **`test_complete_nomination_locks_voting_on_start`** (`ElectionModelLockAndAuditTest.php`) is a separate, pre-existing, latent test defect — it asserts `completeNomination()` sets `voting_locked = true`, which the legacy implementation never actually did and which directly contradicts the Slice A/B invariant. Deliberately left untouched; deferred to a possible future Slice C.
- **The 23 remaining pre-existing test failures (RC1/RC2, in `ElectionStateMachineTest.php`/`StateMachineTransitionAuditTest.php`/`ElectionModelLockAndAuditTest.php`) are explicitly out of scope** and were not touched — they predate this session and involve actions this slice never modified (`complete_administration`, `open_voting`, `close_voting`, `approve`, `publish_results`) plus unrelated assertion/message mismatches.

## Problems

- Discovered (read-only, not yet acted on): `Election::enforceVotingLock()` is a second, pre-existing, explicitly-documented "infrastructure enforcement... bypasses the constitutional state machine intentionally" writer of `voting_locked`, called from **two** separate places in `ProcessElectionAutoTransitions` — `processNominationToVotingTransition()` (auto-locks voting once nomination is done + grace period elapsed + no pending candidates, i.e. a self-service auto-open-voting equivalent that never touches `open_voting`/the Constitution at all) and its own `enforceVotingLock()` private wrapper (seals an already-expired voting window that was never explicitly closed). This means the eventual Slice C invariant statement needs to be "only `open_voting` (human) or the grace-period auto-transition equivalent (system) may set `voting_locked` — never `complete_nomination`," not simply "only `open_voting`." Recorded here and in `.claude/MEMORY.md`; no files changed as a result of this finding.
