## Consumer 1 — ElectionMiddleware (Election Context Resolution)

**The consumer the 58A observer proved live**, reading `is_active` (severity `strict` — the enforcement-escalation blocker).

**Discovered before editing:** 16 routes traverse it — 12 demo + **4 real voting routes** (`/vote/create`, `/vote/submit`, `/vote/submit_seleccted`, `/vote/verify`). And `is_active` is **another conflated field**: real elections → "voting open now" (lifecycle question); demo elections → "demo platform switched on" (platform toggle, outside the constitutional lifecycle per the demo/production policy-contexts ADR; their `voting_*` are NULL so the engine says `draft` — PBDIGIT-59).

**Migration boundary drawn between the two Priority-4 queries:**
- Real branch (`:113-116`) → `ElectionLifecycle::of($e)->isActive()` (DeprecationPolicy's documented replacement for `is_active`).
- Demo fallback (`:127-130`) → **intentionally NOT migrated**; marked LEGACY COMPATIBILITY with the reason in the code. Migrating it would return `draft → false` for every demo election and take down the demo flow until PBDIGIT-59 settles.

**Behaviour preservation, measured not asserted (fresh sessions, before vs after):**
| Route | Before | After |
|---|---|---|
| `/vote/create` (no slug) | 500 — pre-existing `Route [vote.direct] not defined` in VoteController; Demo Election attached | **identical** |
| `/demo/vote/create` | 302 → `/demo/code/create` | **identical** |

**Both-directions domain proof:** a real election with `is_active=false` + open window IS selected by the new branch; `namaste 2026` with stale `is_active=true` + `results_published` is NOT (the legacy branch would have chosen it).

**Pre-existing defects recorded, not fixed:** the `/vote/create` 500 (`Route [vote.direct]`); stale `is_active=true` on namaste 2026.

## Consumer 2 — SitemapController::elections() (Public Discoverability)

`Election::where('is_active', true)` → lifecycle `isVotingPhase()` (ReadyForVoting ∥ VotingActive), matching the code's own stated intent — it already styles "active" and "upcoming" entries separately, and those are exactly the two states.

**Pre-existing oddity found and preserved, not fixed:** the elections sitemap has been emitting an **empty document for every public request all along** — `TenantContext` doesn't run on sitemap routes, so the `BelongsToTenant` scope filters everything for sessionless crawlers. Before: 0 URLs. After: 0 URLs, valid XML, HTTP 200. The `is_active` read was dead weight on a scope-blanked query.

**Predicate proven both directions** (in-memory models, no HTTP): `is_active=false` + open window → **IN**; `is_active=true` + no window → **excluded**.

**Recorded, not fixed:** a sitemap that structurally cannot list anything is arguably a defect (SEO feature with zero output) — but making it list things means deciding scope semantics for public requests, which is not this migration's call.
