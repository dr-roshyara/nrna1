## Artifact ingestion rule (AI-sourced supporting material) — adopted 2026-07-28
- **Rule:** material the user feeds in — AI outputs (Gemini/ChatGPT/etc.), articles, research papers, notes, brainstorming — is **supporting input**, never a governed repository artifact by itself. Claude must read/evaluate it, extract evidence/findings/hypotheses, classify per the project's governance, and produce a **new** governed artifact with correct Kind/Authority/Status/Provenance metadata — never copy supporting material directly into a governed artifact. Provenance is preserved by reference (pointing at the raw file), not by embedding the source's review commentary inside the governed artifact. **Exception:** if the user explicitly states a document *is itself* the governed artifact, follow that instruction instead.
- **Why this exists:** surfaced when a raw Gemini-output file (`architecture/ai_architecture/documentation/what_gemini_suggested.md`) turned out to carry review commentary — including a simulated "if I were chairing the ARB, I would approve…" verdict — appended directly after the actual discovery content with no marker separating the two. Submitting it as-is to a real ARB would have let simulated-authority text ride along inside a candidate artifact (session log 2026-07-28, PKS track).
- **Placement scope note (same event):** for AI-engineering artifacts specifically, only `./engineering` and `./docs` are treated as official/governed locations — `./architecture` (repo root) is not, even though EM-001 groups `docs/`+`architecture/` as "Product" namespace generally. Narrow scoping, not an EM-001 override.
- **Wording discipline:** provenance/scope notes in a governed artifact must read as *descriptive* ("only X constitutes this artifact; Y is preserved as supporting material"), never *procedural* ("per [date] instruction, Y is excluded") — the latter reads as if content was altered after the fact rather than stating the artifact's scope.
- **How Claude uses this file:** read MEMORY.md + CONTEXT.md at the start of every task (existing Workflow rule below); precedence on conflict is **user instruction > repository governance (Constitution/Standards/ADRs) > this memory > default behavior** — memory is a hint layer, never authority (consistent with "MEMORY holds hints only," above). When a new stable convention like this one is established mid-work, record it here rather than letting it live only in a session log.
- **ENFORCED, not just stated (2026-07-28):** project knowledge may never go to global Claude storage. Two controls in `.claude/settings.json` — (1) `"autoMemoryEnabled": false` disables the auto-memory system entirely (read AND write); (2) `.claude/scripts/project-knowledge-guard.sh` is a **blocking** PreToolUse(Write|Edit) hook (exit 2) denying writes under `$HOME/.claude/{projects,plans,memory}/`.
