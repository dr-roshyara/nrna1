# What the Migration Plan Must Solve

## 1. Single Authority Resolver

This is now the biggest technical design point.

Current risk:

```text
workflow-state.php
        |
        v
path A


session-resolve.php
        |
        v
path B
```

Future requirement:

```text
Any reader
Any writer
      |
      v
Authority Resolver
      |
      v
Governance Evidence Location
```

One resolution mechanism.

No hidden second authority.

---

## 2. Safe Migration Order

The plan must preserve:

```text
1. Inventory
        ↓
2. Create durable location
        ↓
3. Copy bytes
        ↓
4. Verify hashes
        ↓
5. Switch authority path
        ↓
6. Demote runtime copy
        ↓
7. Remove obsolete runtime copy
```

The key invariant:

> Durability before demotion.

---

## 3. R-CONFLICT Operationalization

Already decided:

```text
Do not:
- delete history
- pick one side silently
- rewrite sequence
```

Migration interpretation:

If:

```text
Old record
     +
New record
```

are compatible:

```
merge preserving both
```

If:

```
same sequence
different content
```

then:

```
preserve both
record conflict
escalate
```

---

## 4. Migration Evidence Location

Important new point:

The migration itself creates governance evidence:

Examples:

* inventory report
* hash verification
* migration result
* reconciliation record

Those cannot live only in runtime.

Otherwise:

```
Migration proves durability
but its proof is not durable
```

which defeats B′.

# 4. Prevents Expensive Architecture Drift

A common enterprise problem:

Team A implements one interpretation.

Team B implements another.

Why?

Because the original decision context was lost.

Example:

Original decision:

```
Receipt identity ≠ receipt authority
```

Later developer interprets:

```
receipt_id = trusted identity
```

Without governance evidence:

The drift is hard to detect.

With durable evidence:

Architecture rules remain visible.

Business impact:

✅ fewer redesigns
✅ fewer incompatible implementations
✅ reduced technical debt
