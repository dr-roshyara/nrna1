## 1 · The problem in plain terms

Two research documents, saved the **same day** (2026-09-02) into the **same directory**
(`docs/knowledgeos/brainstorming/mathematical_ideas_that_can_be_implemented/`), both build a formal
apparatus for **the same kind of question — "how do we decide whether a claim/state satisfies a
requirement, and what must be recorded to preserve the reasons that decision depends on?"**

- **One thread** (`M0043`→`M0132`, the `K_t`/`Δ_t` lineage this reconstruction has itself been
  working from since `MD-057`) defines `Sat(K,EC_t)` as a bare boolean predicate and freezes only its
  *shape* (`Δ_t={r∈Req(EC_t):¬Sat(K_t,r)}`), explicitly leaving the predicate's own body open.
- **The other thread** (`M0127`, `KR-CONTR-FDE-2026-09`) runs a real, executed 14-scenario experiment
  asking exactly the *sibling* question — does a proposed evaluation representation preserve the
  distinctions a claim's standing actually needs? — and reaches a specific, well-evidenced answer:
  bare values are never enough; a `Reason`/`Provenance`/`Context`/`Condition` boundary channel is
  required alongside any value channel, or required distinctions collapse (its own measured range:
  Classical loses 12/14, K3 loses 8/14, FDE loses 6/14, only a structured representation reaches 2/14).

**Neither document cites the other.** Nothing in either file's own text signals that a directly
relevant sibling experiment exists a few files away, dated the same day.

## 2 · Why this is a business problem, not a one-time curiosity

**a. The gap was found only by accident of a later reader, not by either thread's own discipline.**
This reconstruction built and validated a `Sat*` construction (`MD-061`) using only the `K_t`/`Δ_t`
lineage's own material — the exact material `M0127`'s own finding bears directly on — and only
discovered `M0127` because the user separately pointed to it after `MD-061` had already been written
and frozen. Had the user not done so, the gap would have stood unnoticed.

**b. The two threads' own conclusions are in tension, not agreement, which makes the omission
consequential rather than merely untidy.** The `K_t`/`Δ_t` lineage's own later `Sat*` construction
(this reconstruction's own `MD-061`) uses a bare value-membership predicate — precisely the
representational shape `M0127`'s own executed experiment, on the same day, found inadequate for a
structurally analogous question. A reader working from the `K_t`/`Δ_t` lineage alone has no way to
learn that a sibling experiment already tested — and refuted — the adequacy of exactly this shape of
representation.

**c. Both threads are otherwise disciplined; the gap is structural, not a quality failure of either.**
`M0127` is a genuinely rigorous, executed, countermodel-backed experiment. The `K_t`/`Δ_t` lineage is
the frozen, governance-ratified backbone this whole reconstruction has been working from. Neither
lane did anything wrong — the same directory simply holds two independently-developed answers to
adjacent questions, with no mechanism connecting them.

**d. This is the same failure shape this reconstruction has already found and recorded once, one
level up** (`EKS-28`: two governance commissions on sibling kernel questions never cross-referencing).
Here the pattern recurs one layer down, between two **research** documents rather than two governance
commissions, inside the very same, single directory — arguably a tighter, more surprising instance,
since both files sit a few keystrokes apart in the same folder rather than in separately-governed
tracks.

## 3 · What is *not* the problem

⛔ **Not a claim that `M0127`'s own findings are correct and the `K_t`/`Δ_t` lineage's are wrong**, or
the reverse. `MD-062` used `M0127` only as a structural analogy, never as direct proof against `Sat*`.

⛔ **Not a call to merge the two apparatuses**, or to have one thread adopt the other's vocabulary.

⛔ **Not a claim that this is the only such pair in the directory.** `mathematical_ideas_that_can_be_
implemented/` holds hundreds of same-day files; this is the one pair a reader happened to compare.

## 4 · Candidate requirement (a direction, not a design)

> **When a new research document proposes an evaluation/satisfaction/representation-adequacy
> construction, a lightweight check — does another same-day or nearby document already test the
> adequacy of a structurally similar representation? — would surface pairs like this one before, not
> after, a later reconstruction builds on the un-cross-checked half.**

The cheapest version costs one keyword pass per new "evaluation adequacy"-shaped document against its
own same-day neighbors — not a general reconciliation of the whole directory.
