## D9: an exact authoritative kernel, with approximation only in labelled projections

- **Principle (approved in principle).** The authoritative kernel is exact for **designated critical decisions**. Any approximation (forecasts, ML, belief summaries) lives only in **explicitly labelled projections**.
- **Not decided** (requires stakeholder agreement before implementation):
  - the list of critical decisions;
  - who designates them;
  - how a projection is labelled and consumed.
- **Theory status.** O5-1 shows that, *once exactness on all histories is demanded*, a recursive kernel is exactly sufficient. The **demand itself is the normative choice.** It is not derived from the theory (internal review, 1900 §9.1).

## D10: record decision-relevant outcomes, subject to privacy and data minimization

- **Principle (approved in principle).** The system records the decision-relevant outcomes needed to explain its actual behaviour, subject to privacy and data-minimization requirements. Questions about alternative paths not taken need an explicit stakeholder justification.
- **Not decided:**
  - which outcomes are "decision-relevant";
  - the retention policy;
  - the privacy rules.

## A theoretical note for D10 (analytical; PROVED by Session B, **not yet internally reviewed**)

**Proposition D10-1 (coarsest sufficient input record).** For required decisions 𝔇 over the input alphabet Σ, define

a ≈ b iff d(h a w) = d(h b w) for all h, w ∈ Σ\* and all d ∈ 𝔇.

Then:
1. ≈ is an equivalence.
2. Recording only the class [a]_≈ of each input preserves every required decision.
3. ≈ is the **coarsest** letter-wise abstraction with this property.

*Proof sketch.*
- (1): reflexivity and symmetry are immediate; transitivity holds by chaining equalities.
- (2): replace the letters one position at a time; each replacement preserves every d(…).
- (3): any valid abstraction identifies only letters that satisfy the defining condition.

**Consequences, stated as hypotheses.**
- **Data minimization has a canonical letter-wise optimum** relative to 𝔇, where 𝔇 includes the explanation and audit decisions.
- Recording **more** than [a]_≈ is justified only by a further decision.
- If a privacy rule demands a record **coarser** than [a]_≈, the decisions and the privacy rule are **jointly infeasible**, by the same argument as R4(c). That conflict is visible before any implementation.
- **Caveats:**
  - Context-dependent abstractions, which record an attribute only in some states, can be strictly coarser overall. Their optimum is the kernel transition itself, so the letter-wise result is a bound, not the whole story.
  - Attribute-wise minimal records (which fields to drop) need not be unique, by the same argument as C-2.
- **Status:** analytical. It goes to the next internal-review batch and to the external review.
