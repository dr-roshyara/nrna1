# 15 — Falsification Conditions (Part XXII)

Every "irreducible" claim carries a conceivable falsifier. A claim without one is not a result.

| # | Claim | Falsifier — what would refute it |
|---|---|---|
| F-1 | `Observe` is primitive (`world-contact`) | Exhibit a typed composition of the remaining operators that yields an `Observation` carrying empirical content about the world. Would require some other operator to introduce world contact — i.e. would violate property P7 (no information creation) or be smuggling. **Refuting this refutes P7.** |
| F-2 | `Interpret` is primitive (`meaning-assignment`) | Show that the context index can be recovered downstream from an unindexed encoding. §12 measures the loss at exactly 1.000 bit and the DPI forbids recovery — so the falsifier must attack the *model*: show that context need not be attached at the meaning step (variant V1 does exactly this, and under V1 `Interpret` becomes derivable *from* `Represent`). |
| F-3 | `Represent` is primitive (`symbolic-encoding`) | **Already falsified under V1**, where encoding and meaning are one atom. Survives only if the corpus distinction `Observation ≠ Proposition ≠ Knowledge` is load-bearing at *both* steps. Decisive test: exhibit a KnowledgeOS operation that must act on semantic content *before* encoding, or one that must act on an encoding whose meaning is not yet fixed. |
| F-4 | `Relate` is primitive (`relational-linking`) | Construct a `Relation` as a `Claim` produced by `Infer` over a rule that asserts the link. This requires an explicit rule carrier supplying the relation type; if such rules are ambient in KnowledgeOS, `Relate` collapses into `Infer` + `Rule`. **Not tested here — a real open falsifier.** |
| F-5 | `Discriminate` is primitive (`difference-decision`) | Show the *Buddhi* vocabulary (different / contradictory / more-specific / superseding / compatible / incomparable / unknown) is computable from `norm-comparison` plus `entailment` alone. Note the LOO result already "falsifies" it degenerately via `DetectGap` — which is why V4 exists. |
| F-6 | `Hypothesize` is primitive (`content-generation`) | Exhibit a composition producing content **not entailed** by current content without a generation atom. Since `entailment` is by definition entailed, this requires either a new atom or smuggling into `Infer` (probe run, rejected). Strongest falsifier: argue that KnowledgeOS never needs non-entailed content — which would delete C6, C19, C20 and scenarios S5, S7, S8, S14. |
| F-7 | `Infer` is primitive (`entailment`) | Show that `Validate ∘ Hypothesize` (generate-and-test) suffices. **This experiment says it does not**, but only because `Claim` is typed as producible solely via entailment (§06). Falsifier: show KnowledgeOS never requires the DEDUCTIVE warrant kind, only the evidential one. That is a *substantive* epistemological claim and it is genuinely open. |
| F-8 | **`DetectGap` is derivable** | Exhibit a required capability delivered by `DetectGap` that `{Determine, Discriminate}` cannot deliver — e.g. a gap notion not expressible as a decided difference against a normative target (an *unknown unknown*). Corpus Zero-finding #3 says the system can only expose "evidence of incompleteness", which *supports* the derivation; a counterexample would have to overturn that finding. **Survived 8/8 variants including V4.** |
| F-9 | `Challenge` is primitive (`adversarial-negation`) | Show a `Defeater` obtainable from `Hypothesize` (generate a competitor) + `Discriminate` (prefer it). Not tested here — plausible and important. **Real open falsifier.** If it succeeds, P10's protection would have to be re-sited. |
| F-10 | `Validate` is primitive (`warrant-assessment`) | Show warrant is computable as `Discriminate` over `{claim, defeaters}` given evidence. Under V6 a verdict already *requires* a surviving-defeater step, halfway to this. **Real open falsifier.** |
| F-11 | `Revise` is primitive (`state-mutation`) | Show that commitment to `K_t` is an infrastructure concern rather than an epistemic one — i.e. that the kernel's output is a *proposal* and committing is another context's job. Would demote `Revise` from kernel to orchestration. `[OPEN]` — §13 flags this as genuinely ambiguous. |
| F-12 | `Determine` is primitive (`closure-judgment`) | **Already falsified under V3**, where adequacy is `difference-decision` over the norm delta w.r.t. requirements. Survives only if closure carries something a difference verdict does not — plausibly the *epistemic contract* `EC`. Decisive test: is `EC` reducible to a requirement set? |
| F-13 | `Select` is primitive (`preference-over-actions`) | **Already falsified under V5**. Survives only if choosing under an objective is more than deciding a difference. Also open on the *other* side: `Select` may belong to a neighbouring bounded context entirely (§13). |
| F-14 | `Qualify` is primitive (`evidential-qualification`) | Show evidence status is derivable from meaning + warrant, i.e. that `Interpret` then `Validate` suffices with no separate admission step. This would contradict both the corpus `G1` record and the protocol's constraint 9. |
| F-15 | **All 14 atoms are irreducible** | Fuse any two atoms into one and show no capability distinction is lost. V1 does exactly this for `meaning`/`encoding` and **no capability was lost** — so this claim is already *conditionally* falsified, and holds only relative to the declared capability model. Reported honestly in §16. |
| F-16 | The kernel is better described as `(𝒫, ℛ, δ)` than as an operator set | Exhibit a required capability that depends on the *packaging* — something two kernels with identical atoms but different operator groupings do differently. This experiment found none, but did not search hard for one. `[OPEN]` |
