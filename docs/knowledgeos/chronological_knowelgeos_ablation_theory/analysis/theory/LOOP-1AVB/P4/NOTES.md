# Coding notes: hard or ambiguous events

Conventions: quotes have their markdown bold markers removed, and `...` marks an omission. Session-log excerpts are coded source_act NONE because a log reports acts and performs none itself. For the same reason, dual is NO for log excerpts.

- **E01**: The anchor is the annotation on R-81..85, but only the R-81 and R-83 annotations are in SOURCES (R-82/84/85 are missing). The annotation records the adoption performed by R-86 and also carries an earlier refusal of self-adoption ("PREPARED RULINGS AWAITING ADOPTION"). Both count as ACT_OBSERVATION. dual is YES because the annotation (ANNOTATE) also states a norm about adoption ("One sentence of confirmation from the authority converts these to ADOPTED").
- **E03**: R-91 was proposed for adoption and then HELD, so it counts as attempted-then-held (ACT_OBSERVATION). The row's own act is a determination on evidence, so I used OTHER:DETERMINE rather than ADOPT. It is dual because it also says "no repair is authorized".
- **E05**: R-89 is PREPARED and not adopted. I still coded it ACT_OBSERVATION because the row itself performs the authorization, even though its validity is pending. The row authorizes both planning and implementation; I chose AUTHORIZE-IMPL to match the event's operation.
- **E06/E07, E25 (S0804-L576)**: The target is UNK. The excerpt records a filing/numbering act ("filed as R-90"), a refused number (R-89) and a retirement (R-90). It also contains a general statement ("the register holds constitutional decisions") that could be read as GENERIC_PRACTICE. I coded ACT_OBSERVATION. E06 and E07 are identical duplicates and are coded identically.
- **E08/E09**: The opening is contested inside the row itself: it was placed under a "Recording Notes" heading, then filed as a ruling. The row still performs OPEN-WORK. dual is YES because it also sets a norm on implementation ("behaviour unchanged") and states that "a recording note cannot open a work package".
- **E10**: R-72 authorizes WP-4B "in principle" but says "IMPLEMENTATION DOES NOT BEGIN". TASK gives "does not begin" as an example of NORM_STATEMENT, so I coded NORM_STATEMENT/FORBIDDEN rather than attempted-and-held.
- **E11**: The commit is the RED start itself, so both observation and source_act are START. There is a tension I recorded but did not resolve: R-77 (same date) says "WP-4B REMAINS BLOCKED", yet this commit starts RED.
- **E13/E14, E31–E34, E36**: Authorizations to begin RED only grant permission. None of them records that RED was actually started, so all are NORM_STATEMENT and not ACT.
- **E15–E21 (R-36 → AST-013)**: TASK does not define RAISE. On that reading, R-36's "Promoted into AST-013" is ACT_OBSERVATION. If RAISE instead means raising an issue, these would be UNKNOWN. All seven are identical duplicates and are coded identically.

The word "methodology" does not appear, and the excerpt also names new items raised (O-CLOSURE-VOCAB). The ruling text itself could be coded GENERIC_PRACTICE instead.
- **E23**: I used the same RAISE reading as E15–E21. R-41 adopts a general rule, but the adoption is a particular act, so ACT_OBSERVATION rather than GENERIC_PRACTICE.
- **E24, E28**: SOURCES provides no source text for these anchors, so UNKNOWN. R-36 mentions ADR-MP-06 but says nothing about superseding it.
- **E26**: Supersession of ADR-T14 was raised as a question and expressly refused, which counts as proposed-then-refused (ACT_OBSERVATION). The row's own act is to adjudicate a characterization, so OTHER:ADJUDICATE.

R-94 is a disposition that selects the annotation, and the annotation itself was done elsewhere (IMPLEMENTATION_PROGRESS.md:58), so the row's act is OTHER:DISPOSE rather than ANNOTATE.
