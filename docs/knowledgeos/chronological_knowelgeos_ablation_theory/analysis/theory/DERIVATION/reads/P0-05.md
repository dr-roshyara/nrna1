- **[INT] What this batch contributes to the theory:**
  - [INT] Authority is separated from storage, existence and record presence. It becomes a claim-scoped, event-defined property: the transfer event, not a file position, and not "a location".
  - [INT] Evidence is stratified into claim, record and proof. Receipts evidence *toward* world-facts and *of* record-facts, and never independently prove the event (rule 7).
  - [INT] Capability existence is formalised as graded establishment (L1/L2/L3) with an observable trigger. Existence, authority and maturity are distinct, and existence precedes categorisation.
  - [INT] There is a four-layer ontology: Execution, Governance Evidence, Knowledge (interpretation), and Authority (PO/ARB). Derived state is never a second authority source.
  - [INT] A process epistemology appears: self-check ≠ assurance; author ≠ independent reviewer; ADDRESSED ≠ CLOSED; superseding a question ≠ overwriting an answer; history only as successive, visible acts.
  - [INT] The roles/DDD method holds that an operating role licenses no domain conclusion. Capability analysis proceeds through admissible categories rather than defaulting to a bounded context.
  - [INT] The same-day, non-authoritative brainstorms (S0156/S0155/S0159) propose a technical architecture: a modular kernel, hexagonal contexts, domain events, outbox, and selective event sourcing. They also name kernel primitives (Identity, Lifecycle, Version, Provenance, Relationships). This runs in parallel with, and largely ungrounded in, the governed track.
  - [INT] The brainstorms reuse governed terms (R-CONFLICT, Evidence Durability) with shifted meanings. This is a terminology drift risk between the governed record and brainstorming.
