 R-81 | 2026-08-04 | **REDRIVE FAILURE ISOLATION AUTHORIZED (Q4) — Execution Governance · Authorization · ARB.** **`AdjudicationProcessManager::redriveIssuance()` must isolate failures PER PROCESS.** **EVIDENCE:** decision package §5 — the method iterates `concludedAwaitingIssuance()` with no per-item error containment, so **one throwing process aborts the entire pass**; the query is `orderBy('concluded_at')`, so **the oldest stuck process starves every newer one indefinitely**. **The defect holds under crash models A, B and C alike**, which is why this ruling is reachable before Q1. **WHAT IT CHANGES:** one engineering slice is authorized inside the seam already authorized by R-72; **Batch 7's freeze is lifted FOR THIS REPAIR ONLY.** **WHAT IT DELIBERATELY DOES NOT CHANGE:** it **adopts no crash model** (that is R-83) · it **does not widen R-76** · and it **does not choose the mechanism**

 R-82 | 2026-08-04 | **THE ISSUANCE MARKER MEANS “A REQUEST WAS MADE” (Q3) — Architecture Governance · Adoption · ARB.** **`issuance_requested_at` records that an issuance request WAS MADE. It does NOT record that issuance was CONFIRMED.** **EVIDENCE:** R-76 excluded PM-6's issuance-confirmation half from WP-4B, so **nothing in this slice observes whether a `Determination` was written** — the meaning is **forced by the adopted scope, not chosen for convenience** (decision package §6). **WHAT IT CHANGES:** fixes the redrive predicate's meaning — *concluded, and no request yet made*. **ACKNOWLEDGED CONSEQUENCE, ADOPTED WITH THE RULING:** a marker of this meaning **CANNOT distinguish crash model A from model B**, because in both a request was attempted and in neither was the marker written. **That is a property of the adopted meaning, not a defect**, and it is why R-83/R-84 are needed. **WHAT IT DELIBERATELY DOES NOT CHANGE:** it does **not allocate PM-6's confirmation half** (that remains OPEN) · and it does **not rule that a confirmed-semantics marker would be wrong**

 R-83 | 2026-08-04 | **ALL THREE CRASH MODELS ARE IN SCOPE (Q1) — Architecture Governance · Adoption · ARB.** **WP-4B's redrive must recover crash models A, B and C:** **A** the conclusion committed and the issuance transaction never started · **B** the request SUCCEEDED and the marker was not written · **C** the request FAILED and the marker was not written. **EVIDENCE:** (1) EPIC-004K §11 seats the conclusion and the issuance in **separate transactions**, which is what creates all three windows — they are consequences of accepted architecture, not hypotheticals. (2) **A and C are indistinguishable in persistence** (same row, no determination), so any redrive recovering A necessarily recovers C; the live division is A/C versus B. (5) **B compounds R-81's defect** — a single model-B row would abort every redrive pass. **WHAT IT CHANGES:** the redrive's obligation is now fully specified. **WHAT IT DELIBERATELY DOES NOT CHANGE:** it **APPLIES §12 rather than superseding it** · it **reopens neither ADR-T1's transaction separation nor R-76's scope** (see R-84) · and it **chooses no mechanism**

 R-84 | 2026-08-04 | **§12's RECONCILE FALLS INSIDE WP-4B; R-76 IS NOT WIDENED (Q2) — Execution Governance · Adoption · ARB.** **Implementing §12's reconciliation is WITHIN WP-4B's existing scope.
