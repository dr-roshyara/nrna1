## C. New findings

**N-01 · MATERIAL (BLOCKING for every human-ref-gated step: independent-audit CONFIRMED, re-extraction, every exception terminal) · a "human reference" is any log section naming the F-ID**
- **Where:** `f_integrity.py:209-215`.
- **Evidence:**
  - [real] `human_ref_ok(ref,"F3082")` is True for F-LOG-0004, 0005, 0006, 0007 and 0008. These are planning, review, evidence and AI-remediation entries; several state "no decision recorded".
  - [exp A03] It is also True for an entry reading "This entry does NOT accept anything about F9001".
  - [exp A21] PLACEHOLDER→AUDITED passed with such a ref.
- **Why it matters:** C14 §2 and §4 make these references *human decisions*. The code turns every AI log entry into one. It also accepts sections inside fenced blocks.
- **Action:** require a dedicated, machine-readable decision line at column 0 outside fences and comments, e.g. `HUMAN-DECISION: <F-ID> <ACCEPT-L1|EXCEPTION-<STATE>|RE-EXTRACT> <run> <sha of the artifact accepted>`. Bind it to the artifact hash (for L1 acceptance, the CONTENT-EXTRACTED freeze hash). Optionally require that the line was added in a commit whose author is the human.

**N-02 · MATERIAL (before RECONSTRUCTED) · the in-lane chain is not tamper-evident against deletion or recomputation**
- **Where:** `f_integrity.py:75-127`.
- **Evidence:**
  - [exp A05] Delete the last line, edit the inventory, re-run CONTENT-EXTRACTED: accepted, chain VERIFIED.
  - [exp A04] Recompute `prev_hash`/`hash` by hand and append a full path to AUDITED: `f_status` VERIFIED, and the next F-ID becomes readable.
- **Why it matters:** the freezes (F-01), hypothesis immutability (C10 §7) and the audit verdict all live in this same forgeable file. Only git stops this, and R-COMMIT is not checked.
- **Action:** make R-COMMIT mechanical. Every gate should refuse unless the committed `HEAD:F-SERIES-STATE.jsonl` is a prefix of the working file and equals it minus at most the event being written; the same check applies to frozen artifacts. The hand-rolled chain then becomes largely redundant (see §8, proportionality).

**N-03 · MATERIAL (before RECONSTRUCTED) · the independent L1 audit has no completeness floor for the auditor**
- **Where:** `f_compare_inventory.py:44-85, 88-119`.
- **Evidence:** [exp A15] one auditor item against 4 extractor items gave 0 discrepancies and CONFIRMED.
- **Why it matters:** C13 §3 names this the decisive semantic control (F3082 is due [real]). It reports only what the auditor chose to extract.
- **Action:**
  - run `check_inventory`-equivalent coverage rules on AUDITOR-INVENTORY (every non-markup unit covered, and the cue/math bindings);
  - report the extractor's releases, dispositions and items per unit for review;
  - report category divergence per unit, not only group-absence.

**N-04 · MATERIAL (beyond D1) · hindsight re-entry**
- **Where:** `f_common.py:93-94`; `f_transition.py:82` skips the freeze check for AUDIT-FAILED; `f_transition.py:104` asks for a human ref only on CONTENT-EXTRACTED→CONTENT-EXTRACTED.

  - [exp A02] lines inside a ```` ````-fence containing an inner ``` ``` ``` fence approve, though they render as code;

**N-06 · MATERIAL (before the first later F-ID uses cross-file evidence) · AUDITED artifacts are never re-verified**

- **Evidence:** [exp A07].
- **Action:** require a valid `STATE.jsonl` OPEN record whose snapshot hashes match.

**N-08 · MINOR · lexical guards are blacklists that are trivially paraphrased**
- **Covers:** prescription (A09), outcomes (A11), temporal language (A19), S identifiers (A10).
- **Why it matters:** they make contamination harder by accident, not by design. The quote-stripping rule (`f_checks.py:55`) turns quoting into a bypass for anything.
- **Action:**
  - turn outcome fields into a whitelist schema (closed key set per kind);
  - make the S guard case-insensitive and apply it to all strings;
  - accept that prescription and temporal leakage are review items, and say so in C06/C08/C10 rather than claiming a guard.

**N-09 · MINOR · the math binding is weak**
- **Evidence:**
  - releases are allowed on MATH-kind units (A17);
  - `latex` has no minimum length (A20);
  - arrows and Greek letters are not markers (A14).
- **Action:**
  - forbid releases on MATH/CODE kinds;
  - require `latex` of at least the unit's marker span, or a whole-unit quote;
  - add arrows (U+2190–21FF) and Greek letters when adjacent to an operator or colon, as markers.

**N-10 · OBSERVATION · the matrix claims more than the code does**
- F-21: the L1 prescription guard is claimed, not implemented.
- F-16: "clusters" are claimed; only pairs exist.
- C02 §5: "the audit reviews every release" is not produced mechanically.
- C13 §2: the listed check order (legality before approval) is not the code's order. This is harmless.

## F. Statistics / ML

**Populations and duplicates:**
- The exact-duplicate collapse and the F-specific / CONTENT-IDENTICAL-TO-S split are deterministic and correct as flags.
- Near-duplicates are reported as pairs only; nothing uses them to define a dependence-adjusted population.

**Near-duplicate signal:**
- It is deterministic (sets, manifest order).
- The threshold of 0.8 is *stated, not justified*.
- Jaccard misses superset revisions, which are the typical pattern of iterated AI documents (A18: J 0.60, containment 1.00).
- **Recommendation:** report containment (max of |A∩B|/|A| and |A∩B|/|B|) alongside Jaccard, and publish the score distribution rather than a single cut-off.

**Exploratory → confirmatory:**
- The separation is textual only (C09 §3). `population_rule` is free text, and nothing checks that the population excludes the exploratory one.
- De-facto hypotheses can be recorded per file as suggestions (A12).

**Pre-registration immutability:**
- It is mechanical only until AUDITED, and only against non-adversarial edits (N-02, N-06).
- The checkpoint's `immutable` flag is informational.

**One confirmatory look:**
- `confirmatory_checkpoint` is a required field.
- It is not enforced, because the test engine is not implemented. That is acceptable while blocked.

**Multiplicity (HDR-3 proposal: SINGLE-PRIMARY / HOLM / BH-FDR as exploratory only):** reasonable. Two recommendations:
- Define the family *mechanically* as all confirmatory comparisons scheduled at the same checkpoint; otherwise one family per hypothesis nullifies correction.
- Require per-file hypotheses to be capped or pooled.

**HDR-2/HDR-3 blocks:**
- They block exactly the kinds they name, plus `f_checkpoint run`.
- They do not block substance filed under SUGGESTION kinds, or paraphrased temporal claims.
- `file_mtime` from a git working tree reflects checkout time, so it is not historical evidence. HDR-2 should not rely on it.

**Checkpoint interval of 50:** labelled as the initial, operational cadence, which is honest.
