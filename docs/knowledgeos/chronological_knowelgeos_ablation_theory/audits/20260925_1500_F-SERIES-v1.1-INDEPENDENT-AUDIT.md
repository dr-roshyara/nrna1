## A. Executive verdict

**GO WITH CONDITIONS.**

- **Scope of the GO:** step D1 only, up to and including the `CONTENT-EXTRACTED` transition. It covers nothing past that.
- **What must wait:** F3082 must not reach `RESEARCHED` or `AUDITED` under v1.1 as it stands. The C10, C11 and C13 corrections (F-01, F-06, F-07, F-10, F-11, F-12) must be in place first, as a human-approved v1.2 or a recorded interim control.
- **Why the stop at AUDITED matters:** `AUDITED` cannot be undone. `ALLOWED_FROM` has no transition out of it.

**Why this is not a HOLD:**
- F3082's reading evidence is intact.
- The layer design (L1/L2/L3, gated order, pre-registration idea) is sound.
- D1 can be undone: a failed audit re-enters the pipeline.
- The conditions that must be met *before* D1 are procedural and cheap.

**Why this is not a plain GO:**
- The mechanical `CONTENT-EXTRACTED` gate can be passed with essentially no real extraction (F-03).
- Nothing mechanical freezes L1 once the gate is passed (F-01).
- The extractor's standing context contains prior KnowledgeOS and S-Series conclusions about the very concepts F3082 defines (F-02).

## B. Critical findings

Severity for a BLOCKING finding is tied to the stage it must be fixed before.

**F-01 · BLOCKING (before the CONTENT-EXTRACTED transition) · L1 is never frozen, and hypotheses are not immutable**
- **Where:**
  - `scripts/f_transition.py:75-81`: the CONTENT-EXTRACTED event stores `run_id` plus summary stats only.
  - `f_transition.py:96-99`: the RESEARCHED event stores only `run_id` and `empty_reason`.
  - `f_audit.py`: AUDIT.json holds no hashes of the artifacts it checks.
- **Evidence [exp E3]:**
  - The CONTENT-EXTRACTED event contains only `['inventory','run_id']`.
  - I rewrote an inventory item's `content` after the gate. RECONSTRUCTED still passed, and nothing recorded the edit.
- **Why it matters:**
  - Rule L1-3 ("L1 never depends on L2/L3") cannot be checked. An extractor can go back and adjust L1 after doing analysis or forming hypotheses, and it will not be detected.
  - C11 §1.1 says a hypothesis's "record hash is verified against the RESEARCHED event". No such hash exists, so that procedure cannot be carried out.
  - C10 §3 immutability ("never edited after registration") exists on paper only.
- **Action:**
  - Put the sha256 of UNITS, CONTENT-INVENTORY, UNIT-DISPOSITIONS and CATEGORY-CHECK into the CONTENT-EXTRACTED event.
  - Put the sha256 of research.jsonl into the RESEARCHED event.
  - Make every later gate and `f_audit` check those hashes.
  - Interim control, if code has to wait for v1.2: commit the ledger right after each gate, and name that commit in the governance log.

**F-02 · BLOCKING (before D1 starts) · Theory and S contamination through the extractor's context and a leftover draft**
- **CONTEXT.md and MEMORY.md:**
  - The repository's `.claude/CLAUDE.md` workflow tells every session to read `.claude/MEMORY.md` and `.claude/CONTEXT.md` first. Any subagent inherits that instruction; I did.
  - CONTEXT.md mentions KnowledgeOS 587 times and has 42 S-Series/P3B/S5 references. It includes conclusions such as "Kernel is NOT invariant under operation-…".
  - F3082's page-1 digest quote is "The kernel is not a set of invariants. It is …". The overlap is direct.
- **The unquarantined draft generator:**
  - `scratchpad/f3082/p1.py` (28 KB, 13:06) is the script that wrote the draft `files`, `contributions` and `index-proposals` (line 219). It sits outside the quarantine, in the orchestrator's shared scratchpad.
  - That same scratchpad is where C13 §3 says the independent auditor builds its inventory.
- **The parked draft:**
  - `ledger/F3082/_draft-v1.0/` holds 45 contributions and 40 working labels, sitting beside the live ledger.
  - **Code path check:** no code reads it. There is no glob, walk or listdir in the lane scripts except `f_register.repair`, which only looks at corpus directories. `ledger_path` joins fixed file names.
  - **No filename collision:** the draft lives in a subfolder. If someone moved it into the ledger root, the gate would reject it, because the draft contributions have no `inventory_refs`.
  - So the draft cannot contaminate the pipeline through code. It can contaminate through what an agent reads.
- **Action:**
  - Launch the D1 extractor as a fresh agent whose prompt explicitly overrides the CLAUDE.md session workflow: no CONTEXT.md, MEMORY.md, `_draft-v1.0/`, scratchpad, S ledgers, or F-files other than F3082.
  - Move or archive `p1.py` out of the shared scratchpad, or record its existence.
  - Give the independent auditor a separate scratch location.
  - Record the isolation instructions in the governance log.

**F-03 · MATERIAL · Mechanical completeness can be satisfied with no semantic work**
- **Where:**
  - `f_checks.check_inventory:206-208`: the quote only has to appear inside the covered units once they are joined.
  - `:239-240`: coverage means "listed in some item's `covers_units`".
  - `:260-262`: a definition-cue unit only has to be covered by *some* item, of any category.
  - `check_reconstruction:331-341`: a single contribution can carry every item.
- **Evidence [exp exp2]:** on a fixture with a MATH unit and a definition-cue unit, one `CONCEPT` item did all of this and CONTENT-EXTRACTED passed:
  - `covers_units` = all 4 non-markup units;
  - `verbatim_quote: "is"`, `content: "x"`;
  - no DEFINITION item and no FORMULA item.
- **Evidence [exp E2]:** one catch-all contribution then passed RECONSTRUCTED.
- **Further gaps [code]:**
  - No minimum quote length.
  - No contiguity: a quote can be spliced across non-adjacent units.
  - `content` may simply equal the quote.
  - A loop that emits one CONCEPT item per unit, which is what the test fixture does, passes.
- **Why it matters:** "every inventory item carried" (§F-3.2 row 32) is a floor near zero. Semantic loss can only be caught by the independent audit, and that audit is weak (F-06).
- **Action:**
  - A definition-cue unit must be covered by a DEFINITION or TERM item.
  - A MATH unit must be covered by a FORMULA, NOTATION or THEOREM item whose `latex` lies inside that unit.
  - Quotes must be contiguous, with a minimum length or the whole unit.
  - `content` must not equal the quote.
  - The audit should report items per unit and the category distribution.

**F-04 · MATERIAL · The math/code rule sees only `$$` blocks and ``` fences**
- **Where:** `f_checks.units_of:142-165` and `NEVER_NON_SUBSTANTIVE = {"CODE","MATH"}`.
- **Evidence [exp E12]:**
  - Inline `$…$`, `\begin{equation}…`, `\[ \]`, `~~~` fences, indented code and unicode math are all classed `LINE`, so they can be dispositioned `NO-SUBSTANTIVE-CONTENT`.
  - A line `$$a=b$$ holds` opens a block that swallows the prose lines after it.
- **F3082 counts only (no text printed):**
  - 448 units: 24 MATH, 8 CODE, 31 definition-cue.
  - 59 non-MATH units contain `$`, 49 contain LaTeX backslashes, 12 contain unicode math.
  - For a file about mathematical theory, this is a direct D1 exposure.
- **Action:** until code is fixed, treat any unit with `$`, `\` or math unicode as non-dispositionable, as a D1 run rule. The audit must review every NO-SUBSTANTIVE disposition (C02 §5 already requires this).

**F-05 · MATERIAL · The definition detector misses F3082's own central definitions**
- **Where:** `f_checks.DEFINITION_CUE:114-116`.
- **Evidence [exp]:** both F3082 page-digest quotes return False:
  - "The kernel is not a set of invariants. It is …" is a negative definition, a form C03 §1 names.
  - "UNKNOWN is **indexed by the shape…**. There is no general UNKNOWN." also evades it.
- **Evidence [exp E11]:** these forms are missed too: "refers to", "Let K be", `:=`, "By X we mean", "We say that", "**Definition 1.**" in bold (not a heading), "stands for", "X — the …".
- **Why it matters:** §F-15 acknowledges the limitation. For F3082 it means most definitional content depends on extractor diligence plus the audit.
- **Action:** widen the cue patterns, or have the audit enumerate definitions on its own and compare.

**F-06 · MATERIAL · The independent audit cannot be verified and can be forged**
- **Where:**
  - `f_audit.py:64-68` accepts `INDEPENDENT-AUDIT.json` if it has `verdict=="CONFIRMED"` and a matching `run_id`.
  - The test writes exactly that two-field file (`tests/test_f_pipeline.py:205`).
- **What is not checked:**
  - whether the auditor actually read the file (a complete FR-F####-9NN coverage in READ-LOG);
  - any stored auditor inventory, or any mechanical comparison against it;
  - any definition of what counts as a DISCREPANCY;
  - "without access to ledger/F####/" (unenforceable);
  - that the auditor is independent: it is the same model family, and it shares the scratchpad (F-02).
- **Why it matters:** given F-03, this audit is the *only* control on semantic completeness, and F3082 requires it (`independent_required` → 0 % 5 == 0).
- **Action:** require the auditor's own inventory artifact, a complete auditor read-coverage record, a mechanical unit-by-unit and definition-by-definition comparison, and human sign-off on the discrepancy list.

**F-07 · MATERIAL · Audit and state can be forged**
- **Hand-written AUDIT.json [exp E6]:** `{"run_id","audited_state":"RESEARCHED","verdict":"PASS"}` was enough. f_transition moved to AUDITED (`f_transition.py:100-112` never re-runs the audit), and f_status advanced to the next F-ID.
- **Forged event line [exp E7]:** I appended a `RESEARCHED→AUDITED` event directly after READ-COMPLETE.
  - f_status accepted it, and the next F-ID was allowed into READING.
  - `f_audit`'s `state-ledger-legal` check (`f_audit.py:42-43`) only checks that each (from, state) pair is legal on its own. It does not check that `from` equals the previous event's state, or that `seq` is continuous.
- **Append-only is not enforced:** only git provides it, and no step in the runbook commits.
- **Action:** have the AUDITED gate call the audit function itself, or check AUDIT.json against AUDIT-LOG; hash-chain the events (prev-hash); verify the `from`/`seq` chain in the audit; commit at each gate.

**F-08 · MATERIAL · Escape hatches reach AUDITED without extraction or a human decision**
- **Where:**
  - `ALLOWED_FROM`: READ-COMPLETE → CONTENT-EXTRACTION-UNRESOLVED or PLACEHOLDER, then → AUDITED.
  - `f_audit.py:83-88` checks only that a reason was recorded, or read coverage for PLACEHOLDER.
- **Evidence [exp E8]:** each one, given `--reason "too hard"`, returned audit rc 0 and reached AUDITED. No independent audit ran.
- **Action:** any terminal exception after READ-COMPLETE should need a human decision reference in the event, and should count toward the independent-audit cadence.

**F-09 · MATERIAL · The C06 and L2/L3 rules exist in the schema only**
- **Where:** `check_analysis:414-416` requires only statement, research_time, run_id and model_id. `reasoning`, `severity` and any epistemic basis are never checked (grep confirms).
- **Evidence [exp E4]:** both of these passed as Level 2:
  - a `CORRECTNESS-FINDING` with no reasoning;
  - a `DOMAIN-INTERPRETATION` saying "KnowledgeOS should implement X as the aggregate root of its Kernel bounded context".
- **Relation to review notes:** confirms RN-03, RN-05 and RN-07 with mechanical evidence. Nothing in the gate distinguishes L2 description from L3 prescription.

**F-10 · MATERIAL · L3 records are not bound to L1/L2 and can carry outcomes**
- **Where:** `check_research:495, 497-501, 527-529`.
- **Evidence [exp E5]:** a per-file record passed RESEARCHED with all of the following:
  - `analysis_refs: []`;
  - epistemic class `THEORY-CANDIDATE`, allowed because the record declared `scale:"CORPUS"` for itself;
  - `"result":"SUPPORTED"` and `"test_outcome":"SUPPORTED"`: only the literal key `outcome` is refused;
  - a same-file quote that only needs to be somewhere in the file, not in the inventory.
- **Why it matters:** C12 chain links are broken, L3 records can exist with no L1/L2 support, and a single-file theory candidate can be presented as a corpus-scale one.

**F-11 · MATERIAL · C10 schema and code disagree on `disconfirmation_search`**
- **Evidence [exp E5b]:** a spec-conformant structured `disconfirmation_search` (population, method, completeness, bound, result, negative label) crashes the gate with `AttributeError: 'dict' object has no attribute 'strip'` (`f_checks.py:538`).
- **Related tension:** C10 asks for a per-file search "result", which is itself an in-sample per-file test outcome. That sits uneasily with "no outcome per file".

**F-12 · MATERIAL · List order is not historical order, so "no look-ahead" and "out-of-sample" are mislabelled**
- **Evidence:**
  - List positions 1–27 (F3082…F3108) are dated Sep 23–25. Position 28 (F0109) is Aug 22.
  - I found six date drops along the list.
  - §F-2 acknowledges that F-IDs are non-monotonic, but not that time runs backward.
- **Why it matters:** F3082 ("hegel_upgrade_of_knowledgeos_mathematical_theory") builds on earlier theory. Hypotheses registered at F3082 would be "tested out-of-sample" (C09 §2, C11 §1.2) on its own historical antecedents, and anti-projection (C12) points the wrong way for these files. This is a human decision (H-2).

**F-13 · MATERIAL · The reader does not enforce look-ahead**
- **Where:** `f_read_source.py:49-60` has no sequential check.
- **Evidence [exp E9]:** it served a later F-ID's page (rc 0) before the earlier F-ID was AUDITED.
- **Detection:** the read is logged, but no audit inspects later F-IDs' READ-LOGs. The F-files are also ordinary repository files that any tool can open.

**F-14 · MATERIAL · S/F isolation is only a regex for S-IDs**
- **Where:** `S_ID = \bS\d{4}\b` is applied only to L2/L3 statement fields and research evidence `f_id`s.
- **Evidence [exp exp2]:** "S0472" placed in inventory `content` and in contribution `labels` and `statement` still passed RECONSTRUCTED.
- **What cannot be detected by construction:** S labels or interpretations written without an S-ID.
- **CONTENT-IDENTICAL-TO-S (175 files):**
  - `files.jsonl` must carry the correct flag. That is enforced (`:297`).
  - The flag is not carried into the output of `f_crossfile` or `cross_file_candidates`, which C05 §3 requires.
- **Duplicates:** only exact sha256 duplicates are collapsed. Near-duplicates become artificial independent observations.

**F-15 · MATERIAL · C11 does not handle repeated testing across checkpoints**
- Every registered hypothesis is retested at each checkpoint on growing data.
- There is no rule for this (optional stopping / sequential looks), and nothing says which checkpoint's outcome governs.
- This is not covered by RN-10, which deals with multiple comparisons.

**F-16 · MATERIAL (before F-ID #51) · Checkpoints exist on paper only**

**F-17 · MINOR · Re-entry after AUDIT-FAILED does not match the documented semantics**

**F-22 · OBSERVATION · The corpus contains prior AI conclusions as "source"**

## D. Epistemic integrity

- **L1/L2/L3:**
  - Forward direction: enforced in structure (records cite lower levels; wrong kinds are refused).
  - Reverse influence (L3→L2→L1): undetectable (F-01).
  - The L2/L3 boundary is not gated (F-09).
  - DOMAIN-INTERPRETATION *is* a usable hidden theory channel. Any prescriptive text passes as L2.
- **Hindsight and look-ahead:** blocked only at the research-evidence check. There are several open paths:
  - the reader (F-13);
  - direct file access;
  - CONTEXT.md (F-02);
  - model priors;
  - list order that inverts history (F-12).
- **Provenance:** resolvable F-ID → manifest → page → unit → item → contribution/analysis. It breaks at L3 (F-10) and at checkpoints (no code). Orphan L3 records are possible. Orphan L1 items are not.
- **S/F isolation:** ID-shaped only (F-14).
  - CONTENT-IDENTICAL-TO-S is correctly a flag, not an exclusion.
  - Exact F-internal duplicates become pointers and produce no inventory. Cross-file candidates skip them correctly, because they have no inventory.
  - S interpretations of those same 175 contents exist in S ledgers and in CONTEXT.md, and an agent can reach them.
- **Theory contamination:** structural. The corpus is itself AI-generated KnowledgeOS theory, and the extractor's standing context holds KnowledgeOS DDD governance (`.claude/CLAUDE.md`) and S conclusions. The closed categories (e.g. ARCHITECTURE-COMPONENT) are neutral enough, but choosing a category is judgment.
- **Researcher degrees of freedom:**

| Decision | Control |
|---|---|
| Substantive vs not (NO-SUBSTANTIVE) | closed vocabulary; math/cue rule (partial); otherwise agent judgment plus audit |
| Category choice | closed list of 26; judgment |
| Item granularity / splitting | none (F-03) |
| NOT-APPLICABLE lens | any non-empty reason; judgment |
| Cross-file relatedness / hint | closed hints; quotes required for RELATED; judgment |
| Correctness finding | judgment only; reasoning not required (F-09) |
| DDD structure (L2 vs L3) | judgment only |
| Hypothesis distinctness / number | none (feeds multiplicity) |
| Pre-registration content | fields must exist; content free |
| PLACEHOLDER / *-UNRESOLVED | judgment only; no human involved (F-08) |
| PRIMARY vs SECONDARY-SYNTHESIS | closed vocabulary; judgment |

## E. C06, C07, C08

- **C06 (mathematical analysis):**
  - The text keeps "source claim" separate from "our assessment" (R6), and verbatim `statement`/`latex` checks stop L1 from quietly repairing the source (P).
  - It does *not* separate: analyst cannot verify / internally inconsistent / conflicts with external mathematics. There is no epistemic-basis field and no external-source field; `proof_status` has three values.
  - A CORRECTNESS-FINDING can be produced with no reasoning (E4).
  - Free-text `content` and contribution `statement` fields can still present a "repaired" version.
  - Conclusion: sound in intent, not enforceable. Adopt RN-04, RN-05 and RN-06, backed by a gate requiring `reasoning` and `basis ∈ {INTERNAL, EXTERNAL(+source), UNRESOLVED}`.
- **C07 (logical analysis):**
  - Source-framed contradictions (L1 CONTRADICTION-OR-TENSION) vs analyst-found tensions (L2 INTERNAL-TENSION) are separated in text only. Nothing checks that an L1 contradiction is actually framed by the source.
  - Analyst observations *can* reach L1: through `content`/`context`, through USED-UNSTATED assumptions (inherited XC), and through the CONTRADICTION category.
  - Conclusion: adequate spec, human-only control.
- **C08 (DDD / domain analysis):**
  - "The source describes a domain structure" vs "KnowledgeOS should implement this" is stated in one sentence and not gated (E4).
  - The repository's DDD architecture sits in every agent's context, so it works as a possible answer key.
  - Conclusion: needs the RN-03/RN-07 rule plus a gate. At minimum, L2 statements that contain prescriptive or KnowledgeOS-targeted wording should be refused or flagged.

## F. Statistics / ML (C09)

- **Independence:**
  - Exact duplicates are collapsed.
