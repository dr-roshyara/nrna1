## 0. What this document changes in the design (the review's six points)

| # | Review point | Adopted as |
|---|---|---|
| 1 | Option B must not be called a HumanDecision | two different types: **`SignedDecision`** (cryptographically authenticated, HDR-6 Option A) and **`ProceduralDecisionRecord`** (an AI-recorded representation of a human interaction, HDR-6 Option B). They are never interchangeable: every gate declares which type it requires, and a gate that requires `SignedDecision` refuses a procedural record. If B is chosen, the gates that would need a signature are *explicitly weakened*, and the weakening is recorded in every record and every report |
| 2 | the gate should not make its own commit | the transition is split in three: **Gate** (verifies, then writes a `TransitionProposal` = exact artifact set + event + hashes, and does not append to the state ledger) → **Commit boundary** (a separate script that commits exactly the proposal's paths, refuses any other staged or dirty path, and appends the event only as part of that commit) → **next Gate** (verifies the commit). The commit is an evidence boundary, not an authorization. *Qualification Q-1 (§0a).* |
| 3 | Git is integrity, not authority | four named invariants, never used as shorthand for each other: **GIT-INTEGRITY**, **AUTHORIZATION**, **EVIDENCE-INTEGRITY**, **PROVENANCE** (§2) |
| 4 | auditor independence | the auditor has its **own method**, `auditor_method_id` + `auditor_method_version`. The shared element is the *measurement frame* (the deterministic units), not the method. The minimum validity condition is **frame coverage** (every non-markup unit examined and recorded), *not* the extractor's category bindings. The comparison is a separately identified method. *Qualification Q-2 (§0a).* |
| 5 | EvidenceObject must be self-contained and reproducible | the evidence hash covers the source identity and content hash, the reader and extractor implementation hashes, the prompt hash, the configuration hash and the artifact hashes (§3.2) |
| 6 | no infinite hardening regress | a **closure criterion** (§5): a guarantee is closed when it is stated, classed, tested and has a named residual. An attack that exploits a *labelled* residual is not a defect of v1.3 |

### 0a. Qualifications

**Q-1 (on point 2).** The Gate and the Commit boundary are separate *code paths and records*, but in this environment
both are run by the same agent. The split gives:
- auditability: the proposal is inspectable before the commit, and the commit contains exactly the proposal;
- fail-closed behaviour: a gate can never leave half-written state.

It does **not** give separation of *actors*. Actor separation exists only where a `SignedDecision` is required (HDR-6
A). I recommend saying exactly this, not implying more.

**Q-2 (on point 4).** "Independent method" must stay comparable. If the auditor used a different unit segmentation,
the comparison would need an alignment step, and alignment errors would masquerade as discrepancies. So the frame
(units) is shared deliberately; independence lies in:
- what the auditor extracts from each unit;
- its category choices;
- its own reading;
- its own prompt, drawn up without the extractor's output.

The floor, "every non-markup unit examined", is an observation-space requirement, not an agreement requirement.

## 1. Threat model

**Assets:**
- source identity;
- L1 evidence (EvidenceObjects);
- human authorizations;
- audit records;
- the state history;
- downstream provenance (consumptions, hypotheses).

**Actors and assumed capabilities** (worst case first):

| Actor | Can | Cannot (assumed) |
|---|---|---|
| **A-AI** (any AI agent in this environment: orchestrator, extractor, auditor, researcher) | read and write any file; run any tool; create commits authored as the human; push to `origin`; hold a contaminated context (repository CLAUDE.md, model priors) | use a signing key that is locked or held off-machine (**only if HDR-6 = A**); change the human's key, or the public key pinned in an approved index, without the change being visible |
| **A-S** (the concurrent S-Series session in the same checkout) | change files outside the lane; move HEAD | nothing specific to the lane (but it can make HEAD move and the tree dirty — the boundary must tolerate foreign paths) |
| **A-H** (the human) | make decisions; sign (if a key exists); read everything | — (trusted) |

**Adversary classes the design addresses:**
- **E1** honest error: a wrong edit, a forgotten commit, a mis-sequenced run;
- **E2** a confused or contaminated agent: acts on material it should not have seen, or rewrites L1 after seeing L2/L3;
- **E3** a deliberate forger among the AI agents: fabricates approvals, states, audits or evidence.

v1.3 aims at **E1 and E2 mechanically**. It aims at **E3 only where cryptography is available (HDR-6 A)**; otherwise E3
is **detectable after the fact** (git history, pushed remote, audit diff), not prevented.

**Trust boundaries:**
1. the source bytes (manifest hash);
2. the reader;
3. the extractor's context (C15);
4. the evidence seal;
5. the commit boundary;
6. the human decision (signature);
7. the auditor's context;
8. downstream consumption.

**Guarantee classes used below:**
- **CRYPTO**: holds against E3 (requires HDR-6 A).
- **MECH**: code refuses; holds against E1/E2, and against E3 only until the code or the ledger is forged.
- **DETECT**: not prevented, but leaves evidence that an audit or history comparison finds.
- **PROC**: holds only if the run rules are followed.
- **NONE**: not guaranteed; stated as residual.

## 2. The four invariants (never shorthand for each other)

```
GIT-INTEGRITY       A transition consumes only artifacts that are members of the committed tree at HEAD; the lane's
                    state files and ledgers in the working tree equal HEAD; no transition acts on truncated,
                    uncommitted or foreign-modified lane state.
AUTHORIZATION       A transition that requires human authority consumes a valid authorization object of the TYPE the
                    gate requires (SignedDecision or ProceduralDecisionRecord), whose action, target and bound hash match.
EVIDENCE-INTEGRITY  An EvidenceObject is identified by its canonical evidence hash; its artifacts hash to it; it is
                    never modified after sealing; a new extraction is a new EvidenceObject with a supersedes-link.
PROVENANCE          Every downstream consumption (cross-file quote, analysis, hypothesis, checkpoint population) names
                    the exact EvidenceObject hash it consumed, and that object must be sealed and accepted.
```

"Git verified" means GIT-INTEGRITY only. "Accepted" means AUTHORIZATION plus a valid AuditRecord. "Trustworthy" is not a
term the system uses.

## 3. The seven P0 areas

### 3.1 Human authorization (N-01, N-05; HDR-6)

| Field | Content |
|---|---|
| **Invariant** | AUTHORIZATION. `authorized(action, target, bound_hash, required_type)` ⇔ ∃ a record `r` in `decisions/` with `r.action = action`, `r.target = target`, `r.bound_hash = bound_hash`, `type(r) = required_type` (for SignedDecision: the signature verifies against the pinned public key), and no later record `r'` revokes `r` |
| **Precondition** | the pinned key (A) or the declared procedural mode (B) is itself part of an `APPROVE-PROTOCOL` decision; the decision files are committed (GIT-INTEGRITY) |
| **Transition** | any gate needing authority calls `authorized(…)` before evaluating evidence |
| **Postcondition** | the transition event records `authorization: {record id, record sha256, type}` |
| **Mechanically guaranteed** | log prose never counts; the record fields must match; binding to the exact hash; type enforcement; revocation |
| **Cryptographically guaranteed (A only)** | the actor is the key holder |
| **Procedurally guaranteed (B)** | that the AI recorded what the human said; labelled `ProceduralDecisionRecord` everywhere; the weaker guarantee appears in every report that relies on it |
| **NOT guaranteed** | under B, that the human actually decided; under A, that the human understood what was signed (the record is shown to the human in plain form before signing) |
| **Attack model** | an E3 agent writes a decision file (B: succeeds — **DETECT** only by the human reviewing `decisions/`; A: fails, the signature does not verify). The agent edits a committed decision (fails: the hash is bound, GIT-INTEGRITY). The agent reuses a decision for another evidence hash (fails: `bound_hash`). The agent hides a decision in prose, a fence or a comment (irrelevant: prose never counts) |
| **Adversarial tests** | forged record (wrong type / unsigned under A); a valid record for another hash; revoked record; prose-only "approval"; an HTML-comment / nested-fence line (must be ignored); a record in an uncommitted file |
| **Closure evidence** | all tests pass; the re-auditor fails to forge under the chosen HDR-6 mode, or confirms that B is labelled everywhere |
| **Residual** | B: E3 can fabricate procedural records (DETECT). A: key compromise or a mis-signed record (NONE) |

### 3.2 Evidence immutability (F-01, N-06; review point 5)

| Field | Content |
|---|---|
| **Invariant** | EVIDENCE-INTEGRITY. `evidence_hash(v) = H(canon{source_id, source_sha256, execution_environment, prompt_sha256, config_sha256 (unit-segmentation version, detector versions, thresholds), artifact_sha256[] (UNITS, INVENTORY, DISPOSITIONS, CATEGORY-CHECK, ATTESTATION, PROMPT)})`, where `execution_environment = {scripts_sha256 (every script in force, incl. the reader), python_version, os_platform, model_id (self-reported)}`. This is **execution-environment identity, not reproducibility**: equal hashes mean the same declared inputs, code and environment, **never** "the same extraction would be produced again" (r2) |
| **Precondition** | READ-COMPLETE for the same source hash; D1 artifacts complete (the check_inventory floor) |
| **Transition** | the CONTENT-EXTRACTED Gate computes the hash and emits a proposal. The Commit boundary writes `ledger/F####/L1-v<k>/EVIDENCE.json` (the canonical manifest) and commits it with the artifacts |
| **Postcondition** | the committed tree holds `L1-v<k>/` with a manifest whose recomputed hash equals the hash recorded in the event |
| **Mechanically guaranteed** | any change to any artifact or manifest field changes the hash, and every consumer recomputes it; nothing writes into a sealed `L1-v<k>/` (the write guard refuses a sealed directory) |
| **NOT guaranteed** | that the *model* behind the extractor is what `model_id` says (self-reported; the hash covers scripts and the prompt, not model weights); byte-reproducibility of an LLM extraction (re-running does not reproduce the same items — the evidence object is reproducible in its *identity*, not in its generation) |
| **Attack model** | edit an artifact after sealing (E1/E2/E3 → refused or detected by recomputation); forge the manifest and the artifacts consistently and commit (E3 → GIT-INTEGRITY accepts; **DETECT** by the audit diff against the AuditRecord's recorded hash and the pushed remote; CRYPTO only if `ACCEPT-L1` is signed and binds the old hash) |
| **Adversarial tests** | edit an artifact; edit the manifest; swap in another version's file; write into a sealed directory; recompute and recommit (must fail acceptance: no decision binds the new hash) |
| **Closure evidence** | tests pass; the re-auditor cannot change accepted evidence without breaking acceptance |
| **Residual** | model identity (self-reported); generation non-reproducibility (by nature) |

### 3.3 Git boundary (N-02; review points 2, 3; Q-1)

| Field | Content |
|---|---|
| **Invariant** | GIT-INTEGRITY. At the start of every Gate: the lane's `F-SERIES-STATE.jsonl`, `F-READ-INTEGRITY.jsonl`, `decisions/`, `ledger/` and `proposals/` in the working tree equal `HEAD`; no pending proposal exists except one this Gate is about to verify |
| **Precondition** | a clean lane (foreign paths outside the lane are tolerated and recorded — A-S) |
| **Transition** | Gate → `proposals/P-<F-ID>-<seq>.json` {event, exact paths, their sha256, parent HEAD}. Commit boundary → verifies that parent HEAD = the current HEAD, that the staged set = the proposal's paths exactly, and that the hashes match; appends the event; commits with a fixed message `f-series: <F-ID> <from>→<to> <proposal sha256>`; deletes nothing. The next Gate → verifies that the commit exists at HEAD or among its ancestors and matches the proposal |
| **Postcondition** | every state event exists in exactly one boundary commit whose tree contains the proposal's artifacts |
| **Mechanically guaranteed** | against E1/E2: no acting on uncommitted, truncated or partially written state; the history is ordered by commits |
| **NOT guaranteed** | against E3: a forged history committed and even pushed by the AI (it has the credentials). Detection: comparison with the remote's earlier history (a force-push is visible on the remote), SignedDecision ancestors (A), and the human's review of the boundary commits |
| **Attack model** | truncate the ledger (the Gate refuses: the working tree ≠ HEAD); commit a truncated ledger (the next Gate refuses: HEAD's ledger is not an extension of the previous boundary commit's ledger — each boundary commit must extend its parent's ledger by exactly one event); rewrite local history (**DETECT** via the remote / signed ancestors) |
| **Adversarial tests** | A04, A05, A16 from the v1.2 re-audit; a dirty tree; a proposal with extra paths; a stale parent HEAD; a commit that removes an event; a commit that adds two events |
| **Closure evidence** | tests pass; the re-auditor cannot act on non-committed state |
| **Residual** | E3 history rewriting before push (DETECT, not prevented); retiring the hand-rolled chain is justified because it added no guarantee beyond GIT-INTEGRITY (the re-audit's A04/A05) |

### 3.3a Concurrency — HEAD compare-and-swap (r2)

The threat model admits A-S, a concurrent session committing to the **same branch** (`refs/heads/knowelegeos-modelling`)
and dirtying the tree. "The working tree equals HEAD" does not cover HEAD moving between proposal and commit, and a
plain `git commit` would also sweep A-S's staged files into an F-Series commit.

| Field | Content |
|---|---|
| **Invariant GIT-CAS** | a boundary commit `C` is written only if `C.parent = proposal.parent_commit = the branch tip at the moment the ref is updated`; `C.tree = tree(proposal.parent_commit)` with exactly the proposal's paths replaced by exactly the proposal's blobs; the branch ref moves from `proposal.parent_commit` to `C` in **one atomic compare-and-swap** (`git update-ref refs/heads/<branch> <C> <proposal.parent_commit>`), which fails if the tip moved |
| **Invariant LANE-OWNERSHIP** | every commit since the last boundary commit that touches a lane path (`docs/knowledgeos/chronological_knowelgeos_ablation_theory/`) must itself be a boundary commit (fixed message format + proposal hash). A foreign commit touching the lane is a violation, not a tolerated change. Foreign commits touching only non-lane paths are tolerated, recorded, and require a new proposal (the parent changed) |
| **Precondition** | lane paths in the working tree equal the branch tip; no other proposal pending; LANE-OWNERSHIP holds from the last boundary commit to the tip |
| **Proposal creation** | the Gate reads the branch tip `P`, verifies the preconditions against `P`, and writes `proposals/P-<F-ID>-<seq>.json` = {`parent_commit: P`, event, [(path, blob sha1, sha256)] for every created or changed lane path, `created_utc`}. It hashes the blob contents once and keeps them as the proposal's payload |
| **Commit-time check** | the Commit boundary (a separate script): (1) the branch tip = `P`, else REFUSE (`STALE-PROPOSAL`: a new proposal is required); (2) the working-tree bytes of each proposal path hash to the proposal's sha256, else REFUSE (the file changed after proposal); (3) it builds the tree in a **temporary index** (`GIT_INDEX_FILE=<scratch>`, `git read-tree P`, then `git update-index --add --cacheinfo` for exactly the proposal's blobs), so A-S's staged index is never touched or included; (4) `git commit-tree <tree> -p P -m "f-series: <F-ID> <from>→<to> proposal <sha256>"`; (5) the atomic `update-ref` compare-and-swap; if the CAS fails, the new commit object is discarded (unreferenced) and the result is REFUSE, `STALE-PROPOSAL` |
| **Postcondition** | the tip is `C`; `C` differs from `P` exactly in the proposal's paths; the event is in `C`'s ledger and in no uncommitted state; the proposal file is in `C` |
| **Mechanically guaranteed** | no lost update between the F and S sessions (a git ref CAS is atomic); no foreign staged content in an F commit; no F transition on top of a foreign change to lane paths |
| **NOT guaranteed** | against E3 (the AI can run the git plumbing itself); the S session's own correctness; that A-S does not later rewrite history (DETECT via the remote) |
| **Adversarial tests** | the tip moves between proposal and commit (a foreign commit on a non-lane file) → `STALE-PROPOSAL`; a foreign commit edits a lane file → the next Gate refuses (LANE-OWNERSHIP); A-S has staged files → they are absent from the boundary commit; a lane file edited after the proposal → refused; two proposals raced → exactly one wins, the other is `STALE-PROPOSAL`; `update-ref` CAS failure → no ref change, no event |
| **Closure evidence** | tests pass on a scratch repository with a simulated second writer; the re-auditor cannot produce a lost update or a mixed commit |
| **Residual** | E3 (DETECT only); a window between check (2) and the ref update in which a lane file can change in the working tree — harmless, because the commit uses the proposal's blobs, not the working tree |

### 3.4 Re-extraction and versioning (N-04; F-17)

| Field | Content |
|---|---|
| **Invariant** | a new L1 for an F-ID is always a new EvidenceObject `v<k+1>`, with `supersedes: v<k>` and a reason. It exists only with `authorized(AUTHORIZE-REEXTRACTION, F-ID, hash(v<k>), SignedDecision or the declared procedural type)`. `v<k>` stays sealed and readable. Everything derived from `v<k>` (L2, L3, consumptions) stays bound to `v<k>`, and is never re-bound silently |
| **Precondition** | a reason exists: an AuditRecord DISCREPANCY, or an AUDIT-FAILED whose findings name L1 |
| **Transition** | the READING (fresh run) or CONTENT-EXTRACTED Gate checks for existing EvidenceObjects: if any exists, authorization is required |
| **Postcondition** | lineage `v<k> → v<k+1>` recorded; the audit reports the diff; L2/L3 of `v<k>` are marked `STALE-SOURCE`, not deleted |
| **Mechanically guaranteed** | no path to a new L1 without authorization (closes A08 for CONTENT-EXTRACTED *and* fresh-run READING); old evidence preserved |
| **NOT guaranteed** | that the new extractor's context is free of what L2/L3 revealed (the agent may have read them) → **DETECT**: the lineage records that L2/L3 existed, and the audit diffs `v<k>` against `v<k+1>` with that flag |
| **Adversarial tests** | A08; fresh-run READING after L2; re-extraction under the wrong bound hash; attempted deletion of `v<k>`; downstream consumption of `v<k+1>` by records made for `v<k>` |
| **Closure evidence** | tests pass; the re-auditor cannot produce `v<k+1>` without authorization |
| **Residual** | contamination of the re-extractor (DETECT via lineage + diff) |

### 3.4a Lineage binding of derived artifacts (r2)

| Field | Content |
|---|---|
| **Invariant LINEAGE** | every L2/L3 artifact (contributions, analysis, cross-file dispositions, research, checkpoint entries) carries `source_evidence_hash`. It is evidence **only** for that EvidenceObject version. No artifact derived from `v<k>` may be consumed or represented as evidence for `v<k+1>` unless a **REVALIDATION event** creates a new artifact bound to `v<k+1>`. The three statuses are distinct and never collapse: `DERIVED-FROM-v<k>` (produced against v<k>) · `DERIVED-FROM-v<k+1>` (produced fresh against v<k+1>) · `REVALIDATED-FOR-v<k+1>` (a v<k> artifact re-checked against v<k+1>, carrying `revalidated_from: <old artifact sha256>`) |
| **Precondition** | for REVALIDATION: `v<k+1>` sealed and accepted; the old artifact's hash recorded |
| **Transition** | REVALIDATION runs the stage's own gate checks (the reconstruction, analysis or research gate) against `v<k+1>` in a new run, and writes a **new** artifact bound to `v<k+1>`. The old artifact is never edited. Its status becomes `STALE-SOURCE` (recorded in the lineage, not in the file) |
| **Postcondition** | the consumer resolution (§3.6) returns only artifacts whose `source_evidence_hash` equals the version being consumed; STALE-SOURCE artifacts are readable as history, never as evidence for the new version |
| **Mechanically guaranteed** | implicit re-binding is impossible: resolution filters by `source_evidence_hash`; a revalidated artifact is a different file with a different hash, and it names its origin |
| **NOT guaranteed** | that REVALIDATION is a genuine re-check rather than a copy — it passes the same gates, so its semantic quality is as good as those gates and the audit |
| **Adversarial tests** | an L2(v1) consumed after v2 is sealed → refused; an L2(v1) edited to say `source_evidence_hash = v2` → refused (its content hashes no longer match the recorded artifact, and the v2 lineage has no REVALIDATION event for it); a REVALIDATION without a sealed v2 → refused; a checkpoint mixing v1 and v2 artifacts for one F-ID → refused |
| **Closure evidence** | tests pass; the re-auditor cannot make a v1-derived artifact count for v2 |
| **Residual** | the semantic adequacy of a revalidation (DETECT by the audit) |

### 3.5 Auditor independence and completeness (N-03; review point 4; D-3, Q-2)

| Field | Content |
|---|---|
| **Invariant** | a valid AuditRecord for `v<k>` requires: auditor coverage of the frame (every non-markup unit carries ≥ 1 auditor item or an auditor disposition, with reasons); the auditor's own complete read (C01 coverage under its run); the auditor's own prompt (sealed, hash in the record, containing no extractor output); `auditor_method_id` + `version`; `comparison_method_id` + `version`; the comparison recomputed from sealed artifacts; `ACCEPT-L1` bound to `hash(v<k>)` **and** to the AuditRecord hash |
| **Precondition** | `v<k>` is sealed and committed |
| **Transition** | the auditor produces its artifacts; the Gate computes the comparison and emits a proposal; the Commit boundary commits it; the human decides `ACCEPT-L1` / `REJECT-L1` / `AUTHORIZE-REEXTRACTION` |
| **Postcondition** | the AuditRecord reports **separately**: (a) auditor completeness (frame coverage, items per unit); (b) agreement (per-unit category divergence, protected-group absence, definition-term differences, the extractor's releases and NO-SUBSTANTIVE dispositions listed for review); (c) its own limits |
| **Mechanically guaranteed** | the trivial auditor (A15) fails the frame-coverage floor; a forged or stale record fails recomputation; acceptance binds both hashes |
| **NOT guaranteed** | statistical independence (same model family); that the auditor examined each unit *carefully* (frame coverage is a floor); that the auditor did not read the extractor's L1 (**DETECT** via its attestation and prompt; PROC otherwise) |
| **Adversarial tests** | a one-item auditor (A15); an auditor that covers every unit with trivial items (reported as low-quality in (a), not hidden); a forged AuditRecord; an AuditRecord for another evidence hash; an acceptance bound to only one of the two hashes |
| **Closure evidence** | tests pass; the re-auditor cannot obtain a valid AuditRecord with less than frame coverage |
| **Residual** | shared frame (deliberate, Q-2); same model family; auditor diligence |

### 3.6 Cross-file consumption (N-06; C05)

| Field | Content |
|---|---|
| **Invariant** | PROVENANCE. Every cross-file candidate, RELATED disposition, `other_quote`, research evidence item and checkpoint population entry stores `(F-ID, evidence_hash)` and resolves only against a sealed, accepted EvidenceObject whose artifacts recompute to that hash |

| **NOT guaranteed** | that the consumed evidence is *right* (that is the audit's job); cross-file relatedness judgements (review signals) |
| **Adversarial tests** | A06; consuming a superseded version; consuming an unaccepted version; a quote present in the file but not in the accepted evidence |
| **Closure evidence** | tests pass |
| **Residual** | none mechanical beyond 3.2's |

## 4. What is explicitly NOT a gate in v1.3 (review signals only)

These produce **review obligations** recorded in the AuditRecord, and are never guarantees:
- the math-bearing detector (with *measured recall* on a versioned synthetic notation set);
- the definition-cue detector;
- the prescription and temporal-language detectors;
- the near-duplicate signal (Jaccard **and** containment, with the distribution published; 0.8 labelled a design choice).

**Structural rules stay hard,** because they are not lexical:
- the outcome **whitelist** schema;
- no release on MATH or CODE kinds;
- the S-identifier check, case-insensitive on every string field, with path normalisation for attestations;
- mechanical multiplicity families (all confirmatory comparisons at one checkpoint).

## 5. Closure criterion (the anti-regress rule)

v1.3 is closed when, for each §3 area:
1. its invariant is implemented and classed (CRYPTO / MECH / DETECT / PROC / NONE);
2. its listed adversarial tests pass;
3. a fresh adversarial re-auditor confirms that the *classed* guarantee holds;
4. its residual is written in the protocol.

A later attack that succeeds **only by exploiting a written residual** is recorded as confirming that residual. It is
not a v1.3 defect and does not trigger a v1.4. A v1.4 is warranted only by an attack that defeats a guarantee v1.3
*claims*.

## 7. Formal state-transition table (r2)

**Rules for every row, unless the row says otherwise:**
- **Commit.** Each transition is `Gate → TransitionProposal → Commit boundary (GIT-CAS, §3.3a) → the next Gate verifies`.
- **Approval.** Each transition requires the `APPROVE-PROTOCOL` decision for the documents and scripts in force, of
  the HDR-6 type.
- **Integrity.** Each transition requires GIT-INTEGRITY and LANE-OWNERSHIP.
- **Run.** The run id is the one of the previous event, except where the row opens a new run.
- **Freezes.** A transition into stage X re-verifies the freezes of all stages before X.
- **"Decision(action)"** means an authorization object of the type HDR-6 prescribes, bound as stated.
- **Artifact location.** v1.3 stores L1 artifacts under `ledger/F####/L1-v<k>/`, and L2/L3 artifacts under
  `ledger/F####/L1-v<k>/derived/`, so every derived artifact is physically bound to its evidence version.
