## ⛔ Fail-closed, with no warning tier

**Admission requires ALL of:** the manifest resolves the token to **exactly one** `file_id` · the file exists · its `sha256` **matches**.

⭐ **Anything else is `STOP`:** unknown path · **ambiguous prefix** · missing file · changed bytes · defective manifest row · a receipt with no unit.

> ⚠️ **Ambiguity is `STOP`, never "the first match."** *The canonical log's space-truncated paths make near-misses real, so "closest" is exactly the wrong rule.*

## ⭐ A finding about the canonical manifest itself

⛔ **This qualifies `ID-ROOTCAUSE-01 Addendum A`, which said the manifest was *"not defective."***

|---|---|
| ✅ **Identity column: SOUND** | **3,081 rows · 0 duplicate `file_id`s** |
| ⚠️ **Path column: 18 rows (0.6 %) do not resolve** | **space-truncated filenames** — the log appears generated by a whitespace split, so `…/prompts/Yes.` is really `Yes. I read the relevant material…` |
| ⭐ **The region that matters: CLEAN** | **top-level `docs/knowledgeos/*` — 51 rows, 0 missing.** ⛔ *The `F0031` divergence happened entirely inside the clean region and is not excused by this defect* |

⭐ **Defective rows are RECORDED (`defect: PATH_DOES_NOT_RESOLVE`) and are `STOP` on admission** — never silently dropped, never guessed at.

> ⭐ **Design point:** a duplicate `file_id` is **FATAL** and refuses the build — identity is the one thing that cannot degrade. An unresolvable **path** is **recorded**. *Refusing to build over a 0.6 % path defect would throw away a sound identity column; fail-closed belongs at **admission**, not at construction.*
