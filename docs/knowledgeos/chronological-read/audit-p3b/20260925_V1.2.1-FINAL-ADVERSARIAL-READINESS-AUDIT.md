- invalid → RUN-INVALID;
- VALID never with a failed run;
- VALID never with NOT-COMPUTABLE;
- VALID never with a reference quote or schema failure;
- VALID never with incomplete M1;

- reference failure alone never → INSTRUMENT or NOT-USABLE;
- NOT-COMPUTABLE alone never → INSTRUMENT;

## 6. Remaining limitations and residual trust (acceptable; disclosed)

1. **Harness transcript completeness** is assumed (not provable). Linkage, truncation and post-ingest tampering are checked.
2. **Orchestrator-recorded status.** A run's `COMPLETED` status and its `failure_reason` are frozen, but their truth rests on the orchestrator's reading of harness evidence.
   - An open-ended reference run labelled COMPLETED can still have **narrow output breadth**. Page proof shows reading, not output breadth.
   - Capture would then be measured on a narrower reference. That is a weaker claim, not a false one. Reference completeness is unmeasurable by design.
3. **M1 judgment bias in the same direction as M2** (same vendor) on decisions: κ checks only a 30% sample. This is the stated capture limitation.
4. **Coordinated tampering** of PROVENANCE together with files is visible only through git history (per-stage commits).
5. **Standing limitations:**
   - six previously exposed files;
   - single vendor;
   - M2 = the E1 model;
   - E2 is a smaller model;
   - κ conditional on M1 clustering, and agreement ≠ correctness;
   - structural source inference;
   - arbitrary engineering values;
   - the opus-alias model-id risk (by design, it would make the run invalid).
6. **Test hygiene (MINOR):** one guard test depends on the full repository layout.
