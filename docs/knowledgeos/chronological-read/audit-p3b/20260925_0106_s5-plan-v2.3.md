## C. OMQ-16: research-testing budget

**Measured [MEASURED]:**
- R2.2: 87 register records for 20 labels (71 OBSERVED, 10 ANALYSED, 6 TEST-DEFINED); none TESTED.
- Step-10 reads ≤ 0.08 MB per batch.
- H/SC sets did not reproduce between R2-001 and R2.2.

### C.1 In batches (records up to TEST-DEFINED)

1. **Reads:** step 10 through `p3b_read_source.py`, logged and **label-local**: only files in the label's slice.
   - For a **hub**, a file that is one of the hub's stage-1 hit files may not be read at step 10 unless OMQ-14 already requires it at step 1. This keeps stage 2 out of the back door.
   - There is no cross-label reading in batches.
2. **Cap:** step-10 bytes ≤ **0.9 MB per batch** [PROPOSED]: about 10% of the stage-2 limit and about 11× the largest S4 research-read load. Actual use is reported.
3. **Repeats:** a re-read counts again against the cap. The verifier reports the repeat ratio.
4. **No record quota and no minimum** (D-38). The audit checks for manufactured hypotheses (§21 item 5). H/SC/TC records must reach TEST-DEFINED with `test_plan_sha256` [FROZEN §13.9].
5. **Exhaustion:** no further step-10 reads in that batch. The **batch report** records `research-read budget exhausted`, and records keep their reached stage. No new register value is introduced.

### C.2 Test pass (TESTED and STATUS) [FROZEN selection rule, §13.9 RC-9g; mechanics PROPOSED]

- **When:** after S5a. The frame is **all non-CORPUS TEST-DEFINED records of the primary run**: OBJECT records from batches and CROSS-OBJECT records from S5a, persisted before the frame freeze. **COMPARISON (rerun) records are excluded** (MINOR-7). CORPUS records are all TESTED in S5b [FROZEN].
- **Selection, mechanized:**
  1. The frame is written and hashed.
  2. A seeded permutation (seed `20260927`) of the frame is written and hashed **before any test runs**.
  3. The test plans' `test_plan_sha256` values are recorded in `P3B-INPUT-MANIFEST.json` before the testing run (§13.10a).
  4. Tests run strictly in permutation order.
  5. The share is **s = 20%**: the first ⌈0.2·N⌉ records.
  6. **The share is fixed at 20% for S5** (MINOR-8). v2.2's option to lower it after 20 tests is withdrawn: any act taken after tests exist could be informed by outcomes, since STATUS values sit in the repository. Cost is bounded instead by the per-test caps below.
- **Read budget per test [PROPOSED]:**
  - The lexical B and D searches run as scripts over the **discovery population** (addendum §2).
  - **Unit (MINOR-7):** a test's load = the number of distinct hit keys (S-id × anchor or offset × term) of the **union** of its B and D lexical searches over discovery files, using every participant's A.4 terms.
  - If the load exceeds **4,081** (the T4 figure), the test is not run: the record stays TEST-DEFINED, and the test-pass report records `LOAD`. **A LOAD-skipped record keeps its place in the prefix and is not replaced**, so selection stays by rule.
  - Otherwise, whole-file reads per test are ≤ **8.63 MB**. If the cap is reached mid-test, the test stops, the record stays TEST-DEFINED, and the report records `LOAD-PARTIAL` with the reads made. No STATUS is assigned from a partial test.
  - **CORPUS records are exempt from the LOAD skip and from LOAD-PARTIAL.** "CORPUS-scale records are always TESTED" is frozen (§13.9, §27 OMQ-16, D-57).
    - Every CORPUS test is run in full.
    - Its load (same unit) and its whole-file read volume are reported.
    - If a CORPUS test's load exceeds 4,081, or its reads would exceed 8.63 MB, **the orchestrator escalates to the human before running it** (`P3B-ESC`, load). The human either authorizes the full test with a recorded budget, or invokes the §19.4/§23 stop-the-line, which leads to a §26 change.
    - The test is never skipped or truncated silently.
  - LOAD-skip and LOAD-PARTIAL rates for non-CORPUS tests are reported, and summaries of the tested set are stated as conditional on **load ≤ 4,081 and reads ≤ 8.63 MB** (MINOR-7). The 8.63 MB cap is a read budget. It is not a §20 batch gate, but it does bound whether a non-CORPUS record can reach STATUS.
- **Formal, mathematical, logical and DDD analysis:** reasoning within the selected test. It uses no reads beyond the four disconfirmation searches (§13.10).
- **Infrastructure:**
  - its own pass-contract section and verifier;
  - run ids `OT####-R2`;
  - an extension of the reader's run-id pattern, as reviewed tooling.
- Testing never blocks acceptance. Untested records carry forward (§13.9).

## F. H-16: N_support

- **Unit (from the frozen text) [FROZEN]:** a threshold **per record** (claim or structure), not per label.
  - OBJECT scale: independent PRIMARY sources.
  - CORPUS scale: independent occurrences per §9E.3.
  - CROSS-OBJECT: never SUPPORTED at freeze (L-1).
- **Already enforced [FROZEN]:**
  - in-file repetition counts once (R2.2 collapsed 74 repeated occurrences);
  - duplicates count once (`08-OVERLAP-REGISTER`);
  - SECONDARY-SYNTHESIS and PROVENANCE-UNRESOLVED sources create no occurrence;
  - no shared label or source between counted occurrences (A.8);
  - SELF-DERIVED, DESCRIPTIVE and control findings never count.
- **Not captured:** restatement across PRIMARY files of one authoring session. This is a stated limitation. No reliable pre-S5 measure of authoring sessions exists, since mtime blocks are undefined for many files and BULK blocks are copy artefacts. v1 proposed an mtime-block field; v2 drops it.
- **Choices:** 1; 2; 3; or 1 for OBJECT scale with 2 for CROSS/CORPUS. The protocol recommends **2**, the smallest value that requires independent replication.
- **Instrument instability** (P3a 20.9% exact agreement; S4 R1/R2 30–95%) concerns runs, not sources. N_support does not address it. §K does.
- **What "independent" means operationally (certification §4) [FROZEN rules]:** distinct S-ids; each PRIMARY per `02-FILES.jsonl`; not a registered duplicate; in-file repetition collapsed; no shared member label and no shared or duplicate source between occurrences; not SELF-DERIVED, DESCRIPTIVE or control. This is **"distinct, non-duplicate PRIMARY"**: a necessary proxy, not epistemic independence.
- **Not known to the system:**
  - same authoring or AI session;
  - unregistered copying between PRIMARY files;
  - a shared upstream prompt or source;
  - near-duplicates below the overlap register.

  Filenames, rows and timestamps are not evidence of independence.
- **Reporting fields [PROPOSED; MINOR-11]:** every record carrying SUPPORTED-IN-CORPUS or `evidence_level ≥ RECURRENT` also carries `independence_basis: "DISTINCT-PRIMARY-NON-DUPLICATE (§9E.3)"` and `authoring_session_independence: "NOT-ASSESSED"`. These are reporting fields, not semantic_status values; the phase report restates the limitation next to every count.
- **Wording:** "H-16: N_support = 2 (OBJECT: independent PRIMARY sources; CORPUS: independent occurrences per §9E.3), with the two reporting fields."

## H. H-17: controls, test and decision rule (MAJOR-1, MAJOR-2, MAJOR-4)

### H.1 Control draw [FROZEN A.7 + PROPOSED parameters]

- **Arity [PROPOSED; frozen §9E.2 item 3 requires H-17 to fix it]:** **k ∈ {2, 3}**, pooled per cell. Arity enters the test as a blocking variable (§H.3), and controls always match the candidate's arity exactly.
- **Draw:** r = 2 control sets per analysed candidate, drawn per A.7 in the frozen order: controls for every analysed candidate → drop NO-CONTROL-AVAILABLE → label-disjoint candidate family (§9E.2 item 6). Within a matched set, the controls share no label with that set's candidate or with each other. **Reuse across matched sets is allowed** [HUMAN DECISION: the sampling design is not changed to reduce reuse; G-LOG-0039].
- **Matching:** exact arity, **never relaxed** [FROZEN]. Banded variables:
  - row_count (1 / 2–3 / 4–9 / ≥ 10);
  - pair_count (0 / 1 / ≥ 2);
  - provenance mix of rows (all PRIMARY / mixed / none PRIMARY);
  - historical-span band of row files' best dates (< 1 day / 1–7 days / > 7 days);
  - max row-file degree over the 2,452 discovery labels (≤ 5 / 6–10 / > 10).

  **G-TYPE-SIM additionally matches on has-formal-rows, which is never relaxed** (§9E.1).
- **Set-band definition (MAJOR-1):** a set's band profile on a variable is the **sorted multiset of its members' bands**.
- **Control seeds:** per-candidate draws use streams spawned from root 20261009 (§G.3), recorded with each control record.
- **Relaxation:** in reverse list order (degree first, row_count last), one variable at a time, each recorded.
- **Partial availability:** a candidate with 1 control available keeps it (r_s = 1), and this is recorded. With 0 it is NO-CONTROL-AVAILABLE and dropped (A.7).
- **Control-availability simulation (O-12):** run before the first batch for the pre-S5 generators, reporting the NO-CONTROL-AVAILABLE rate, the relaxation levels and **control-label reuse** per generator. It is design evidence, not a tuning input.

### H.2 Inferential target and assumptions

- **Null hypothesis H0 (per registered cell g × c):** within every block b (§H.3), conditional on the observed class outcomes of the block's units, **the assignment of the candidate role to units is exchangeable**. Every assignment of the block's n_C,b candidate roles to its N_b units is equally likely.
- **In words:** within label-connected, arity-matched blocks, generator-defined candidate status carries no information about whether class c is recorded.
- **H1 (one-sided):** candidate units record c more often.
- **Assumptions (stated explicitly; not a randomization test):**
  - **(A1) Conditional exchangeability of roles within blocks.** Candidate status was not randomized; it comes from the generator. H0 is therefore a model-based assumption of no confounding within blocks beyond what the block structure and the matched draw control. It is **untestable**. **The design also makes many permuted assignments impossible:** candidates are pairwise label-disjoint, and a set's controls are disjoint from its candidate. So the within-block permutation distribution is an **approximation** to the design's reference distribution, even without confounding. A DIFFERENTIATED result means "candidate units differ from label-connected, matched control units", **not** "the generator link causes the class".
  - **(A2) No independence across units is assumed.** The test conditions on the observed outcomes and permutes roles only. Because outcomes are conditioned on, dependence among them (shared labels, reused controls) enters only through A1, never through an independence assumption. Each distinct set therefore counts once. The design evidence in §H.6 shows the matched-set test of v2.2 inflating under reuse, and the label-cluster test **conservative in the simulated regimes**. Those regimes have no matching, no removal and no triples, and R1's 500 draws cannot resolve a rate near 0.0016.
  - **(A3) Undetermined status carries no information about role** (it applies to FULL-blinded cells; PARTIAL cells take p = 1 anyway). Hub and RC-13 unscoring are deterministic structural removals made before analysis, and are not covered by A3. H0 and A1 are taken to hold over the three-valued disposition (1 / 0 / undetermined). Symmetric removal (§H.4) is outcome-dependent, because "undetermined" is an analysis result. This is acceptable only because FULL blinding keeps undetermined status blind to role, and it is stated as an assumption.
- **What the test does not establish:** truth, causation, or theory validity (§N).

### H.3 The label-cluster permutation test [HUMAN DECISION: the frozen §9E.2 item 6 alternative, G-LOG-0039; specification PROPOSED]

| Element | Specification |
|---|---|
| **Order of operations** | (1) frozen family and controls; (2) hub and RC-13 unscoring (pre-analysis); (3) reveal; (4) **symmetric removal** (§H.4); (5) **then** build the label components and blocks on the **retained** units; (6) statistic and exact p |
| **Exchangeability unit** | a **distinct set** in the cell's pool: every candidate set of the frozen family (after hub and RC-13 handling) and every distinct control set drawn for them. A control set drawn for several candidates is **one** unit; a set appears once (§9E.2 item 11) |
| **Cluster definition** | the connected components of the **label graph** of the cell: vertices are labels; two labels are joined when they occur together in any unit of the cell. Each unit lies wholly within one component |
| **Block** | component × exact arity (× has-formal-rows for G-TYPE-SIM). Bands serve the control draw and a reported balance table, and are **not** a blocking variable. Blocking on the full band profile would empty most blocks; this is stated as a choice |
| **What is permuted** | within each block, the candidate/control **role labels** among the block's units, keeping the block's number of candidate units fixed |
| **What stays fixed** | the units, their outcomes, the label graph, the blocks, the per-block candidate counts |
| **Clusters spanning several matched sets** | expected, and handled naturally: a block may contain units from many matched sets. The matched-set structure governs how controls are drawn, not the permutation |
| **Repeated control labels or sets** | a repeated control **set** is one unit, counted once. Repeated control **labels** join their units into one component, so dependent units are compared only within their block |
| **Uninformative blocks** | blocks without both roles are dropped from the statistic and counted. If no informative block remains, the cell is UNDERPOWERED |
| **Statistic** | T = number of candidate units in informative blocks that record class c at ≥ ANALYSED. With the block margins fixed, T is equivalent to the candidate-minus-expected difference summed over blocks |
| **Null distribution and p** | under H0 the candidate-showing count in block b is Hypergeometric(N_b, K_b, n_C,b), with K_b = units in b showing c, independently across blocks under the permutation. **Exact p = P(Σ_b X_b ≥ T_obs)**, computed by convolution of the per-block pmfs. **No Monte-Carlo, no seed, no Monte-Carlo error** |
| **m, x_min** | **m as frozen** (§9E.2 item 6): independent candidate sets in the cell's pool after NO-CONTROL-AVAILABLE drops, where **the cell's pool is link 6** (post-hub, post-RC-13). **x_min counts candidate units showing c among the retained, informative units.** Also reported: **m_inf**, the candidate units in informative blocks after symmetric removal. TESTED requires m ≥ 20, x_min ≥ 3 (candidate units showing c) and m_inf ≥ 1; otherwise UNDERPOWERED [protocol recommendation]. m_inf < 20 is reported, not gated. A cell may therefore be TESTED with few informative candidates. The p-value stays exact, and this is reported |
| **Raw p into BH** | every **tested** registered cell contributes its exact raw p. Registered cells that are UNDERPOWERED, REPORT-ONLY-PARTIAL-BLIND or empty contribute **p = 1** [FROZEN §9E.2 item 6]. BH at q = 0.10 over all K registered cells; only cells significant after BH may be DIFFERENTIATED |
| **BH dependence** | BH assumes PRDS. Cells of one generator share units, so the sign of their dependence is unknown. **Benjamini–Yekutieli** (q / Σ 1/i) is reported alongside as a sensitivity analysis, and decides nothing |

### H.4 Missing, undetermined and unscored outcomes [HUMAN DECISION: symmetric removal, G-LOG-0039]

**Principle: UNDETERMINED is not 0.** Epistemic uncertainty is never converted into negative evidence.

- **Undetermined or unscored candidate unit** (analysis DEFERRED, analysis failure, or an RC-13 unscored identity outcome): the **whole matched set** is removed from that cell. That is the candidate plus its controls, except controls that also serve another retained matched set.
- **Undetermined or unscored control unit:** that control unit is removed from the cell, and from every matched set it serves. A matched set left with no control is removed, candidate included.
- **Closed form:** the retained matched sets are exactly those whose candidate is determined and that keep at least one determined control. Removing a set never removes a control that serves another retained set, so nothing cascades. **This is a per-cell missing-data rule. The frozen test family is unchanged** (§9E.2 item 6 selection is not re-run).
- **Attrition** is reported per cell **by role** (candidates removed, controls removed, sets lost) and by cause.
- **RC-13 is role-symmetric under this rule.** In identity-class cells (EQUIVALENCE-CLASS, where it is DISCOVERY), any unit containing a P3a-judged pair is unscored, whether candidate or control, and is removed as above.
- **Hub rule (absence-based classes MISSING-TRANSITION, MISSING-INVARIANT):** units containing a hub are treated as unscored in those cells, which is deterministic and pre-analysis. **G-13 check:** no CROSS-OBJECT or CORPUS finding may cite a hub's absence resolution as basis (§23 item 3b).

### H.5 Detectable difference and power (MINOR-1, MINOR-2)

- **Name:** the per-cell **"Bonferroni-calibrated (single-rejection BH) detectable difference" (BCDD)**. It is the smallest candidate-minus-control difference in proportions that the §H.3 test detects with 80% power at level **q/K** (0.10/64), on the cell's realised block structure and observed control proportion.
  - It is computed by seeded simulation (root 20261011, per-cell streams). **Alternative model:** each candidate unit in informative block b shows c with probability min(1, p̂_b + Δ), where p̂_b is block b's observed control proportion. Controls keep p̂_b, and outcomes are independent. Δ is increased on a grid of 0.01, with **2,000 simulated tables per step**, until 80% reject at the level. If no Δ reaches 80% before every p̂_b + Δ caps at 1, the BCDD is reported as `NOT-REACHED`.
  - It is reported as `NOT-COMPUTABLE` when no informative block exists.
  - It is also reported at α = 0.05.
- **It is not called a BH MDD.** q/K equals the BH threshold only when a cell is the sole rejection. With j true alternatives, BH thresholds grow up to jq/K. The certifier's simulation (m = 40, 0.2 → 0.4, K = 63) gave per-cell BH power 0.165 / 0.338 / 0.584 for j = 1 / 10 / 30.
- **Optional pre-registered sensitivity table:** BH per-cell power for j ∈ {1, 10, 30}. It is reporting only.
- **Reference power figures** (computed by the certifier for the v2.2 **matched-set** test at independent sets; **not** the power of the §H.3 test):

  | Figure | Value |
  |---|---|
  | power at m = 20, r = 2, 0.2 → 0.4, α = 0.05 | 0.382 (Fisher 0.385; both from the certifier's report, `/tmp/s5cert/power.py`, not stored in the repository) |
  | same, at q/K | 0.050 |
  | 80%-power detectable difference from 0.2 at q/K: m = 20 / 40 / 100 | 0.55 / 0.40 / 0.25 |

  The power of the §H.3 test depends on each cell's block structure. It is reported per cell through the BCDD. **Most cells are expected to be UNDIFFERENTIATED or UNDERPOWERED, and that is never evidence of absence.**

## K. Repeated-run stability

- **Object-level rerun [PROPOSED]:**
  - Population: a seeded (`20260928`), proportional **5%** of non-hub labels over the 24 strata plus the **purposive group** (348 non-hub labels with no stratum), 25 groups in all. Group size = max(1, round(0.05 · n_g)), with Python's round-half-to-even (round-half-up would give 99): **97 labels** [MEASURED allocation].
  - Inclusion probabilities range from 0.037 to 0.5, so **agreement estimates are design-weighted** by inverse inclusion probability. Unweighted figures are reported alongside.
  - Drawn from `P3B-SAMPLE-PLAN.jsonl` only.
  - Held constant: v1.7, contract sha, slices, reader, **model (claude-opus-5-5)**.
  - Regenerated independently: fresh agents, run ids `OB####-R2S`, private scratch, blind to the primary outputs.
  - Timing: after the primary batches are accepted.
  - **Rerun records are COMPARISON records.** They are verified and audited like batches, but never ACCEPTED as P3b results, and never enter S5a or the S5c baseline.
- **Metrics:**
  - per field (births ×5, type_status, mathematical_status, primary_layer, per-dimension absence resolution): exact agreement and Cohen's κ, each with a **design-following** bootstrap 95% CI: labels are resampled **within each of the 25 groups** (dimensions stay with their label). Groups with a single sampled label are collapsed into one pooled group for variance estimation. Seed 20260930. Category prevalence and prevalence-adjusted agreement (PABAK) are reported alongside κ, because skewed fields give low κ despite high agreement;
  - per label: the Jaccard overlap of the pre-registered classes recorded.
- **Baseline:** **no test–retest baseline exists.** v1's "S4 R1/R2" figures were inter-instrument (P3B-R1 against R2.2) and are dropped as a threshold. S5 establishes the baseline.
- **Flag [PROPOSED; human; a convention, not a measurement]:** `METHOD-INSTABILITY` for a field whose κ 95% CI upper bound is < 0.40, clearly below "moderate" in the Landis–Koch convention. At n ≈ 97 this flags only κ̂ of about 0.2 or less. It is a floor for gross instability, not a certificate of stability. Otherwise agreement is reported without a verdict.
- **S5a same-model re-analysis [PROPOSED]** (renamed from "second analyst", MINOR-12):
  - A fresh agent of the same model re-dispositions a seeded (`20260929`) **20% of all blinded units**, drawn from candidates and controls alike and **blind to role**.
  - The re-analysis **never feeds any cell**. It measures same-model re-analysis reproducibility only.
  - Agreement is measured on class disposition per set.
  - Per CORPUS finding, the plan reports **the number of its participating sets in the 20% subset and the proportion whose class disposition agreed**, with a Wilson 95% CI. `STABILITY-NOT-ASSESSED` applies if none was sampled. There is no binary flag: v2's any-disagreement rule would have penalised better-supported findings.
  - These are **reporting fields**; §13.9a/§13.9b are unchanged.
- **Cross-contract comparison:** under P-1 (a), the 25 accepted S4 labels (R2.2 PB02–PB05, PB06) are compared with their S5 records. It is labelled cross-contract, not test–retest.

**What the stability design can and cannot establish:**

| Component | Establishes | Does not establish |
|---|---|---|
| object rerun (same model, contract, slices) | instrument (AI-procedure) test–retest reproducibility | analyst independence; accuracy (a shared model can be identically wrong); truth |
| S5a same-model re-analysis | reproducibility of class dispositions on fixed blinded inputs | inter-analyst agreement; variability from generation and control draws |
| RECURRENT (§9E.3) | within-run count of independent occurrences | run reproducibility; theory validity |

**Stable agreement is never read as "the finding is true".**
