**The extraction and matching instructions are word-for-word identical.**

**M-1 (MATERIAL): the prompt actually dispatched is not verified against the frozen prompt.**
- The orchestrator pastes each prompt into the Agent dispatch.
- `result` re-checks that `PROMPTS/<run>.txt` equals the generator output (§15 item 10), but it **never compares the prompt the agent received** (the transcript's first user message) with that file. The repair prompts are likewise not compared.
- An orchestrator error (a truncated, edited or stale prompt) would therefore pass every check, provided the run id and canary survive. X5 linkage checks only those two strings.
- **Feasibility shown on PX0106:** the harness transcript's first prompt is **byte-identical** to the frozen prompt file (U01: 4,041 = 4,041 characters, equal; U04: 2,022 = 2,022, equal). The check is mechanical and cheap.
- **Minimum fix:** `result` (and `ingest`) require `first_prompt.strip() == PROMPTS/<run>.txt .strip()`, and each repair SendMessage text must equal `PROMPTS/REPAIR-<run>.txt`. Otherwise RUN-INVALID.

**M-2 (MATERIAL): the "runs from any directory" claim is false.**
- Every generated prompt states that each command "is complete and runs from any directory".
- But the reader imports `p3b_s3_mechanical_prep.py`, whose `REPO_ROOT = git rev-parse --show-toplevel` (l.74) is resolved **from the current working directory**. Run from outside the repository, the reader fails; run inside another git repository, it resolves the wrong root.
- The working-directory dependence that V1.2.2 meant to remove survives in the dependency. The allowlist also still permits `cd <any dir>`, so an agent that changes directory breaks its reads. That is exactly the situation in which PX0106's U06 began exploring.
- PX0106 agents ran with the harness cwd inside the repository, so the default path works. But the contract's stated guarantee is untrue.
- **Minimum fix, with no change to the reader or allowlist:** generate every command as `cd <repository root> && python3 <absolute reader> …` (accepted by the frozen `bash_allowed`, since `cd` plus `&&` is permitted), and correct the wording. The gate additionally checks that the `cd` target equals the repository root.

## 5. Security and allowlist findings (frozen `bash_allowed`, not weakened)

| Probe | Accepted? | Assessment |
|---|---|---|
| newline injection; `;`; `&&` followed by a non-allowed command; `\|\|`; pipe; `&`; redirect | no | enforced |
| command substitution (`$()`, backticks); glob; `$VAR`; quoted argument; tab separator | no | enforced |
| Unicode lookalike in the label; Unicode S-id; wrong run; wrong batch; foreign S-id; extra argument; page 0 | no | enforced |
| trailing spaces | yes | harmless (stripped) |
| **alternate executable path** (`python3 /tmp/x/scripts/p3b_read_source.py …`); **`..` traversal** of the correct path | **yes** | **m-1 (MINOR):** the script prefix is character-restricted, not pinned. The run, batch, label and S-id restrictions still hold, so no other file can be requested. But a planted or altered reader copy would be accepted. Planting requires a Write or Bash breach, which is detected. Existing files named `scripts/p3b_read_source.py` do exist under `/tmp` (see m-3), but they contain `DEP` and are not executable Python |
| **Unicode digit in the page** (`--page 1١`) | **yes** | **m-2 (MINOR):** `\d` matches non-ASCII digits. The first digit must be ASCII 1–9, and any two-digit page exceeds every file's page count (max 9), so no additional content becomes reachable. Hygiene: `[0-9]` |

**Runtime equivalence:**
- the runtime audit (`audit_calls`) evaluates the recorded Bash command string with the same `bash_allowed`;
- the generator emits exactly those strings, and the gate evaluates them with the same function;
- **accepted by the gate means accepted at runtime.**

**m-3 (MINOR, hygiene):** the V1.2.1/V1.2.2 guard tests create `mkdtemp()` directories without cleanup. **156** leaked `/tmp/tmp*/scripts/` directories contain fake dependency files. Harmless, but they enlarge the m-1 surface. Fix: `TemporaryDirectory` in tests, and clean `/tmp` of those directories.

## 8. Statistical findings (the design is audited, not changed)

1. **Estimands.** They are conditional on these six files, this model pairing and M1's clustering:
   - (a) mechanical segment coverage and verbatim-quote fidelity of SEG;
   - (b) inter-matcher agreement κ_target on the sampled decision units;
   - (c) capture: the share of the E1∩E2-agreed set (as judged by M1) that M1 matched to SEG.
2. **Population.**
   - The files are six previously exposed files from **two labels**, chosen purposively (smallest/middle/largest by size).
   - This is **not a probability sample**. There is no inferential population beyond these files.
3. **Local conclusions:** all metric values are local.
4. **What could generalize:** at most qualitative feasibility, i.e. that the pipeline can run end to end with coverage 1.0 and verified quotes on files of 15–174 k characters. It says nothing about other labels, file types or models.
5. **κ is agreement only**, conditional on M1's clustering. It does not measure matching correctness (agreement ≠ correctness), clustering validity, or extraction quality.
6. **κ's sampling uncertainty is not pre-registered.** For illustration only: at about 180 units, with p_o = 0.85 and p_e = 0.5, κ ≈ 0.70 with a standard error of roughly 0.05. The 0.60 and 0.40 gates are engineering rules, not tests.
7. **Quote verification** establishes string provenance, not semantic support.
8. **Segment coverage** establishes accounting for every segment, not completeness of propositions. It is satisfiable vacuously, which is why the capture gate exists.
9. **Capture** estimates relative recall of SEG against a same-vendor, M1-judged reference.
   - It cannot estimate absolute recall (shared blind spots are invisible) or recall on other corpora.
   - **Binomial uncertainty is large at the minimum agreed-set size.** For illustration: 16/20 = 0.80 has a 95% Wilson interval of about [0.58, 0.92]; 40/50 is about [0.67, 0.89]. A pass at n ≈ 20 is statistically weak.
10. **Engineering rules, not guarantees:** κ ≥ 0.60 / < 0.40, capture ≥ 0.80, agreed ≥ 20, coverage < 0.95, and quote-miss rate > 5%.
11. **Still impossible even with INSTRUMENTS-VALID:**
    - corpus-wide or label-wide extraction completeness;
    - semantic correctness of propositions or matches;
    - model independence;
    - performance of other models or prompts;
    - any strategy comparison;
    - any change to a P3b or v3.5 obligation.

**The concepts are kept distinct:**
- **Reliability:** κ, and reproducibility of the deterministic stages.
- **Validity:** not measured.
- **Completeness:** relative, capture only.
- **Agreement:** κ.
- **Reproducibility:** deterministic stages yes; LLM stages no.
- **Semantic correctness:** not measured.
- **Generalization:** none.

- **Forbidden transitions:**
  - dispatch before PROMPTS-GATED or SEGMENT-FROZEN;
  - repair before CHECK-1;
  - unseal before M2-FROZEN;
  - any re-dispatch.

**Exhaustive enumeration:**
- **all 362,880 orderings** of the nine freeze stages: the canonical order is clean, **all 362,879 non-canonical orders are flagged (0 missed)**;
- every single-stage omission is flagged;
- all six agent-window violations (SEG before `segment-map`; E1 after `check-2`; M1 before `lists` or after `m1`; M2 before `sample` or after `m2`) are flagged.

**The invariant** "no corpus execution unless the exact authorized protocol, tool, dependencies, namespace **and prompt set** are the artifacts executed":

| Component | Status |
|---|---|
| protocol, tool, dependencies | **enforced** (guard on every sub-command; N2) |
| namespace | **enforced** (constants; allowlist) |
| prompt set (files) | **enforced** (gate; freeze; result re-check) |
| **prompt set as dispatched** | **not enforced (M-1)** |
| **agent read environment** (working directory) | **not guaranteed (M-2)** |

**Converse:** an authorized execution can proceed only when the guard passes. Dispatch itself is orchestrator-mediated and not mechanically blocked, but a dispatch before the gates is **detected** at `result` through the ordering checks (a limitation: detection, not prevention).

**TOCTOU:**
- tool or dependency drift after authorization is caught (the guard runs on every invocation);
- stale prompt files are caught (generator identity);
- stale hashes are caught (X7);
- **dispatched-prompt drift is not caught (M-1).**

## 10. ML and computational architecture opportunities (for the next layer; not added to V1.2.2)

**Principle: ML may classify, cluster, prioritize or propose. It never becomes source evidence.**

**Layers are never merged:**
`SOURCE` → `MODEL EXTRACTION` → `COMPUTATIONAL DERIVATION` → `HUMAN ADJUDICATION` → `RECONSTRUCTION` → `THEORY`.

**Every computational object carries:**
- its inputs (by hash);
- model and version;
- algorithm and parameters;
- timestamp and seed;
- output hash;
- its human disposition.

| Component | Use | Guard against misuse |
|---|---|---|
| **Semantic embeddings** of extracted propositions (a sentence-embedding model, versioned) | near-duplicate and paraphrase detection within and across extractors; candidate omissions (propositions in one source with no close neighbour in another) | similarity is a *review signal*, never a match decision; thresholds pre-registered per experiment |
| **Clustering comparison** (e.g. agglomerative clustering on embeddings) vs M1 clusters | disagreement between computational and matcher clusters produces a review queue | no cluster becomes canonical without adjudication |
| **Uncertainty score** (observable signals: extractor disagreement, M1/M2 disagreement, low similarity, conflicting types, weak quote alignment, unusual cluster size) | prioritizes human review | used only for ordering; never gates a V1-type decision unless pre-registered |
| **NLI / relation candidates** (contradiction, refinement, specialization, derivation) | proposes relation candidates for the P3 reconciliation workload | candidates only; P3b's relationship rules (§12) and evidence adjudication decide |
| **Active learning** (lightweight classifiers for proposition type, relation type, duplicates, trained on adjudicated items) | reduces manual review | train and test on disjoint adjudicated sets; never retrain on its own outputs; a held-out audit sample |
| **Hybrid pipeline** | SOURCE → deterministic reader → model extraction → schema and provenance validation → **ML diagnostic layer** → disagreement queue → human adjudication → reconstruction | the ML layer is read-only over evidence and writes to a separate diagnostics store |

## 14. Verdict

### NEEDS-REVISION

- The implementation is internally consistent. The scientific and statistical design is **unchanged** (verified independently), and the integrity additions are genuine integrity controls.
- **But two material defects remain:**
  - **M-1** means the invariant "the authorized prompt set is what was executed" is not mechanically enforced;
  - **M-2** means the execution contract's central guarantee (no working-directory dependence) is false because of a bound dependency.
- Both belong to the same defect class that invalidated PX0106, and both are repairable **without** touching the scientific design, the allowlist, the thresholds or §15/§17/§18 semantics (M-1 adds one integrity check).

## 16. Recommended next research architecture (proposal)

**Keep these questions as separate experiments, each pre-registered:**
- (1) extraction completeness (a multi-source capture–recapture design with deliberately **diverse** sources, reported as a lower bound);
- (2) extraction reliability (repeat runs, same inputs);
- (3) semantic equivalence (human-adjudicated matching gold set; measures matcher correctness, not just κ);
- (4) relation classification (P3-style relations against adjudicated pairs);
- (5) human adjudication efficiency (time per item vs. error found);
- (6) ML-assisted review efficiency (uncertainty-ordered vs. random review queues, the same adjudicators).

**No single "KnowledgeOS accuracy score".** The §10 diagnostic layer serves (3)–(6) only after V1-type instrument validity is settled.
