## 6. The E-run quote-miss gate (the critical question)

**Rule as frozen:** a completed run with a quote-miss rate > 5% after repair → **NOT-USABLE**. Any quote miss in any completed run → **INSTRUMENT**. Both apply to E1 and E2.

**What is declared unusable when E1's quotes are poor?**
- V1.1 declares the **instruments under test** (the segment inventory and the matching procedure) unusable.
- But E1 and E2 are **reference extractors**. Their outputs are inputs only to capture, a relative-recall reference.
- Poor E quotes indicate E extraction or model or prompt quality, i.e. **reference-data quality**. They are not a property of SEG or of matching.
- So the rule **cannot distinguish reference-extractor failure from failure of the instrument under test**, and it applies the strongest outcome to the wrong object.

**Categories evaluated:**

| Category | Fits? | Reason |
|---|---|---|
| hard instrument gate | **no** | E is not the instrument |
| run-integrity condition | no | a poor quote is not a protocol breach |
| **reference-quality condition** | **yes** | it degrades the reference that capture depends on |
| INSTRUMENT-UNDETERMINED | **yes, as the outcome** | reference defects leave SEG validity undetermined |
| diagnostic only | insufficient alone | it would let VALID rest on a reference with unverifiable quotes |

**Minimum logically correct treatment (proposal; changes scientific interpretation; needs a human ruling):**
- **SEG quote gates:** unchanged (NOT-USABLE above 5%; INSTRUMENT above 0).
- **E1/E2 quote misses after repair:**
  - they are a **reference-quality condition** that **blocks INSTRUMENTS-VALID**, with qualifier **INSTRUMENT-UNDETERMINED**;
  - they **never** produce NOT-USABLE or INSTRUMENT;
  - the E miss rate is reported.
- **No new threshold** is introduced.
- **BLOCKER**, because as frozen, a V1.1 outcome could condemn instruments that were not at fault.

## 7. R2: adversarial test of the tool-call audit

**Detected (17 of 20):**
- M2 reading DECISIONS-A01, SOURCE-KEY or the governance log, via Read, `cat`, `git show`, `python3 -c`, Grep or Glob;
- M1 reading DECISIONS-A02;
- an extractor reading or writing another extractor's output;
- NotebookEdit; Agent spawn; `../` traversal (normalized);
- `reader || cat`;
- `cd $(cat …)`.

**NOT detected (BLOCKER):**
- **Command substitution inside the allowed script path.** Example: ``python3 $(cat${IFS}pilot-s5-decomp/v1/DECISIONS-A01.jsonl>&2)/scripts/p3b_read_source.py --run PX0106-A02 …``.
- The same with backticks, and the same in the validator path.
- **Root cause:** the path prefix pattern `(?:\S*/)?` in `READER` and `VALIDATOR` accepts any non-whitespace, including `$(`, `` ` ``, `${IFS}` and `>&2`. The shell executes the substitution before Python starts, so the protected file is printed and the audit sees an allowed command.
- **Consequence:** the claim "impossible for M2 to read DECISIONS-A01 without detection" is **false as frozen**.
- **Minimum fix:** restrict the prefix to `[A-Za-z0-9_./@-]*/` (as the `cd` pattern already is), and add the three probes as tests.

**Persisted-output injection (MATERIAL):**
- The Read allowlist includes every path found after "Full output saved to:" in **any** tool-result text, including results that carry agent-authored content. For example, a matcher's Read of MATCH-LISTS returns extractor-written statements.
- A crafted statement could whitelist any path.
- **Fix:** accept only paths under the session's own `tool-results/` directory, taken from harness persisted-output markers.

**Does the audit detect actual tool usage rather than prompt strings?**
- **Yes** for tool type and file target: it inspects every recorded tool call, not the prompt.
- **No** for shell semantics inside an allowed command form, until the prefix is repaired.
