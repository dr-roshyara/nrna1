## 2. What changed, why, and which PX0106 failure mode it prevents

| Change | Why | Failure mode prevented |
|---|---|---|
| **E-1:** every permitted read is a complete command (absolute reader path, real S-id, real label, numeric page), one per page, generated from the frozen §2 page counts | the V1.2.1 template `python3 scripts/p3b_read_source.py … --page K S####` was not executable as written | U05 (literal `--page K`), U06 (wrong working directory) |
| **E-2:** absolute validator command | removes working-directory dependence | the same class |
| **E-3:** absolute input and output paths in task text, identical to the tool-rule lists | the task text used relative paths | a Write via a relative path from the wrong directory |
| **E-4:** matchers get the six files with labels and page counts, plus 19 complete commands | P-M1/P-M2 had fragments and a `<file's label>` placeholder, and matchers were not given labels | the exploration a matcher would need to find labels |
| **E-5:** the repair prompt includes the run's commands and the real failure-list sha256 | the V1.2.1 repair prompt had no command | the same class during repair |
| **E-6:** a committed deterministic generator (`prompts`); templates reproduced verbatim in pre-registration §8 (a test asserts equality) | PX0106 prompts were filled ad hoc | untested prompt text |
| **E-7:** the pre-dispatch gate (`check-prompts`), frozen with the prompts in stage `segment-map`; result-time re-check (§15 item 10) | detect the defect class before any dispatch | the whole PX0106 class (S-1…S-8) |
| **E-8:** fresh namespace constants | PX0106 must not be overwritten; the frozen reader accepts only `PX\d{4}-[USA]\d{2}` | overwriting historical evidence |
