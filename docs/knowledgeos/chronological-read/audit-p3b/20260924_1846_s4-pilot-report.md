## B. Method findings (cross-batch recurrence; within this pilot workload)

**Retrieval (stage 1):**
- **1,058 stage-2 hits were dispositioned** (per-hit counts self-reported; coverage verified against the stage-1 counts:
  all labels complete except boring-kernel 4/5).
  - All hits: FALSE-HIT **78.3%** · FOUND 15.5% · ESCALATED 6.2%.
  - Without the glyph label: 53.2% / 37.6% / 9.2%.
  - A lexical match is very frequently not semantic evidence.
- Stress cases: glyph label 609/646 FALSE-HIT (the 2-character notations `h1` and `v3`); shannon-weaver 116/131
  (`H(x)` hash functions); nyaya 59/61.
- **Within this workload, stage-1 NEGATIVE-CENSUS demonstrably misses some semantically relevant material:**
  - ASCII notation terms don't match LaTeX text (`!=` vs `\neq`, step185). A.4 generates Unicode→ASCII variants but
    not the reverse.
  - `\mid` inside a formula is missed.
  - Coined labels and placeholder terms don't occur in the corpus (five-blocker, uncertainty).
  - In several cases the label's own row or file is not hit.

**Semantic classification:**
- There is no disposition for **"hit on the same object, dimension not supplied"** (all six batches). The state space
  of §11.4 is incomplete: this is neither FALSE-HIT nor properly ESCALATED, and it makes GENUINELY-UNDEFINED-AFTER-CENSUS
  unreachable where it applies.
- **Incident 6.** NEGATIVE-CENSUS contradicted by whole-file step-1 reading was resolved FOUND by PB01, PB02 and PB05,
  and ESCALATED by PB03, PB04 and PB06.
  - The audit rules ESCALATED protocol-correct: FOUND is defined only as a stage-2 disposition (§11.2, §11.4).
  - This is a cross-batch inconsistency that needs a ruling.

**Provenance:** slices carry no 02-FILES provenance or date basis for stage-2 and other non-row files, so agents
cannot check G-08. This is the root cause of the PB02 and PB04 failures.

**Temporal:**
- §14.2 rule 2 has no outcome for a birth dated only by MTIME outside any BULK block. Batches used ESCALATED /
  TIMESTAMP-ANOMALY, UNORDERED-BLOCK with invented block names, or ESTABLISHED (PB05, a violation).
- Dates are file-level, so amendment layers inside one file cannot be positioned.

**Schema:**
- The closed value lists for `type_status`, `mathematical_status`, B3 layers and edge kinds were not in the contract.
  Batches invented values (OPEN, FORMALIZED, WELL-DEFINED, AMENDS, …).
- There was no P1-gap schema and no proposed-topic output.
- Object-record layouts diverge by batch: dispositions sit in five different structures. Mechanical verification of
  per-hit dispositions is therefore impossible.
