## 2. Part B: M-1 deep audit

**A. OBSERVED** (harness transcripts; 50 matched SendMessage events across sessions):
- A message sent to a subagent with **SendMessage** is recorded in the subagent transcript as a **user turn with `isMeta: true` and `origin: {"kind": "coordinator"}`**, with string content.
- **The content wraps the sent text.** In all 50 matched cases:
  - prefix `"The coordinator sent a message while you were working:\n"`;
  - suffix `"\n\nAddress this before completing your current task."`.
- **Other injected user turns exist**, all `isMeta: true`:
  - `origin.kind = "human"` (13);
  - `"task-notification"` (57);
  - `"peer"` (5).
- **Harness-generated non-meta user turns exist:**
  - **compaction summaries** (`isCompactSummary: true`, 17 cases);
  - the interruption marker `"[Request interrupted by user]"` (seen after a stop, e.g. PX0106);
  - an `isMeta` SubagentHandback reminder (304 characters, no origin) appears at the start of every subagent.
- **The first dispatched prompt** is the first user message (PX0106: byte-equal).

**B. INFERRED:**
- the same wrapper is used for a SendMessage to an agent that has **already completed** (the repair case);
- `task-notification` turns arise only when the agent itself runs background tasks.

**C. UNTESTED:**
- whether a SendMessage to a **completed** subagent uses the same wrapper, or a different one. All 50 observed wrappers say "while you were working";
- whether any other origin kinds exist.

**D. RISK OF A FALSE PASS: YES (demonstrated from code plus observed schema).**
- `later_user_texts` **skips every `isMeta` line**, and every observed SendMessage, human and peer message **is** `isMeta`.
- **Consequences under the V1.2.3 checker:**
  - **(i) false PASS:** an unfrozen extra SendMessage (or a human or peer message) to an agent **without** a frozen repair prompt is **not seen**, so "no further user message permitted" passes;
  - **(ii) false FAIL:** a legitimate repair is also not seen (0 ≠ 1). And even if it were seen, it would not equal the frozen text, because of the wrapper;
  - **(iii) false FAIL:** a compaction summary (non-meta) counts as an unfrozen message. That is plausible for long SEG runs;
  - **(iv) false FAIL:** the interruption marker counts as a message. That is acceptable, since an interrupted run is not a valid run, but it is misattributed.
- The checker is therefore **neither empirically verified nor conservative in all directions**: (i) is a false PASS.

**Minimum repair (specification; not implemented).** Classify every user turn after the first prompt by structure:

| Turn kind (observed) | Rule |
|---|---|
| `isMeta` + `origin.kind = "coordinator"` | strip the observed wrapper exactly (unknown wrapper → RUN-INVALID). If `PROMPTS/REPAIR-<run>.txt` exists, **exactly one** such turn, whose inner text equals it (strip). Otherwise **zero** |
| `isMeta` + `origin.kind ∈ {"human", "peer", "task-notification"}` or any other origin | RUN-INVALID (unregistered input to the agent) |
| `isMeta` without `origin` | permitted only if it matches the known harness SubagentHandback reminder; otherwise RUN-INVALID |
| `isCompactSummary: true` | permitted (harness compaction), counted and reported |
| non-meta `"[Request interrupted by user]"` | the run is FAILED/interrupted (not valid evidence) |
| any other non-meta user text | RUN-INVALID |

**Empirical closure of C (needs a human decision):** a **no-corpus harness conformance probe**. Dispatch one trivial agent on a non-corpus task, let it complete, send one SendMessage, and record the transcript structure. That turns "completed-agent wrapper" from UNTESTED into OBSERVED. **It requires dispatching an agent, so it was not done.**

## 6. Part F: stopping principle

The M-1 defect is **not** theoretical perfection. It permits a false PASS on an input channel (coordinator, human and peer messages) that is **observed** to exist in this harness. ## 9. Parts I–K: review optimization, roadmap and efficiency

**Measured quantities, kept separate (never one score):**
- human minutes per reviewed proposition;
- errors found per 100 reviewed items;
- inter-adjudicator agreement;
- matcher disagreement;
- candidate precision, and recall where a gold set exists;
- compute cost (tokens, wall time);
- review reduction versus a random-order baseline;
- false-negative risk, estimated from a random audit sample of unreviewed items.

**Efficiency without weakening protection:**
- deterministic preprocessing once (segment maps, hashes), and caching by content hash;
- incremental processing keyed by the identity manifest;
- deduplication at the **diagnostic** layer only (duplicates are still recorded; R9);
- stratified sampling for audits;
- uncertainty- and graph-prioritized review;
- parallel independent extraction;
- human review concentrated where disagreement or information gain is high, **plus a random audit sample** to bound false negatives.
