## C. OMQ-16: research-testing budget

**Measured [MEASURED]:**
- R2.2: 87 register records for 20 labels (71 OBSERVED, 10 ANALYSED, 6 TEST-DEFINED); none TESTED.
- Step-10 reads ≤ 0.08 MB per batch.
- H/SC sets did not reproduce between R2-001 and R2.2.

### C.1 In batches (records up to TEST-DEFINED)

1. **Reads:** step 10 through `p3b_read_source.py`, logged and **label-local**: only files in the label's slice.
   - For a **hub**, a file that is one of the hub's stage-1 hit files may not be read at step 10 unless OMQ-14 already requires it at step 1. This keeps stage 2 out of the back door.
   - There is no cross-label reading in batches.
2. **Cap:** step-10 bytes ≤ **0.9 MB per batch** [PROPOSED]: about 10% of the stage-2 limit and about 11× the largest S4 research-read load. Actual use is reported.
3. **Repeats:** a re-read counts again against the cap. The verifier reports the repeat ratio.
4. **No record quota and no minimum** (D-38). The audit checks for manufactured hypotheses (§21 item 5). H/SC/TC records must reach TEST-DEFINED with `test_plan_sha256` [FROZEN §13.9].
5. **Exhaustion:** no further step-10 reads in that batch. The **batch report** records `research-read budget exhausted`, and records keep their reached stage. No new register value is introduced.

### C.2 Test pass (TESTED and STATUS) [FROZEN selection rule, §13.9 RC-9g; mechanics PROPOSED]

- **When:** after S5a. The frame is **all non-CORPUS TEST-DEFINED records**: OBJECT records from batches and CROSS-OBJECT records from S5a, persisted before the frame freeze. CORPUS records are all TESTED in S5b [FROZEN].
- **Selection, mechanized:**
  1. The frame is written and hashed.
  2. A seeded permutation (seed `20260927`) of the frame is written and hashed **before any test runs**.
  3. The test plans' `test_plan_sha256` values are recorded in `P3B-INPUT-MANIFEST.json` before the testing run (§13.10a).
  4. Tests run strictly in permutation order.
  5. The share is **s = 20%**: the first ⌈0.2·N⌉ records.
  6. **The share may only be lowered, and only by truncating to a shorter prefix.** That decision is one governance act after the first 20 tests. The act receives **cost figures only** (bytes, calls, time per test), never lifecycle stages or STATUS. Raising is not permitted in S5.
- **Read budget per test [PROPOSED]:**
  - The lexical B and D searches run as scripts over the **discovery population** (addendum §2).
  - **Unit:** a test's load = its B/D distinct stage-1 hit keys (one tested dimension per test, so hit keys = dispositions).
  - If the load exceeds **4,081** (the T4 figure), the test is not run: the record stays TEST-DEFINED, and the test-pass report records `LOAD`. **A LOAD-skipped record keeps its place in the prefix and is not replaced**, so selection stays by rule.
  - Otherwise, whole-file reads per test are ≤ **8.63 MB**. If the cap is reached mid-test, the test stops, the record stays TEST-DEFINED, and the report records `LOAD-PARTIAL` with the reads made. No STATUS is assigned from a partial test.
  - **CORPUS records are exempt from the LOAD skip and from LOAD-PARTIAL.** "CORPUS-scale records are always TESTED" is frozen (§13.9, §27 OMQ-16, D-57).
    - Every CORPUS test is run in full.
    - Its load (same unit) and its whole-file read volume are reported.
    - If a CORPUS test's load exceeds 4,081, or its reads would exceed 8.63 MB, **the orchestrator escalates to the human before running it** (`P3B-ESC`, load). The human either authorizes the full test with a recorded budget, or invokes the §19.4/§23 stop-the-line, which leads to a §26 change.
    - The test is never skipped or truncated silently.
  - LOAD-skip and LOAD-PARTIAL rates for non-CORPUS tests are reported, and summaries of the tested set are stated as conditional on load ≤ 4,081.
- **Formal, mathematical, logical and DDD analysis:** reasoning within the selected test. It uses no reads beyond the four disconfirmation searches (§13.10).
- **Infrastructure:**
  - its own pass-contract section and verifier;
  - run ids `OT####-R2`;
  - an extension of the reader's run-id pattern, as reviewed tooling.
- Testing never blocks acceptance. Untested records carry forward (§13.9).

## E. OMQ-07: track mapping

- **Tracks [FROZEN, §14.5]:**
  - `TRACK-A-PHASE-MEASURE`;
  - `TRACK-A-VERIFICATION-CLUSTER-UNCONFIRMED`: the MD-043 subcluster, whose A-membership is doubted;

- **Measured over the S5 population (1,975)** [MEASURED] (labels touching each tag):

  | Tag | Labels |
  |---|---|
  | UNCLASSIFIED | 1,029 |
  | PHASE-MEASURE | 791 |
  | UNCONFIRMED | 138 |
  | TRACK-B | 122 |

  MIXED A+B is **31 if UNCONFIRMED counts as A**, and **17 if only PHASE-MEASURE counts as A**.
- **Mapping:** a deterministic directory lookup, per cited S-id (already in `bundle_index_discovery.jsonl`). It feeds `track_composition`, the CROSS-TRACK signals and G-08. Track is **not** a matching variable.
- **Hindsight:** the mapping is a later audit's classification of directories. It restricts what later material may establish, and adds no meaning.
- **The open point is two-sided:**
  - (1) UNCONFIRMED as A. It restricts Track-B sources relative to UNCONFIRMED-earliest objects, but leaves UNCONFIRMED sources themselves unrestricted. If the cluster is really later material, that is too lenient.
  - (2) UNCONFIRMED as B. It is restricted relative to PHASE-MEASURE-earliest objects, but then fails to restrict Track-B sources relative to UNCONFIRMED-earliest objects.
  - (3) **Restricted both ways:** relative to a PHASE-MEASURE-earliest object, an UNCONFIRMED source is restricted like Track B; relative to an UNCONFIRMED-earliest object, a Track-B source is restricted as usual.
- **Scope and route:** §14.5 leaves OMQ-07 open for **the directory mapping only**, not the rule. Options (1) and (2) are mappings and fall within OMQ-07. Option (3) builds a three-level ordering (PHASE-MEASURE > UNCONFIRMED > Track B) that no A/B mapping can express, so it **refines D-23**. It can only be adopted by a **run-level ruling** (the route used for F1–F3, G-LOG-0027), or by a §26 core change.
- **MIXED and CROSS-TRACK under (3):**
  - `MIXED` = evidence spans {PHASE-MEASURE or UNCONFIRMED} and TRACK-B: 31 labels.
  - Evidence spanning PHASE-MEASURE and UNCONFIRMED is recorded as a **register topic** `PROPOSED:CROSS-TRACK-UNCONFIRMED`: "the object's evidence spans TRACK-A-PHASE-MEASURE and TRACK-A-VERIFICATION-CLUSTER-UNCONFIRMED sources". It follows the §13.3 proposed-topic rule and is promotable only under H-14. It is not a new object-record field.
- **Proposal [PROPOSED; human]:** (3) as a **run-level ruling**. It is the only option that never lets doubtful material establish a birth against better-established material. The tag stays distinct.
- **Within-scope fallback, if no ruling is wanted:** mapping (2), UNCONFIRMED as B. It is the stricter mapping for births against PHASE-MEASURE objects; its cost is the leniency described above.
- **Wording (run-level ruling, with OMQ-07):** "OMQ-07: the KSME-20 directory mapping is confirmed as recorded. Run-level ruling (refines D-23 for S5): TRACK-A-VERIFICATION-CLUSTER-UNCONFIRMED is restricted like Track B relative to a TRACK-A-PHASE-MEASURE-earliest object, and counts as Track A relative to TRACK-B-GAP-DISCOVERY sources; MIXED = {PHASE-MEASURE or UNCONFIRMED} with TRACK-B; register topic PROPOSED:CROSS-TRACK-UNCONFIRMED for PHASE-MEASURE with UNCONFIRMED; the tag stays distinct in track_composition."

## K. Repeated-run stability

- **Object-level rerun [PROPOSED]:**
  - Population: a seeded (`20260928`), proportional **5%** of non-hub labels over the 24 strata plus the **purposive group** (348 non-hub labels with no stratum), 25 groups in all. Group size = max(1, round(0.05 · n_g)), with Python's round-half-to-even (round-half-up would give 99): **97 labels** [MEASURED allocation].
  - Inclusion probabilities range from 0.037 to 0.5, so **agreement estimates are design-weighted** by inverse inclusion probability. Unweighted figures are reported alongside.
  - Drawn from `P3B-SAMPLE-PLAN.jsonl` only.
  - Held constant: v1.7, contract sha, slices, reader, **model (claude-opus-5-5)**.
  - Regenerated independently: fresh agents, run ids `OB####-R2S`, private scratch, blind to the primary outputs.
  - Timing: after the primary batches are accepted.
  - **Rerun records are COMPARISON records.** They are verified and audited like batches, but never ACCEPTED as P3b results, and never enter S5a or the S5c baseline.
- **Metrics:**
  - per field (births ×5, type_status, mathematical_status, primary_layer, per-dimension absence resolution): exact agreement and Cohen's κ, each with a **design-following** bootstrap 95% CI: labels are resampled **within each of the 25 groups** (dimensions stay with their label). Groups with a single sampled label are collapsed into one pooled group for variance estimation. Seed 20260930. Category prevalence and prevalence-adjusted agreement (PABAK) are reported alongside κ, because skewed fields give low κ despite high agreement;
  - per label: the Jaccard overlap of the pre-registered classes recorded.
- **Baseline:** **no test–retest baseline exists.** v1's "S4 R1/R2" figures were inter-instrument (P3B-R1 against R2.2) and are dropped as a threshold. S5 establishes the baseline.
- **Flag [PROPOSED; human; a convention, not a measurement]:** `METHOD-INSTABILITY` for a field whose κ 95% CI upper bound is < 0.40, clearly below "moderate" in the Landis–Koch convention. At n ≈ 97 this flags only κ̂ of about 0.2 or less. It is a floor for gross instability, not a certificate of stability. Otherwise agreement is reported without a verdict.
- **S5a analysis rerun [PROPOSED]:**
  - A second blinded analyst (same model) re-dispositions a seeded (`20260929`) **20%** of analysed sets.
  - Agreement is measured on class disposition per set.
  - Per CORPUS finding, the plan reports **the number of its participating sets in the 20% subset and the proportion whose class disposition agreed**, with a Wilson 95% CI. `STABILITY-NOT-ASSESSED` applies if none was sampled. There is no binary flag: v2's any-disagreement rule would have penalised better-supported findings.
  - These are **reporting fields**; §13.9a/§13.9b are unchanged.
- **Cross-contract comparison:** under P-1 (a), the 25 accepted S4 labels (R2.2 PB02–PB05, PB06) are compared with their S5 records. It is labelled cross-contract, not test–retest.
