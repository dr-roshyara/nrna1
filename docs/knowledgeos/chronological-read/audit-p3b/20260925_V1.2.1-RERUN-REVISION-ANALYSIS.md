## 1. Executive finding

- **The stop was correct.** V1.2.1 execution was stopped under pre-registration §18 after extractor PX0106-U06 made 11 tool calls outside the §15 allowlist.
- **The outcome is RUN-INVALID** (§17 step 1) and contains **no instrument evidence**. No check pass, repair, matching, κ or capture was computed.
- **The cause is an execution-contract defect** in the frozen §8 prompt text, which became visible through the smaller E2 model:
  - the reader command is shown with a template page `K`, a template S-id `S####` and a relative path, but no working directory;

- **PX0106 remains immutable** historical evidence of a failed attempt.

## 3. Root cause (three separate factors)

1. **Missing working directory (Defect A-1).**
   - §8 shows `python3 scripts/p3b_read_source.py …`, which is relative to `docs/knowledgeos/chronological-read/`. No working directory is stated.
   - U06 ran it from the repository root (`scripts/` does not exist there), then explored the filesystem.
   - U01–U04 inferred the directory: for example, `cd <repo>` followed by a call that the frozen allowlist accepted.
2. **Literal page placeholder (Defect A-2).**
   - §8 shows `--page K S####`. U05 passed `K` literally.
   - **As written, the template command is not executable and fails the frozen allowlist** (`bash_allowed` returns False for the example line in all six generated prompts, verified). Only an agent that substitutes both `K` and `S####` correctly can comply.
3. **E2 execution behaviour (an observation).**
   - Both runs assigned the smaller model failed on the two ambiguities above. All four opus/fable runs resolved them.
   - **This is one invalid execution attempt.** It does **not** establish that the E2 model is unsuitable as an extractor. Its extraction quality was never observed.

## 5. Required revision (minimum; not implemented)

**Principle: repair the execution contract, not the scientific decision rules.**

### 5.1 §8 prompt text (Defect A)

1. **Replace every template reader command with executable commands.** Either:
   - give the absolute script path, e.g. `python3 <abs>/docs/knowledgeos/chronological-read/scripts/p3b_read_source.py …`. The frozen allowlist already accepts an absolute prefix made of safe characters (verified: U01–U04's accepted commands and the `SAFE_PATH` rule);
   - **or** state the exact working directory, as an explicit `cd <abs>/docs/knowledgeos/chronological-read`, followed by the relative command.
2. **Remove `K` and `S####` from command lines.** Either:
   - **(i) enumerate the exact per-page commands** for the run's files (for example, S1022 page 1; S1021 pages 1–2; …). These are fully determined by the frozen §2 page counts, so no placeholder remains; **or**
   - (ii) state "replace K with the page number 1…N, one call per page; never pass a letter", with one concrete numeric example per file.

   Option (i) leaves nothing to interpret.
3. **Give the validator command** with the same absolute path or working-directory form.
4. **Give absolute output paths** in the task text, matching the tool-rule `<WRITES>` list. The task text currently uses relative paths.

### 5.2 Matcher and repair prompts (the same defect class; §7 below)

5. **P-M1 and P-M2:** give complete executable reader commands, **and the label of each of the six files**. MATCH-LISTS items carry `source_id` but not the label, and the allowlist requires `--label` to equal the file's label. A matcher currently cannot build a valid command without exploring.
6. **Repair prompt:** include the run's executable reader commands (as in item 2).

### 5.3 Mechanical guard on the prompt contract (makes the contract executable and checkable; no rule weakened)

7. **Commit the prompt generator** as part of the frozen tool, rather than as the ad-hoc fill used in PX0106. Add a pre-dispatch check that:
   - **every command line in every generated prompt passes the frozen `bash_allowed()` for its run**;
   - no template token (`K`, `S####`, `<…>`) remains in a command line.

   This check would have failed the PX0106 prompts before dispatch.

### 5.4 Fresh-namespace constants (§8 of this analysis)

8. **Tool constants:** `RUNS` ids, `V1_DIR`, `PREREG`, `AUTH` and `TOOL_REL` are updated to the fresh namespace and the revised files. The reader and dependencies are unchanged (still bound by N2).

**Items 1–8 change neither the allowlist, nor §15/§17/§18, nor any threshold or metric.**

## 8. Fresh namespace

- **Rule:** PX0106 (`pilot-s5-decomp/v1/`, `pilot-s5-decomp/PX0106-*`) is historical evidence and must not be overwritten. A re-run uses a **fresh namespace**, frozen before execution.
- **Constraint from the frozen, bound reader** (`p3b_read_source.py`, N2): run ids must match `PX\d{4}-[USA]\d{2}` and the batch must match `PX\d{4}` (verified). A suffix form such as `PX0106-R1` **would be refused by the reader**, and changing the reader would break N2.
- **Candidate (proposal only, not adopted):** batch `PX0107`, runs `PX0107-U01…U06` and `PX0107-A01…A02`, artifact directory `pilot-s5-decomp/v1-r1/`, authorization file `V1.2.2-AUTHORIZATION.json` (if the revision is versioned V1.2.2).

The final values are fixed in the revised pre-registration and frozen before execution.

## 9. Re-authorization requirements

**Correction (recorded here; the committed stop report is not edited):** the stop report cites "§17 step 1: 'a re-run needs a new authorization'". That sentence is in the **V1** pre-registration (`ec4b5912e`, §17 item 1), **not** in V1.2.1.

**For V1.2.1, the requirement follows from three sources:**
- **(a) the execution guard (X3/N2):** an authorization binds one exact commit and byte-identical pre-registration, tool and dependencies. A revised pre-registration is a new commit and file, so `V1.2.1-AUTHORIZATION.json` cannot unlock it (mechanical);
- **(b) V1.2.1 §18:** "No re-dispatch of any run";
- **(c) G-LOG-0070:** authorized execution under `51e04f8cb` only.

**Before another run may begin:**
1. the human approves the revision content (§5; the model option of §6);
2. the revised pre-registration, tool (including the generator and its check) and tests are implemented and frozen in one commit;
3. an independent adversarial audit of the revision finds it READY;
4. **a new human authorization**, whose record states:
   - the revised pre-registration commit (full 40-hex) and its sha256;
   - the fresh namespace;
   - that PX0106 ended **RUN-INVALID** (G-LOG-0071);
   - that the new run is **independent evidence** (it reuses no PX0106 output);
   - the **unchanged F-13 limits** (four statements);
5. the pre-dispatch prompt check (§5 item 7) passes on the generated prompts before any agent is dispatched.
