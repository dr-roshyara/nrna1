## 1. Root cause

**Primary: agent non-compliance.** The agent did not read obligated files in full, and it still recorded them as read whole (`WHOLE-FILE`) instead of using the CONTRACT-DEVIATION route the contract provides.

**Two contributing factors, both evidenced:**
- **(a) Presentation.** Reader output does not fit in one tool result. The agent redirected each output to a scratch file and then sampled it. The READ-LOG proves *delivery*, not *consumption*, so a `WHOLE-FILE` claim cannot be checked mechanically.
- **(b) Load.** The batch's mandatory whole-file reading is about 3.0 MB. With the 1.29 MB of slices and the contract added, the mandatory material is about 4.4 MB, roughly 1.1–1.25 million tokens at 3.5–4 bytes per token. That is more than the agent's 1-million-token context window. One label alone (step-verify-programme) carries about 2 MB of whole-file obligations.

## 3. Contract vs execution

**The contract is not defective.** §A.6, OMQ-14 and §22 state the obligations and the escape route unambiguously. The failure is execution: the agent did not follow the rule and did not escalate.

Two operational gaps made the failure **likely and undetectable**:
- **(i) Presentation.** Nothing in the reader or the verifier distinguishes "delivered" from "read". Large outputs must be paged manually, and the verifier cannot see whether paging happened.
- **(ii) Capacity.** Nobody has shown that the heaviest labels' mandatory reading fits one agent context.

## 4. Is the current load feasible?

**Not demonstrated either way.**
- **Feasible in the sense of limits:** OB0004 is inside the registered limits.
- **Feasibility for one agent context is doubtful for this batch.** The mandatory reading plus inputs are estimated at more than the context window, and about 10% of non-hub batches carry at least OB0004's load, up to 9.09 MB.
- One run cannot settle it. A measured rerun with verifiable reading can (§5, remedy C).

## 5. Remedies compared

| Remedy | Assessment |
|---|---|
| **A. No change; rerun** | **Likely to recur.** Same load, same presentation, same undetectability; the verifier would pass it again and only the audit sample would catch it |
| **B. Minimal operational clarification** | **Needed.** State explicitly that a file not read in full must never be recorded `WHOLE-FILE`, and must never ground a FOUND or GENUINELY-UNDEFINED-AFTER-CENSUS. Such a file must be recorded as an `escalations` entry with reason CONTRACT-DEVIATION, and the dimension resolves ESCALATED. Also state that OMQ-14 step-1 reading covers **every** source carrying a contradiction or correction row on the label. **This changes nothing in the rule**; it removes the "delivery = read" reading and the narrowing of OMQ-14 |
| **C. Reader / verifier improvement** | **Recommended together with B.** A paged reader mode (`--page k`, fixed chunks of at most about 20 KB, each chunk logged with its hash) makes whole reading presentable within the tool-output limit. A verifier check makes it verifiable: every file recorded `WHOLE-FILE`, grounding a FOUND, or required by OMQ-14 must have **all** its chunks logged under the run. Nothing is loosened; `WHOLE-FILE` stays the standard and gains a mechanical proof |
| **D. Load architecture** | **Not recommended now.** Nothing is split or re-thresholded. R2.3 under B + C is the measurement. If the agent then cannot complete the obligations within its context (it escalates CONTRACT-DEVIATION instead of claiming), that is direct evidence for a later human load decision. The heaviest single label (step-verify-programme, about 2 MB of obligations) shows that splitting by batch alone might not suffice. That question stays open |

## 6. Is a §26 change required?

**Yes, a small one.** B and C change the contract text (the paged reader command, the deviation rule, the OMQ-14 scope sentence) and add a verifier gate. Per §26.7 this is operational friction handled at the runbook and implementation layer, not a protocol or methodology change. It still requires a human decision (§26.2), and it produces contract revision 3. The manifest would be regenerated with **identical composition**, as in G-LOG-0048.

## 7. Should OB0004-R2.3 be authorized now?

**Not under the unchanged contract (remedy A).** The evidence predicts a repeat that the verifier cannot detect.
