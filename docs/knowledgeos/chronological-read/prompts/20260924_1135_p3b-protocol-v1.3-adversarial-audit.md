## 1. CRITICAL DEFECTS

### C1 — The random-control mechanism is not statistically meaningful as specified (§9E step 1, §9E mandatory content, G-13)

§9E defines the control as "label tuples with **none of these links**". As written:

| Problem | Why it defeats the control |
|---|---|
| **Excludes the defining property** | For structure-defining generators (dependency components, shared group, shared notation) the control is unlinked *by construction*, so it trivially shows no structure. The comparison tests the generator's definition, not the corpus |
| **Not matched** | No matching on tuple size, row count, pair count, provenance mix, time span, file overlap or file degree. Differences between candidates and controls can come from any of these |
| **Not blinded** | The analyst knows which sets are controls. Finding "nothing" in known controls is expected and uninformative |
| **No pre-specified outcome** | "How the control set behaves for this structure" has no measurable outcome (for example "proportion of sets for which structure S is recorded at ≥ ANALYSED"), so no comparison can be computed or audited |
| **Size and tuple arity unspecified** | OMQ-18 leaves size open, but the arity (pairs? k-sets?) is not even a parameter |

**Consequence:** G-13 can pass while control comparisons carry no information, and "structure everywhere" artefacts
stay undetected, which is the exact risk the control was meant to catch.

### C2 — Generator circularity and recurrence inflation (§9E steps 1 and 3; §13.10; v3.5 R9 not carried to higher scales)

Several generators select on the very property a finding would report, or on the researcher's own prior output:

| Generator | What it can manufacture |
|---|---|
| dependency edges / components | "dependency graph" or "partial order" among candidates chosen *because* they have edges (tautology) |
| shared P2a group | "equivalence class" among labels already grouped by string similarity or co-occurrence. P2a CO-OCCURRENCE groups are inflated by registry co-listing (`09-ORCHESTRATOR-FLAGS.md` l.2577) |
| shared notation / alias | spurious sameness from false-cognate short codes (KSME-22D: 6/15) |
| co-change (one source changes several labels) | spurious coupling from census/registry and SECONDARY-SYNTHESIS documents that restate many labels at once. This is also a **hindsight** route, since synthesis documents restate earlier material |
| similar timeline sequences / similar type signatures | similarity undefined. The inputs are **AI-produced** layer-A fields (change classes), so the generator is not purely mechanical, and shared authoring sessions (mtime blocks) produce similarity |
| shared register topics / joint appearance in HYPOTHESIS records | a **self-reinforcing loop**: the researcher's object-level hypotheses select the cross-object candidates, whose findings the corpus pass then counts as "recurrence" |

There is also **no independence accounting at the cross-object or corpus scale.** v3.5 R9 ("duplicate ≠ independent
evidence; repetition is not confirmation") governs layer A but is not restated for recurrence counting. The same
structure can be counted again through duplicate files, synthesis restatements, overlapping candidate sets, or the
same hypothesis re-found. **A corpus-level "recurrence" can therefore be an artefact of how candidates were
generated.**

### C3 — No assignment criteria for register STATUS values (§13.9, §13.10)

`SUPPORTED-IN-CORPUS`, `REFUTED-IN-CORPUS` and `UNDETERMINED-FROM-CORPUS` are listed, but nothing states **when** each
may be assigned. As a result:
- an empty contradiction search (B) with a search record could be read as support. **Absence of contradiction is not
  forbidden as confirmation;**
- "support not found" could be recorded as REFUTED. **Not found ≠ false is not operationalized for STATUS;**
- nothing excludes `EXTERNAL-THEORY-COMPARISON` items from the evidence that sets a corpus STATUS (§13.12 rule 5
  keeps its own status apart, but does not bar it from the corpus-status basis);
- nothing requires the competing hypothesis (C) to have been *discriminated against* before SUPPORTED.

These statuses flow to P4–P7, so status inflation propagates.

### C4 — No temporal scope for cross-object and corpus structures (hindsight gap; §9D, §9E, §13.11, §1C)

§1C separates research time from historical time for **statements**, but a **structure** over objects from different
periods has no temporal-scope field. A partial order over concepts from August and September may never have existed
at any single historical point. It is a research-time construct over the union. Nothing prevents a CORPUS record from
reading as "the corpus had structure X" when X exists only across time slices that never co-existed. This is the
hindsight failure the protocol exists to prevent, at the scale v1.3 introduced.

### C5 — Execution-ordering contradiction for the sample plan (§9C.1 vs §28 status list)

The checklist population is computed "mechanically at S2/S3" and uses **track composition** (strata) and **MIXED
track** (a purposive criterion). The track directory mapping is **OMQ-07**, which §28 lists only as needed "before S5".
S2/S3 therefore depend on an undecided question scheduled later. Also, "formal rows" (a purposive criterion) is
**undefined**, so the plan is not mechanically reproducible.

## 2. IMPORTANT BUT NON-BLOCKING ISSUES

| # | Issue | Evidence / location |
|---|---|---|
| I-1 | **Traceability chain incomplete for CORPUS findings.** §9E requires `participating_objects[]` but not `participating_findings[]` (the CROSS-OBJECT records a CORPUS record aggregates). Re-examination on correction is stated for direct participants only, not transitively (object → cross-object → corpus). No de-duplication or linking rule between an object-scale STRUCTURE-CANDIDATE and a cross-object record describing the same structure | §9E, §13.6 |
| I-2 | **Structure standard lacks four distinctions.** (a) `relation_source`: CORPUS-STATED (a source defines the relation) vs RESEARCHER-CONSTRUCTED (the researcher defines it from data). This is exactly the line between "the corpus defines a lattice" and "appears lattice-like". (b) Property status granularity: `STATED-BY-SOURCE` / `VERIFIED-ON-ALL-ENUMERATED-INSTANCES (n)` / `INSTANCES-CONSISTENT (partial)` / `NOT-DETERMINED` / `VIOLATED`. A universal property cannot be "observed", only verified on finite instances or stated. (c) A **weakest-structure rule**: name the weakest structure the verified properties establish (for example preorder, not lattice, when joins and meets are NOT-DETERMINED). (d) `competing_structures[]` explicitly, not only generic `competing_hypotheses` | §13.11 |
| I-3 | **Disconfirmation not yet executable in detail.** B and D record "terms, scope, negative label", which suits lexical searches but not structural claims. Each operation should record `population` (enumerated set or corpus scope), `method` (LEXICAL / STRUCTURAL-ENUMERATION / WHOLE-FILE-READING), `completeness` (EXHAUSTIVE / SAMPLED with seed and size) and a **termination bound**. For finite X, a counterexample search is exhaustive enumeration and terminates; for lexical searches the bound is the corpus | §13.10 |
| I-4 | **Sampling design weaknesses** (OMQ-15 territory, but the principle text should anticipate them). (a) The purposive set is a majority (≥ 56.7% measured), dominated by "any SOURCE-CLAIMED lineage" (944), so it is not "high-signal". (b) Seven stratification dimensions × bands → many empty or singleton strata; "fixed number per stratum" is infeasible without a stated allocation rule. (c) Unequal inclusion probabilities → corpus-level rates must be **weighted by stratum size**; not stated. (d) The **outcome metric** for "discoveries per stratum" is undefined and not pre-registered. (e) The contract rightly gives membership, not the reason, but this should be stated as a **blinding** rule. (f) The design must be **frozen before S4**; any later change needs a new seed, with the old plan preserved and both analyses reported. (g) **Which hypotheses get TESTED** is agent choice within budget, a selection bias (agents test likely winners); selection should be rule-based (all CORPUS-scale plus a seeded share of others) | §9C.1, §13.9, OMQ-15/16 |
| I-5 | **Register bureaucracy conflict.** §13.6 makes `contradicting_evidence[]` "must be searched for" mandatory for **every** record kind, including OBSERVATION. That contradicts "an observation may remain an observation" (§13.9) in cost and spirit. A light OBSERVATION profile is needed; the search obligation belongs to HYPOTHESIS / STRUCTURE-CANDIDATE / THEORY-CANDIDATE (§13.10) | §13.6 l.~1006 vs §13.9 |
| I-6 | **Reproducibility gaps** — see §7 clean-room list | various |
| I-7 | **Factual error:** §19.4 says comparison candidates are "computable from R1-baseline timelines … as a rough preview". R1 records have **no timeline field** (measured). Only group-, notation- and dependency-edge-based previews are possible from R1 | §19.4 |
| I-8 | **Audit independence limited.** The auditor and batch agent may be the same model family: correlated blind spots, so the under-discovery measured by §21 item 5 is a **lower bound**. The model identity is not recorded anywhere (see §7) | §21 |
| I-9 | **Cross-object analysis over P3a-paired labels** could slide into re-judging identity. It should state that any identity or sameness claim between P3a-paired labels is recorded only as `VERDICT-EVIDENCE-CONFLICT` | §9E step 2 |
| I-10 | **External comparison: one missing sentence.** §13.12 bars evidence and intent but does not state explicitly that correspondence never supports "KnowledgeOS *is* structure S" (it is implied by §1D). Add explicitly, and bar EXTERNAL items from any corpus STATUS basis (ties to C3) | §13.12 |
| I-11 | **CORPUS "recurrence" has no explanatory requirement.** A THEORY-CANDIDATE should state what the structure *explains* or *predicts* that could be checked in the corpus. Otherwise frequency alone produces candidates | §9E step 3 |

## 6. FINAL RECOMMENDATION

### **READY AFTER TARGETED CORRECTIONS**

The architecture holds and should not be redesigned: object → cross-object → corpus research, chronological
reconstruction as the primary evidence process, layer and time separation, discovery without canonicalization, and
disconfirmation. The adversarial pass found five defects that would let the new v1.3 mechanisms produce **artefactual
structure** (C1, C2), **inflated status** (C3), **anachronistic structure** (C4), or an **unexecutable ordering**
(C5). All five are local: they can be corrected in §9C.1, §9E, §13.6, §13.9–13.11, G-13 and §28 without touching the
architecture.

**Required before freeze:** RC-1 … RC-5, RC-6, RC-7, RC-11, RC-12. **Recommended in the same pass:** RC-8, RC-9,
RC-10, RC-13. New open questions a v1.4 would need: the SUPPORTED threshold (RC-3), control matching variables and
arity (RC-1), the co-change file-degree cap (RC-2).
