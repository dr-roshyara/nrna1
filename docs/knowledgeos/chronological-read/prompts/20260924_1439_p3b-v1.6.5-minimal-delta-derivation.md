## 0. Two corrections that change the review's premises

1. **P1's `file_mtime` is not a cross-check.** v3.5 §A6 dispatched each P1 agent with `file_mtime` taken from P0's
   roadmap. The manifest equals P0 in 2,779/2,779 records, and P1 copied it in 2,596 of 2,767 CONTENT records. The
   other 171 are transcription defects, except S2344/S2345, where P1 wrote the true value. The review's chain
   "P0 SHA → bytes → P0 mtime → **P1 mtime** → P1 evidence" therefore loses its P1-mtime link. The replacement is
   **working-tree stasis** (§1.2), which is independent of P1 and stronger.
2. **The recorded `commit` is the dispatched P0 snapshot, not "HEAD at read time".** `00-CORPUS-SNAPSHOT.txt` =

   (2026-09-12 17:33), before P1 read those batches (ledger mtimes 09-14 to 09-16).

**Consequence (the central finding of this derivation):** for **every** CONTENT file, including the 2,660 "verified at
the recorded commit", the evidence that P1 read particular bytes is the same kind: **P0's hash plus the file's stasis

## 2. Evidence chain required for a file's identity (Q2)

These are deterministic, in order, and produce one frozen **identity manifest** row per CONTENT file.

1. **P0 row alignment.** If the content at the path (in any location) never matches P0's hash, **and** P0's hash equals
   the content of another census row's path, the P0 row is **misaligned**. Identity = path content, **only if** it is on
   the human-accepted exception list with P1 summary and row convergence recorded (currently exactly S2344–S2346, §B of
   the calibration report). A new case found mechanically → `UNRESOLVED` → escalate. Never auto-accepted.
2. **P0-hash uniqueness.** P0's hash must not be shared with another CONTENT row. *Measured: 0 shared.*
3. **Blob resolution.** Search for the blob whose sha256 = P0's hash: recorded commit → unique 36-char-prefix commit →
   every git version of the path → HEAD → working tree. Record the location spec and sha256. None found → `UNRESOLVED`.
4. **Read linkage.** Stasis test against the working tree at manifest time → `STASIS-OBSERVED` / `STASIS-UNOBSERVABLE`.
5. **Contrary evidence.** Any known P1 evidence describing content absent from the identity bytes → `UNRESOLVED` →
   escalate. *Known cases: none. S2880 is positive evidence; the trio is handled by step 1.*
6. **Freeze.** The manifest is written, hashed per §19.5, reviewed, recorded in the governance log and committed
   **before** any search runs (pre-registration: identity is fixed before any hit is seen).
