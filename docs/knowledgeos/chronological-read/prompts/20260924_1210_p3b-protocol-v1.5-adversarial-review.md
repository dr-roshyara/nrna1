## 1. CRITICAL DEFECTS

### W-C1 [A+I] — The temporal-scope fix re-opens hindsight through a single-source clause, and contradicts its own algorithm (§14.4c vs A.10)

- §14.4c allows WITHIN-SLICE when relation evidence is dated ≤ t "**or all relation evidence in one source**". That
  clause only matters when the single source is dated **after** t. A later synthesis document relating
  earlier-born objects then yields "at [t], the corpus shows …" for a relation first asserted later. That is T-H6
  again.
- A.10 ignores the clause, and its claim "any valid t must be ≥ every evidence date" is false under §14.4c. Two
  implementers get different scopes.
- **[I]** "Historical position" is not defined as an ordered key, although v3.5 R1/R1a make dates attributes, not
  sort keys. Ties at day granularity, the 809 SOURCE_ID-only files, `birth(p)` for a participant with no ORDERED
  point, the position of a "corroborated SUPERSEDED lifecycle", and the block test (`"None"` strings, date strings)
  are all undefined.

**Correction:**
- delete the one-source clause;
- define position as an ordered key per R1a (signal rank, then date), with ties → UNORDERED;
- state whether SOURCE_ID-only positions count as ORDERED (recommendation: no, they are ingestion order);
- block test := `mtime_block` matches `^BULK-`;
- no ORDERED point → the participant is UNORDERED.

### W-C2 [I] — Pre-registration can still be written after the data is seen (§13.10a)

- TEST-DEFINED follows OBSERVED/ANALYSED, and nothing requires it to be persisted **before** TESTED runs. Both can be
  written in one batch output, and G-09 only compares hashes.
- Census scope fixes the files but not the **search terms**: terms chosen to miss a known contradiction still earn
  NEGATIVE-CENSUS.
- The structure's "full X" is still a researcher-written list that can omit counterexample objects.

**Correction:**
- TEST-DEFINED is persisted in an earlier run (separate `run_id`, hash in the manifest) before any TESTED run;
- B/D terms must include the mechanical A.4 terms of **every participant label**, plus any researcher additions;
- X must be mechanically defined (a generator candidate, or a stated predicate evaluated by script), never a
  hand-written id list.

### W-C3 [A+I] — The control decision rule is statistically unsound as recommended (§9E.2 item 6, OMQ-20)

- **Multiplicity** [A+I]: there is no correction across generator × class cells, so false DIFFERENTIATED results are
  near-certain at realistic cell counts (§0).
- **Non-independence** [I]: all k-subsets of a group share members, and controls are matched 2:1. Fisher assumes
  independent units, so p-values are too small.
- **Partial blinding** [I]: when the analyst can tell candidates from controls, the candidate proportion is
  inflated, yet a PARTIAL comparison can still satisfy §13.9a condition (4).
- **Power** [A]: at m = 10, power is 0.23–0.42 for moderate effects. An UNDIFFERENTIATED result mostly reflects
  **insufficient data**, and must not be read as absence (the protocol's own "not found ≠ false" principle).
- **Ambiguity** [I]: "at least m candidate sets" does not say whether m counts the pool or the sets showing the
  class.

**Correction (H-17 decides the values):**
- pre-register Holm (FWER) or Benjamini–Hochberg (FDR) over all pre-registered cells of a pass;
- test on the A.8 independent family, or use a permutation test that swaps candidate/control keys at cluster level;
- m counts candidate sets in the pool, with a minimum numerator of sets showing the class;
- **PARTIAL blinding → report-only; it cannot be DIFFERENTIATED for §13.9a condition (4)**;
- UNDIFFERENTIATED splits into `UNDIFFERENTIATED` and `UNDERPOWERED`. The latter records the minimum detectable
  difference at the observed sizes;
- raise the recommended m toward 20–40, per the power table.
