## 0. What changed from KSME-01, and why

KSME-01 (BC-02.19) proved the **method** works on a purpose-built synthetic world — it could not, and did
not claim to, answer *"what are KnowledgeOS's actual distinctions?"* This pass answers a narrower,
better-grounded question: **for the small number of KnowledgeOS objects that already have a real,
executed, or source-verbatim formula (not a reconstructed guess), what does the same machinery reveal?**
Per the review that commissioned this pass, extraction was **not** done by re-reading 20–50 fresh files —
it reused BC-02.1–19's own already-verified findings, re-reading only where an *exact* structure (not a
remembered summary) was required (`bandtest.py`'s `NEEDS` table).

## 1. Sub-experiment 1 — S0881's real `Status₅`, S2377's real `Sat₂`

**Domain, entirely source-cited**: `Status ∈ {Satisfied, Unsatisfied, Unknown, Conflicted,
NotApplicable}` (`SOURCE-ESTABLISHED`, S0881, BC-02.4, full-file read, §§9–10). Modeled over `n=3`
requirements (`r₁`="hard", `r₂`="critical", `r₃`=ordinary — a bounded instance, not a claim about the
real requirement count) → **125 raw status vectors, exhaustively enumerated.**

**`𝒪_real`, the real, named, S0881-sourced consuming computations**:
- `Coverage(e)` — `SOURCE-ESTABLISHED` shape (S0881/BC-02.7): `|Satisfied| / |R(P)|`.
- `EpistemicDebt_set(e)` — `SOURCE-ESTABLISHED` shape (BC-02.4 §39, verbatim formula
  `EpistemicGap(K,P)=R(P)-SatisfiedRequirements(K)`): the *set* of unsatisfied requirement indices,
  `NotApplicable` correctly excluded (S0881's own distinction).
- `Ready(e)`, `CriticalGaps_set(e)` — **`DERIVED`, not verbatim**: the three named conjuncts
  (`HardSatisfied`, `ConflictAcceptable`, `CriticalUncertaintyAcceptable`) and the qualitative finding
  that `Ready`/`CriticalGaps` need more than two values **are** `SOURCE-ESTABLISHED` (BC-02.7's
  Certificates 1–3); the *exact* Boolean wiring used here is this experiment's own, disclosed
  reconstruction of that argument, not a source quotation. Flagged honestly, not oversold.

**The oracle minimal quotient — genuinely new, never computed anywhere in this investigation before**:

$$
125 \text{ raw status vectors} \;\longrightarrow\; \boxed{27} \text{ behaviorally distinct classes}
$$

BC-02.7 showed `π₁` (S2377's binary `Sat` collapse) was *insufficient* by hand-picked counterexample;
this pass computes, exhaustively, exactly how insufficient, and what the *true* minimum actually is —
neither of which existed before this pass.

| Representation | Sufficiency | False equivalences (of 125) | Classes |
|---|---|---|---|
| `π₁` (S2377's binary `Sat`, per-requirement) | **`FALSE`** | **117** | 8 |
| 3-valued collapse (`OK`/`SOFT`/`HARD_FAIL`) — this experiment's own candidate, not source-attested | **`FALSE`** | **84** | 27 |
| Full `Status₅` vector (baseline) | `TRUE` | 0 | 125 |
| **Oracle** | `TRUE` | 0 | **27** |

**A genuinely useful incidental finding, worth flagging on its own**: the 3-valued collapse has **exactly
27 classes — the same count as the oracle — yet is still insufficient (84 false equivalences)**. Matching
*cardinality* does **not** imply matching *partition*: a representation can have exactly the right number
of buckets and still sort states into the wrong ones. This is a precise, executed instance of the
distinction the commissioning itself asked to keep separate (representation minimization vs. behavioral
minimization) — a coarser encoding can hit the right size by coincidence and still be wrong.

**Per-behavior breakdown — quantifies and sharpens BC-02.7's own Certificates**:

| Behavior | `π₁` sufficient alone? | False equiv. | 3-valued sufficient alone? | False equiv. |
|---|---|---|---|---|
| `Coverage` | `TRUE` | 0 | `TRUE` | 0 |
| `EpistemicDebt_set` | **`FALSE`** | **117** | `FALSE` | 79 |
| `Ready` | **`FALSE`** | 21 | `FALSE` | 15 |
| `CriticalGaps_set` | **`FALSE`** | **114** | `FALSE` | 65 |

`Coverage` is the *only* one of the four real behaviors `π₁` preserves — confirming, with an exact count
rather than a hand-picked example, BC-02.7's own conclusion (*"sufficient for `Coverage`/`EpistemicDebt`,
insufficient for `Ready`/`CriticalGaps`"*) — **with one sharpening**: `EpistemicDebt_set` is *not*
actually preserved by `π₁` either, once it's defined as the *set* of unsatisfied indices (not merely
their count) — `π₁` collapses `NotApplicable` into the same bucket as genuine failure, which `S0881`'s
own definition explicitly forbids. `EpistemicDebt`'s aggregate *count* may still be recoverable in some
weaker sense (not tested this pass, flagged as an evidence gap) — the *set*, which is what BC-02.4's own
formula literally defines, is not.

## 2. Sub-experiment 2 — canonical-construction's real, executed `NEEDS` table

`bandtest.py`'s `NEEDS` table (re-read verbatim this pass, 18 operations, 8 components
`{A,R,S,EL,Dt,PI,T,H}`) is honestly characterized, per BC-02.17's own prior finding, re-confirmed by
direct inspection: **intensional (a static dependency-table lookup), not extensional (no operation is
actually executed to observe behavioral divergence)**. This means it **cannot** be used to manufacture a
joint/interaction-relevance claim without inventing operation semantics beyond what the source provides —
this experiment explicitly declines to do that, unlike Sub-experiment 1, where real formulas exist.

**What it *can* honestly support — a precise information-loss count for `K=(𝒜,ℛ)`-style
representations**, computed directly against the real table:

$$
\text{Dropping } \{S, EL, D_t, \Pi, T, H\} \text{ (keeping only } A, R) \Rightarrow
\boxed{17 \text{ of } 18 \text{ operations lose a well-definedness requirement (13 of 14 forced ones)}}
$$

Only `Remove` (whose entire `NEEDS` entry is `{A}`) survives unaffected. **This is a new, precise
quantification** of what BC-02.13/16/17 already established qualitatively ("all 8 components shown
necessary") — now expressed as *exactly how much of the real, executed operation registry a `K=(𝒜,ℛ)`
reduction would break*, using the actual source table rather than a summary of it.

## 3. Comparison to KSME-01's synthetic findings — consistent, not contradicted

- KSME-01's `p3/p4` XOR lesson ("marginal relevance ≠ representation adequacy") **recurs here**: the
  3-valued collapse's failure on `Ready`/`CriticalGaps` is exactly a positional/joint-information loss —
  knowing *how many* requirements are in the `HARD_FAIL` band is not the same as knowing *which specific*
  requirement (the hard one? the critical one?) is in it, precisely analogous to `XOR(p3,p4)` vs.
  `(p3,p4)` individually.
- KSME-01's regime-dependence finding (`K_{𝒯₁}≠K_{𝒯₂}`) is **not directly re-tested here** (no second
  behavior set was added mid-experiment this pass) — an acknowledged evidence gap, not a contradiction.
- Both passes agree on the same methodological lesson your review named explicitly: **sufficiency is
  always relative to a stated, bounded behavior set — never a property of a representation alone.**

## 4. Evidence gaps (disclosed, not smoothed over)

1. **No SAT/SMT solver was available in this environment** (`z3`, `python-sat` both absent, checked
   directly). Exhaustive enumeration was used instead — for `125` and `256`-scale domains this is a
   **decision procedure, strictly stronger than a solver call**, not a weaker substitute; the limitation
   only becomes real once a domain is too large to enumerate, which did not occur this pass.
2. **`Ready`/`CriticalGaps`'s exact Boolean formulas are `DERIVED`, not `SOURCE-ESTABLISHED`** — a
   different, equally-defensible formalization of BC-02.7's own Certificates could shift the exact false
   equivalence counts (though not the qualitative "`π₁` insufficient" conclusion, which is robust across
   any reasonable formalization using more than 2 status values per position).
3. **`n=3` requirements is a bounded instance**, not a claim about KnowledgeOS's real requirement count;
   the `27`-class oracle result is specific to this bound and would grow differently (not linearly) for
   larger `n` — not tested this pass.
4. **The two sub-experiments were not joined into one model** — `Status₅`/`Sat₂` and
   canonical-construction's 8-component `K` were tested separately; whether they interact (e.g., does
   `Σ`'s 4-value decomposition, already `PROVEN` minimal elsewhere per BC-02.16, relate numerically to
   this pass's 27-class result?) is `OPEN`, flagged for a possible future pass, not investigated here.
5. **`K_min⁴`, `K_t¹¹`, ratified 8-primitive, ABK-1 were not tested this pass** — Sub-experiment 1's
   domain (per-requirement status) and Sub-experiment 2's domain (canonical-construction's own 8
   components) don't have a non-arbitrary mapping to either without repeating the same
   `NOT COMPARABLE UNDER CURRENT FORMALIZATION` judgment KSME-01 already made for most of them; not
   re-attempted here to avoid manufacturing a forced mapping.

## 5. Updated theory statement

Consistent with the reviewing analysis's own reformulation, and now with two independent, real-corpus
witnesses (not one synthetic one):

$$
K_{\mathcal T,\mathcal O} = E / \sim_{\mathcal T,\mathcal O}, \qquad
e_1\sim_{\mathcal T,\mathcal O} e_2 \iff \forall O\in\mathcal O: O(e_1)=O(e_2)
$$

For **`𝒪 = {Coverage, EpistemicDebt_set, Ready, CriticalGaps_set}`** (all four real, S0881-named): the
minimal `K_𝒪` has **27** classes over this bounded `n=3` instance — `π₁` (`8` classes) is not it, and
matching class-count alone (the 3-valued candidate, also `27` classes) is not sufficient either. For
**`𝒪` = canonical-construction's own 18-operation well-definedness requirement**: the minimal `K_𝒪`
requires all `8` of `{A,R,S,EL,Dt,PI,T,H}` — `K=(𝒜,ℛ)` alone breaks `17` of `18` operations' own stated
preconditions.
