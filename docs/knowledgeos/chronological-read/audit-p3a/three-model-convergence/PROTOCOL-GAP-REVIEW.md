## 2. Where `three_model_convergence`'s own methodology found gaps the Master Protocol v3.5 doesn't

- **`PROTOCOL-EXTENSION-CANDIDATE-1` — a "confirmed independence" state, distinct from
  `UNKNOWN`/`UNRESOLVED`.** P3a's own enum has `INDEPENDENT` (requiring a NEGATIVE-CENSUS bar per
  this session's own Quality Gate work) but no cross-model equivalent that distinguishes "we never
  checked" (`UNKNOWN`) from "we checked and confirmed zero connection" (GA-002's K_t/Δ_t case). Both
  currently render as `UNRESOLVED` in this task's own vocabulary, losing information. Proposed name,
  **not adopted**: `CONFIRMED-INDEPENDENT` — analogous to P3a's own `NEGATIVE-CENSUS` distinction.
- **`PROTOCOL-EXTENSION-CANDIDATE-2` — categorical-type mismatch as a first-class relationship
  state.** GA-001's Kernel finding (aggregate/noun vs. operator/verb) is stronger and more specific
  than plain `CONTRADICTORY` or `UNRESOLVED` — it identifies *why* no comparison is even
  well-formed. Neither this task's vocabulary nor P3a's enum has a value for "these two things are
  different kinds of formal object, not merely differently-valued instances of the same kind."
  Proposed name, **not adopted**: `CATEGORY-MISMATCH`.
- **`PROTOCOL-EXTENSION-CANDIDATE-3` — a designed-independence-authorization tag**, distinct from
  observed independence. Model B's explicit "does not import Model A material, per the
  authorization's independence requirement" is a *stronger* evidentiary class than merely finding no
  citation (GA-002's case) — it is a controlled condition. This session's own `P3-DERIVATION-
  DEPENDENCY-MODEL.md` already has `SHARED-PROMPT-LINEAGE` as a strong-positive-dependency tag; this
  is its natural strong-negative counterpart. Proposed name, **not adopted**:
  `DESIGNED-INDEPENDENCE`.
- **Reaffirmed, not new:** `PARALLEL-UNRECONCILED` (already proposed by this session's own
  Derivation Discovery Audit) would also apply to at least one case surfaced here if a future pass
  finds A and C1 material produced close together with no cross-citation — not confirmed in this
  pass, named only as a candidate reuse.

## 3. Methodology worth reusing from `three_model_convergence` into KnowledgeOS's own protocol
   practice (the "learn from it" half of the mandate)

- **The six-level evidentiary ladder** (Lexical → Conceptual → Functional → Structural → Formal
  equivalence → Demonstrated identity) is a genuinely useful **general-purpose discipline** for any
  future cross-label or cross-model correspondence work, including a possible future P3a extension.
  Not adopted into P3a's schema by this document — flagged as a `PROTOCOL-EXTENSION-CANDIDATE` for
  whoever governs that decision.
- **The same-day self-audit pattern** (M0043→M0045; M0057→M0058) — a concrete, repeatable practice
  of immediately adversarially re-checking one's own freshly-produced formal claims — is worth
  naming explicitly as good practice, independent of whether its specific findings (THM-1/5/11,
  Zero Closure) are ever reused. This mirrors this session's own row_brief()/mechanism-F bug-catching
  discipline and is mutually reinforcing evidence that adversarial self-review catches real defects
  other methods miss.
- **Explicit governance-blocking as a first-class disposition** (GA-006's K-1 collision) —
  distinguishing "unresolved because we haven't looked" from "unresolved because a governance
  boundary forbids looking right now" is a useful distinction P3a's own `UNWITNESSED` category does
  not currently make. Named as a candidate refinement, not adopted.
