## 0. What this is, and is not

This is **not** an attempt to determine KnowledgeOS's actual Kernel. It is the **smallest formal model
capable of testing whether a behavioral-equivalence Kernel construction is even well-defined**, applied
to a **purpose-built synthetic world**, not to any historical corpus object. Existing candidates
(`K=(𝒜,ℛ)`, `K_min⁴`, `K_t¹¹`, canonical-construction `K`, the ratified 8-primitive set) are tested only
as *representations against this synthetic ground truth*, and only where a non-arbitrary mapping into
the model exists — most cannot be mapped without inventing semantics, and are reported as
**`NOT COMPARABLE UNDER CURRENT FORMALIZATION`**, per the commissioning's own explicit instruction, not
forced.

## 2. Formal Model (Artifact A)

$$
W \xrightarrow{\Omega} O \xrightarrow{f=\mathrm{id}} E \xrightarrow{\rho} R
\qquad\qquad
T : E\times C \to E \ \ (\text{Merge}: E\times E\times C\to E)
\qquad\qquad
O_{\mathrm{req}} : E\times C \to \{0,1\}
$$

- `W = {0,1}^8`, one Boolean per named property `p1..p8`.
- `Ω(w) = w` with coordinate `p7` forced to `0`. **Type**: `{0,1}^8 → {0,1}^8`. **Provenance**: this
  experiment's own stipulation, built to instantiate `31.19`'s non-injectivity claim concretely.
- `E = O` (via `f = id`). **Type**: `{0,1}^8`.
- `C` = `(policy_threshold ∈ {0,1}, external_p5 ∈ {0,1})` plus, for `Revise`/`Supersede`, an explicit
  argument `new_p1 ∈ {0,1}`. **Type**: a small product type, fully enumerated (4 contexts × 2 args where
  applicable).
- `T_req^{(1)} = \{Revise, Supersede, Merge, Qualify\}`; `T_req^{(2)} = T_req^{(1)} \cup \{Contest\}`.
- `𝒪_req = \{O\_query\_p1, O\_conflict\_status, O\_qualification\_status\}` (`+O\_contest\_outcome` in
  regime 2).
- `signature(e) = ⟨ O(e) \text{ for } O∈𝒪_{req} ⟩ \frown ⟨ O(T(e,c)) \text{ for every } T∈𝒯_{req}, c∈C, \text{arg}⟩`
  — the **behavioral fingerprint**, computed exhaustively (§6).
- `e_1 \sim_B e_2 :\iff \mathrm{signature}(e_1)=\mathrm{signature}(e_2)`.
- `K \cong E/{\sim_B}`.

**Every symbol's reason for existing** (per Task 6's requirement to remove anything unnecessary):
`p2` exists solely to give the detector a true negative; `p7` solely to instantiate non-identifiability;
`p5` solely to instantiate the context-vs-state question; `p8`/`Contest` solely to instantiate
regime-dependence; `p3,p4` solely to instantiate representation-redundancy (a joint, not marginal,
effect). No property was added without a specific falsification target.

**§6.1 — the two "disagreements" are not errors; they are the experiment's most important findings.**
- **`p5`**: the *quantity* matters (it drives `O_qualification_status`), but the **state's own stored

  that *the in-state field* `p5` is behaviorally inert, which is exactly the distinction Task 11/World F
  asks for: **relevant-as-a-fact ≠ relevant-as-a-stored-field**. Confirmed directly (§9, KSME-01F):
  zeroing `e.p5` for all `e,c` never changes `O_qualification_status` — `0` cases where the state copy
  affects behavior, out of the full enumeration.
- **`p7`**: relevant *in principle* (if it were observable), but **no two reachable epistemic states
  ever differ only in `p7`** (since `Ω` already forced it to `0` in all 128 of them) — so the sensitivity
  test cannot even pose the question. This is the exact truth-table cell *"behaviorally relevant but not
  observable"* required by Task 18 (§10 below).

## 7. Congruence results and the bug found in-flight (Artifact F)

**A real methodological error was made and caught during this pass, not before.** The first version of
`check_congruence` aggregated `Revise`'s two argument branches (`new_p1=0` and `new_p1=1`) into one
"operation" when checking whether an equivalence class's *images* stayed in one class — this manufactured
**64 spurious "violations"** that were artifacts of comparing `Revise(e,0)` against `Revise(e,1)` (which
of course land in different classes, since `p1` is relevant — that was never a meaningful congruence
question). **Fixed** by holding the operation's argument fixed as part of `c`, per the model's own stated
signature `T:E×C→E` (§2) — after the fix, **congruence violations: `0`**, confirmed exhaustively.
This is recorded here, per the commissioning's own instruction never to "repair the model silently" —
the fix is a bug fix in the *test harness*, not a repair of the *hypothesis*, and is disclosed as such.

**Separately, and not an artifact**: the *naive* representation that simply drops `p3` and `p4`
(assuming pairwise redundancy implies individual removability) produces **32 confirmed sufficiency
violations** (§8, C7) — a real, non-buggy finding that a plausible-looking field-drop breaks behavioral
sufficiency, because the true relevant information is the *pair's joint* `XOR`, not either field alone.

## 11. Does a Kernel exist? Which case? (Artifact, Task 19)

**Case 1 holds for the bounded system `(T_req^{(1)}, 𝒪_req, Ω)`**: a valid equivalence relation and a
finite (8-class) quotient Kernel were constructed and confirmed congruent, exhaustively.

**But Case 4 also holds, simultaneously and unavoidably**: §6's KSME-01G result shows the quotient
**depends on the operation universe** — adding one operation (`Contest`) changes the Kernel from 8 to 16
classes. **These two cases are not in tension**: Case 1 is a *relative* result (true kernel-for-this-`𝒯`),
and Case 4 is the correct, honest generalization once a second `𝒯` is considered. **No evidence for Case
2, 3, 6, or 7 was found in this bounded experiment** — but the experiment was never large enough to rule
them out for a real KnowledgeOS-scale operation universe (§12).

## 12. Evidence gaps (honest limitations, not smoothed over)

1. **Only 8 properties, 2 operations-with-arguments, 1 binary `Underdetermined`-adjacent case were
   modeled** — a real KnowledgeOS operation universe (the commissioning's own illustrative 11-operation
   list) is far larger; nothing here demonstrates these results scale (`C8` was not positively tested,
   only left open).
2. **No property instantiates the "behaviorally-necessary-but-unobservable" × ... ` wait — this cell WAS
   populated (`p7`); the genuinely empty cell is "not-observable AND irrelevant," which is a
   low-stakes gap (an irrelevant-and-unobservable property would be uninteresting by construction) —
   noted for completeness, not pursued.
3. **`Retract` and `Underdetermined`'s explicit return value were implemented in code but not exercised
   in a reported experiment** — an incompleteness relative to the commissioning's own B-series list.
4. **`ML` (Section 22) was not used at all this pass** — the state space was small enough for exhaustive
   enumeration to be strictly stronger evidence than any ML-based discovery step; this is a deliberate
   choice (exhaustive proof > statistical inference, where exhaustive proof is available), recorded per
   the commissioning's own "ML must remain subordinate" instruction, not an oversight.
5. **Statistical confidence intervals were not computed** — because every reported result is an
   **exhaustive enumeration** (a decision procedure over `2^8`/`4^8`-scale spaces), not a sample; per
   Task 16's own instruction not to report percentages without specifying the population, the honest
   report is "100% of a fully enumerated population," which needs no interval.
