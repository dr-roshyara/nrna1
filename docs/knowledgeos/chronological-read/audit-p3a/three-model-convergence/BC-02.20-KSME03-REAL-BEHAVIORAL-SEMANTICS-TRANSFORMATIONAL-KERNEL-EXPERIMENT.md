## 4. The `HYPOTHESIS`-tier `T` construction, `K_O` vs `K_B`

**Carrier** (`HYPOTHESIS`, 109 reachable states): a single tracked item with
`present∈{0,1}`, `tier∈{Candidate,Knowledge}`, `content∈{0,1,2}`,
`id∈{0,1,2}`, `withdrawn∈{0,1}`, `validated∈{NA,Pass,Fail}`.

**Operations** (`HYPOTHESIS`-tier effect; existence real per `oderive.py`):
`Add`, `Remove`, `Withdraw`, `Promote`, `Revise(c)`, `Supersede(c)`,
`Validate(c)`. Each effect is the minimal structural reading of its cited
non-collapse law (e.g. `Revise`: *"content may change while identity
persists"* → mutate `content`, hold `id` fixed; `Supersede`: *"identity may
change while content persists"* → the reverse; `Withdraw` vs `Remove`:
*"retraction that is not deletion"* → `Withdraw` sets a flag without
clearing state, `Remove` clears it fully; `Validate`: *"structural check"*
→ compares hidden `content` against an asserted context value `c`, records
`Pass`/`Fail`).

**Observation set `O_THIN`**: `present`, `tier`, `withdrawn`, `validated`.
Deliberately **excludes** `content` and `id` — the probe for whether hiding
an attribute from direct observation also hides it from behavior.

**`K_O` and `K_B` as two separate, compared quotients**, computed by proper
fixed-point (bisimulation-style) partition refinement — this is the correct
way to honor `∀T∈𝒯*` (arbitrary composed sequences, not one step): starting
partition = `K_O` (the `∼_O` classes); repeatedly split any class whose
members produce different `(op, context, resulting-class)` signatures,
until stable. The fixed point **is** `K_B`.

| Quantity | Value |
|---|---|
| `K_O` classes | **13** |
| `K_B` classes | **37** |
| Refinement rounds to fixed point | 2 |
| `K_O` strictly coarser than `K_B`? | **Yes** |

**Counterexample certificate** (an `∼_O`-equal, `∼_B`-distinct pair, with
witness):

```
e1 = (present=1, tier=Candidate, content=0, id=0, withdrawn=0, validated=Fail)
e2 = (present=1, tier=Candidate, content=1, id=0, withdrawn=0, validated=Fail)
O_THIN(e1) == O_THIN(e2)                      # e1 ~_O e2 HOLDS
witness: T = Validate, c = 0
O_THIN(Validate(e1,0)) = (1,Candidate,0,Pass)
O_THIN(Validate(e2,0)) = (1,Candidate,0,Fail)  # differ!
⟹ e1 ~_O e2  but  e1 ≁_B e2
```

This is exactly the shape of error the user's correction anticipated:
`content` is invisible to direct observation, so `∼_O` merges `e1`/`e2`;
but `Validate` (a real, named, corpus-cited operation) makes a
content-dependent distinction visible under a later observation. `∼_O` is
therefore too coarse to serve as `K_B` under this (disclosed, `HYPOTHESIS`)
transformation family — the same structural lesson as the user's correction,
now demonstrated constructively rather than only asserted.
