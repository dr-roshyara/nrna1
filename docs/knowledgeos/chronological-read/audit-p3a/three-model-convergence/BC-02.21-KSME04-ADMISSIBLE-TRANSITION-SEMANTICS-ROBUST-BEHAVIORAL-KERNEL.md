## 3. Parts C–E — reusing the real `𝔐_T`, computing `K_O`/`K_B(T)`/`K_R`

**Discipline**: we did **not** build a new synthetic `𝔐_T` from scratch. `so_model.py`
already **is** a real, cited, executable `𝔐_T` generator for 8 operations. Building
a second, independent, invented one would duplicate real work with weaker evidence —
directly against the commissioning's own "use the already-established real evidence"
instruction (echoing KSME-03's closing line). `ksme04.py` therefore **verbatim-reuses**
`so_model.py`'s `Obj`/`State`/`OPERATIONS`/abstraction functions (copied, not
reimplemented from memory — see the "no reproduction from memory" note below) and
`so_exp01_congruence_matrix.py`'s own 208-state bounded domain and argument-generation
rules, and adds what neither source file computed:

1. **True `K_B(T,O)` via fixed-point (bisimulation-style) partition refinement**,
   honoring `∀T∈𝒯*` (arbitrary composed sequences) — `so_exp01` tested only
   **single-step** congruence per operation (Step 259's own stated criterion,
   correctly applied there), which is weaker than the corrected central formula
   this whole KSME-02→03→04 line has been building toward.
2. **`𝔐_T` treated as 2⁸=256 independent per-operation variant assignments** (not
   just the two "all-blind"/"all-sensitive" extremes `so_exp01` tested), and `K_R`
   computed as the **robust (intersection) quotient** across that family.

### A real bug caught and fixed in the open (disclosed, not hidden)

The first draft of `ksme04.py` ran the fixed-point refinement directly over
`so_exp01`'s 208-state `SPACE`. That domain is **not closed** under the real
operations (`Add`/`Merge` can introduce a new object id, `"z"`, absent from the
original 208-state enumeration) — fine for `so_exp01`'s single-step check (it only
ever compares `O(r₁)` vs `O(r₂)` directly, never needs `r`'s *class*), but invalid
for a multi-step fixed point, which needs the codomain to lie inside the domain
being partitioned. The bug: out-of-domain results were silently scored as
`None` (conflated with "operation's precondition failed") by Python's
`dict.get(r, None)` default — **4088 such silent misclassifications**, caught by an
explicit closure check before any result was reported, not discovered after the
fact.

**Fix**: compute the true reachable BFS closure of the 208 seed states under every
operation and both variants (`E`, exact, not sampled: **41,820 states**, computed in
11.4s), and require every transition inside the fixed-point refinement to land
in `E` (an `assert`, not a silent default). A second performance issue followed
directly from this fix and is disclosed the same way: refining a single model over
41,820 states took ~56s, and the *full* 256-model sweep × 2 observation sets would
have taken an estimated **4–8 hours** — judged disproportionate for this pass.

### Scope reduction, disclosed (Part N discipline: sampled, not exhaustive)

`𝔐_T`'s full 2⁸=256-model sweep was reduced to **13 representative models**:
baseline (all-blind), the opposite extreme (all-sensitive), all 8 single-operation
flips from baseline (marginal sensitivity — directly answers Part H's per-operation
question), and 3 pairwise flips (a *limited*, not exhaustive, joint-relevance
probe: `{Revise,Supersede}`, `{Revise,Transform}`, `{Merge,Supersede}`).

**Correction (see the notice at the top of this document): the sentence originally
here claimed the 13-model `K_R` was an "upper bound" on the full-model result. That
is backwards — testing fewer models imposes fewer constraints on `∼_R`, so it can
only produce a partition AT LEAST as coarse (i.e. a class count AT MOST as large) as
the full computation. The 13-model count is a LOWER bound, not an upper bound.** This
error was caught by the user before any number was ever inserted below — see
`BC-02.22-KSME05` for the corrected terminology and, more importantly, the exact
(not sampled) computation that makes the bound question moot for this domain.

## 4. Part F — model differences vs. Kernel differences

Because `K_R` here is computed as a combined-signature intersection (each state's
signature is the tuple of its class-id under every one of the 13 tested models), two
models `T_i`,`T_j` that happen to produce the **same class count** are not assumed
isomorphic — the construction only ever merges states whose behavior is identical
under *every* tested model, so a same-cardinality coincidence between two individual
`K_B(T_i)` and `K_B(T_j)` partitions (if it occurs in `results04.json`) is reported as
a raw fact, not interpreted as isomorphism, per the commissioning's explicit warning
against that conflation.

## 5. Part G — robust relevance lattice (honest scope note)

The commissioning asks for a `RobustNecessary`/`PossibleRelevant`/`RobustlyIrrelevant`
classification **per attribute** (not just an aggregate class-count comparison).
`ksme04.py` computes the aggregate result exactly (`K_R` vs. `K_O`, whole-signature),
but does **not** attempt automatic per-field attribution (which hidden field —
`id`, `origin`, `sup`, `merged` — is responsible for a given class split): the
counterexample certificate names a witnessing *model* and a witnessing *pair of
states*, from which the responsible field can be read off by inspection (the two
states in the certificate differ in exactly one or two fields, visible in their
printed content), but a fully automated per-field lattice was judged out of scope for
this pass and is named here as **`NOT COMPUTED`**, not silently assumed. This is a
concrete, scoped TODO for a follow-on, not a gap papered over.

## 6. Part H — joint/interaction relevance

The 3 pairwise-flip models (`{Revise,Supersede}`, `{Revise,Transform}`,
`{Merge,Supersede}`) test a **limited** joint-relevance question: does flipping two
operations' variants together produce a class count different from what the two
single flips would predict by simple union/composition. This is a bounded probe, not
an exhaustive subset search over all `C(8,2)=28` pairs (let alone higher-order
subsets) — disclosed as partial coverage, consistent with Part N's sampling
discipline. A full joint-relevance sweep (all pairs, or the `Relevant(S)`
generalization for `|S|≤3`) is named as a follow-on, not attempted here.
