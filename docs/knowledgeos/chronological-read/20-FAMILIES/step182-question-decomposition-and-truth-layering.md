## Sources (how this label entered the ledger)
- **OBJECT-INDEX** batch `B0033`, scope `THEORY-LEVEL`: Step 182's key discovery: a seemingly single question ('is port 8081 okay?') decomposes into at least six distinct propositions (PortExists, PortReachable, PortExposed, PortPermitted, PortRequired, PortApproved), each potentially owned by a different domain (worked example: infrastructure has epistemic authority over 'port 8081 is technically reachable' while security has authority over 'port 8081 is permitted per policy' -- same system, same port, different proposition). Requires an AI/KnowledgeOS to decompose a question into 'what proposition, which context, which authority, what evidence' before retrieving an answer, rather than returning one flat result. Layers organizational reality into ObservedState -> InterpretedState -> DomainDetermination -> GovernanceDecision -> AuthorizedAction -> ActualOutcome (worked Nexus 8081 example: each statement true in a different semantic sense), and states the philosophical-but-engineering-consequential boundary World != RepresentationOfWorld -- KnowledgeOS records observations and interpretations of reality, it does not make reality true, so a record NexusRunning=true means 'KnowledgeOSDetermination: NexusRunning=true under specified Time/Scope/Evidence', never reality itself.
