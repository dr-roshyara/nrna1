## Rationale
- [S0466] (ARGUMENT/EXAMPLE) Justifies choosing semi-Markov over ordinary Markov modelling: KnowledgeOS epistemic states (e.g. 'architecture proposal') have no reason to follow a geometric duration distribution, so each state needs its own duration model D_i~p_i(d), enabling metrics like expected duration, variance, and time-to-transition probability (e.g. 'how long does a governance proposal typically remain contested?').
- [S0466] (PRINCIPLE/ANALYSIS) Deepest result and final recommendation: Observed != Inferred != Authoritative != True as the core architectural invariant, with Temporal Epistemic Modelling added as a first-class research track (Model Registry -> Temporal Inference (filtering/smoothing/prediction) -> Assurance -> Wisdom -> Action) without changing the core DDD architecture yet.
- [S0664] (ALTERNATIVE/CONTRADICTION) Records the block's sole dissent: an HSMM source proposes KnowledgeOS should contain a Semi-Markov epistemic layer inferring hidden states from observations — the only document proposing a formalism be contained rather than merely supporting; flags this as in tension with the block's uniform placement verdict, though the tension may be dissolvable via the extent/contents distinction (a layer inside KnowledgeOS need not be inside the Kernel's extent, though neither document says so); identifies hidden-state-from-observation as a second route (after S1-F014) to a derived-epistemic-state hypothesis, this time from time-series statistics rather than DDD.
- [S0665] (ALTERNATIVE/CORRECTION) Records a duration-modelling proposal explicitly conditional on a test ('does this observation sequence actually require explicit duration modelling?') rather than asserted generally, narrowing S1-F032's semi-Markov dissent: duration modelling is proposed only where duration matters, softening the earlier tension into a conditional, scoped temporal mechanism rather than a general Kernel component.
