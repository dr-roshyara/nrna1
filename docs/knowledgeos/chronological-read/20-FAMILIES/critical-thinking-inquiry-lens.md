## Rationale
The emerging epistemic lifecycle (Context->Problem->Question->Inquiry->{Observation,Sources,Existing Knowledge}->Evidence->{Hypothesis,AlternativeHypotheses}->Test->Observation->Inference->Argument->Claim->Assessment->{Supported,Refuted,Unresolved}->Knowledge Candidate->Governance->Accepted Knowledge) must not be implemented as one giant KnowledgeAggregate; instead five bounded responsibilities are proposed: Knowledge Kernel (Question/Hypothesis/Evidence/Claim/Argument/Inference/Assessment/Provenance), Inquiry Context (Inquiry/Problem/Investigation/Test/CounterEvidence/AlternativeHypothesis/Sufficiency), Reasoning Context (Argument/Inference/ReasoningMethod/Fallacy/BiasIndicator/Decomposition/Pattern), Decision Context (Decision/Alternative/Criterion/Evaluation/Tradeoff/DecisionBasis), and Governance Context (Authority/Approval/Accountability/Policy/Mandate/Review), collaborating through explicit contracts [S0404]. The source book is itself a collection of lenses (Critical Thinking/Logic/Reasoning/Bias/Fallacies/Induction/Deduction/Pattern/Causation/Problem framing/Decomposition/Decision/Communication) validating KnowledgeOS's 'established lenses' approach: the kernel supplies domain objects (KnowledgeClaim->Assessment) and different lenses (Epistemic/Logic/Governance) supply evaluation; a critical design rule follows that lenses inspect domain objects but do not redefine them, preventing KnowledgeOS from becoming a philosophical monolith [S0404].
