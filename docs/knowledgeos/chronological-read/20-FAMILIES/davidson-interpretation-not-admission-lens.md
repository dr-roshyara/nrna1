## Rationale
Provenance is deeper than 'who supplied this': a naive Kernel preserving only content/source/timestamp is insufficient; Davidson motivates Expression->{Source, Context, Declared role, Intended force, Interpretation}->Candidate, but DDD blocks putting all those fields directly into a KnowledgeAggregate -- the correct question is which distinction the admission boundary must preserve so linguistic material is not accidentally converted into epistemic authority [S0418]. D-6 Raw Evidence Fallacy: Davidson rejects a scheme/content dualism where an organizing conceptual system acts on neutral uninterpreted content; a KnowledgeOS model of RAW EVIDENCE -> Ontology -> TRUTH is suspect because 'raw evidence' already involves selection, measurement, representation, categorization, interpretation; the corrected principle is not that the Kernel should interpret evidence, but that it 'should not falsely claim that interpretation did not happen.' [S0418]. DDD reading: naively importing Davidson would wrongly build InterpretationEngine/MeaningResolver/BeliefModel/ContextModel/ReferenceResolver/CharityEvaluator/MetaphorInterpreter inside a KnowledgeCore; instead the sheer amount of work interpretation involves is reason to keep interpretation OUTSIDE the smallest authoritative Kernel, in a surrounding 'Cognitive/Semantic World' layer that feeds candidates to a small KNOWLEDGEOS KERNEL protecting identity/provenance/justification/authority/epistemic-integrity/transitions -- 'intelligence scales outward; epistemic authority remains small.' [S0418].
