## Rationale

Strongest cross-system finding: all three systems (EKS, PKS, AIP) independently converge on 'knowledge/evidence/assessment may inform authority, but it does not create authority' -- EKS via transitions[] ≠ grants[] and Assessment never granting authority; PKS via AP-1/promotion as an explicit authority act; AIP via produced-record ≠ owned-authority; DeepSeek classifies this as ESTABLISHED in EKS/PKS, PARTIALLY ESTABLISHED in AIP -- described as 'already observable architecture', not merely a liked principle. [S0203] Second most important finding: the governance mechanism RECORDS authority, it does not GRANT it, and cannot ENFORCE it -- an illegal write to the record is a refused transition (exit 65, nothing appended); authority is a recorded reference to a human act, and the record refuses malformed writes to itself while preventing no engineering action whatsoever. [S0206] The authority-scope finding (first-hand to this baseline, class D): the `authorized` query is implemented as raw string equality on grant `scope` (workflow-state.php:429-431); since scope has a median length of 2,337 characters (max 6,037; only 2/126 under 200 chars), asking 'is this session authorized for scope X?' requires reproducing a multi-thousand-character prose paragraph byte-for-byte -- the query is structurally implemented (class A) yet practically unanswerable (class D): 'scope is not a scope. It is a commission narrative stored in a field named scope.' [S0206]
