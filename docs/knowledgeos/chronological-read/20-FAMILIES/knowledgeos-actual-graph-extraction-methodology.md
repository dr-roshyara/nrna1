### Theme: Four-graph/layer model, extraction rule, evidence hierarchy, schemas (10 rows condensed; source_ids: S1014)
States Step 116's shift from Conceptual Reconstruction to Evidence Extraction, aiming to construct the actual graph G_actual=(V_actual,E_actual) from real evidence rather than declared architecture; states the strict extraction rule Claim_architecture=>Evidence_implementation, defaulting missing evidence to Status=UNKNOWN (never FALSE); defines a seven-level evidence hierarchy E0 (no evidence) through E6 (governance evidence); defines the SemanticObject node-extraction schema (ID/Type/Meaning/Representation/Owner/Lifecycle/Authority/Provenance/Evidence and a tenth field) and the SemanticRelationship edge-extraction schema (Source/Target/Type/Direction/Evidence/Confidence/Status); defines the implementation graph G_I, data graph G_D, and semantic graph G_S as related but distinct (G_I != G_D != G_S); defines the governance graph G_G=(Actors,Authorities,Decisions,Policies); and presents the four-layer stack Governance->Semantic->Data->Implementation as more accurate than forcing everything into one diagram.

### Theme: Evidence-grading experiments 1-8: components, tables, endpoints, events, workflow, config, runtime (14 rows condensed; source_ids: S1014)
Runs eight worked PASS experiments validating the evidence-extraction principles: (1) an EvidenceRepository component's actual semantic concept cannot be inferred from its class name alone; (2) a knowledge_items table may actually represent IndexedDocumentChunk rather than the claimed concept; (3) a POST /knowledge endpoint does not itself prove CreateKnowledgeObject without behavioral inspection; states tests are particularly strong semantic evidence and formalizes a documented-E1/code-enforced-E3/test-verified-E4 confidence ladder (4); states event names are evidence of a semantic concept only if actual behavior supports the name, and that a KnowledgeUpdated event meaning only "search index updated" is not necessarily SemanticKnowledgeUpdated (5); distinguishes technical publishing workflow from authoritative governance workflow, showing a Review->Publish transition with no authority check establishes only technical, not governance, lifecycle (6); states configuration reveals dependency, not semantic ownership, shown via a GITHUB_URL entry establishing integration, not authority (7); and states runtime evidence (E5) is the strongest evidence for actual operational relationships, shown via a never-invoked integration remaining below E5 (8).

### Theme: Declared-vs-observed graphs, drift, and git-history/ADR-linked evidence (7 rows condensed; source_ids: S1014)
Defines G_declared and G_observed with Gap=G_declared-G_observed and Unexpected=G_observed-G_declared, enumerates four causes each for declared-not-observed and observed-not-declared discrepancies, and runs a PASS experiment showing a documented Agent->KnowledgeOS diverging from an observed Agent->LegacyService is a Declared/ObservedMismatch classified DRIFT; states Git history can help reconstruct temporal relationships but correlation alone does not prove causality, shown via a PASS experiment where temporally close Decision and CodeChange commits show correlation, not automatic causation; and states a commit explicitly referencing and implementing an ADR provides stronger evidence than mere temporal proximity, shown via a PASS experiment grading an "implements ADR-042" commit message as E2/E3 depending on verification.

### Theme: Graph identity resolution, similarity != identity, confidence, unknown edges (7 rows condensed; source_ids: S1014)
Defines the graph identity resolution problem (the same authoritative object referenced under multiple names requiring IdentityResolution), shown via a PASS experiment where three differently-named references to one decision yield SameObject=True only with a stable identifier or explicit cross-reference; defines a three-level identity-resolution confidence scale (High/Medium/Low); states Similarity(A,B) != Identity(A,B), particularly important for AI systems since highly similar documents can represent different decisions, shown via a PASS experiment where a 0.97 embedding similarity score does not prove two documents are identical; defines per-edge Confidence(E) in {High,Medium,Low} with concrete criteria; and requires explicitly recording UnknownEdge rather than inventing a relationship type, essential for architectural honesty.

### Theme: Contradictory evidence, drift findings, and legitimate agent caches (6 rows condensed; source_ids: S1014)
States contradictory evidence should be recorded as both DeclaredEdge and ObservedEdge, yielding a DriftFinding rather than silently resolving the conflict, shown via a PASS-classified experiment where agents reading .claude/memory/ directly despite documentation claiming all knowledge flows through KnowledgeOS is potential HIGH-severity drift; restates the pointer-layer model (Agent-pointer->KnowledgeOS, not Agent-with-private-knowledge), now directly testable via the extracted graph, shown via an experiment classifying Claude's local memory containing a differing architecture decision as a potential semantic authority conflict; and states local agent caches can be legitimate projections of KnowledgeOS given SourceID/Version/Timestamp/RefreshPolicy (not automatically wrong), shown via a PASS experiment where an agent cache with a versioned reference to a KnowledgeOS object is a valid projection candidate.
