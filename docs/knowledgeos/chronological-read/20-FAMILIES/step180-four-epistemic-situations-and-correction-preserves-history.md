## Sources (how this label entered the ledger)
- **OBJECT-INDEX** (batch B0033, scope THEORY-LEVEL): Step 180 distinguishes four semantically different epistemic situations: (1) Unknown -- not enough evidence; (2) Contradiction -- evidence supports incompatible claims under the SAME scope/time assumptions; (3) Supersession -- a later valid state legitimately replaces an earlier one (different scope/time); (4) Correction -- an earlier determination is found to have been wrong (e.g. D1=MigrationFeasible based on an invalid assumption, later corrected by D2=MigrationNotFeasibleUnderActualConditions, recorded as Corrects(D2,D1)). States the invariant 'correction should preserve the existence and provenance of the corrected artifact' -- D1 must never be erased because it is part of organizational history; Update(D1) is judged the wrong semantic operation, replaced by an explicit D2--corrects-->D1 relation, event/history-oriented rather than mutation-oriented (KnowledgeOS should behave like a lineage graph K1--superseded/corrected by-->K2, not like an overwritable knowledge.txt).
