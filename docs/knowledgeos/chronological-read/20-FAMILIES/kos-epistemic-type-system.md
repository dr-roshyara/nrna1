## Rationale
States not all epistemic types form a simple ordered hierarchy (e.g. Prediction and Observation are not 'higher' or 'lower', just different semantic roles), giving EpistemicTypeSystem != SimpleLinearHierarchy; the better model is TypedDirectedGraph + TransformationRules + Invariants. Formalizes computational semantics as E = (T,R,I,P): T=epistemic types, R=permitted transformations, I=invariants, P=provenance rules, with type(x) in T for artifact x and a transformation r: T_i -> T_j valid only if its preconditions hold.
