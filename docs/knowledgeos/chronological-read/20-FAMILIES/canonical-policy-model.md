## Rationale
The decisive discrimination for Policy's category: a Policy is an OBJECT that is *applied* (having identity, version, an applicability window, and composability/comparability), not a bare function that is called — versioning (corpus-named "Migration-Policy v3") is only meaningful for an object [S1651]. Per-property analysis fixes the type as three-valued, partially total, deterministic given fixed gates, composable only under conjunction (a meet-semilattice), with identity `(id,version)` and version proven semantically load-bearing — while policy provenance (who authored/authorised it) is recorded as explicitly absent from the governing corpus definition, an unresolved gap [S1651]. Three-valued semantics matter because a two-valued policy would have to silently coerce Unknown to True or False, whereas `ResolutionBehavior` makes that coercion an explicit, named, auditable choice — the same epistemic-humility pattern recurring at the Sigma (epistemic status) level [S1651]. The full corpus lineage of Policy is traced across nineteen-plus prior steps, each classified normative/descriptive/executable/superseded/survives, closing the coverage gap that had made Policy look conceptually undefined when it in fact already existed but had not been found and run [S1652]. A structural duality closes a major architectural question: `(K, merge, empty)` is a join-semilattice (knowledge only grows) while `(Policy, AND)` is a meet-semilattice (permission only contracts) — "knowledge accumulates; permission contracts," an executed structural finding [S1655]. All 18 EKP lint rules are classified against the theory's own categories, giving a clean, evidence-grounded count (3 invariants, 7 policies, 3 governance rules, 3 validation/structural rules, 2 descriptive rules) that applies the Policy/Invariant discrimination criterion directly to real running code [S1656]. Sigma could not have been resolved before Policy because Sigma is literally the codomain of Assessment, which takes Policy as an argument — the same evidence under different policies producing different Sigma values is direct evidence that Sigma is a property of an assertion *under a policy*, confirming the mandate's Policy-before-Sigma ordering [S1657]. A final consolidated engineering-correspondence verdict maps exactly what the EKP does and does not implement of the theory, and where the theory in turn constrains the implementation [S1660]. A closing gap is registered rather than smoothed over: Policy, authority, evidence, statistics, and uncertainty are each shown to contain a non-computable normative core, so no amount of formalization eliminates the need for a normative input somewhere in the chain [S1664]. Four candidate Policy models (predicate, constraint-set, decision-procedure, normative-document) are set out for testing, with the last explicitly identified as where the theory becomes blocked [S1669].
