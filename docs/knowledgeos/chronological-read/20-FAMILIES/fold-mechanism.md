## Rationale
Event-driven knowledge-system research finds event history valuable for lineage/auditability/reconstruction, but event sourcing carries real costs (replay complexity, temporal complexity, reconstruction cost) and is 'not universally necessary' -- evidence is mixed. [S0202] State-as-fold is identified as one of the strongest common properties across systems: EKS derives current state purely from an append-only transition log with no independently mutable state that can drift from history; PKS uses append-oriented governed registers; AIP shares the same underlying workflow/state machinery. Classified as kernel candidate C-2, 'State-as-fold / append-only forward-only log' -- said to describe the architecture's state philosophy, not merely its storage format. [S0203] Cross-system invariant: authoritative record -> {interpretation -> recommendation; diagnostics -> reports}, with no path back to mutate authority. EKS's resolver is read-pure with derived dashboards/graphs/recommendations; PKS states projections are regenerable and non-authoritative; AIP is weaker but still distinguishes produced records from owned authority. DeepSeek's verdict: 'Diagnostics must not mutate authoritative state — ESTABLISHED.' [S0203] Persisted-vs-derived separation: persisted are schema/workItem/workflow/roles[], transitions[] (verbatim, append-only, seq-stamped), grants[] (verbatim, append-only), and every JSONL row; derived-never-stored are sessions{}, each session's state, mutationOwner, workItemState, handoffsTo{}, authorizationLinkage, the authorized boolean, every resolver verdict/reason/authorizationFact, and all lint/check/dashboard output. Framed as 'the strongest single design property in EKS, and it is what makes the fold trustworthy.' [S0206] Eight governance disciplines are made structural, not merely promised: lifecycle ≠ authority (two arrays never merged); absence ≠ permission ('no record = ungoverned = free' is explicitly forbidden reasoning in code); recommendation ≠ decision; observation ≠ verdict (three verdicts are structurally unemittable by machine); discovery ≠ activation (the resolver is write-free by construction, pinned by test T-11); one interpretation authority (the resolver subprocesses fold rather than parsing records itself, T-13); ambiguity is an answer (AMBIGUOUS lists all candidates, chooses none, exits 0); producer ≠ acceptor (the durability ADR binds its own producing process out of approving it). 'Refusal, ambiguity, and "I cannot know" are first-class, tested, non-error outcomes. Very few systems get this right.' [S0206] EKS's only inter-component protocol is a subprocess call (session-resolve.php spawns workflow-state.php fold via proc_open); nine integration mechanisms total are catalogued (filesystem, git CLI, the subprocess delegation, shell_exec/require_once between scripts, Composer autoload, AI-harness hooks, GitHub Actions, the KOS_MECHANISM_PATH env var, and prose cross-references resolved only by humans); there is no network integration, no API, and no serialization contract between components other than the JSON that `fold` prints to stdout. [S0206]
