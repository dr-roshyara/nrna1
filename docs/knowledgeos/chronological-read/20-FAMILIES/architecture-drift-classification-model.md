### 1. The core discrepancy-classification model D1–D6, with six worked experiments (12 rows)
Frames the document's central question: what a discrepancy between A_I/A_C/A_D/A_R (intended/current/deployed/runtime architecture, presumably) actually means, since not every difference is a defect [S1006]. States the central principle: A_I≠A_R does not automatically mean ArchitectureWrong — Difference->Classification->Decision [S1006]. Defines six mutually exclusive discrepancy categories D1-D6 (architecture defect, implementation defect, deployment defect, runtime defect, authorized deviation, unknown/insufficient evidence), with D6 called essential [S1006]. Six worked experiments each classify a concrete case: Experiment 1, an already-approved architecture change observed at runtime, is D1 (architecture evolution, not a violation) [S1006]; Experiment 2, a forbidden A->Database connection in source with no exception, is D2 (implementation defect) [S1006]; Experiment 3, production running an older version than source, is D3 (deployment drift) [S1006]; Experiment 4, a forbidden connection opened despite correct version/config, is D4 (runtime violation) [S1006]; Experiment 5, an authorized temporary exception in use, is D5 (authorized deviation) [S1006]; Experiment 6, incomplete repository/runtime evidence, is D6 (Unknown — the answer explicitly not invented) [S1006]. Names two dangerous mistakes the model prevents: silently redefining A_I:=A_R (hiding defects), and declaring nonconformance without recognizing legitimate intentional changes [S1006].
