## Sources (how this label entered the ledger)
- **OBJECT-INDEX**, batch B0033, scope THEORY-LEVEL: Step 182 states OrganizationalAuthority != EpistemicEvidence (a senior executive's statement about server behavior carries organizational authority but not technical epistemic authority over runtime facts), preventing 'authority-based truth': Authority(A) does not imply Truth(P) -- a Board decision to use Kubernetes creates Decision=UseKubernetes but does not prove KubernetesIsBestTechnology (which remains a separate epistemic/engineering proposition). States the symmetric converse: evidence does not create organizational obligation (EpistemicAuthority != GovernanceAuthority; evidence that migration is safe does not itself create an obligation to migrate). Organizes organizational knowledge along two independent axes -- Epistemic (how well supported) and Normative (how authoritative/binding) -- given a worked comparison table (engineer observation: strong epistemic/non-binding; Board decision: evidence-dependent epistemic/binding within scope; AI recommendation: variable epistemic/non-binding; authorization: not necessarily empirical/binding for action), recommending AI responses separate 'evidence strength' from 'governance status (binding?)' rather than one conflated confidence number.
