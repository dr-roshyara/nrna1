A query conceptually satisfies State_after=State_before while a command may produce State_after != State_before. Event immutability: once DecisionAuthorized has occurred it is never rewritten into DecisionRejected; instead a later event DecisionAuthorizationRevoked is emitted -- history is append-oriented. Observation != DomainEvent: an observation says 'source reports X', an event says 'domain state transition X occurred' -- example, CPU=98% is an Observation, not automatically ServerOverloaded (an interpretation/claim); preserves Observation -> Evidence -> Claim, never Observation === Truth." (anchor: "Four interaction types Command/Query/Event/Observation; Intent != Fact; query preserves state; Observation !== DomainEvent")
