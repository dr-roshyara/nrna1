## Rationale

Subject-matter neutrality is judged unattainable by any verifier in this estate, because every process occupies roles and the discovery's own subject is the role model itself; this is stated as a structural, not merely personal, limitation [S0089]. The adoption decision retroactively supersedes the narrow thesis Verification #2's finding W-1 was testing ('the six-role model is not currently established as governed architecture'), because that thesis is now false by decision; the verdict-G re-scoping requires the still-pending Verification #3 lane to be redirected to the evidence-quality question rather than the adoption question itself [S0093]. Testing all four forbidden role-capability pairings (C-5->Verification, C-10->Knowledge, C-14->Governance, C-19->Communication) against evidence, none is established: consumer is not necessarily owner (C-5), the gap is delivery-mechanism not content (C-10, two-sided BC-1/BC-6), the live instance sits in BC-3 not Governance (C-14), and adoption of a role is explicitly not evidence a capability exists (C-19) -- framed as the discipline working correctly rather than failing to find an answer [S0102]. Argues for extending a four-role production-lifecycle engineering model (Governance/Architecture/Implementation/Verification, mapping to Decide→Design→Build→Assure) with two cross-cutting platform roles, Communication Engineer (owns human↔AI communication quality/handovers/actor instructions) and Knowledge Engineer (owns knowledge lifecycle/evidence linking/architectural memory), analogized as the platform's nervous system and memory system respectively [S0153]. An initial discovery pass claims the six-role model is a commissioning-persona vocabulary, not architecture, since the estate already owns the authority dimension via a capability-shaped decision-rights matrix ('AI Responsibility Matrix') that contains no actors at all [S0164].
