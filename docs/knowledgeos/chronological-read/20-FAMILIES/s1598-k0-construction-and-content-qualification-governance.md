## Rationale

Establishes, via the worked example, that Observation and Proposition must be distinct typed objects related by Supports(o,p) rather than identified (o=p); without this distinction the theory cannot separate 'the proposition is true' from 'evidence was observed supporting the proposition' -- flagged as critical for the later epistemic theory [S1598]. Additionally, Considers two alternatives for context: embedding it directly into each proposition (p_c=(p,c)) versus keeping propositions context-free and defining a separate Interpret:Proposition x Context -> Meaning function; prefers the latter to preserve separation of concerns, flagged as a design hypothesis needing later testing [S1598]. Further, Defines governance/policy application as Validate:Proposition x Evidence x Policy -> Assessment, arguing this is preferable to embedding policy directly into the proposition object [S1598]. Relatedly, Mandates a direct test of whether policy pi belongs inside the Knowledge State (Model A: K=(C,sigma,theta,lambda,pi)) or is external, expressed only through Validate:K x Evidence x Policy->Assessment and/or T:K x Input x Policy x Authority->K' (Model B: K=(C,sigma,theta,lambda)), to be decided on type-discipline grounds rather than intuition [S1602]. In the same vein, Formalizes three explicit candidate models for epistemic status (a pure function of the proposition; a function of proposition+evidence+context; or a derived projection of a full Assessment function including policy), to be tested with 3 concrete counterexample patterns (same proposition/different evidence; same proposition+evidence/different context; same evidence/different policy), anticipating that EpistemicStatus may not be a Knowledge-State primitive at all [S1602].
