## Rationale
Defines evidence archaeology (identifying existing mechanisms recording commands/tool calls/test results/repository state/checks/runtime observations/agent changes/approvals) and 'fragmented evidence' — many existing evidence sources exist independently, but a piece of evidence may have no traceable relationship to the decision it should support; defines the evidence-integration test 'can we traverse from a change to its authorization, implementation, evidence, and verification?' (Change->Decision->Commit->Deployment->Verification), recording a broken chain as a TraceabilityGap — 'the gap the Assurance Graph is designed to close.' [S1033] Defines a six-level registry maturity ladder R0-R5 (name list -> structured catalog -> identity+metadata -> relationships -> provenance+lifecycle -> evidence-backed governance) to measure the existing registry, arguing that if the registry already provides identity+relationships+lifecycle+provenance, building a wholly new 'Knowledge Graph' could be unnecessary — instead ExistingRegistry->Strengthen->AssuranceGraph, 'exactly why archaeology must precede implementation.'
