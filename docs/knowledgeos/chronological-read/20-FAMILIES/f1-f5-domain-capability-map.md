## Rationale
F-3's result that KnowledgeCore accepts any representable submission gives the Sanskrit/FST/compiler research a clean architectural home outside the Kernel: natural language, structured data, and formal notation all reduce to the same canonical candidate shape before admission, validating the earlier candidate-set insight (AH-6) while explicitly removing it from the Kernel [S0361]. Nine domain capabilities claimed as existing-law, all MUST EXIST: single admission gate, contract-conformance enforcement, identity assignment, evidence admission, justification preservation + sufficiency evaluation, history recording, representation-agnostic intake, epistemic-state determination, confidence assignment inside boundary. Used to argue a minimal rule-evaluator Kernel ('(command, state, rules, evidence) -> admissibility verdict') is too small, since the domain already holds authoritative responsibility for these nine. A specific ownership split is quoted: the domain owns the admitted JustificationPath and its sufficiency evaluation, while the reasoning mechanism owns only production [S0610]. Implementation-relevance verdict: the nine-capability map itself yields no implementation work (every item is claimed to already exist as law; six of nine are found present in v1.1's own coverage comparison), but the anti-minimalist warning that 'the Kernel cannot simply be a generic rule evaluator' is preserved as a standing review question at boundary decisions -- a failure mode invisible to conformance testing (each rule can pass while identity assignment migrates into a mechanism) and visible only to the question 'does anything the domain must own now happen somewhere else?' [S0626]. Records the strongest claim in the corpus about evidence: the acquisition procedure itself constitutes whether an observation can function as evidence, so two identical observations can differ in evidential standing depending on how they were obtained; this makes acquisition provenance a precondition of admissibility rather than a desirable attribute, a different and finer requirement than source-type retention or a justification-path obligation; intersects S1-F029's role constraint (role and acquisition together determine what an evidence reference must carry) and adds a further cost to S1-F018's shareable-Entity horn (one acquisition history may qualify an Entity for one use and not another) [S0658]. Concludes the smallest domain fact whose integrity must be protected is 'a justified claim' (asserted, evidence-supported, constitutionally evaluated), with justifiability as the sole retained invariant; explicitly excludes Identity ('an administrative concern'), Epistemic State ('a projection of events'), Confidence ('an assessment'), and History ('an audit record') from the required invariant — the most reductive result in the corpus, demoting four of the six components every other member list treats as core, including Identity, which a separate ledger treats as the core domain and S1-F015 said never changes [S0660].
