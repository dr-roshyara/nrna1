## Rationale
The evidence base attributes the following rationale to this object (as recorded, cited to its source):

- **[FORMALIZATION/ARGUMENT]** [S2247]: Formalizes Buddhi as mode-sensitive: B_t:(E_t,K_t,M_t)->{accept,reject,investigate,suspend,transform}. The same evidence E can lead to different actions depending on mode: in Sattva, E->B_S->investigate carefully; in Rajas, E->B_R->act/acquire immediately; in Tamas, E->B_T->ignore/suspend/block. Refines the earlier 'kernel always busy determining right and wrong' into: the kernel continuously evaluates the epistemic condition of its current state and determines which transitions are admissible under its current operational mode; a kernel may legitimately decide DO NOTHING because evidence is insufficient, and that itself is a Buddhi decision.
- **[ANALYSIS/OPEN-QUESTION]** [S2251]: Sharpens the Guna flag (open since REFINED-STEP-286 sec4, which required Guna to declare a scale type before being opened, touching the untyped Threshold/theta gap) into a two-branch fork P1': Branch 1, G_t derived from Sigma (e.g. mode=goodness when support is strong) -- the theta/scale-type gap returns, since a derivation rule over S's ordinal bands is exactly what sec4 flagged; Branch 2, G_t independent of Sigma -- a new state component with no carrier, and K_t=(Sigma_t,G_t,...) becomes another open-ended tuple that 258.35 warns against. Neither branch is free; sec4's gate still binds since neither branch declares a scale type. Contrasts with external_research mapping Guna->Sigma directly, which artifact 19's E2 finding already showed produces a type error.
