## Rationale
Lens 0 (Zero): simple vector retrieval breaks on multistep or multi-data-type questions, requiring orchestration beyond similarity search -- 'a single vector retriever is not a KnowledgeOS retrieval architecture'; retrieval is a pipeline, not one operation (query->candidate generation->filtering->ranking->context expansion->context assembly), giving Pattern 1 Multi-Stage Retrieval (Candidate Retrieval->Filtering->Fusion->Reranking->Context Selection), with reranking described in the source as an explicit second-stage operation over initially-retrieved candidates. [S0441] Lens 3 (Chinese Philosophy) applied to RAG: Context Is Constitutive (query+role+situation+institution+time+purpose->meaningful retrieval, rather than bare query->similar chunks, giving Pattern Contextual Retrieval: Retrieve(query, context)); Relational Identity -- Graph RAG's example (a Clause anchored to ClauseType/Company/Address/SLA) is read as 'not merely an optimization of vector search, it is a representation of relational context', a direct technical realization of the relational-identity observation. Names Are Not Enough -- vector retrieval for an ambiguous term like 'Customer' across 500 documents cannot resolve which institution/jurisdiction/version/role/business-context is meant, so Name-Referent Separation (from S0440 Pass 2) should feed directly into retrieval: Query->Entity/concept resolution->Context resolution->Retrieval, not Query->Embedding. [S0441] Lens 5 (Agent): the book's agentic-RAG patterns (Prompt Chaining, Routing, Parallelization, Orchestrator-Workers, tool-based workflows) map onto the AI Engineering Platform, but Lens 0 asks 'should KnowledgeOS itself become an agent?' -- answered 'No': KnowledgeOS should expose Knowledge Query/Evidence/Context/Assessment/Actions to agents, which orchestrate, avoiding KnowledgeOS=Agent+RAG+VectorDB+Graph+LLM (which would collapse bounded contexts); proposes a Knowledge Tool Boundary pattern exposing focused single-responsibility tools (search_knowledge/retrieve_evidence/resolve_concept/compare_claims/get_authority/get_lineage/evaluate_claim/find_conflicts) rather than one giant ask_knowledgeos() tool.
