## Rationale
This object addresses why a mathematically correct KnowledgeOS design is not automatically an operable one: Step 90 opens by arguing that organizational-scale reliability additionally requires Correctness+Scalability+Predictable resource usage, and that computational complexity T(n) is therefore itself part of the architecture, since two mathematically correct algorithms can have radically different engineering properties depending on complexity class [S0989]. The motivating problem is that naive reasoning over a full knowledge graph risks combinatorial explosion, so the architecture must constrain reasoning to a query-relevant subgraph — but doing so raises a completeness question (does the relevant subgraph contain everything necessary?) explicitly linked back to Step 88's completeness problem [S0989]. A first efficiency/assurance tension is used to justify ordering the two concerns: an efficiency-improving retriever that omits a mandatory governance rule shows efficiency improving while assurance fails, which grounds the principle that optimization cannot precede assurance — information sufficiency must be established before processing is optimized [S0989]. Several further arguments justify treating caching, distribution, and parallelism as epistemic rather than purely performance concerns: caches are argued to carry epistemic semantics via a validity interval because a derived artifact can silently become stale when any of its inputs, policy, or model version changes [S0989]; distributed organizational-scale computation is argued to have no single instantaneous global state, so a repository at one commit and a deployment system at another must be represented as genuinely different states rather than treated as simultaneous [S0989]; and computational outputs that share a common dependency are argued not to be independent evidence merely because several agents or parallel branches produced them, since their errors can be correlated. The economics section is motivated by the claim that computing further is only worthwhile when the value of the resulting information exceeds its computational cost, except when governance mandates the computation regardless of economic value — keeping a bounded set of checks outside pure cost-benefit optimization [S0989]. This is extended into an argument that approximation is itself an economic decision, and that the required computational precision should scale with proximity to the decision boundary, because an approximate estimate is only sufficient when its uncertainty interval does not straddle the threshold that the decision depends on [S0989]. The overarching architectural argument is a three-way separation of Correctness, Computability, and Scalability — a system can succeed on one axis and fail on another (a correct, decidable algorithm can still be operationally infeasible; a fast approximation can be scalable yet produce unacceptable governance decisions) — which is used to justify a single constrained-optimization framing of KnowledgeOS execution: minimize cost subject to explicit floors on correctness, completeness, and assurance and a ceiling on latency [S0989]. Finally, the object argues that performance optimization must never be allowed to silently weaken assurance or convert an incomplete computation into a definitive result: resource exhaustion is framed as epistemic information (a timeout should read Verification=Unknown, Reason=Timeout, never Verification=False) rather than a negative finding, closing the case that graceful degradation must be explicit, never silent [S0989].

### Theme 1 — Framing: complexity is architecture, not incidental (4 rows)
Opens Step 90 by requiring Correctness+Scalability+Predictable resource usage for organizational-scale reliability, and argues complexity class T(n) is itself an architectural property, not incidental — demonstrated with an O(n) operation on 1,000,000 objects scaling proportionally (Experiment 1, PASS) against an O(n²) pairwise comparison on the same population becoming ~10^12 comparisons and operationally infeasible despite being mathematically valid (Experiment 2, PASS).

### Theme 2 — Reasoning-relevant subgraph vs. optimization-before-assurance ordering (4 rows)
States GraphSize ≠ ReasoningSize — naive reasoning over the full graph G=(V,E) risks combinatorial explosion, so the architecture must constrain reasoning to a query-relevant subgraph G_Q⊆G, tested by a decision over 500 of 10^7 entities correctly reasoning only over the relevant subgraph (Experiment 3, PASS); this immediately raises whether G_Q is complete (linked to Step 88), sharpened by a retriever that improves efficiency (10M→1000 objects) but omits a mandatory governance rule, showing efficiency and assurance can diverge (Experiment 4, PASS) — grounding the principle that optimization cannot precede assurance.

### Theme 3 — Incremental computation and dependency tracking (4 rows)
Defines incremental computation ComputeIncremental(K_t,ΔK) as preferable to full recomputation when semantic correctness is preserved, demonstrated by a 0.1s incremental update vastly outperforming a 1000s full recomputation for one changed fact (Experiment 5, PASS); argues this requires tracking a DependencyGraph, since a change to A in a chain A→B→C→D can require invalidating B, C, D, tested by a change to source E correctly marking dependents K_1, K_2, K_3 as candidates for revalidation (Experiment 6, PASS).

### Theme 4 — Cache validity as an epistemic, not merely performance, property (4 rows)
Argues caches carry epistemic semantics via a ValidFrom/ValidUntil interval, since continuing to use a cached policy after it has changed is StaleKnowledge (Experiment 7, PASS); formalizes CacheValidity=f(InputVersion,PolicyVersion,ModelVersion) — a derived artifact D=f(E,P,M) can become invalid if any input changes — tested by correctly recognizing a cached result as derived under an old ModelVersion even after the live model advances (Experiment 8, PASS).

### Theme 5 — Parallelism, dependency DAGs, cycles, and fixed points (12 rows)
Defines decomposable, parallelizable reasoning tasks Q=Q_1∪...∪Q_k when independent, demonstrated by five independent 10s checks completing in ~10s in parallel vs 50s sequentially (Experiment 9, PASS); notes dependencies constrain parallelism (Q_1→Q_3 cannot be evaluated independently), tested by starting Q_3 before Q_1 completes risking invalid computation (Experiment 10, PASS); formalizes a dependency DAG D=(V,E) whose acyclicity permits topological ordering, confirmed valid for A→B→C (Experiment 11, PASS); notes a cyclic dependency (A→B→A) is not necessarily an error but breaks ordinary topological evaluation, tested by correctly flagging mutual A/B dependency as CircularDependencyDetected (Experiment 12, PASS); proposes fixed-point computation x*=F(x*) for cyclic systems, demonstrated by an iterative governance-state update converging to a stable fixed point (Experiment 13, PASS); and warns Iteration ≠ guaranteed solution — iterative systems may converge, oscillate, diverge, or become chaotic — demonstrated by the diverging iteration x_{t+1}=2x_t from x_0=1 reaching no finite fixed point (Experiment 14, PASS).

### Theme 6 — Distributed state and temporal consistency (8 rows)
Notes organizational-scale KnowledgeOS computation is distributed across repositories, databases, CI, observability, policy engines, model services, and AI agents, introducing DistributedState, tested by treating two differently-timed observations S_A(t)/S_B(t) as simultaneous being flagged a TemporalConsistencyError (Experiment 15, PASS); states distributed KnowledgeOS may have no single instantaneous global state (K_A(t) may differ from K_B(t) across subsystems), tested by requiring a repository at commit C_5 and a deployment system at C_4 to be represented as distinct states (Experiment 16, PASS); distinguishes eventual consistency (temporary divergence resolving over time) from the stronger consistency governance-critical decisions may require, tested by production authorization correctly refusing to rely blindly on a stale policy replica (Experiment 17, PASS); and formalizes ConsistencyRequirement=f(Criticality) — low-risk operations can tolerate stale data, production authorization cannot — tested by flagging eventual-consistency-without-freshness-guarantees applied to critical deployment authorization as PotentiallyInsufficient (Experiment 18, PASS).

### Theme 7 — Computational economics: value of information vs. compute cost, bounded by governance (6 rows)
Defines computational economics — compute further only when VOI>C_compute, or when governance mandates the computation regardless of economic value — tested by an investigation with VOI=€10,000 and cost €100 correctly judged worth performing (Experiment 19, PASS) against one with VOI=€10 and cost €10,000 correctly judged not worth performing for an ordinary optional decision (Experiment 20, PASS); states EconomicOptimization ⊆ GovernedFeasibleSpace — mandatory checks remain required even when VOI<C_compute — tested by a €5000 security scan remaining ScanRequired=True despite appearing economically unjustified, because policy mandates it (Experiment 21, PASS); and defines cost-aware reasoning as optimizing ExpectedDecisionValue − ComputationalCost subject to HardAssuranceConstraints.

### Theme 8 — Approximation as an economic decision and decision-sensitive precision (8 rows)
Argues approximation is itself an economic decision — a cheaper approximate analysis is preferable when its bounded error is acceptable — tested by an approximate risk estimate (€980,000±€30,000) being sufficient when far from a €2,000,000 decision threshold (Experiment 22, PASS), but insufficient when the threshold (€1,000,000) falls inside the estimate's uncertainty interval, called "very important" (an implicit experiment, PASS); states decision-sensitive precision — required computational precision should scale with proximity to the decision boundary T — tested by an estimate (150±2) far above threshold 100 needing no expensive refinement (Experiment 23, PASS) against an estimate (101±5) straddling threshold 100 that cannot be confidently classified (Experiment 24, PASS); and proposes an adaptive-computation pattern CheapApproximation→CheckBoundary→RefineIfNecessary as more scalable than always computing exactly.

### Theme 9 — Hierarchical retrieval and assurance preservation under optimization (4 rows)
Proposes a hierarchical retrieval architecture GlobalIndex→CandidateSet→EvidenceVerification→Reasoning to avoid reasoning over every artifact, tested by narrowing 10^8 documents to 30 for reasoning being preferable if completeness guarantees remain intact (Experiment 25, PASS); and states the core invariant that performance optimization must not silently weaken assurance — if it does, AssuranceLevel must be explicitly downgraded — tested by a fast-mode approximate-retrieval path being required to report Assurance<Formal unless formal equivalence is established (Experiment 26, PASS).

### Theme 10 — Graceful degradation and timeout as epistemic information (4 rows)
Defines graceful degradation: under resource insufficiency the system must return Exact/Approximate/Partial/Unknown explicitly, never silently, tested by a system running out of compute correctly returning "risk assessment incomplete" rather than "no risk" (Experiment 27, PASS); and states Timeout is part of a result's provenance and is not evidence for False, tested by requiring a post-timeout result to read Verification=Unknown, Reason=Timeout rather than Verification=False (Experiment 28, PASS).

### Theme 11 — Independence and correlation of parallel/ensemble computational outputs (6 rows)
Warns that parallel AI-agent outputs are not automatically independent evidence merely because they improve throughput, tested by five agents relying on the same source not counting as five independent confirmations (Experiment 29, PASS); argues outputs sharing a common dependency may have correlated errors, tested by ten agents agreeing on a summary of the same incorrect document showing consensus does not establish truth (Experiment 30, PASS); and states ensemble value depends on genuinely diverse errors, which must be established rather than assumed, tested by models using genuinely different methods and independent evidence sources producing potentially stronger ensemble evidence (Experiment 31, PASS).

### Theme 12 — Computational budget and a richer Assurance formalization (3 rows)
Defines a computational budget B constraining Cost(computation)≤B, allocated by DecisionCriticality, tested by differing budgets (1 vs 100) for low-risk vs. critical decisions being judged reasonable (Experiment 32, PASS); and generalizes the object's earlier simple Assurance=f(Evidence) into the richer Assurance(Q)=f(Evidence,Model,Algorithm,Completeness,ComputeBudget,Scope).

### Theme 13 — Architecture pipeline and the Correctness/Computability/Scalability separation (6 rows)
Presents the emerging computational architecture Ingest→Index→Retrieve→Verify→Reason→Validate→Decide, wrapped by Cache, IncrementalUpdate, Parallelism, Approximation, and Provenance; states the critical three-way separation Correctness/Computability/Scalability — a system can succeed on one axis and fail on another — tested by a correct, decidable algorithm requiring 20 years' runtime being OperationallyInfeasible (Experiment 33, PASS) and by a fast (1s) approximation producing incorrect governance decisions being Scalable but Unacceptable (Experiment 34, PASS); and states the KnowledgeOS execution optimization objective (minimize Cost subject to Correctness≥C_min, Completeness≥K_min, Assurance≥A_min, Latency≤L_max), tested by an optimization achieving low latency but sub-floor assurance being correctly rejected (Experiment 35, PASS).
