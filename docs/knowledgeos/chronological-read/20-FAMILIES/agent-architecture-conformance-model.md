## All rows (source_id order)
All 69 rows come from a single document (`S1004`, the Step 105 agent-architecture conformance walkthrough), which interleaves definitions/principles with 22 numbered (plus a few unnumbered) PASS/FAIL conformance experiments in one continuous narrative. Grouped below by the document's own topic progression, in row order; statements are condensed, not quoted in full — complete text is in `03-CONTRIBUTIONS.jsonl`.

**Theme 1 — Framing and target architecture (3 rows).** Frames Step 105's central test — whether Claude/Codex operate as governed actors atop a shared KnowledgeOS or have become parallel knowledge/governance systems — restates `AgentBehavior != EngineeringKnowledge` as foundational, and presents the target architecture (KnowledgeOS shared at the top, Claude/Codex as specialized harnesses beneath it).

**Theme 2 — Knowledge-location conformance and the pointer-layer principle (6 rows).** Experiment 1: duplicating authoritative architecture knowledge across `.claude/memory/` and `.codex/memory/` creates DivergenceRisk — **FAIL**. Experiment 2: an agent-behavior instruction correctly staying classified as AgentPolicy — **PASS**. Experiment 3: an engineering architecture rule existing only inside `.claude/` is a KnowledgeBoundaryViolation — **FAIL**. States the pointer-layer principle `AgentHarness -> KnowledgeOS` (never `=`). Experiments 4-5: Claude and Codex each pointing to the same KnowledgeOS-held Constitution rather than duplicating it — both **PASS**.

**Theme 3 — Configuration symmetry (2 rows).** States `ClaudeConfig != CodexConfig` is valid — only the architectural `AgentBehavior -> SharedKnowledge` boundary must stay symmetric; Experiment 6 confirms differing configuration mechanisms between the two agents is not itself a violation — **PASS**.

**Theme 4 — Agent action attribution and authorization scoping (11 rows).** Defines the `AgentAction=(AgentID,AgentVersion,Session,Actor,Tool,Action,Timestamp)` attribution tuple; Experiment 7: an audit record lacking agent/session identity is incomplete attribution — **FAIL**. Distinguishes `HumanActor` from `AgentActor` and the permitted `Human->Authorizes->Agent->Executes` chain from the forbidden `Agent->SelfAuthorizes`; Experiment 8: a developer-requested migration executed by Codex preserving authorization semantics — **PASS**. States `HumanAuthority=A` does not imply `AgentAuthority=A`; Experiment 9: Codex cannot inherit approval authority merely by being asked, absent explicit delegation — **PASS**. Defines per-tool `ToolPermission(agent,tool,scope)`; Experiment 10: Codex's differentiated tool permissions (repo write allowed, production deploy denied) function correctly — **PASS**. States `AgentAuthority = MinimumNecessaryAuthority` (least privilege) per resource category. Distinguishes `Context != Authority`; Experiment 11: retrieving a deployment policy does not confer deployment authority — **PASS**.

**Theme 5 — Context freshness and recommendation provenance (7 rows).** States retrieved context needs Where/When/Version/Authority/Confidence fields to prevent reasoning over stale or non-authoritative information; Experiment 12: Claude must detect a retrieved rule is stale relative to the current version — **PASS**. Distinguishes required decision-relevant provenance (`Recommendation -> EvidenceUsed/ReasoningContext`) from unnecessary private chain-of-thought; Experiment 13: a Claude recommendation with no retained evidence references has incomplete provenance — **FAIL**. States KnowledgeOS must preserve Evidence/RelevantSources/DecisionRationale/Outcome rather than becoming a repository of hidden model reasoning. Defines the recommendation lifecycle `KnowledgeOSContext -> AgentReasoning -> Recommendation -> Human/GovernanceDecision`; Experiment 14: an Architecture-Board-approved Claude recommendation becoming `Recommendation -> Decision` — **PASS**.

**Theme 6 — Autonomy and risk-based control (6 rows).** States `Autonomy != Forbidden` but requires `Autonomy subseteq AuthorizedPolicy`; Experiment 15: Codex's policy-permitted automatic unit-test execution is AuthorizedAutonomy — **PASS**. Defines `Risk(Action) -> RequiredControlLevel`; Experiment 16: an agent must be blocked from automatically deploying to production after failed verification — **PASS**. Defines the agent action ledger `AgentSession -> Requests -> ToolCalls -> Changes -> Verification -> Outcome` (the agent analogue of the governance evidence chain); Experiment 17: an agent's action history connecting a code change to a resulting failed test — **PASS**.

**Theme 7 — Observation, evidence, and knowledge promotion (8 rows).** Defines `AgentObservation -> Evidence`, requiring an AI-generated claim to retain its agent origin; Experiment 18: an agent's discovery becomes `Observation -> Evidence -> CandidateKnowledge`, not automatically an authoritative fact — **PASS**. Defines the four-stage promotion lifecycle `Candidate -> Reviewed -> Verified -> Authoritative`; Experiment 19: a Claude-proposed bounded-context classification remains a candidate pending human/domain review — **PASS**. Distinguishes three non-collapsible memory categories (Ephemeral context, Agent state, Organizational knowledge); Experiment 20: user-preference interaction state must never be promoted to ArchitectureKnowledge — **PASS**. Defines the promotion pipeline `AgentMemory -> CandidateKnowledge -> GovernedKnowledge`; Experiment 21: an unrecorded remembered decision cannot automatically become authoritative organizational knowledge — **PASS**.

**Theme 8 — Cross-agent convergence and handoff (6 rows).** Experiment 22 (implicit): KnowledgeOS must flag a version discrepancy when Claude and Codex retrieve different rule versions — **PASS**. States the shared-knowledge convergence principle `Claude -> K` and `Codex -> K` (both converging on one governed state), strictly stronger than direct Claude<->Codex memory-copy synchronization. Defines required agent-to-agent handoff fields (Context, Task, Authorization, Evidence, ExpectedOutcome); an unnamed experiment: a vague handoff ("fix the architecture") lacking scope/evidence is poorly governed — **FAIL**. Provides a corrected handoff example with explicit Task/Evidence/Scope/Authority fields; a further experiment: a well-formed `Finding -> Task -> Action -> Verification` handoff chain executing correctly — **PASS**.

**Theme 9 — Centralization semantics and distributed storage (7 rows).** Restates `KnowledgeOS = Shared Semantic Control Plane` for agents and engineering. Warns that independent private memory/rules/interpretation per agent eventually creates KnowledgeFragmentation. Presents the centralized-hub architecture (KnowledgeOS connecting Claude/Codex/Human, feeding Engineering). Clarifies "centralized" means `OneAuthoritativeSemanticModel`, not `OneDatabase` — physical storage may remain distributed; an experiment confirms physically distributed storage (object storage/PostgreSQL/Git/observability) remains valid as long as semantic relationships hold. States agents must not bypass KnowledgeOS for governed knowledge; an experiment: Codex reading a superseded architecture file directly, bypassing KnowledgeOS, is a stale-context violation — **FAIL**.

**Theme 10 — Authority hierarchy and trust boundary (8 rows).** States local files remain useful but `LocalArtifact != AuthoritativeKnowledge` unless explicitly designated. Defines a five-layer authority hierarchy `GlobalGovernance -> KnowledgeOS -> RepositoryArchitecture -> AgentOperatingContract -> TaskContext`, where lower layers cannot silently override higher ones; an experiment: a task-level instruction to ignore an architecture rule must lose to the higher-level rule — **PASS**. Restates `UntrustedInput != Authority` as the semantic basis for prompt-injection resistance; an experiment: a README instructing disabling of security controls remains untrusted content, not authority — **PASS**. States distinguishing Instruction from Authority as a major KnowledgeOS advantage over simply telling an LLM to "be careful." Defines `AgentActionAssurance=f(Identity,Authority,Context,Policy,Evidence,Verification)`; an experiment: a production modification with full identity/authorization/policy/change-record/verification/evidence yields strong assurance — **PASS**.

**Theme 11 — Closing conformance status and handoff to Step 106 (5 rows).** Presents a ten-capability agent-architecture conformance matrix (Intended/Claude/Codex/KnowledgeOS/Evidence columns), mostly unresolved pending empirical scan. States eight new agent invariants (including `I_SharedKnowledge` and `I_AgentBoundary`). Records the Step 105 verdict as architecture-level PASS conditional on maintaining the pointer-layer boundary, while implementation conformance remains open. States the concrete artifact mapping (`AGENTS.md -> OperatingContract`, `.claude/ -> ClaudeBehavior`, `.codex/ -> CodexBehavior`, `KnowledgeOS -> EngineeringKnowledge+Governance+Evidence`).
