## Rationale
Correction: Rejects the naive model K_{t+1}=K_t∪e_t as insufficient, listing eleven distinct effects new evidence can have (introduce/strengthen/weaken/contradict/resolve/create conflict/invalidate/stale/reinterpret/expose unsupported/reveal new dimension) to establish K_{t+1}≠K_t∪e_t in general. [S0862] Argues that Illustrates the multidimensional assertion state Σ_A=(Acquisition,Support,Uncertainty,Validity) with an example where only Validity changes (Current→Stale) while Support stays unchanged, confirming a single linear lifecycle is mathematically inadequate. [S0862] Argues that Argues policy version must be preserved with every assessment/conclusion, since a threshold change (e.g. 0.90→0.95) makes the same evidence yield different conclusions across time, and omitting it makes historical reconstruction ambiguous. [S0862] Argues that Argues a SemanticModelVersion (or equivalent provenance) must also be preserved, since changes to a concept's meaning (e.g. SecurityStatus) can make old conclusions uninterpretable under a newer ontology. [S0862] Argues that Argues KnowledgeOS needs belief-revision semantics rather than either deleting a contradicted assertion or keeping both as current truths, defining a six-value Status(A) enum {Active,Superseded,Retracted,Expired,Contested,Historical}. [S0862] Shows a conflict resolving by discovering a missing context dimension (staging vs production), establishing that Conflict may reveal a missing dimension, connecting back to the Ideal State and Zero. [S0862] Argues that Argues knowledge evolution is inherently multidimensional: resolving one discrepancy (Conflict→0) can create another (a newly discovered Unknown dimension), so KnowledgeOS cannot optimize a single scalar metric. [S0862]
