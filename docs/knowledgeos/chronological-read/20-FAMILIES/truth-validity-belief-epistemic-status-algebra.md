## Rationale
This object addresses a foundational gap the document treats as more urgent than any single feature: KnowledgeOS never has direct access to whether an assertion is actually true in the world, only to observations and evidence, so Truth ≠ Evidence ≠ Knowledge must be kept apart from the start [S0906]. The argument is built from two symmetric worked counterexamples that make the separation concrete rather than merely definitional: before KnowledgeOS ever receives evidence, a proposition can already be true in the world (truth does not depend on whether KnowledgeOS knows it), and conversely an erroneous database record can produce strong support for a proposition that is in fact false — the latter explicitly framed not as a model defect but as an unavoidable property of finite, fallible observation [S0906]. This licenses an operational rather than metaphysical redefinition of knowledge itself: Knowledge=GovernedAcceptance, not Knowledge=TrueWorldTruth, on the grounds that Truth(A,W) remains an external semantic target KnowledgeOS cannot directly calculate, so it must instead follow Evidence→Assessment→Acceptance and estimate epistemic status rather than claim omniscient world access [S0906]. The document further argues truth itself is not a single, uniform notion: logical/mathematical truth (established by axioms and inference rules), empirical/world truth (established by observation), and domain/governance truth (established by organizational authority) are named as three distinct regimes with different validation mechanisms, and KnowledgeOS is argued to need to know which regime applies to any given assertion rather than treating "true" as regime-free [S0906]. A related argument separates belief/probability from truth: a probability P(A|E)=0.95 is a model-relative uncertainty measure, not a 95%-true claim, and the term "belief" itself is argued to invite anthropomorphic confusion, motivating the more neutral term Assessment(A) [S0906]. The document's single most emphasized rule — called "one of the most important rules in the entire architecture" — is Unknown ≠ False: absence of evidence must not be inferred as evidence of absence, defaulting to an open-world assumption unless a domain explicitly and legitimately adopts a closed-world one (illustrated by a registry table where absence does imply non-existence, but only because that domain rule was made explicit) [S0906]. This rule is then generalized into two non-implications treated as the equation of the whole step: Accepted(A) does not imply Truth(A,W) (acceptance only means KnowledgeOS is justified in treating A as accepted under its current model — "a much more defensible claim"), and its converse, Truth(A,W) does not imply Accepted(A), since a true assertion can remain unobserved [S0906]. The resulting four-quadrant crossing of world-truth against system-acceptance is used to argue that a false-but-accepted quadrant is not a bug to be engineered away but "unavoidable in any empirical knowledge system" — which reframes the architecture's own promise: not KnowledgeOS=Oracle, but KnowledgeOS=Governed epistemic system, measured by evidence quality, provenance, calibration, reproducibility, revision behavior, error detection, and conflict handling, argued to be "much more scientifically defensible" [S0906]. Several further distinctions are motivated by the same underlying concern that collapsing categories loses information the architecture needs: context is part of knowledge identity (the same assertion can be true for one server and false for another); GovernanceTruth (an authoritative approval) is explicitly not TechnicalTruth, and both may be independently required before an action is executable; and truth does not automatically imply action, so Truth→Knowledge→Decision→Authorization→Action must remain separate transitions [S0906]. This all converges on the document's strongest warning: a single universal is_true boolean field is rejected outright as the central knowledge representation, because it would collapse Unknown into False and Supported into True — "both are wrong" — which is why a six-dimension EpistemicStatus tuple, typed Assessment structures per truth regime, a five-value TruthRegime enum, and a required Basis(A) field (making reasoning auditable) are proposed instead of any scalar truth value [S0906]. The document's own closing framing of why this matters is explicit: it reframes the unsolved philosophical problem of absolute truth into the tractable engineering problem of what epistemic status a proposition can legitimately be assigned given evidence, context, model, and governance [S0906].

### Theme 1 — Foundational separation: Truth ≠ Evidence ≠ Knowledge (4 rows)
States the fundamental separation Truth(A,W_t) ≠ Evidence ≠ Knowledge, since KnowledgeOS only has observations and evidence, never direct world access; distinguishes four separate questions for any assertion (is it actually true; do we have supporting evidence; does the system currently accept it; is it sufficiently established for a decision) as explicitly non-equivalent; gives the worked example that truth can hold before KnowledgeOS ever receives evidence (Truth=True while Known=False) — "truth does not depend on whether KnowledgeOS knows it"; and gives the symmetric reverse example that an erroneous database record can produce strong support for a false proposition — "strongly supported knowledge can still be false," explicitly not a model defect but an unavoidable property of finite, fallible observation.

### Theme 2 — Redefining knowledge operationally: GovernedAcceptance, not world truth (2 rows)
Redefines KnowledgeOS knowledge operationally rather than metaphysically as Knowledge=GovernedAcceptance, not Knowledge=TrueWorldTruth; and states Truth(A,W) remains an external semantic target KnowledgeOS cannot directly calculate, following Evidence→Assessment→Acceptance and estimating epistemic status instead of obtaining omniscient world access.

### Theme 3 — Truth is not one thing: computable truths and three named truth regimes (5 rows)
Gives three examples of directly computable truth (arithmetic, regex matching, validity-interval evaluation), concluding some truths are computable while world truth in general is not; distinguishes LogicalTruth (e.g. a classical tautology) from EmpiricalTruth as established by different mechanisms; introduces DomainTruth, evaluated from GovernanceRules and distinct from empirical world truth; adds Truth_math (a theorem true relative to axioms/definitions/inference rules), naming three truth regimes (Logical/Mathematical, Empirical/World, Domain/Governance) that KnowledgeOS should be able to tell apart; and formalizes TruthContext=(Domain,Model,Axioms,ReferenceTime), arguing "true" is underspecified without it.

### Theme 4 — Belief/probability is not truth (2 rows)
Introduces Belief(A) (renamed Assessment(A) to avoid anthropomorphic confusion) as distinct from truth, since a human or AI can assign high probability to a false proposition; and clarifies that P(A|E)=0.95 is a model-relative uncertainty measure, not Truth(A)=0.95 — "probability measures uncertainty; truth is not a confidence score."

### Theme 5 — A four-value epistemic-status space and the open-world default (5 rows)
