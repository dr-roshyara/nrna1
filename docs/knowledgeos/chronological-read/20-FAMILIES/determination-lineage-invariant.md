## Rationale
The reference/ideal state is itself knowledge requiring its own epistemic history: not merely RequiredVersion=3.85, but why 3.85 is accepted (who stated it, what evidence/justification, what trust rule, when valid, who accepted it, has it since changed), giving the recursive chain Evidence -> Justification -> Trusted Statement -> Reference State -> Comparison -> New Determination. Trust is not the same as truth: a trusted source's statement must preserve why it is trusted (Statement -> Reason -> Logic -> Justification -> Trust/Acceptance), not merely who said it. [S0706] An owner's resolving decision (e.g. 'treat Nexus as non-compliant, security position prioritized') is itself a new fact/dimension added to the evolving state, D_{t+1}=D_t union {d_ownerDecision} (with value, reason, authority, time), not something that overwrites or erases the prior conflicting evidence -- the security and architecture evidence both remain part of the Knowledge state; KnowledgeOS preserves the evidence and the decisions made from it rather than collapsing history into the latest decision. Whether the decision describes reality or becomes a new rule/reference for future evaluation is resolved as: it becomes a new organizational fact/reference that future observations must be considered against, without automatically overriding a later change in underlying conditions (e.g. the security issue being fixed does not retroactively change the recorded decision). [S0706] Called 'perhaps the most architecturally important discovery': determination is recursive — F_1 is determined from observations, F_2 from F_1, F_3 from F_2, etc., creating a determination history O->F_1->F_2->F_3->...; if F_3 is later challenged, reconstruction requires tracing F_3<-F_2<-F_1<-O. This is where provenance, temporal identity, revision and reconstruction become mathematically necessary rather than merely architectural preferences. [S0830] File 235738 (23:57:38, filename-timestamped 16 seconds before the synthesis document it corrects -- a timestamp/logical-order conflict) argues 'raw evidence' is dangerous terminology since an observation is not evidence until interpreted relative to a hypothesis, deriving that Evidence is a relation Supports(O,p,C,t), not an object -- flagged as 'a very important DDD consequence'; rejects as premature the candidate invariant 'the set of possible worlds/states consistent with the evidence' via a five-way counterexample (Bayesian P(S|E)>0, Dempster-Shafer Bel/Pl, argumentation acceptability, non-monotonic defeasible derivability, and fuzzy membership all disagreeing on what counts as 'consistent'); advances instead the determination lineage p<-R<-E<-O (with context/time/method attached), termed epistemic provenance, as more fundamental to the Kernel than any particular probability distribution; and splits the research into Question A (mathematical invariant across regimes) versus Question B (Kernel substrate for reconstruction).
