## 8.64.1 In plain language

1. **The extraction calls a list of seven "knowledge dimensions" the "knowledge kernel"** and closes its architecture diagram with "The kernel is complete." Here "kernel" names a list of dimensions, not the book's set of mechanisms.
   - A claim of completeness needs a requirement set to be complete against, and none is stated.
   - The source's own table marks five of its seven concepts "Candidate", and the next file calls the grammar "incomplete".
   - "The kernel enforces truth conditions", read plainly or in the sense of formal semantics, falls outside the book's kernel. The book's kernel answers standing, not the truth or meaning of a claim's content.
2. **The performance part is labelled a "theoretical projection", yet concludes that the compiler is "practically implementable".**
   - Its "overall" accuracy copies the parser row.
   - If stage errors compound, the typical figure is about 43%, not 82%.
   - Its throughput summary does not match its own time per page.
3. **The benchmark answer reports two runs on a CPU**, the second with 74.2% on 120 test sentences.
   - The figures are internally consistent.
   - The file has no transcript, code or case list, so by the book's own rule this is a report, graded Src. Whether a run occurred is not established.
   - "Not good enough" judges the result against a bar set after the run.
   - It does not validate the compiler analogy, as the answer says. Nor does it refute flat rule sets in general. At most, it puts this one grammar below a bar set afterwards.
4. **The validator is called "the epistemic authority" and marks a candidate "accepted".** Input the parser understands goes straight to the representation, with no validator at all. In the book a check is not an authority: standing needs a recorded act, and no act appears on either path.
5. **The extraction keeps the type check inside a supporting context and runs it before evidence is linked**, so it checks parsed content. §8.63 C2's preferred reading, an application's well-formedness check, stands.
   - The test cases that keep "after the audit", "despite the audit" and "yesterday" apart agree with the book's "context is part of identity".
   - The compiler's UNKNOWN agrees with the book's U only in form: it is a parse declined, not an answer about standing.
