## 8.63.1 In plain language

1. **The adviser's prompt asks for "the smallest coherent architecture that can still truthfully be called KnowledgeOS",** and tests each principle by asking whether KnowledgeOS stops being KnowledgeOS without it. §9.19 shows that "smallest" has no fixed answer until the requirements and the granularity of the parts are fixed. It also shows that a removal test can find nothing necessary when parts can substitute for each other. The prompt fixes neither. It also defines the kernel as what "must exist", which merges two of the book's three separate questions: is it necessary, and must the kernel provide it.
2. **The compiler answer proposes that "a decision with no evidence" be an "epistemic validation error",** like a type error. If that blocks the decision, it contradicts the Principal's ruling that standing does not depend on evidence (T9-20), and the prompt's own "evidence must not become authority". If it only flags the decision as unsupported, it agrees with the book's display of "not attested".
3. **The assistant gave speed, accuracy and cost figures** ("5–20× faster", "95%", "10–50× cheaper") and in the next answer withdrew them: "My previous numbers were an architectural estimate, not a real simulation." The withdrawal is the source's own correction. Any later record that cites the figures carries unmeasured numbers.
4. **The proposed intermediate representation carries "status: accepted" and "confidence: 0.87"**, and an update is "add: PolicyVersion 3 supersedes PolicyVersion 2". No act is named for any of them. In the book, acceptance and supersession are acts, and supersession is not yet admitted to the evaluator's domain.
5. **Several statements agree with the book.** Conflicting claims are kept side by side as "unresolved". An unknown state is shown with its reason. The language model is a component, "not a source of truth". The prompt's candidate invariants (representation is not identity; revision must not erase history; similarity is not equality) match laws the book already has.

## 8.63.2 Claims and derivations

**C1. "The smallest coherent architecture" asked without a pool; the kernel as what "must exist" (Src; Int against §9.19).**
- **S0306:**
  - "> \"What is the smallest coherent architecture that can still truthfully be called KnowledgeOS?\"" (L193);
  - "## Failure Test 'If this principle disappears, does KnowledgeOS stop being KnowledgeOS?'" (L697–699);
  - "Kernel: Must exist · Mechanism: Can change · Representation: Projection" (L632–648);
  - "Find the smallest core. Possible candidates: … Knowledge Identity · Epistemic Evolution · Meaning Preservation · Wisdom Formation. Evaluate. Do not assume." (L364–386).
- **Int:**
  - **"Smallest" without (A, Req).** §9.19 T1: a minimal set is defined only for a fixed requirement set and a fixed pool of parts at a fixed granularity. With these unfixed, minimal sets differ between pools (§9.19.8), and a unique "smallest" needs a structure condition (T3, T10). The prompt names neither the requirements nor the parts, so its question has no fixed referent in the book's sense. *It echoes S0039's "smallest coherent KnowledgeOS" (S0039 L210, §9.2) without its product litmus.*
  - **The failure test is a removal test.** With substitutes, a removal test can find nothing necessary even though the empty system fails (§9.19 T9). The prompt applies the test "for every major concept" and principle, without asking whether another concept could do the same work.
  - **"Kernel: Must exist."** It defines the kernel by necessity. RESEARCH-PURPOSE keeps three questions apart: is it necessary; must the kernel provide it; could an application provide it. A necessary capability may be delegable (§9.19.3, E1 and N1). *The prompt's definition merges the first two.*
  - **Prohibitions only.** All four example invariants are "must not" (L453–459), and no must-do is asked for (W, step 1). That is the shape §8.42 C1 found: a set of prohibitions met by a system that does nothing. The book's floor is O1–O4 (§8.42 C1; §9.19 T7).
  - **"Do not assume"** (L386) is the right instruction. The book's reading is that the answer must be relative to a stated (A, Req).
- **Not a new concept.**
