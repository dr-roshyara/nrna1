## 8.86.1 In plain language

1. **One file holds three texts: a review by one provider and two replies by another.** The replies agree with the review's direction and reject its final definition of the kernel. All three are advice.
2. **The review defines the kernel as a pure function from a command, a state, rules and evidence to a verdict.** The first reply doubts that a function and a domain aggregate are the same thing. The book's evaluator is a function of the record and its inputs; its recording of acts is not.
3. **The review lets the kernel apply rules "as provided by the Governance Context".** The first reply objects that the kernel would then accept whatever someone calls the constitution; the source and version of the rules must be governed. The book records policy values and the evaluator's version as entries, set by acts.
4. **The first reply warns that if one step judges a transition admissible and another applies it, the state can change in between.** The book names the same gap: writes between a check and an act are not covered, and its carrier-change gate requires that no write fall between them.
5. **The review puts confidence scoring outside the kernel; the second reply, citing the estate's F-1…F-5 results, lists "Confidence assignment inside boundary" as a capability that must exist.** The two halves of one file disagree.
