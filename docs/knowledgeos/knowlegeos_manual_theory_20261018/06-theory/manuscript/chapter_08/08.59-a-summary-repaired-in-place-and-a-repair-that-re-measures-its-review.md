## 8.59.1 In plain language

1. **The correction summary in the corpus is not the text its reviewer read.** The review read 403 lines; the file now has 405 and carries the repair's notes. The repair kept the old wording and labelled it "superseded", so the change is visible in the text. But the header still names only the first author, and which lines the second process wrote is shown only by the repair's own disposition record. An entry that changes under one header is not an entry in the book's sense; the book would read it as two entries.
2. **The repair re-measured a count instead of copying it.** The review said the scripts folder held "11 shell scripts" in 13 entries; the repair counted 10 shell scripts in 13 entries and said so. Either the review miscounted, or the folder changed between the two acts; the records do not show which. A reviewer's measurement is evidence, and the repair treated it as evidence.
3. **One record will carry three pieces of evidence: the closed comparison object, the receipt of the comparison, and the record of the copy write.** The receipt says the comparison was made and passed, not that the copy is right, and not that the write happened; so the write needs its own record. The summary calls the new placement "a row, not a rule"; whether adding a row applies the rule or extends it is the line's own open point.
4. **A closed comparison object belongs to one attempt.** If the final check fails, the run stops; a later attempt measures again and closes a fresh object. The first one is not reused.
5. **Several points agree with the book:** the repair closes nothing and accepts nothing; it reads its grant as limited to the findings, and records why it touched a second file; a test that passes because it matches nothing is not evidence.

**C2. A repair that re-measures its review (Src; Int).**
- **S0253 (as S0299 quotes it):** "🔴 It contains 13 entries — 11 shell scripts plus a `README.md` and those two PHP files. … ⭐ the finding is that the stated measurement is false while its conclusion is true — the estate's own final rule, inverted." (S0299 L103).
- **S0299:** "**Evidence (measured, not assumed)** … **10** shell scripts (…) + `README.md` + `session-resolve.php` + `workflow-state.php`. ⚠️ The review's sub-breakdown said "11 shell scripts"; the re-measured count is **10** shell scripts (the total of 13 entries is correct)." (L109–111).
- **Int:**
  - 11 + 1 + 2 = 14, not 13: the review's breakdown does not sum to its own total; the repair's (10 + 1 + 2) does. *A Ded on the quoted figures only*; the folder itself is not on the allowed list and is not opened.
  - Two readings of the difference: **(a)** the review miscounted; **(b)** the folder changed between the review and the repair. The internal sum favours (a) for the breakdown, but does not show the folder unchanged.
  - The repair act treated the review's measurement as evidence to re-take, not as a finding to copy, and recorded the difference with a warning mark instead of routing it to the reviewer. *Agreement* with §8.36 C1 (a report is not an acceptance) and with a check's independence (§8.06): the review is not authoritative over a count. *The review itself is "NOT modified"* (S0298 L319; S0299 L157), so its wrong figure stands in the record, corrected only from outside.
  - §8.46 C2 recorded RV-5's "measurement false, conclusion true". Here the same holds of the review's own breakdown. *An instance, not a new pattern.*
  - **The self-check passed on the wrong text** (from W's inventory): T18, "this correction summary is itself clean" (S0298 L351), passed while the summary still carried the false script count and the irreconcilable counts that RV-5 and RV-6 later corrected. *The source's own rule* ("a self-check … is EVIDENCE, never assurance", L231) *shown on itself*; evidence for §8.20 C11. And the §10 propagation row (L317) still names only the two PHP files: the RV-5 correction did not reach it. *Narrower than L153, not false.*
- **Not a new concept.**

In the book, an entry's standing covers what it records and no more (A1), and the designation is the new carrier's first append (§9.17 R1); here the switch-over record **is** that append and carries the other three, so the designation stays single (S0298 L266).

Two readings: **(a)** an application, as the producer claims; **(b)** an extension of the rule's domain, which the producer leaves to the reviewer (Outcome B). **C4. A closed comparison object belongs to one run (Src; Int).**
- **S0299 (RV-7):** "⛔ **Never re-construct or re-close the enumeration at (iii) or (iii-b) WITHIN THIS SLOT-3 RUN** … a `3(iii-b)` FAIL is a STOP, not a completion — a LATER re-attempt RE-MEASURES at (i) and RE-CLOSES a FRESH enumeration at (ii); the closed object belongs to the aborted run only." (L146).
- **Int:** the comparison object is immutable within one attempt and is not carried to the next. In the book, the outside reference of a carrier-change check is fixed before the check it constrains (CON-0265); the book does not say whether a failed check's reference may be reused. S0299's answer is no: a new attempt is a new check with a new reference. *An analogy for the book's check; the book has no rule on it.* **TODO:** whether a failed carrier-change check binds the reference of the next attempt (not in the map; a topic, not a claim).
- **Not a new concept.**
