## 8.19.1 In plain language

These five sources review and amend the migration plan, four times over. The book takes six points from them.
1. A writer that is not serialised can tell a process that its write was accepted and then lose it, and the sequence still looks complete. So "accepted" shows that a write happened, not that it survived (C1).
2. Since "nothing was lost" cannot be proved, the reviewers proved "nothing was written" instead, by freezing writes and re-hashing. That check must be placed right before the destructive step, or it protects nothing after it (C2, C11). And when the migration itself must write records, the claim becomes "nothing was written except what we declared". That needs a real declaration and a way to check who actually wrote (C17, C25).
3. Which store is "the record" changes when the writers move. A later merge must not import writes made to the old store, which would add authority silently, the opposite of dropping a side (C3, C18, C26).
4. A status kept outside the evidence must be retracted when it changes, and for a reader who opens only the file, it reaches that reader only if the non-authoritative file is kept out of reach (C4, C12, C22).
5. Assigned identifiers (grant names, section numbers) collided three times. Each repair had to keep the labels already cited (C5, C21, C27).
6. Remedies kept reintroducing the defect class they fixed, and the chain of reviews ends only when a review finds nothing that needs a remedy (C16, C23).

**C17. A freeze the operator must break: the claim becomes "nothing written except the declared" (Src; for C2 and CON-0243; restated at review, W-01).** `[CON-0249 · provisional]` `[CON-0247 · invalid as stated]`

So the manifest "is stale the moment the migration records its own next transition" (S0138 L248, in meaning). It is "Not unsafe" (S0138 L256, in meaning): the loss is "evidential clarity, not integrity" (S0138 L256, in meaning).
- **Int (§8.19 C2; CON-0243; §8.18 C8).** C2 recorded the source's move from "nothing was lost" (unprovable) to "nothing was written" (checkable). S0138 shows when that move fails. **The operation being guarded writes into the record it guards**, because its own evidence must be durable in the same boundary (§8.18 C8). Then "nothing was written" is false by design, and an anchor that expects no change can tell a violation from the operator's own bookkeeping only if the operator's writes are **named in advance**.
  - *Deduction:* the checkable claim becomes "nothing was written **except the named entries**". Its anchor is a manifest plus an expected-write list. Detection is then of **unexpected** writes.
  - This is CON-0243 again, one level up: a commitment covers what it lists, and here it must list the future as well as the past.
  - *In D terms:* the entries the operator expects are known before the operation only by kind and actor, not by content. So the expected list must be a **predicate** (these kinds, by this lane, in this window), not a set of identities. *Recorded; no kernel change.*

- *Corrected at review (W-01).* CON-0247's two "musts" fail.
  - (i) An exact alternative exists: declare a predicate in advance, then check the delta against an **identity log** the operator keeps of its own writes. That catches a writer using the lane's name without authenticating anything. So neither a predicate check nor L10 is necessary. Each is one sufficient means.
  - (ii) The trivial predicate "everything" is "named in advance" and detects nothing. So a declaration must also **exclude** something.
  - (iii) A loss **among** the expected writes stays undetectable.
  - (iv) Granularity: the book's claim is stated per entry, while S0140's "delta ⊆ the DECLARED migration-lane records" (S0140 L70, in meaning) is per record (file). Per file, any write to the migration's own record file is masked.
  - *Restated as CON-0249:* when the guarded operation writes into the record it guards, the checkable claim is "nothing written except the declared". Losses among the declared writes stay out of reach. *Premises (stated at the consolidation, A-16):* the declaration must exclude what a violator could write, and the operator's identity log is the operator's testimony, which itself needs an anchor.
