## 8.7.1 In plain language

Correcting a document is itself work that can go wrong:
- the old figure can survive somewhere the finding did not name;
- reordering sections can break every reference to them;
- each round of corrections can bring new findings, so the chain never ends.

The sources show three practical answers. Search the whole document for the old value. Move a section without changing its number. Decide in advance which findings are worth another round. They also show that accepting a verification is not the same as accepting what was verified.

## 8.7.2 Claims and derivations

**C1. A correction is complete only when no occurrence of the superseded value remains (Src; Ded).**
- S0056's verifier ran a "**Residual sweep**": no occurrence of the old hook count or the old ratio remains, and the new figure "appears in exactly the three sites D-1 named". It adds: "**The D-2 residual in `U-1` was also corrected**, which the commission's list did not require but the finding did." [S0056 L51]
- **Ded:** a list of sites to correct is a claim about where the wrong value occurs. If the list is incomplete, a correction made exactly to the list leaves an occurrence behind. Only a search of the whole object for the old value tests the list. That search is an absence claim, so it needs its scope stated (CON-0120).
- **Int (§8.5 C7):** here the verifier went beyond the finding list to the finding's meaning, so this is a case where §8.5 C7's limit was avoided.
- **The other direction, regression (S0164, second case):** "AMD5's first draft reintroduced DI-1" [S0164 L2601]. A correction can bring back a defect closed earlier; the author reports that "The mandated verification caught it" [S0164 L2601]. A residual sweep looks for the old value. A regression check looks for old defects coming back.

**C2. Moved, not renumbered: an identifier others cite must survive a reordering (Src; Ded).** `[CON-0129 · provisional]`
- **The source:** N-2 restored the order "by **moving** the existing §6.4 block below §6.3. **The identifier `6.4` is preserved** — the block was moved, never renumbered, because the banner, §1 and Verification #2 reference it by that identifier" [S0057 L13]. The verifier re-derived the references, "not taken from the delivery note", and found that every one "points at a `§6.4` that exists" [S0059 L55].
- **Second case (S0164):** "The originals keep their numbers deliberately" [S0164 L2603], because renumbering them would break citations in two independent reviews already delivered. Only the additions not yet cited were renumbered.
- **Ded.** Let a reference bind to an identifier. If the section with identifier i is given the identifier j, then:
  - every reference to i now points to whatever carries i next, or to nothing;
  - every reference to j that was meant for the earlier holder of j now points to the moved section.

  Neither failure is visible at the reference. Renumbering is safe only if every reference is updated, and references in documents that may not be edited (delivered reviews, settled records) cannot be. **So renumbering is safe exactly for identifiers with no reference outside what is being edited.** This is the rule S0164's author applied.
- **The trade-off:** stable identifiers can leave the order non-monotonic, or duplicate a number (S0164's DI-1). The second case resolves it by keeping the cited numbers and renumbering only the uncited additions.
- **Int:** this is §1.10's rule (identity needs governed names) applied to section numbers, and the sibling of I-7. As I-7 makes a supersession a link and not an edit, the sources treat a reordering as a move and not a renaming. *Hyp (two cases, one estate):* that this is a general rule for cited identifiers. The proof above covers only the narrower claim about where renumbering is safe.

**C3. A correction chain needs a stopping rule; diligence does not provide one (Src; Ded under a stated model; Hyp).** `[CON-0130 · provisional]`
- **The source's stopping rule:** a further observation is "**an explanatory-power improvement, not a defect, and must NOT trigger another correction cycle**", because the corrected text "already establishes the domain distinction that matters". It was "Recorded here so a future corrector does not mistake it for outstanding work." [S0056 L109]
- **The chain that had no such rule (S0164, second case):** each amendment's remedies are reviewed by a fresh process, so "The bound recurs one level down" [S0164 L2512]. The log counts "4,315 lines, 5 amendment commits, 4 independent reviews, 0 lines of implementation" [S0164 L2738]. **The measurer also wrote AMD6.** It says so, and it says the share measurement below is independent of that work while another paragraph is not [S0164 L2752].
- **Model (Ded, a standard result applied):** treat each finding as producing, through its remedy and the next review, a random number of new findings with mean m. Assume the findings act independently, which a real amendment does not guarantee. Then the chain is a Galton–Watson branching process: it ends with probability 1 if and only if m ≤ 1, excluding the case where every finding produces exactly one. If m > 1 it continues for ever with positive probability.
- **Trivial-case test:**
  - m = 0, so no remedy creates a finding: the chain ends after one round;
  - every finding produces exactly one: the chain never ends, although m = 1. This is why that case is excluded.

  Both are the expected results.
- **What a stopping rule does in the model:** a disposition that keeps non-material findings from opening a cycle (§8.5 C5, materiality) lowers m. S0056's rule is one such disposition. Diligence alone, where every finding opens a cycle, sets no bound on m.
- **No m is estimable here.** The counts come from one chain and are purposive: reviewers looked for defects. S0164 counts "17 mechanical of 39 distinct" findings across three reviews [S0164 L2736]. That is the measurer's own count, and no one has checked it. Under Rulebook §4 it is given as a count only: the reviews were not a random sample, so no share or trend is drawn from it. *Hyp:* that a mechanical check run before review lowers m by removing the mechanical part.

**C4. Accepting a verification is not accepting what it verified (Src; an instance of Ch. 5 §5.6).**
- **The act:** "Record acceptance only of the verification evidence. Do not accept the architecture baseline in this act." [S0060 L7]. The record lists what is not accepted: "**The Phase A architecture baseline itself.**" [S0060 L24]
- **The verdict's own scope:** "*"All seven repairs correctly applied"* answers **only** the question this commission asked. **It does not mean the document is ready to enter the canon**" [S0056 L11]. The sequence keeps the two acts apart: accept the verification → accept the baseline [S0056 L157].
- **Int (§5.6):** the object of an act is what the act names. Here there are two objects, the verification evidence and the baseline, and two acts.

**C5. The verifier does not repair: "wrong pen" (Src; an instance of Ch. 1 §1.14.3 and §8.5 C1).**
- S0056 reports two new defects and does not fix them, on "two independent grounds": no grant exists, and "**Wrong pen.** Correcting defects this report found would make this process the producer of that correction", which would bar it from the next verification [S0056 L166].
- S0057 closes its delivery the same way: "This session does not verify its own correction." [S0057 L41]
- **Int:** §1.14.3 forbids the verifier to repair. The source adds the reason as a dynamic: a repair would turn the verifier into the producer for the next round, and so use up the independent verifiers.
