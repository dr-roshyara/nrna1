## 9.5.1 In plain language

A rule can be decided, written down and approved, and the next session still breaks it, because nothing brought the rule to that session. The corpus found this the same hour it recorded a placement rule. Its conclusion: having the rule is not enough; the session that acts must hold the current rule when it starts.

## 9.5.2 Claims and derivations

**C1. The failure case of context assembly: a recorded rule did not reach the actor (Src).** `[CON-0117 · provisional]`
- "**Recording a rule is not sufficient. The responsible session must reliably discover and apply the current rule.**" [S0048 L67]
- The evidence: within the hour, the next lane wrote four documents to the old location, because "the lane's only taught path was the workflow record's `tokenRef`" [S0048 L51].
- **Its home:** Ch. 0 §0.7 assembles a working context "from *live* sources". Here the context was assembled from a **pinned** reference, the `tokenRef` to a superseded path (§1.16.6). The failure is a pin used where a live reference was needed: evidence needs pins, operating rules need resolution at use. That distinction is new here (fork F18).
- The proposed invariant: "*the executing session holds the CURRENT governed rule at START*" [S0091 L188]. **It is degenerate on its own:** a system that never starts a session satisfies it. It needs a must-do partner, that governed work proceeds (a required capability, §9.1 C2).
- *Hyp (n = 2, one line, one day):* a breach at this point looks like a breach by the session, but it is a gap in the system.
- "Current" here means the latest adopted version of a rule, not "not superseded" (§9.4 C3) and not "currently authoritative" (§1.14.1).

**C2. A precedent becomes an implicit rule (Src).**
- The ARB's diagnosis: "*path inheritance became a substitute for architectural placement derivation* — … a locally convenient precedent becomes an implicit rule." [S0048 L12]
- The rule: "Placement is derived from the knowledge subject and governed product/domain — never from the producing session, predecessor path, terminal, or convenience" [S0047 L15]. And "*historical location is evidence; canonical future location is architecture.*" [S0047 L27]
- **Int:** an inherited path is a rule nobody adopted. Under A1 (Ch. 1), an unadopted rule has no standing, but it still governs behaviour. This is Ch. 2 §2.8.7's "specific, consequential value that nobody chose", met as a path.

**C3. Assurance is strong where it is executable and weak where it is prose (Src).**
- "every invariant BC-7 owns is MECHANICALLY enforced; almost every invariant outside BC-7 is DECLARED ONLY … *the platform's assurance is strong exactly where it is executable and weak exactly where it is prose*" [S0091 L192]
- **Int:** a corroboration of §6.4 C3's distinction from another work stream, but the same repository and operator, so not independent support. *Limits:* "every" has a counterexample in the source's own table: I-4, owned by BC-7 and BC-5, is "declared" only [S0091 L182]. And BC-7 is the workflow engine, so part of the claim holds by definition.

**C4. A two-valued response cannot fire where its condition cannot be decided (Src; Ded).** `[CON-0118 · invalid as stated]` (valid in the restricted form)
- Of five conditions (missing, stale, superseded, invalidated, disputed), "The platform can currently establish only one of them." [S0113 L24] "**A tier table cannot assign a response to a condition whose state nothing owns.**" [S0113 L34]
- **Ded (restricted):** a two-valued rule "if c then r, else r′′" cannot fire correctly where c cannot be decided. A rule with an explicit clause for "c unknown" can act there (Ch. 2 §2.8.3, three-valued applicability). Fail-closed and fail-open are such rules, and each needs its own authorizing act (§1.14.5).
- **Homes:** enforceability needs a decidable verdict set (CON-0108); "Missing" asserting absence where only "not looked at" is known (CON-0081). S0113's "Missing" means "no receipt", a third sense beside these.
- **Even "missing" is not decidable** in the source's own terms: a receipt cannot be bound to the session presenting it, because identity binding lies outside the capability [S0113 L44]. So the count is zero of five, not one.

- **Choosing a response chooses a category**: "Selecting HALT or BLOCK for any tier decides the category by consequence", converting distribution "into a control-plane capability" [S0113 L18]. **Int:** a response rule is not neutral about what the capability is; a blocking response makes it a gate (compare CON-0108).

**C5. A blocking gate enabled before anything can pass stops everything; the book's §1.14.5 already answers most of this (Src).**
- "**Every session, for every required context version, is in state `Missing`.**" So "**Any blocking response to `Missing` halts the entire estate on the day it is enabled.**" [S0113 L40–42]
- **Ch. 1 §1.14.5 already holds the answer:** INV-A3 is not adopted ("No adopting act for INV-A3 was located"), and the advisory mode "is the correct mode for **any rule for which no current act authorizes a block**". That is S0113's floor of warn and record. Its exception path, "the **recorded human START act** *is* a compensating control" [S0113 L77], is §1.14.5's confirmation by a person who holds the grant, recorded as an act.
- **The residue:** whether INV-A3, if it were adopted, would cover a missing knowledge receipt. Its domain is the absence of an authority record (assignment, grant, start); a receipt is not one.
- **Int:** a must-never gate over a capability that has produced nothing lets nothing pass. Its must-do half has to exist first (§9.1 C2; C1 above).

## 9.5.4 What does not hold

- **The claim that distribution had no home in the book.** Refuted: Ch. 0 §0.7 and Ch. 1 §1.16.6 are homes; the first search was lexical (review C9, finding 4).
- **CON-0117's order "stated → distributed → applied → enforced".** INVALID: AST-007 enforces on sessions that never received the rule, so enforcement does not presuppose distribution (review C9, verdict on CON-0117).
- **CON-0118, as first stated:** "the rule is inert, whatever r says". INVALID: a rule with a clause for "unknown" acts where c is undecidable (review C9, finding 6).
- **§9.5 C5 as first stated:** it presented INV-A3 as an established rule. Refuted by §1.14.5: no adopting act was found (review C9, finding 5).
