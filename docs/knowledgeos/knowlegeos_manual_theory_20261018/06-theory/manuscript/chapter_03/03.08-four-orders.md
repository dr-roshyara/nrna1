# 3.8 Relations among the kinds: per relation, not one hierarchy

## 3.8.1 In plain language

It is tempting to draw the platform's concepts as one ladder, with purpose at the top and files at the bottom. The corpus tested such a ladder edge by edge and found it unsupported. What the evidence shows is **several relations**, each with its own direction:
- who **justifies** whom;
- who **produces** whom;
- what **realizes** what;
- what **contains** what.

Some questions are about one relation only, such as "who must approve?". Others cross relations, such as "what is affected if this changes?". A single ladder serves neither kind well.

Two further points are less settled than they first look:
- whether **domain** owns nothing, since the evidence for that is only absence;
- **what it means to execute**, since the book uses three senses (fork F11).

Source: S0026 (Ontology Discovery, 2026-08-03, a generated candidate), at the level of **archetypes**, the kinds of §3.3.

## 3.8.2 Definitions

- **Nodes.** The archetypes of §3.3: purpose, domain, capability, process, knowledge, artifact, runtime asset, container (candidate), projection. The relations below also run through nodes that are **not** archetypes: strategy, principle, design policy, evidence [S0026 L83–84]. The node set used here is *A*⁺ = archetypes ∪ {strategy, principle, design policy, evidence}.
- **Relation ρ.** A set of directed, evidenced edges *E*ρ ⊆ *A*⁺ × *A*⁺. Its **reachability** ≤ρ is the reflexive-transitive closure of *E*ρ.
- **The four relations named by the source** [L81–86]:

  | Relation | Meaning | Evidenced edges |
  |---|---|---|
  | **authority** | who justifies whom | purpose → strategy → principle → design policy → capability |
  | **production** | who produces whom | process → knowledge, artifacts, evidence · capability → evidence · container → projection (n=1) |
  | **realization** | concept → executable or persistent form | knowledge → artifact · capability → runtime asset |
  | **containment** | what moves together | container ⊃ artifacts (⊃ spaces: open, H-3) |

## 3.8.3 Claims and derivations

**C1. The proposed ladder is unsupported, not refuted (Src, graded here).**
- The reviewer's ladder: Purpose → Knowledge → Domain → Capability → Process → Runtime → Artifact.
- Tested edge by edge [L66–77]: one edge supported, four unevidenced, one called refuted (domain → capability).
- That "refuted" edge also rests on absence: "no artifact binds a CAP-n to a PD-n". It would be a positive refutation only if anchoring capabilities to design policies were exclusive, and that is not shown.
- The source itself warns that empty cells are "absence-of-evidence, not evidence-of-absence" [L128].
- So the honest verdict is: the ladder is **unsupported**.

**C2. When a relation is an order (Ded).**
- ≤ρ is a partial order exactly when *E*ρ has no cycle of length ≥ 2. Reflexivity and transitivity hold by construction; antisymmetry fails exactly when two distinct nodes reach each other.
- For the listed edges this holds. For **containment** it needs strictly nested spaces (H-3).
- **Reachability is not the relation.** "a produces b, b produces c" does not mean "a produces c". For a relation that is not transitive in meaning, ≤ρ answers "can a's effect reach c?", not "does a produce c?".
- **Not every relation is an order.** S0026's own matrix has two more relations [L36]:
  - **references** is cyclic (knowledge references other knowledge, L42), so it cannot be an order;
  - **constrains** maps to none of the four.
- So "one order per relation" is not automatic. It holds for the four above, on the listed edges.
- **Re-tested on S0021's relations** (contains · references · generates · depends on [S0021 L79–95]): "depends on" has a cycle, **PKS depends on product, and product depends on its PKS** ("guides") [S0021 L92–93], so it is not an order; "references" is cyclic as in S0026; "contains" is an order only if spaces nest strictly (H-3). Acyclicity therefore holds **on S0026's listed edge set only**, not on the relations the corpus uses elsewhere.
- **Mapping §3.6's four relations onto these four:** contains ≈ containment; generates ≈ production (S0021's "generates" also covers space → projection); depends on mixes authority (design policy → principle) with realization (artifact → the knowledge it represents); references maps to none of the four (it is S0026's extra "references" relation). The mapping is the book's (Int).

**C3. What combining the relations does (Ded; one clause H).** `[CON-0064 · validated]` (restated; the typed-union, closure and extension clauses; the impact clause is H)
- **The labelled union**, one graph with typed edges, loses nothing. No listed pair of nodes stands in two relations, so the four orders and one typed graph carry the same information.
- **The unlabelled closure** loses the type. A path *a* → … → *b* that mixes relations has no single meaning, so *a* ≤ *b* no longer says whether *a* justifies, produces, realizes or contains *b*.
- **A total extension** of the combined order exists for the listed edges (and only for them; C2): the union is acyclic, so Szpilrajn's theorem applies. But it **adds** comparisons that no relation supports, for example placing domain above or below projection.
- **What each serves:**
  - per-relation questions ("who must approve?") need the per-relation order;
  - **impact questions** ("in which direction change is allowed to propagate", [L103]): **H, not shown.** The source says the opposite of "the union answers them": the back-edge (evidence → platform) is "visible only when production and authority orders are kept apart" [L103]. Whether impact is reachability over the union depends on each relation's propagation direction, which neither source states. *Stated here, as the book's reading (Int):* a change propagates along **authority** downward (a changed principle can invalidate its design policies and capabilities), along **realization** from concept to form (a changed rule makes its artifacts stale), along **production** from producer to product (a changed process changes what it produces), and along **containment** from container to contents only for what the container's constitution governs. Under that reading, impact is reachability over a union **whose edges are oriented by propagation**, not over the union as listed.
  - A single unlabelled **hierarchy** serves neither: it loses the type and adds false order.
- *Counterexample attempt:* is there a pair in two relations, for example a capability that both is justified by a design policy and produces evidence about it? None is listed. If one appears, the typed graph still loses nothing, but the four separate orders would no longer partition the edges.

**C4. Domain draws boundaries of meaning: proposed, resting on absence.** `[CON-0065 · invalid]`
- The source: "What it does is SCOPE MEANING — it is the archetype of classification, not of ownership." [L49]. Ownership is done by design policies; the source calls this "orthodox Evans, found empirically" [L51].
- **Why invalid:** the row is graded "OBSERVED (by absence)" [L39]. By the absence test of §3.4 and Ch. 1 §1.17.3, not finding an edge is not proof that none exists.
- **A further conflict:** design policies are described as "governance-natured Knowledge" [L51], yet knowledge "may OWN nothing" [L42]. Either design policies are knowledge, and then knowledge owns; or they are outside the archetypes, and then the model cannot express its own central ownership relation.

**C5. What executes: three senses (Open; fork F11).** `[CON-0066 · invalid]` *Developed in §3.9 (Trial T1), where the three senses are traced to a collision of two words.*

| Sense | Where | Statement |
|---|---|---|
| **A** | Ch. 1 §1.5 | whatever executes is a capability ("those execute, so they are capabilities, not knowledge carriers") |
| **B** | S0026 L59 | an executable artifact (a script) is still an artifact; executability is "a REPRESENTATION-dimension property". Only a capability has execution as its "ESSENCE", though "RUNTIME ASSETS execute at the boundary" |
| **C** | S0029 L16, L60 | the capability is an interface (a port); the **adapters** execute |

- **Why CON-0066 is invalid:**
  - it holds only in sense B;
  - it ignores the runtime-asset exception on the same line [L59];
  - its "exactly one" rests on I-11 ("Knowledge does not execute. Capabilities execute.") by stipulation, not by observation.
- **"Execute" is also undefined.** It can mean program text, a running process, or an interpreter evaluating data. Trained weights are evaluated by an engine; they do not run.
- **Consequence for "knowledge does not execute" (CON-0039).**
  - The derivation offered earlier needs "a capability is the only archetype whose essence is execution". That premise comes from I-11, which already contains the conclusion.
  - So the circularity is **not reduced** (SEQ-0012 stays open).
  - What survives is weaker: under sense B, knowledge's **representations** may be executable, and knowledge itself is not a representation (I-1).

**C6. Persistence needs another carrier or a source to rebuild from (Int).**
- The source says "knowledge outlives its artifacts" [L62]. That holds when the knowledge has another carrier (other documents, people, practice) **or** a source from which it can be re-derived.
- It fails when neither exists, for example the only copy of an undocumented decision.
- Trained weights are a borderline case: deleted weights can often be retrained from data and code. Calling learned weights "knowledge" also stretches §3.4's definition.
- So the deletion test of §3.4 shows that knowledge and artifact are **distinct**, not that knowledge **survives**.

**C7. Container: the corpus already holds a test case (Src).**
- The source demotes container to a candidate archetype: generating projections is observed in "exactly ONE space" [L29].
- But a later source (S0029, read in §5.3) records further generated projections: "deterministic PHP projections (dashboard · funnel · lead times · effectiveness)" [S0029 L28]. It also calls itself a projection [S0029 L7].
- Either projection-generating spaces are n > 1, or projections are generated **without** any container, by capabilities with a scope. The second reading supports the source's own refuting branch: container reduces to scope plus boundary (U-ONT-1).
- Undecided here, but no longer unanswerable from the corpus.

**C8. Each relation must enable a decision: proposed, not applied to all.** `[CON-0067 · invalid]`
- "A relation that enables no decision is not admitted, however elegant." [L10]
- Decisions given [L96–103]:
  - *owns* → who must approve;
  - *contains* → what moves together;
  - *realizes* → what survives deleting a file;
  - *constrains* → what blocks;
  - *generates* → what may be rebuilt.
- "References" has none.
- The pairings of relation, decision and "scar" were chosen by the same author who admits the relations, after the fact.

**C9. Other results (Src).** Nature of the archetypes: purpose, domain and knowledge are conceptual; process ("has a clock") and projection (rebuildable) are temporal [L57–62].
