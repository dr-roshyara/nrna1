# 4.2 The improvement cycle: observation, recommendation, decision, outcome, assessment

## 4.2.1 In plain language

S0040 (2026-08-04, a generated candidate) describes how an observation about the code base becomes, step by step, a judgement about whether a rule helped. Each step adds one thing and leaves the earlier steps unchanged. It is a process description, not a new bounded context [S0040 L5].

## 4.2.2 Definitions (Src)

`[CON-0107 · validated]` Stages [S0040 L14–33]:

| Stage | What it is | What it must not contain |
|---|---|---|
| Observation | an instrument saw something | a verdict ("verdict-free") |
| Recommendation | a rule's advice | a decision ("the developer decides, always") |
| Decision | ACCEPTED · IGNORED · DEFERRED, with rationale | — ("IGNORED ends the lifecycle here — that is a COMPLETE path, not a gap") |
| Outcome | what measurably changed | an assessment ("assessment-free") |
| Assessment | SUPPORTED · PARTIALLY_SUPPORTED · NOT_SUPPORTED · INCONCLUSIVE | — |
| Learning (future) | consumes assessments | raw metric deltas ("never raw metric deltas") |

## 4.2.3 Claims and derivations

**C1. Each stage withholds what the next adds (Ded).**
- The table's right-hand column is the cycle's discipline: an observation has no verdict, an outcome no assessment, a recommendation no decision.
- This is §4.1's separation of fact, inference and interpretation (C1), and its rule that patterns are derived and never written into entries (CON-0069), extended to a sequence of stages.
- **A consequence, for projections only:** a projection can be re-derived from the recorded stages without rewriting them; "projections … are read-side interpretations and never write back" [S0040 L38]. A decision is a human act and an outcome a measurement; neither can be derived from earlier stages.

**C2. Non-decisions and inconclusive results are data, not gaps (Src; Int).**
- "A recommendation with no decision is meaningful operational data." [S0040 L39]; "INCONCLUSIVE is a first-class verdict; IGNORED is closure, not a gap" [S0040 L40].
- **Int, for Ch. 5:** in the gap theory (§5.4), an unmet requirement is a gap. Here an ignored recommendation is not: it is a **closed** path. *Scope:* a recommendation is advisory, not a requirement. The analogy holds only where an advisory item is tracked like a requirement: there, "not done" splits into "decided against" (closure) and "not yet decided" (open).

**C3. "Projections never infer missing data" (Src; Ded).**
- "Sub-week windows withhold rates" [S0040 L40]: below a minimum sample, no rate is reported. This is a fixed-class, fixed-unit rule in the sense of CON-0070, with a minimum size added.

**C4. The cycle claims to be falsifiable end to end (Src).**
- "it can show that a rule never helps, that recommendations go undecided, or that KnowledgeOS itself changes nothing" [S0040 L41].
- **Limit:** S0040 describes the process; it reports no run. Whether the cycle has produced an assessment is not shown here. The evidence base it names (RD-1 … RD-7) is not yet read.

**C5. Deferral by watch criteria (Src).**
- Whether these concepts become a bounded context is left to "The recorded watch criteria — not preference" [S0040 L50] after about six months. This resembles deferral with an activation criterion (Ch. 5 §5.3, CON-0077), but the seven criteria have no threshold (how many must hold?), so the activation is not yet pre-specified.
