## 2.6 Scale: partitioning must be sound

**The idea.** Comparing every pair of n rules costs O(n²), about 50 million comparisons at 10,000 rules (and pairs are not enough: §2.3 (d)). RM proposes to **partition first** (by subject, scope, domain, technology) and compare only within partitions that can overlap [RM L259–267]. **Src.**

**Development (Ded).** Partitioning is safe only if it is **sound**: whenever a set of rules *could* all apply at some (c, t), they must land in a common partition. If partition keys are coarser or differently organised than applicability, conflicts across partitions are silently missed. That would turn "no conflict found" into a false "consistent", the error RM itself forbids [RM L191].

Requirement (corrected after audit L-11). Being "a function of applicability" is **neither sufficient nor necessary**: a hash of the predicate text is such a function but separates overlapping rules. The sound condition is **over-approximation**:

> choose a projection π shared by all rules (e.g. onto subjects, or onto validity time). Each rule's key must **contain** the projection of its whole applicability region: key(r) ⊇ π(Region(r)). Every pair whose keys intersect is compared.

Then *non-empty overlap ⇒ overlapping projections ⇒ intersecting keys*, so no conflicting pair is missed. π must be a function of the context and time (c, t) only, as applicability is (§2.3 (d)). Under SC-2, a rule that is unspecified (⊥) on the projected attribute must be placed in **every** partition, or its pairs reported UNKNOWN.

**Re-run on sets (Ded; §2.3 (d)).** Conflict is a property of rule sets, so the unit of comparison must be the partition, not the pair. Let each key be a set of labels in π's range, and let a partition be all rules whose keys contain a given label. If a set of rules is in conflict, all of its rules apply at some (c, t). The label π(c, t) is then in every member's key (over-approximation), so the whole set lies in one partition. **So over-approximation stays sound for sets, provided each partition is analysed point by point**: at each (c, t), the rules of the partition that apply there are tested together (§2.3 (d)). Testing "the whole partition at once" in the sense of (d)'s definition would need every rule of the partition to apply at one point, and would miss conflicting subsets. Comparing every pair whose keys intersect is **not** enough either: the three rules of §2.3 (d) pass it. *(Theory turn 5, §9.14 R5 (b): it **is** enough when the admitted rule language's effect class has Helly number at most 2, with single rules and pairs tested point by point.)*

**Sound is not useful (Ded).** A partition with one block is sound: every rule is compared with every other. It gives no saving. Soundness says that no conflict is missed; how much the partition saves is a separate requirement (§2.3 (e)).
