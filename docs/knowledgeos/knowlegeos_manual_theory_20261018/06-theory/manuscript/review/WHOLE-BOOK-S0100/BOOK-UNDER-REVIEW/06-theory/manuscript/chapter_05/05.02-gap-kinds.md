# 5.2 What closes a gap: modelling, a ruling, or use

## In plain language

When a platform falls short of a goal, three very different things can be missing:
- **a place in the architecture**, which only design work can provide;
- **a decision**, which only an authority can make;
- **use**, which only doing the work can supply.

Treating one kind as another wastes effort. Most often, people design more when the real need is to use what already exists. The corpus's Architecture Fitness Assessment (S0024, 2026-08-02, generated) makes this its main contribution: "THREE KINDS OF GAP ARE BEING CONFLATED — separating them is this assessment's main contribution" [S0024 L16; E-S0024 Q5].

## The three kinds `[CON-0053 · invalid]` (Src)

| Kind | What is missing | Closed by |
|---|---|---|
| **architectural** | "a responsibility the architecture has no place for" [L20] | modelling |
| **governance** | "a clause that couples a reusable thing to one product" [L21] | a ruling |
| **evidence** | "the thing exists but has never been exercised" [L22] | "only by doing it" |

The source applies this to the question "Does today's architecture support `knowledgeos init`?" [L10]. It finds one architectural gap (genesis), one governance gap (the clause SD-1) and several evidence gaps. Its counts disagree: "4 evidence" in the summary [L24] but "3 evidence gaps" in the verdict [L199], with three listed (E-1 … E-3 [L177–181]).

Verdict: "The architecture is not underdesigned. It is under-exercised — and nowhere enforcing." [L202]. The second half was later corrected by the author (Ch. 2 §2.10, RC-60).

## Why this belongs in a chapter on decisions (Int)

The three kinds line up with the book's account of how things change (Ch. 1 §1.6, RC-37a):
- a **governance** gap is closed by an **act** (granted);
- an **evidence** gap is closed by **use** (earned), which no act can decree;
- an **architectural** gap is closed by **design work**, which is neither an act nor evidence. Its result still needs an act to become standing.

So the classification tells the decision-maker **which kind of decision is needed at all**. An evidence gap cannot be closed by a ruling. A governance gap cannot be closed by more work.

**Counterexample attempt:** a gap can need more than one closure. Genesis needs modelling (a place for the first decision) **and** a governance rule (the proposed clause). The source classifies it by its first need: there is no place to put it. *(Corrected after review C4 F-08; SEQ-0014.)* The earlier rescue "by primary closure" is withdrawn: no criterion says which need is primary. The paradigm case is classified differently by the sources: S0024 calls genesis architectural ("no place in the architecture to put it" [L155]) yet sizes it as "one clause" [L162], and S0025 lists it under **governance** [S0025 L155], with existing homes for the clause [S0025 L139]. S0024 also marks "the gap is not architecture, it's evidence" CONFIRMED [L24] while counting one architectural gap. So the three kinds are useful as a vocabulary, but whether each gap has a single kind is not shown.

## The cases in the source

- **Genesis (architectural).** The platform governs change, not beginnings: there is no route from an idea to the first decision [L36, L159–162]. See Ch. 1 (root acts), RC-59; `[CON-0054 · invalid]` (TODO T1-17).
- **SD-1 (governance).** Is SD-1 a product binding or a platform rule? "one clause, one document, and either answer unblocks the entire Strategic DDD method" [L167–171]. It is the highest-leverage single act, though not the architectural gap: "Nothing needs modelling — something needs ruling" [L172].
- **Evidence gaps.** Each closes only when something is done once: one PKS produced ("by a person is fine; that is a valid implementation"), one harvest that changes one platform rule, one candidate that climbs the promotion ladder [L177–181].

## Automating too early (Src, Repeat)

*Corrected by a later source:* two days later the corpus judged this gate "OVER-APPLIED" to deterministic automation, and built `init` [S0029 L43]. The two judgments concern different scopes: S0024/S0025 the bootstrap of new products, S0029 automation within this repository; the n ≥ 2 rule governs claims of reuse (§5.3 C2, later in this chapter).

`knowledgeos init` "is the automation of a process that has been performed once, by a person, with the sequence supplied externally" [L38; Q13]. The rule it breaks is the corpus's n ≥ 2 rule for structure. Its wordings differ: Ch. 1 §1.8 (LA-4) has "only at n ≥ 2, exercised by another"; S0024's P3 has "n ≥ 2 with a repeatable pattern extracted" [L38]. The source adds one precision: "A specification is not an implementation." [L98].
