## 9.7.1 In plain language

To say whether a piece of knowledge counts today, something has to compute it from the record of acts. The three questions get these answers:
- **Necessary?** Some evaluator is necessary, given the Principal's act that the kernel must answer such questions.
- **Must the kernel provide it?** Several applications agree on standing if they use the same rule, the same values for the policy choices that matter, and the same order of acts. With different values for some choices (the ending policy, scope comparison, conditional acts, unevidenced acts) they disagree on some records, not on all. The book's model orders acts by when they happened, and uses one global sequence only to break ties; where act times are missing, as in this estate, that sequence is a uniqueness someone must keep. Where the rule, the choices and the order are kept is not shown; what is shown is that each needs a common, versioned value.
- **Can applications provide it safely?** Not yet. The model is not fully defined, so there is no function to delegate. Once it is, an application could compute it against a declared cut of the record, with a stored result treated as inert.

The computation also needs inputs the present record does not have: when each act happened and was recorded, how long each grant was valid, how far its scope reached, and who the root of authority is.

## 9.7.2 Definitions

- **CE(c, t; θ, R):** the value of currently-authoritative(c, t) of §1.14.1, in {T, F, U}, with:
  - the record R as input;
  - the parameter vector θ = (ρ, κ, χ, ω, σ, π, υ, P, ι).

  Some parameters are policy: P (the ending policy, reserved decision 1), ρ (the record view, reserved decision 2) and υ (reserved decision 6).
- **Agreement:** two applications agree on standing if, for every item c, scope x, time t **and temporal axis**, they return the same headline. *(The axis was added after review TT2.)*
- **"CE" names two things, kept apart after review TT2:** the **role** of an evaluator, some function from records to standing; and **§1.14.1's function**, which is not yet fully defined (formal defects 1, 5, and the undefined covers(B, x) and actor–holder link).
- **Three temporal questions (Src, S2775):** "What contracts were active on 1 June?" is ValidAt; "What contracts did we believe were active on 1 June?" is KnownStateAsOf; "What do we know today about which contracts were active on 1 June?" is CurrentKnowledgeAbout. "These are three different queries." [S2775 L1121–1149]

## 9.7.3 Analysis 1: is CE necessary?

**Assumptions:** the Principal's act, R_s ∈ Req (§9.6.6a); N1 and N2 of §9.6.3.

**Derivation:** by §9.6.3 steps 2–3, R_s needs a registration of acts (CR-a) **and** a derivation of standing from them (§1.14.1, current authority is derived). The derivation is CE. **So CE is necessary** (Ded, given the act).

**What CE needs as input, and what the record lacks (Src; Ded):**

| Input CE uses (§1.14.1) | In the estate's record? | Evidence |
|---|---|---|
| act time t_x | **no:** "Only 2 of 210 transitions carry any `date` field" | [S0128 L49] |
| record position s_x, **one global, gap-free sequence** (§1.14.1) | **no:** `seq` is dense "in every one of the 16 records", that is, per record, not global | [S0128 L48] |
| recording time (a time for each position) | **no:** positions only | §1.14.1 formal defect 4 |
| a grant's act window (start, end, endings) | partly: validity fields 0/144; endings rare (REVOKED 1, CONSUMED 1) | §1.13.2 recount |
| coverage of scope | **no:** the scope is an opaque string matched by equality | §9.6.3 step 4 |
| who issued a grant, and under which authority (delegation) | **no:** delegation fields 0/144 | §1.13.2; formal defect 2 of §1.14.1 |
| adoption acts of knowledge items, with their cited bases | **no:** the measured records are work-item and grant records; "no rule cites the grant" (AMS L200–206, §1.14.1) | §1.14.1; S0128 L45 |
| the root of authority (who the root is) | **no:** a governance fact to be recorded (§1.14.1, Root acts) | §1.14.1 |
| the coverage relation covers(B, x) and the actor–holder link | **undefined** in the model itself | §1.14.1 formal defect 5 |

**Result:** an evaluator is necessary. On the record as it stands, §1.14.1's CE would be **uninformative**, mostly U or F, because act times, recording times, validity periods, scope coverage, delegation, adoptions and the root are missing. *(Corrected after review TT2: CE is three-valued and total by design, so "not computable" was the wrong word.)* S0128 warns against the obvious repair: on import, "commit times become the only time evidence — and they would be IMPORT times, not act times … Do not let an import be mistaken for a chronology" [S0128 L171].

**What a reviewer would need to challenge it:** a reading of R_s that needs no derivation (e.g. standing stored per item), which §1.14.1 rejects; or an input in the table that is in fact recorded.

## 9.7.4 Analysis 2: must the kernel provide CE?

**Assumptions:**
- K3: several independent applications (the Principal's act).
- **K5 (a stipulation, restated after review TT2): standing has one answer per (item, scope, time, axis) across applications**, where the scope does not include the asking application. It is **not** "the reading" of the central question. RESEARCH-PURPOSE glosses "valid" otherwise, and K5 is a further stipulation for the Principal to confirm or reject. A second hidden condition: **one root** of authority per estate (§1.14.1, Root acts). With one root per application, K5 fails trivially.

**Derivation, as corrected:**
1. **Same inputs, same answer, where defined (a tautology).** For a fixed record R, fixed θ and a fixed order of acts, CE returns one value where its least fixed point exists. The substantive premise is that two applications hold **the same R in the same order**, and that is not given.
2. **Where the order of acts is a uniqueness (corrected after review TT2, scoped after review C15).** §1.14.1 orders acts by "the **total order** (*t*ₓ, *s*ₓ): by act time, and by record position when act times are equal", with s_x a position in "the one global, gap-free sequence of record entries" (§1.14.1). So **act time comes first**; the global position only breaks ties. The estate's `seq` is per record, and a set union of several records keeps the acts but not their positions.
   - **Where act times are present, distinct and trusted,** a union of per-record logs is ordered by act time, and CE is a function of it. No serialization point is needed.
   - **Where act times are absent, tied or untrusted,** the global position decides. The reviewer's case of TT2 applies there: one record holding a grant's issue and its revocation, and a second record holding an act x made under the grant, admit three interleavings, which give authorized(x) = F, T, F. Then the global position is a uniqueness that needs a serialization point (U, §1.16.7). Act times are themselves claims in records (§1.12), so "trusted" is not free.
   - **The estate is in the second case:** "Only 2 of 210 transitions carry any `date` field" (input table above). The model is not.
   - **Fork F26, with three options:** (a) a global order of positions, with one serialization point, so that K4 = yes for positions; (b) CE redefined over a **partial order** that answers U where acts are incomparable, as S2775 requires: "unknown order must remain unknown" (S2775 L1650–1688, in meaning); (c) act-time order with a tie rule that needs no serialization point, for example a deterministic rule over the record identity and the per-record position. Option (c) needs act times that are present and trusted.
3. **Different θ gives disagreement on some possible record.** That is an existential claim, shown by the book's cases: P (case 4, a consumed grant), κ (case 9), σ (case 5), υ (case 15). For ρ (case 10) it holds **only if ρ is a policy**. Read with S2775's three queries, ρ = at-the-time and ρ = now are close to two **questions** (what we believed then, what we know now about then), and then case 10 is not a disagreement but two answers to two questions. **Fork F27:** is ρ an organisational policy or a parameter of each query? §1.14.1's safeguard 3 treats it as policy; S2775 treats the axes as queries. Reserved decision 2 stays the Principal's.
4. **What must be one (corrected; finding 5):** under K5, each application must use the same definition of CE, the same coverage relation, the same root and the same policy values. "The kernel must own them" does not follow. **What follows is a common, versioned value** for each, not a kernel home, and not even one home: identical pinned copies would also agree (§6.6 C1's restricted form; §1.16.6). One authoritative home follows only with the further premise of §1.10, one authoritative home per rule *(scoped after review C15)*. Those values are acts (A1), and their record is the place TT1 found delegable. **And they change:** which θ applies to an act, the θ at t_x, at t, or now, is the contract-time question (S2775 L771–803; §1.16.6, pinning of the deciding logic). CE's own definition must also be versioned (S0916 L1390–1416, in meaning).
5. **Execution is not yet delegable (corrected; TT2 critical finding 2).** §1.14.1's CE is not yet defined for **any** θ: covers(B, x) and the actor–holder link are undefined, and σ = conditional recurses outside the fixed point. Under υ = "does not count until evidenced", mutual annulment oscillates (U, U) → (T, T) → (F, F) → (T, T) …, so no least fixed point exists. A function that does not exist cannot be delegated or checked by recomputation.

**Result of Analysis 2, restated:** whether the kernel must provide the evaluator **is not decided by this analysis**. It depends on:
- F26 (a global order, a partial order, or act-time order with a tie rule);
- K5 (for the Principal);
- the repair of CE's definition.

What is shown is narrower. Under K3 and K5, the definition, the coverage relation, the root and the policy values each need **a common, versioned value**; with §1.10's premise, one authoritative, versioned home.

**What a reviewer would need to challenge it:** a merge of per-record logs that fixes CE's order without a serialization point; or a definition of CE that is total and monotone for all θ.

## 9.7.5 Analysis 3: can applications compute CE without violating the invariants?

**Derivation, invariant by invariant:**

| Invariant | Holds if an application computes CE? | Why |
|---|---|---|
| A1 (only an act confers standing) | yes | CE reads acts; it performs none |
| ARCH-INV-1 (the recorder never grants) | yes, if the evaluator is not the recorder | §9.6.2: the recorder may not evaluate; a separate evaluator may |
| P-8 and CON-0134 (a derived representation never gains authority; derived state is never stored) | **only if** CE's output is not stored as standing | a stored result is "a second truth able to drift" [S0071 L208]; the stored value must be inert (§8.8 C1) |
| producer ≠ verifier (§1.14.3) | **for execution only, once CE is defined** | re-running a defined CE on the same cut checks the execution, not the definition; it rests on §8.6 C5, itself PROVISIONAL *(restated after review TT2)* |
| revocation is not retroactive (S1414's I53; §1.14.1's premise) | it depends on P | S1414: "Authority changes affect future authorization but do not retroactively invalidate historically authorized transitions unless an explicit domain rule requires it" [S1414 L1162–1165]. In CE that is P not containing revocation for that kind |

**Result (Ded, restated after review TT2):** once CE is defined (Analysis 2, step 5), applications may compute it, provided that:
1. its definition, coverage relation, root and policy values are the common, versioned values of Analysis 2, step 4;
2. its output is a **derived, inert** value, never stored as standing;
3. **it is computed against a declared cut of the record, CE(c, t; θ, R≤s), with completeness up to the cut checkable.** CE is not monotone in R: a later revocation turns T into F, so a stale or partial copy returns T where F or U is due. That breaks INV-A3 and K5. And dense `seq` is no proof of completeness (§9.6.5);
4. **a must-do: soundness and completeness relative to the evidenced acts.** A constant evaluator that always answers U meets the first three conditions and every row of the table. An implementation must conform to the defined CE: it must answer T wherever the defined CE answers T on the evidenced acts *(rephrased after review C15, so that it is not circular)*.

The one failure that delegation itself would cause is a stored result read as authority. S0128 names the failure from the other side: if the record is lost, "prose becomes authoritative by default — authority drift by attrition" [S0128 L123].

**What a reviewer would need to challenge it:** an invariant broken by an application that computes CE under these four conditions.

## 9.7.6 Agreement with the brainstorm line (Src; Int; a second line)

- **C1. Authority is scoped and temporal:** authority is modelled as Authority(a, C, O, t) (S1414 L411, in meaning), it "can expire" [S1414 L463], and a grant is "not merely an RBAC table" [S1414 L506] but "a governed fact" [S1414 L508]. This is §1.6's act × scope × time and §1.14.1's act window.
- **C2. Authority is necessary, not sufficient:** a valid transition needs authorization, evidence, preconditions and invariant preservation; "Authority is necessary but not sufficient." [S1414 L340–375]. This is §1.17.2 (valid is not well-founded) as a transition rule.
- **C3. A third time:** valid time, transaction time and knowledge time (S0916 L77–87, in meaning), where an assertion "may exist in the system but not yet be accepted as knowledge" [S0916 L216]. Also: "Historical decisions must be evaluated against the historical epistemic state." [S0916 L1699]. **Corrected after review TT2:** acceptance, where it is the adoption act, already has its act time t_x in §1.14.1. What §1.14.1 lacks is a **recording time**: it has positions but no times, and "what did we believe on 1 June?" needs a map from time to position. Whether S0916's "acceptance" is an adoption or an evidential act is not settled here; if it is evidential, mapping it to t_x would merge the two engines §1.6 keeps apart (RC-37a).
- **C4. Delegation cannot exceed its source:** I52, "Delegated authority must not exceed the scope, duration, or nature of the authority from which it derives." [S1414 L614–616]. This is §1.13.3(d), and it bears on formal defect 2 (issuance and delegation unchecked).
- **C5. Reconstruction needs preserved times:** S2775's reconstruction theorem assumes "each relevant event has preserved temporal semantics" [S2775 L1602] and "transaction/knowledge time is preserved" [S2775 L1603]. The estate's record does not meet the first assumption (Analysis 1). *Corrected after review TT2:* the theorem gives sufficient conditions, so failing one does not show reconstruction impossible. The conclusion that historical standing here cannot be reconstructed from the record alone rests on Analysis 1's input table, not on the theorem.

## 9.7.7 Results, prepared (nothing reserved is decided; restated after review TT2)

1. **An evaluator of standing is necessary** (given the Principal's act).
2. **§1.14.1's CE is not yet a function** for any θ: covers, the actor–holder link and a monotone υ are missing, and σ recurses. Until these are defined, neither its placement nor its delegation can be decided.
3. **CE's order is a uniqueness only where act times are absent, tied or untrusted** (F26; scoped after review C15). Then it needs one global sequence, which reopens §9.6.6a items 3–4, or a partial order. With present, trusted act times, act-time order with a tie rule suffices. The estate is in the first case.
4. **Under K3 and K5,** the definition, coverage relation, root and policy values each need a common, versioned value; one authoritative home follows only with §1.10's premise. That any home is the kernel is **not** shown.
5. **Delegated computation needs a declared cut and a must-do** (soundness and completeness relative to the evidenced acts).
6. **On the present record, CE would be uninformative.** It needs act and recording times, validity, endings, comparable scope, delegation, adoptions and the root.

**For the Principal:**
- **K5:** is standing one answer per (item, scope, time, axis) across applications?
- **F27:** is the record view ρ an organisational policy or a parameter of each query? (Reserved decision 2.)

## 9.7.9 What does not hold (first version, refuted at review TT2)

- **"The record input must be shared or mergeable"** (old step 5), and §9.6.6a's "recording is delegable by set union". CE's global position makes order a uniqueness; a union of per-record logs does not fix it (TT2 critical finding 1).
- **"Execution is delegable … deterministic … recompute to check"** (old step 4; result 3). CE is not yet defined for any θ (TT2 critical finding 2).
- **"The kernel must own CE's definition and its policy parameters."** A non sequitur: one value implies one authoritative home, not a kernel home (finding 5). CON-0142 is INVALID as stated.
- **K5 as "the reading of the central question"**, and K5 without a time axis (finding 3).
- **Case 10 as a plain disagreement.** It holds only if ρ is a policy (finding 3; F27).
- **"§1.14.1 lacks an acceptance time".** It lacks a recording time (finding 4).
- **"seq: yes"** in the input table. It is per record, not global (finding 6).
- **"Not computable" for CE on this record.** CE would be uninformative, not uncomputable (finding 10).
- **C5's inference from S2775's theorem.** Denying the antecedent (finding 9).
- **"Producer ≠ verifier: yes, by recomputation"** without qualification. Recomputation checks execution only, and CE is not yet defined (appendix).
- **"Different policies disagree"** (plain language). They disagree on some possible records (appendix).

*Settled after review C15 (Rulebook step 9, the review of this settlement):*
- **"The order is a uniqueness"** without scope (old step 2, result 3, F26 with two options). §1.14.1 orders by act time first; the global position only breaks ties. A uniqueness only where act times are absent, tied or untrusted; F26 gains option (c).
- **"One authoritative, versioned home"** (step 4, result 4, CON-0142 restated). Agreement needs a common value; one home needs §1.10's premise.
- **"Agree only if they use the same rule, the same policy choices and the same order"** (plain language). Only the choices shown to matter, and only orders that differ on comparable acts.
