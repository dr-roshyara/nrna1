# 4. CRITICAL DISTINCTION: DEFINITION ≠ DERIVATION ≠ TEST

For every important proposition explicitly answer four separate questions.

### A. Is the definition clear?

Check:

* every symbol defined?
* domain defined?
* codomain defined?
* type defined?
* scope defined?
* time index defined?
* context defined?
* provenance defined?
* units/scale defined where relevant?
* ambiguity absent?
* overloaded notation absent?

A mathematically elegant expression is NOT a valid definition merely because it looks formal.

### B. Does the derivation follow?

Reconstruct every claimed implication.

For:

```
A → B → C
```

verify whether:

```
A ⊢ B
B ⊢ C
```

actually follows.

If an assumption is needed, expose it explicitly.

Never silently repair the derivation.

### C. Is the construct computable?

Ask:

> Given real admissible inputs, can KnowledgeOS actually calculate the claimed object?

For every computational definition identify:

* input representation
* required data
* algorithm
* output representation
* termination
* determinism/non-determinism
* complexity
* missing parameters
* inaccessible quantities
* undecidable cases

Distinguish:

`FORMALLY_DEFINED`

from

`IMPLEMENTABLE`

from

`COMPUTATIONALLY_FEASIBLE`.

### D. Is it tested?

A definition or theorem being testable does NOT mean it has been tested.

Distinguish:

```
TESTABLE
TEST DESIGNED
TEST EXECUTED
TEST PASSED
TEST FAILED
```

Never convert a conceptual PASS into an empirical PASS.

The previous corpus has already exposed this problem: numerous PASS labels were not backed by software execution. Continue enforcing this discipline.
