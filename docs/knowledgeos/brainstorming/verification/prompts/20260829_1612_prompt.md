# 9. VERIFY COMPUTABILITY

For every important mathematical object determine:

### Can it be computed?

Distinguish:

1. mathematically defined
2. theoretically computable
3. computationally tractable
4. practically computable
5. implemented
6. experimentally executed

These are NOT equivalent.

For example:

`Defined ≠ Computable`

`Computable ≠ Implemented`

`Implemented ≠ Executed`

`Executed ≠ Mathematically Validated`

For each computational claim identify the algorithm, required inputs, complexity and termination assumptions.

# 15. SPECIAL RULE FOR "LATER DOCUMENT RESOLVES EARLIER QUESTION"

Do not infer resolution from similarity.

A later document resolves an earlier question only if:

1. it addresses the same question,
2. it provides a new definition/argument/result,
3. the new result actually answers the earlier problem,
4. no later contradiction reopens it.

Otherwise classify:

`APPARENTLY_RESOLVED`
or
`UNRESOLVED`.
