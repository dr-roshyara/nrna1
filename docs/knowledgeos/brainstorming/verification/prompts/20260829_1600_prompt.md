# 5. COMPUTABILITY TEST — CRITICAL

For every mathematical definition, ask:

> **Can this definition actually be computed?**

Do not accept "computable" merely because an algorithm is described informally.

For each function/operator:

```text
f : A → B
```

verify:

* Is `A` defined?
* Is `B` defined?
* Can valid elements of `A` be represented?
* Can the input be obtained from KnowledgeOS?
* Is `f` total or partial?
* If partial, when is it undefined?
* Are the preconditions decidable?
* Is the result finite/representable?
* Is the algorithm specified?
* Does the algorithm terminate?
* What is its complexity?
* Is exact computation possible?
* Is approximation required?
* If approximation is required, what error guarantee exists?
* Does the implementation correspond to the mathematical definition?

If a quantity is defined mathematically but cannot be obtained from available KnowledgeOS data, mark:

`MATHEMATICALLY DEFINED / OPERATIONALLY UNCOMPUTABLE`

rather than pretending that it is implemented.
