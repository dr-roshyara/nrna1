# MD-045 §3 — The Capability Identity/Granularity Boundary (why Phase C stops here)

## The source's own central finding

File 8 (`021025`), the chain's own most consequential document, states the problem directly:

> Suppose `C = {Observe, Interpret, Determine}`. Now someone defines `Interpret' = {Observe,
> Interpret}`. Suddenly `Determine` might appear irreducible under one decomposition and derivable
> under another. This means minimality can depend on the **granularity of the capability
> vocabulary**. That is exactly the problem we encountered with the 13/12/8 operator cycles.
> Therefore: **minimality is meaningless until semantic granularity is controlled.**

File 9 (`021056`) softens the absolute wording ("relative, not meaningless") but does not resolve the
underlying problem — it explicitly declines to commit to a specific capability representation
(`c=(I_c,O_c,Γ_c,ℐ_c)`) as *the* definition, precisely because doing so would smuggle in an arbitrary
choice disguised as a foundational fact.

File 10 (`021125`), the chain's own final position, converts this into an explicit, binding
methodological rule for whoever executes the next artifact:

> **"If any definition depends on the arbitrary naming or decomposition of the candidate
> capabilities, stop and expose the circularity rather than proceeding."**

## Why this directly determines the outcome of MD-045's own Phase C

Phase C's task — instantiate the real 13-capability universe (`Observe, Interpret, Represent,
Relate, Discriminate, Qualify, Hypothesize, DetectGap, Challenge, Validate, Revise, Determine,
Select`) and test whether `DetectGap` is genuinely derivable and `Qualify` genuinely necessary —
**cannot be attempted without first choosing a capability-identity/granularity convention**, because
"is `DetectGap` derivable from the others" is exactly the kind of judgment file 8 shows can flip
depending on how the 13 names are individually delimited (e.g., if some other candidate implicitly
absorbs `DetectGap`'s function under a different naming, the earlier "derivable" finding would not
hold). **Choosing such a convention would be exactly the "new modelling choice" this study's own
resolution (per `00_index.md`) — and the source's own explicit rule — forbid introducing and then
testing as if it settled anything.**

**Therefore: Phase C stops here, per the Hard Stop clause, rather than proceeding under an invented
convention.** The smallest mathematically necessary missing definition, stated precisely and not
supplied: **a corpus-grounded, granularity-independent criterion for when two candidate capability
descriptions denote the same semantic capability** (`c_1 ≡_𝔠 c_2`), prior to and independent of any
choice of names or decomposition. No such criterion exists anywhere in the corpus this reconstruction
has examined.

## Consequence for the "eight tested variants" / `DetectGap`/`Qualify` finding cited in MD-044

MD-044's own `03_...md` flagged a "STRUCTURAL CORRESPONDENCE CANDIDATE, not confirmed" resonance
between this chain's `DetectGap`-derivable/`Qualify`-needed finding and F3's (kernel-reduction's) own
result. **This finding must now be read with an explicit caveat the earlier study did not have**:
the source material's own later self-critique (file 8) shows that this specific finding is itself
granularity-dependent — it holds under the "eight tested variants" and the toy 3-capability
instantiation's own particular naming convention, but the source's own final position explicitly
warns that a different, equally legitimate decomposition could produce a different verdict. **This
does not overturn MD-044's classification** (still "candidate, not confirmed") — it strengthens the
caution already applied, with a source-internal reason rather than only this reconstruction's own
external caution.
