# Phase 5G — K-1 / K-1-B Independent Identity Audit

## The user's own sharpened mathematical point, taken seriously

*"If they really are the same authored construction, same eight-tuple, same provenance package, and
no transformation is required, then the stronger conclusion may actually be DEMONSTRATED IDENTITY, not
merely formal equivalence. Formal equivalence normally means two distinct representations are shown to
preserve the relevant mathematical structure. If there aren't two distinct objects, there is nothing
to establish an isomorphism between."*

This is mathematically correct, and Phase 5F's own "FORMAL EQUIVALENCE" verdict is now tested against
it directly.

## What evidence actually exists (re-verified, not merely re-asserted)

1. **No transformation, mapping, or distinctness is claimed anywhere between D285-1's K-1 and
   D285-7's K-1.** Both state, verbatim: *"K-1 `K_t`, 8 primitives (ratified)."* Neither document
   frames the other's K-1 as a "different representation of the same concept" — the defining feature
   of a formal-equivalence case (two distinct representations + a preserving map).
2. **No explicit citation of "D285-1" by name was found in D285-6 or D285-7** (checked this phase via
   direct grep — zero hits). **One explicit citation was found**: D285-7 §"The consequence that
   matters" states *"Under the projection result (D285-6), this matrix is not a menu — it is a
   layering"* — proving D285-7 is aware of, and builds on, D285-6 by name. This establishes the
   package is **not** independently authored in isolation (documents within it do read and build on
   each other), even though the specific K-1 definition is not re-cited by name each time it recurs.
3. **The template/dating evidence** (`format: 7-section D285-x template (HPA review, 2026-08-31)`,
   identical across all three files) is **consistent with, but does not alone prove**, single
   coordinated authorship — per the user's own explicit warning not to infer identity from label/
   package/same-day evidence alone.

## Applying the user's own required test (§4 of the authorization)

**Option A — one research object cited twice.** **Option B — two distinct objects with identical
structure.** **Option C — formally equivalent only.** **Option D — UNRESOLVED.**

The decisive discriminator, per the user's own framing, is: *"Formal equivalence requires two DISTINCT
representations connected by a structure-preserving mapping. If no such distinctness or mapping is
even claimed, there is nothing to be 'equivalent' to — the correct report is that there is one
referent."*

**Applying this literally**: no document anywhere proposes that D285-7's K-1 is a *different
representation* of D285-1's K-1 requiring translation. Both use the identical notation, the identical
8-primitive list, in the identical order, with compatible (not contradictory) authority claims,
within a package that is demonstrably internally aware of itself (the D285-7→D285-6 citation).
**There is no second, distinct representation for a formal-equivalence relationship to hold between.**

## Verdict

**Option A — one research object, cited twice, within one authored package.** Reported as
**DEMONSTRATED IDENTITY**, explicitly qualified: this is identity **within the scope of the evidence
this reconstruction has examined** (textual reuse, no claimed transformation, demonstrated package
self-awareness via the D285-7→D285-6 citation) — **not** an externally-constructed referent-identity
proof (e.g., an author's own explicit statement "D285-7's K-1 IS D285-1's K-1," which was not found).
This is a **strengthening** of Phase 5F's own "formal equivalence" verdict, arrived at by applying the
user's own sharper distinction, not by re-asserting Phase 5F's reasoning.

## What would falsify this

Any future-discovered document showing D285-7's (or D285-6's) "K-1" was independently derived without
reference to D285-1, or explicitly distinguishing the two as different constructions, would immediately
downgrade this back to `UNRESOLVED` or lower. None such was found this phase.
