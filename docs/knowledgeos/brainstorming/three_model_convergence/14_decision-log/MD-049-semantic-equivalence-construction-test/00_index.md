# MD-049 — Controlled Semantic-Equivalence Construction Test

**Status: EXECUTED, 2026-09-09.**

## Purpose

MD-048 confirmed the breakthrough does not supply MinKer's missing semantic basis. Rather than search
further or invent a capability-identity theory, this phase tests directly: can the corpus's own
already-defined trace/behavior/simulation machinery be used to test whether pre-registered,
differently-represented Kernel candidates are semantically equivalent — without requiring identical
names, decomposition, or vocabulary?

## Methodological note, stated before executing (not a disagreement)

Based on MD-044/045's own dependency-table findings, this study was expected to hit "insufficiently
specified" quickly, since none of the candidate objects had ever been described anywhere in the
corpus using MinKer's own Trace/Obs vocabulary. This was verified directly, not assumed — see
`02_...md`. The prediction held, but the study was executed in full regardless, per the standing
"let the evidence decide" discipline.

## Pre-registered diagnostic pairs (before any comparison attempted)

Selected from MD-044–048's own already-established candidate inventory, per the user's own naming:

- **F1** — the frozen governance K-1 (8-primitive tuple, N2 PARTIALLY RATIFIED). Read for citation
  only; not reopened, not reinterpreted, not modified.
- **F3** — kernel-reduction's own C0/C0_plus (13/14-operator executable candidate). Already admitted,
  narrow scope.
- **F5** — C1's own DDD-aggregate "K-1" (`KnowledgeAggregate`+`ConflictRecord`).

Three pairs pre-registered: (F1, F3), (F1, F5), (F3, F5). No pair was added or dropped after seeing
comparison results.
