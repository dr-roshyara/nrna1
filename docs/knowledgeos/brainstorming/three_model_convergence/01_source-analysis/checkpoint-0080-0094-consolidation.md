## 1. Reconciling the three Context treatments (not choosing among them)

**CORRECTED 2026-09-01 per adversarial review (`checkpoint-0080-0094-review.md` D1).** The original
version of this section characterized the dispute as "three treatments, one per source." Direct
re-verification against exact source text found this incomplete: the instability is **both
cross-document disagreement AND intra-document inconsistency**, confirmed in three separate files.

| Treatment | Source(s) | Shape |
|---|---|---|
| **A — flat dimension** | 0089 (6-item AND, elsewhere in the same file, 7-item), 0090, 0094 (item #4 of its own "Updated Kernel Formula") | Context is a peer state-dimension alongside Identity/Evidence/Authority/... |
| **B — merged into Identity** | 0091 (5-pillar diagram, `Identity \| Meaning + Context`) | Context has no independent slot; it is absorbed into "what this is" |
| **C — delimiter/boundary condition** | 0094 (Avacchedaka argument, explicitly rejecting shape A in the same document that also uses it) | Context is not a value any object *has*; it is a condition that scopes when another statement is valid |

**Intra-document inconsistency, confirmed in three files, not one:**
- **0089** — a 6-dimension "Final architectural picture" (Context excluded) coexists with a
  7-dimension "Kernel Definition (candidate)" (Context included), in the same document (already
  disclosed in the original version of this section).
- **0091** — Context is an independent point in the 13-point character definition (§9, "KnowledgeOS
  Preserves Context," with its own worked example: "The system is cold" meaning temperature, hostility,
  or market conditions depending on context) — yet is MERGED into the Identity box two sections later
  in the same document's own 5-pillar diagram. (**Not disclosed in the original consolidation —
  found only in the adversarial review.**)
- **0094** — argues at length, using a real Navya-Nyāya technical concept, that Context is NOT a flat
  dimension ("Context is not metadata... Context is a logical boundary") — yet the same document's own
  later "Updated Kernel Formula" lists "4. Context" as a flat Preserves item, the very shape it had
  just argued against. (**Not disclosed in the original consolidation — found only in the adversarial
  review.**)

**Revised characterization:** this is not yet "three theories competing on equal footing." It is one
recurring pattern — a document's own summary table drifting from that same document's own argued prose
— occurring independently in three different files. No file in the corpus has committed consistently
to a single Context treatment for its own full length.

**These are still not three phrasings of one idea — they make different, testable claims,** and that
part of the original analysis stands: A and B disagree about whether Context ever varies independently
of Identity; A/B and C disagree about the *kind of thing* Context is (a value an object has, vs. a
relation that scopes another claim's validity).

**A falsifiable discriminator exists, even though this audit does not apply it:** if Context is ever
observed (in EKS/PKS/AIP evidence, not philosophical argument) varying independently while Identity
stays fixed, treatment B is wrong. If Context never appears as a value in its own right but only ever
as a qualifier attached to some other claim's validity, treatment C is favored over A. **No file read
so far supplies this evidence either way** — the dispute is currently adjudicated by which table in
which document was written last, not by observation. Status: `OPEN / UNRECONCILED`.

**One diagnostic worth naming, without adopting it:** Context is the single most unstable entry in the
registry — now confirmed unstable both across and within documents — while Identity, Evidence,
Authority, and Unknown have each stayed structurally intact across the same span. A plausible
(unconfirmed) reading is that Context's instability is a *symptom* — it may be being forced into a
dimension-shaped registry slot when it structurally belongs to a different category (a
relation/modifier, per treatment C, or per §2 below, per H-KOS-Relation-001 generally). **This remains
a hypothesis about *why* the instability exists, not a resolution of *what Context is*, and — this
qualification is itself a correction (see D9 in §2 below) — the intra-document inconsistency does NOT
by itself confirm the relation hypothesis over treatments A or B. Compatibility with a hypothesis is
not confirmation of it.**

## 2. Auditing H-KOS-Relation-001 against the existing forbidden-collapse pairs

**CORRECTED 2026-09-01 per adversarial review (`checkpoint-0080-0094-review.md` D2).** The original
version of this section tested 8 pairs, but only 3 came from 0094's own stated list of 5 examples; two
of 0094's own examples (Expression≠Meaning, Representation≠Identity) were never tested, and 5 rows
were imported from other files (0081/0084/0085/0090) without disclosing the substitution. This version
tests all of 0094's own examples, marks every imported row's provenance explicitly, and replaces the
"derivation-type" label with the more accurate **`constitutively-relational`**.

Method: for each forbidden-collapse pair, ask whether reframing it as a relationship constraint
(rather than an attribute constraint on a knowledge object) changes what the rule actually forbids, or
merely restates it in different words.

| Forbidden collapse | Provenance | Type | Attribute framing | Relation framing | Explains, or merely redescribes? |
|---|---|---|---|---|---|
| Evidence → Authority | source-native (0094) | authority-type | "evidence-strength" and "authority-level" are two attributes of one object that must not covary automatically | `evidenced-by(X)` and `authorized-by(X)` are two distinct relations to X that must not be inferred from one another | **Redescribes only.** Both framings forbid the same thing equally clearly. |
| Observation → Decision | source-native (0094) | authority-type | "observed" and "decided" are states an item passes through, must not skip | `observed-by(agent, X)` ≠ `decided-by(agent, X)` — two distinct relations | **Redescribes only**, same as above. |
| Assessment → Authority | source-native (0094) | authority-type | same pattern | same pattern | **Redescribes only.** |
| Expression → Meaning | source-native (0094), **previously untested** | constitutively-relational | an "expression" attribute must not be read as a "meaning" attribute | `expressed-as(meaning)` is constitutive of what "expression" *means* — attribute framing can describe an expression without ever naming what it expresses; relation framing cannot | **Explains.** Real advantage. |
| Representation → Identity | source-native (0094), **previously untested** | constitutively-relational | a "representation" attribute must not be read as an "identity" attribute | `represents(identity)` is constitutive of what "representation" *means*, same structural reason as Expression→Meaning | **Explains.** Real advantage. |
| Projection → Source | imported (0081/0084) | constitutively-relational | a "projection" attribute must not be treated as if it had "source" status | a projection is *inherently* `derived-from(source)` — you cannot state what a projection *is* without naming the relation it stands in to its source | **Explains.** Attribute framing can describe a projection without ever mentioning its source; relation framing cannot. |
| Inference → Observation | imported (0090) | constitutively-relational | an "inferred" flag must not be dropped, making the item look "observed" | `inferred-from(premises)` is constitutive of what an inference *is*; an "observation" by contrast has no such relation | **Explains**, same structural reason as Projection→Source. |
| Context Removal → Meaning Preservation | imported (0090) | constitutively-relational (identity-type) | "context" attribute must not be silently dropped while "meaning" is kept | meaning is *itself* `bounded-by(context)` — under treatment C (§1), meaning without a context relation is not merely incomplete, it is not a well-formed claim at all | **Explains**, and is compatible with (does not by itself confirm) Context-treatment-C over A/B. |
| Confidence → Truth | imported (0084/0090) | category-distinction | a "confidence" attribute must not be read as a "truth" attribute | `well-supported-by(evidence)` ≠ `true` — a category distinction (epistemic vs. ontological status), not one thing's constitutive relation to another | **Redescribes only.** |
| Knowledge → Automatic Action | imported (0084/0090) | authority-type | a "recommendation" attribute must not silently become an "executed" state | `recommended(X)` ≠ `executed(X)` — already clear under either framing | **Redescribes only.** |

**Finding (falsifiable, not adopted as a conclusion):** H-KOS-Relation-001 has **real explanatory power
for `constitutively-relational` collapses** (Expression→Meaning, Representation→Identity,
Projection→Source, Inference→Observation, Context Removal→Meaning) — cases where the constrained
concept cannot be *defined at all* without naming what it stands in relation to. Two of these five are
0094's own previously-untested illustrative examples, which strengthens rather than weakens the finding
now that they are included. It has **no discernible advantage over plain attribute framing for
`authority-type`** collapses (Evidence→Authority, Observation→Decision, Assessment→Authority,
Knowledge→Action) or for the one `category-distinction` collapse tested (Confidence→Truth).

**Explicit non-generalization:** this finding does NOT extend to all forbidden-collapse pairs. The
three most load-bearing, most-repeated pairs across the corpus (Evidence≠Authority,
Observation≠Decision, Assessment≠Authority) are all authority-type — where the hypothesis explains
nothing beyond what attribute framing already states. If usage frequency in the corpus is any guide,
the hypothesis explains a minority of actual forbidden-collapse usage, not the majority.

**Consequence:** H-KOS-Relation-001 should not be tracked as a single all-or-nothing hypothesis. It is
better tracked as a claim that applies cleanly to the constitutively-relational subset and is redundant
for authority-type and category-distinction pairs. This is recorded in the registry as a **scoped**
finding, not a blanket endorsement or rejection, and **it remains at maturity stage
`semantic_definition` — this correction sharpens the classification, it does not advance the stage.**

## 3. Does the relation hypothesis explain anything the dimension model cannot?

**CORRECTED 2026-09-01 per adversarial review (`checkpoint-0080-0094-review.md` D9) — the original
version of this section presented the differential prediction as essentially confirmed. That
overstated it.**

**Corrected formulation:** the observed Context instability is **compatible with** the Relation
hypothesis — under the relation model, Context is unstable because it was being asked to sit in a
dimension-shaped slot when it structurally behaves like the constitutively-relational cases audited in
§2 (a condition attached to another claim, not a value in its own right). **But this has not yet been
distinguished from a simpler, equally parsimonious alternative: Context was introduced later (0088,
one file after the anchor's original six dimensions at 0087) and has therefore had fewer files and
fewer iterations to converge than Identity/Evidence/Authority/Transformation/Temporal/Unknown, all of
which trace directly to 0087 itself.** A "recency" account explains the same instability without any
claim about Context's ontological category. Neither explanation is selected here; both are recorded.

This remains the one place in the corpus, as of file 0094, where a structural hypothesis does more
than redescribe existing observations for at least a subset of cases (§2) — but the specific claim
that it *uniquely* predicts Context's instability is downgraded, not confirmed. That is exactly the
kind of caution MD-015's maturity ladder and MD-012's independence bar are designed to enforce, and
exactly why one explained-and-not-yet-distinguished anomaly is not independent corroboration: it is
not a proof that the relation model is correct, and it is not now claimed to be the only model that
could produce this observation.
**Status: still `semantic_definition` in the registry. This finding does not advance its maturity
stage** — a differential explanation, even an undisputed one, is not a constraint, operator, or
preservation test; a disputed one (as this now is) advances nothing further.

## 7. Maturity ceiling — restated as a standing rule, not merely observed

and at least a partial invariant-preservation test (stage 5).** As of file 0094, the furthest any
registry entry has reached is stage 3 (Authority Separation, Unknown Preservation, Revisability,
Observation-vs-Inference, Reasoning Separation). This consolidation pass changes none of that — it
adds classification and cross-references, not maturity advancement. This rule is recorded permanently
in the decision log (MD-016) so that a later session cannot silently treat prose enthusiasm ("strongest
candidate discovered so far," used by the corpus's own authors for several different candidates) as
