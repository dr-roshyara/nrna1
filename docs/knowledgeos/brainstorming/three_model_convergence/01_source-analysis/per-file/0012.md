## What Is This Document About?
The commission asks for a migration path. The document's finding is that **the migration path already
exists, distributed across four authorities, and had never been assembled in one place** — so its
work is assembly and tracing, not design. Its declared discipline is strict: *"identifies architecture
that already exists; invents none, improves none, redesigns none, renames none"*, with every row
traced to a committed artifact and speculative relationships marked `SPECULATIVE` inline.

The landscape section supplies the measured shape of the repository and one central finding, quoted
rather than discovered: a three-document governance framework contains **zero occurrences of the
product's domain vocabulary** and yet **sits in a path classified as product**. *"That misplacement —
not any missing design — is what the migration must resolve."*

The migration map is the substance: sixteen rows, each with current home, future home, reason, and a
**recorded extraction trigger**. Its headline result is arithmetic: **nine of sixteen need no move**
(already in their permanent home), and **seven are blocked — every blocker a recorded governance
gate, not a design gap.** Two constraints recur and are quoted rather than paraphrased: extraction
may proceed **by reference, never by copy**, because a prior decision retired
extraction-by-materialization (*"not deferred — its premise was that the baseline should be
materialized, and that premise is decided against"*); and a structural freeze bars reorganisations.

§5 records that the AI runtime is **already fully modelled in four layers** —
`Governance Policy → Capability Mapping → Runtime Adapter → Concrete Configuration` — with the middle
layer existing specifically so that runtime vocabulary *"cannot LEAK UPWARD"* into governance. It
also surfaces a property the document calls the single most important extraction-safety mechanism,
already built: components carry **stable ids**, and *"paths change; ids never do"* — decisions and
reviews reference ids, not paths, so **references survive relocation**.

§7 assembles five stages with entry conditions, and the finding is again that nobody had drawn the
table: *"Stages 1–5 already have entry conditions written down — by four different authorities, over
three weeks."* Only Stage 1 is open. §9 renders the loop as a dependency graph with per-arrow
evidence: **three of four arrows are speculative or empty**, and the return arrow is empirically
empty. The verdict is that what is missing is **not architecture** — it is four triggers, *"none of
which fires by writing a document — and this document is the last one that should be written before
the first of them fires."*

### Formal definitions
One property worth stating precisely, because it is the first of its kind in the reading order:

```
∀ component c : id(c) is stable  ∧  path(c) is not
references(decision, review) → id(c),  never path(c)
⟹  relocate(c)  does not invalidate  references(·, c)
```

*"Paths change; ids never do."* This is an **identity invariant under relocation** — the artifact's
identity is decoupled from its location, so a move preserves every reference to it. The document
calls it *"the single most important extraction-safety property, already built."*

precondition or failure mode.
