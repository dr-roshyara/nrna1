## What Is This Document About?
The commission's hypothesis is that gaps which *look* ontological are often lifecycle or governance
wearing ontology's clothes. The document tests this with the ontology **explicitly frozen** — nothing
may be added, removed or renamed — so the only admissible move is *reclassification*, not repair.

Its central discovery is mechanical and precise. `statuses.yaml` (8 values) carries an `order` field,
a `settled` terminal marker, a role table (*who may move a document between states*), and
lint-checkable transition guards. `authorities.yaml` (5 values) has **none of these** — no
progression field, no terminal marker, no role table, no guards. **The document derives a specific
consequence from this asymmetry**: attestation (a document becoming authoritative through review) is
itself an authority **transition** (`derived → authoritative`), and because authority has no governed
transitions, the model **cannot express "attested"** — it collapses `derived` into `never
authoritative`. A previously reported ontology falsification (`I-4`) is **withdrawn** on this ground:
*"DP-2 conflates DERIVATION with ATTESTATION"* — now given "a mechanical cause rather than an
intuition."

Four gaps are classified against three failure categories (Structural / Behavioral / Evolutionary):
**one is genuinely ontological** (a missing `SPECIALIZES` relationship), **one is lifecycle** (the
authority state-machine gap, described above, and named the largest), **one is governance** (an
external *obligation* has no home in a model built only on *ownership*), and **one dissolves
entirely without adding a concept** — Product vs Deployment is resolved by observing that a
deployment **is** a nested Knowledge Space, closing an open nesting question (H-3) *"using evidence
rather than preference."*

§5 records a second-order finding surfaced only by checking: the authoritative lifecycle document's
own diagram lists `idea`/`research` as **statuses**, while the executable enum defines them as
**types** — *"a type/status conflation inside the very document whose §1 warns against exactly
that."* Recorded explicitly as an **observation, not a defect claim**, since either the diagram or
the enum may be the one that is stale.

The document opens by naming its own **fourth instance of a recurring error class** — level
confusion, this time *lifecycle vs structure* — and notes a **fifth avoided**: it was about to report
"there is no lifecycle," checked first, and found **nine** lifecycles already governed with roles and
guards.

## TIER 2 — DEEP ANALYSIS
**Trigger status: TRIGGERED** — refines a **corpus-tracked quasi-formal definition** (authority),
diagnoses a **missing state-machine dimension** with a specific formal consequence (an inexpressible

### Mathematical derivation
None. But the diagnosis has exact structural content:
```
status:    S = {draft, discovery, reviewed, approved, baseline, frozen, superseded, archived}
           equipped with: order, terminal marker (settled), role: S x S -> Actor, guard: S x S -> Bool
authority: A = {generated, derived, authoritative, provisional, historical}  (as previously flattened)
           REFINED here into A = P x T
             P (provenance) = {generated, derived, ...}     — IMMUTABLE once set
             T (standing)   = {authoritative, provisional, historical}  — CHANGES by governance act
           equipped with: NOTHING — no order, no terminal marker, no role, no guard
attestation := a transition on T (specifically, provisional -> authoritative, or similar)
```

This is the clearest formal diagnosis of a missing structure anywhere in the C1 lineage so far: a
named object (`authority`) is shown to be a **product of two factors with different mutability
classes**, and a real-world event (attestation) is shown to require **transition structure on one
factor that the model does not supply**.
