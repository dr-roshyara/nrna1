**TRIGGERED — CONFIRMED CORPUS-INTEGRITY FINDING.** This file substantially overlaps 0597's landmark
"Step 25S — Identity, Entity Resolution, Same-As, Distinct-From and Knowledge Atma," treating essentially
the same core question (when may two references be treated as the same entity) under a differently worded
title, **with no explicit cross-reference anywhere to 0597, Knowledge Atma, or 0597's vocabulary**
(`EntityIdentity`/`KnowledgeMeaningIdentity`/`RecordIdentity`). This is a materially different collision
pattern from the earlier CONFIRMED 25N/25C precedent (0578/0592), where the later file self-consciously
extended the earlier one — here the two files read as **independent re-derivations** of the same question.

Substantively, delivers a formal `denotes:R→E` reference-denotation function (`r_1=r_2` neither necessary
nor sufficient for `denotes(r_1)=denotes(r_2)`, worked Nexus hostname/IP/description example), context-
dependent denotation (`denotes(r,c)→e`), and **`RealWorldIdentity≠DomainObjectIdentity`**, explicitly named
"one of the most important DDD principles for KnowledgeOS": no `GlobalEntityIdentity` may be imposed where
a domain has intentionally defined separate identities.

Delivers a **six-value `IdentityStatus` lattice** (`Unknown/Candidate/Probable/Confirmed/Rejected/
Contextual`), functionally parallel to but independently named from 0597's three-level identity split.
Delivers non-transitive Similarity, worked through a concrete numeric counterexample
(`sim(A,B)=0.95, sim(B,C)=0.95, sim(A,C)=0.60`) showing how naive threshold-based transitive closure
produces an accidental false merge.

**Delivers the file's central formal deliverable — asymmetric False-Merge/False-Split cost treatment**:
`Cost(FalseMerge)≠Cost(FalseSplit)`, each with an independent consequence list, requiring domain-specific,
cost-sensitive identity thresholds rather than an arbitrary fixed value. Delivers a Conservative identity
principle (`UnknownIdentity should generally remain Unknown`), explicitly analogous to 0616's abstention
discipline. Delivers Identity-versus-State separation (an entity's identity can remain stable while its
state changes, e.g. IP reassignment), and a formal Identity hierarchy across abstraction levels
(`Product→ApplicationInstance→Deployment→Process`), explicitly connected to DDD aggregate boundaries.

**Delivers a second central formal deliverable — a formal Identity graph `G_I`** with explicitly typed
relations (`sameAs/aliasOf/instanceOf/versionOf/deployedOn/replacedBy/relatedTo`), with the crucial caution
that not all such relations are equivalence relations. Delivers Semantic/statement equivalence distinguished
from entity identity, and unit/format normalization formalized as itself an epistemic operation (worked
