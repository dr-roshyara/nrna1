## Tier 2
**TRIGGERED — LANDMARK: Source Plane vs. Knowledge Plane architecture; Zero→Gap→Sārathi→Retrieval;
three non-conflatable information pathways.** First file in this arc to cite real external sources (three
OpenAI documentation pages) rather than reasoning purely conceptually or from the Gita corpus.

Identifies two LLM information mechanisms: (A) parametric training knowledge (OpenAI explicitly: "not a
database") vs (B) inference-time retrieval (ChatGPT Search) — noting (B) is "much closer to what
KnowledgeOS needs." **Rejects naive RAG** (Documents→Chunk→Embedding→VectorDB→RAG→LLM) as bypassing the
epistemic model. **Central distinction**: **Document≠Knowledge; Document≠Evidence** — a document is an
information-bearing SOURCE from which observations/candidate assertions are constructed, not evidence
itself.

**Introduces a three-plane architecture**: Source Plane ("where did this come from?"), Knowledge Plane
("what do we represent as knowledge?"), Epistemic Engine ("how justified/complete/current/coherent is that
knowledge?"). Makes **Source Connectors** a first-class capability (sixteen named types: PDF, DOCX, Git,
Jira, Confluence, SharePoint, Databases, APIs, etc.), required to produce controlled ingestion events, not
vector-DB dumps. Delivers a **nine-stage ingestion pipeline**: External Source→Source Connector→Raw
Artifact→Document Parser→Structural Model→Semantic Parser→Observations→Candidate Assertions→Evidence
Objects→Knowledge State Update→{Zero,Lord}→Sārathi — reconnecting the corpus's C-parser/Sanskrit-parser
intuition, with candidate assertions carrying Source/Location/ObservedAt/ExtractionMethod metadata pending
evaluation.

Contrasts RAG's single question against a **twelve-step KnowledgeOS retrieval sequence**. **Reformalizes
Retrieval as a goal-directed epistemic operation**: `Retrieve(Q,K_t,I_t,C)→EvidenceCandidates`, replacing
naive `Retrieve(Query)→Documents` — "the retrieval system knows why it is retrieving," worked via a
Nexus-migration example discovering twelve relevant dimensions before targeted retrieval. **Delivers the
file's most powerful insight**: Zero can DRIVE retrieval — Zero identifies specific gaps (backup
verification, firewall rules, certificate ownership); Sārathi generates a targeted retrieval plan for each —
crystallized as **`Zero→Gap→Sārathi→Retrieval`**, "the retrieval engine becomes part of the investigation
loop," an "epistemic retrieval loop" extending the closed-loop diagram.

**Establishes `LLM Output≠Knowledge`**: `LLM Output→Candidate Interpretation`, requiring KnowledgeOS
epistemic processing before becoming knowledge. **Formalizes three non-conflatable information pathways**:
Path A (implicit Model knowledge from training), Path B (explicit but ungoverned External retrieval), Path
C (explicit, traceable, governed KnowledgeOS accumulated knowledge). Addresses the enterprise "memory
problem" via a fully worked concrete Assertion object (A-10291, Nexus version, with complete
Subject/Dimension/Value/Evidence/Source/ObservedAt/Acquisition/Support/Uncertainty/Validity/Provenance
fields). Crystallizes three principles: "Sources provide information; KnowledgeOS constructs governed
knowledge from it." / "LLMs interpret; KnowledgeOS evaluates and governs." / "Retrieval supplies evidence
candidates; it does not automatically create knowledge." Closes rejecting "build KnowledgeOS as our own RAG"
in favor of Source Fabric+Semantic Reconstruction+Knowledge State+Epistemic Engine+Investigation
Engine+AI Models.

**Part B** (an affirming elaboration, not a corrective review) reorganizes Part A into a formal pathway
comparison table with an explicit "critical error" warning, and **formally numbers three "Constitutional
Invariants for Sources" for the first time**: Invariant 1 (Source≠Knowledge), Invariant 2 (LLM
Output≠Knowledge), Invariant 3 (Retrieval≠Knowledge Creation) — escalating Part A's principles into named
governance vocabulary. Closes: "KnowledgeOS is an epistemic investigation system, not a question-answering
system."
