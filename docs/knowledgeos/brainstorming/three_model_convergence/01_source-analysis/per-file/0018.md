## What Is This Document About?
The commissioned question is deliberately reframed at the outset: not *"should authority become a
state machine"* but *"what independent dimensions describe the evolution of engineering knowledge?"*
— and the document opens by **conceding its own predecessor's error**: 0014's LG-1 inferred a needed
repair (a state machine) from an observed asymmetry, which the document names precisely as *"solution
design… exactly what DDD forbids."*

§1 inventories ten progression mechanisms as **observations**, explicitly not assumed to be
lifecycles. §2 runs each through seven commissioned questions (what changes, invariant protected,
owner, mandatory?, kind, independence, is-it-a-lifecycle) and finds the ten are **not ten instances of
one thing**.

§3 delivers the document's structural core: the ten mechanisms resolve into exactly **four kinds of
progression** — **GOVERNANCE-ACT** (moved by a decision from a named role; reversible only by a
further act) · **EVIDENTIAL** (moved by accumulating evidence; *"nobody can decree it… only by
refutation, never by decision"*) · **WORK-EXECUTION** (moved by time and effort; has a clock;
irreversible on conclusion) · **COMPOSITE** (a trajectory crossing the other kinds) — plus a fifth,
**non-progression: PROVENANCE**, which the document states does not progress *at all*, being *"an
immutable fact of origin."* The load-bearing distinction is stated once and used repeatedly: *"a
GOVERNANCE-ACT progression can be **granted**. An EVIDENTIAL progression can only be **earned**."*

§4 is the flagship result. `authorities.yaml`'s own header is shown to ask **two different questions
in one field** — *"how much should I trust this, and where did it come from?"* — and its five values
are split cleanly: `generated`/`derived` answer **provenance** (immutable, never changes);
`authoritative`/`provisional`/`historical` answer **standing** (mutable by governance act). The
document states the consequence precisely: *"this dissolves LG-1 rather than answering it"* —
authority has no state machine not because one is missing but because **half of it cannot have one**
(provenance is a fact, and facts have no lifecycle) while the other half already changes by acts,
lacking only the role/guard apparatus status transitions have. A prior persistent confusion (`I-4`,
withdrawn at 0014) is explained mechanically: `derived` (a provenance value) had been read as if it
implied low trust, when a signed financial statement is simultaneously `derived` in provenance and
`authoritative` in standing, *"without contradiction."*

§5 states the platform's central mechanism in one sentence, treated as the document's most
consequential single line: **"evidence EARNS; governance GRANTS; promotion requires BOTH."** No
ruling can make an observation `Replicated`; no evidence can make a document `frozen`.

## TIER 2 — DEEP ANALYSIS
**Trigger status: TRIGGERED** — delivers the corpus's most precise **formal decomposition** to date,

### Mathematical derivation
None with proof, but the reading order's clearest structural argument:
```
authority(doc) ∈ A = {generated, derived, authoritative, provisional, historical}

A is NOT atomic — it factors:
   A ≅ P × T
   P (provenance) = {generated, derived}          — IMMUTABLE:  ∀t, ∀t' : P(doc,t) = P(doc,t')
   T (standing)    = {authoritative, provisional, historical}   — mutable by governance act:
                       T(doc, t+1) = act(role, T(doc,t))  for some named act

status(doc) ⟂ authority(doc)          — declared, corroborated by a guard:
   transition(doc, → baseline)  requires  T(doc) ∈ {authoritative, derived}
   — a CROSS-DIMENSION GUARD, not a fusion: the guard reads T without status and A merging.

promotion(k)  ⟺  crosses_bar(evidence(k)) ∧ ∃ act : grants(act, k)
```
This is the closest the C1 lineage comes to an actual factorization proof: a five-element set is
shown to be isomorphic to a Cartesian product of a 2-element immutable set and a 3-element mutable
set, motivated by the field's own header asking two questions. **The isomorphism is argued, not
formally verified** (no bijection is exhibited between the five original values and the six
combinations `P × T` would generate if unconstrained) — worth flagging precisely: `A` has 5 elements,
but `|P| × |T| = 2 × 3 = 6`. **One combination is missing or collapsed**, and the document does not
identify which. This is a specific, checkable gap: **either the factorization is not a full product
(some `(p,t)` pairs are inadmissible), or one of the five original values secretly double-counts a
`(p,t)` pair.** Recorded here because it is exactly the kind of precision §17/§18 will demand of any
later knowledge-dimension product, and the C1 lineage's own best attempt at this move has an
uncounted cell.
