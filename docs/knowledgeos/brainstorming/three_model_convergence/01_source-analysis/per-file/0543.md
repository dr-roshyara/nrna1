## Tier 2
**TRIGGERED — LANDMARK: Step 2 of the Identity/Equivalence calculus, delivering DERIVATION_CONFLICT as a
genuinely new conflict sub-type.** Opens: "two statements can look identical while representing different
observations, or look different while representing the same underlying observation." Establishes a
four-way separation extending 0540: **`Identity≠Semantic Equivalence≠Same Observation≠Independence`**.
Formalizes four relations: Identity (`e_1=_Ie_2`), Semantic equivalence (`e_1=_Pe_2`), Observation
equivalence (`e_1=_Oe_2`), Dependency (`e_1≺e_2`).

**Delivers the critical governing invariant**: `SemanticEquivalent(e_1,e_2)⇏SameObservation(e_1,e_2)` —
"semantic equivalence must NOT imply deduplication" — worked via the case a naive deduplication algorithm
would wrongly destroy (an API reading and a filesystem inspection, semantically equivalent but genuinely
independent, must both count).

**Works through seven fully concrete test cases (A-G)**: exact duplicate→one contribution; same
observation, different representation→one underlying observation; LLM transformation→dependent, "not
independent evidence"; two LLMs reading one document→CommonSource, Independence=Unknown; two independent
measurements→corroboration; same source different times→"Same proposition≠same observation"; and — **the
file's most consequential, genuinely novel case** — Different values, same source: a document correctly
states "Nexus 3.69" while an LLM extraction of that SAME document incorrectly states "Nexus 3.70." Both
derive from one source yet disagree with each other. This is explicitly identified as **"contradictory
derived assertions,"** categorically distinct from "contradictory independent observations" — delivering a
structured **`DERIVATION_CONFLICT`** conflict type (with fields: underlying source, count of independent
observations, count of derived interpretations), "much more informative than simply saying 'two sources
disagree.'"

**Formalizes an evidence lineage graph** `G_E=(V,L)` with seven typed edges and `Root(e)` (upstream
acquisition events), then delivers an important qualifying nuance: **`CommonCause≠SameObservation`** and
**`CommonCause≠AutomaticDependence`** — two sensors triggered by one shared weather event may still be
genuinely useful independent measurements, pushing residual correlation concerns into statistical (not
provenance-structural) dependence.

**Delivers a major representational refinement**: evidence relationships must NOT be forced into a single
mutually-exclusive enum — they are co-existing dimensions (Identity/SemanticEquivalent/SameObservation/
Derived/Independent can each be independently true or false), formalized as a multi-relational graph
`G_E=(V,L_1,...,L_n)`. Delivers three new DDD concepts kept separate from Evidence: `EvidenceLineage`,
`EvidenceRelation`, `EvidenceEquivalence`. Delivers a formal law set including
`SameObservation(e_1,e_2)⇒NonIndependent(e_1,e_2)`, while `SemanticEquivalent∧Independent` is valid and
constitutes genuine corroboration.

**Delivers a three-tier computability classification** (Deterministically computable / Algorithmically
inferable / Not universally decidable), requiring every inferred relation to carry an explicit
Confirmed/Inferred/Proposed/Unknown status. Delivers a major architectural principle: **Fact about
provenance vs. Inference about provenance** — "KnowledgeOS should never silently promote the second into
the first."

**Closes Step 2**: `Evidence+Lineage+Relations+Equivalence+Dependency+Assessment`, replacing the naive
`Evidence+Score` model. **Opens "Step 3"**: constructing the Evidence Assessment Algebra FROM the
established relation set (`ℰ,G_E,P,C,ρ→EA`) rather than choosing a formula first.

**Bridge candidate**: trace whether Step 3 is executed as its own file.
