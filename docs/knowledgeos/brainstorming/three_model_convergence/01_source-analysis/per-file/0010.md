## What Is This Document About?
The commission asks whether the failed bootstrap experiment (0008) changes the strategic domain
model. The answer is **no** — and the document's value lies in being precise about what *did* change,
and in correcting itself.

Its opening section accepts three corrections, one of which **refutes its own prior report's F-3**.
The claim *"there is no strategic-DDD method"* is refuted on repository evidence: an ADOPTED
constitution and a BINDING operating protocol exist and contain exactly the method the bootstrap
session reported absent — **nine admissible boundary-justification criteria** (semantic ownership ·
transactional consistency · lifecycle independence · invariants · ubiquitous-language divergence ·
team autonomy · deployment autonomy · integration characteristics · performance constraints), plus a
candidate rejection protocol and the principle *"semantic truth does NOT automatically imply software
structure."* The corrected finding is sharper than either the original claim or its refutation: the
method **exists, is adopted and binding, and its criteria are portable** — what blocks reuse is that
it lives in a product path and that **SD-1 admits only one product's certified knowledge release**,
making it *unconsumable elsewhere as written*.

The second correction separates *"the MVK failed"* from *"KnowledgeOS failed"* — different claims
that the prior report conflated in its verdict. The third, and the document calls it the most
consequential, decomposes what the experiment actually tested:

```
TESTED:      Knowledge  → ARCHITECT (reading rules) → Software   ✅ n=1, FAIL on boundary
NOT TESTED:  KnowledgeOS → PKS GENERATOR            → Software   ⛔ n=0
```

yielding **three distinct bootstrap responsibilities** where the corpus had one: bootstrap a PKS
(n=0) · bootstrap engineering (n=1) · bootstrap software (n=0). *"The PKS Generator slot is currently
occupied by a person reading documents. Whether a generator can occupy it is untested."*

Objective 1 tests six candidate domains **against the repository's own admissible-justification
list**, on the stated ground that using the programme's own test is the only non-arbitrary way to
answer. All six fail to qualify: two already exist, two are subsystems or capability families, one is
a workflow with a governance gap, and one — PKS Generation — satisfies **no** criterion and is
recorded as *merely an observation*. The document then turns the protocol's own words on its own
table: *"'It seems reasonable' is NOT admissible."*

Objective 4 delivers the file's most transferable result. The statement *domain-free ≠ reusable* is
**validated in both directions**, which the document notes is stronger than the original claim: a
corpus with **zero domain vocabulary** can still be ~90–95% one project's case law, and a document
with **fully general criteria** can be unconsumable because its intake rule names one product. This
yields **two distinct extraction blockers needing different remedies** — **case-law dilution** and
**coupling at the boundary** — and neither is detectable by vocabulary search.

Objective 5 draws a conceptual context map with per-arrow evidence status: **one of five arrows is
evidenced**, the loop-closing arrow is **empty**, and the loop contains a component that has never
existed. Objective 6 specifies, for each candidate, the **operational event that would justify
promotion** — a falsifiable trigger per row rather than a wish.

### Formal definitions
The **nine admissible boundary-justification criteria**, quoted from a binding protocol, constitute
the corpus's first genuinely **closed and exclusive** criterion set:
```
promote(seam → boundedContext)  ⟺  ∃ c ∈ C : satisfies(seam, c)
C = {semantic ownership, transactional consistency, lifecycle independence, invariants,
     UL divergence, team autonomy, deployment autonomy, integration characteristics,
     performance constraints}

```
Two properties worth recording. **Exclusivity is explicit** — the protocol names inadmissible
justifications by example (*"it seems reasonable"*, *"the ontology has this concept"*, *"the folder
exists"*). **The promotion condition is existential, not conjunctive** — one criterion suffices,
which the document nonetheless treats as too weak in practice (Bootstrap/Genesis satisfies exactly
one criterion and is still refused, on the added ground of n=1). That gap between the stated rule
and the applied rule is an unrecorded tightening, and is flagged here.
