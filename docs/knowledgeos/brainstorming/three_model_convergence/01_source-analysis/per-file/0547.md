## Tier 2
**TRIGGERED — LANDMARK: the corpus's first complete KnowledgeOS Decision Loop algorithm.** Opens: "this
step connects the static epistemic model to the active behavior of KnowledgeOS." Delivers the foundational
distinction `Evidence Strength≠Information Gain≠Decision Value`, worked via a Nexus-migration example
(patch version adds little info; an unknown backup-status answer could dramatically reduce uncertainty) —
`Highest Evidence Strength≠Highest Information Gain`.

**Formalizes information gain via entropy** (`IG(e;P)=H(P)-H(P|e)`), then immediately refuses to make it
universal — entropy requires probability, but KnowledgeOS may have unknowns/constraints/argument graphs —
delivering a more general **discrepancy-based definition**: `IG_D(e)=D(S_t,I_t,P)-D(S_{t+1}^{(e)},I_t,P)`.
Generalizes to Expected Discrepancy Reduction: `EDR(e)=𝔼[D(K_t,I_t,P)-D(K_{t+1},I_t,P)|e]`. **Delivers the
file's central architectural claim**: EDR is MORE fundamental than entropy reduction for KnowledgeOS,
since the true objective is `K_t→I_t`, not `H(K_t)→0` — proven via a concrete counterexample (two
independent 0.5-probability propositions, one irrelevant to the decision) crystallizing
**`InformationGain≠PurposeValue`**.

**Formalizes Value of Evidence** and a cost-aware **Utility function** `U_ρ(e)=Benefit_ρ(e)-Cost_ρ(e)`,
showing via a worked cost comparison that "maximum information gain alone is insufficient." **Formalizes
Lord's evidence-acquisition optimization problem**: `q*=argmax_{q∈𝒬} U_ρ(q|K_t,I_t,P)` — "potentially one
of the most important equations in the whole KnowledgeOS theory," with Lord delivering
`RankedCandidateAcquisitions`.

**Delivers the cleanest Zero/Lord/Sārathi three-role separation in the corpus**: Zero detects
(`Zero(K_t,I_t)→Δ_t`); Lord ranks remedies (`Lord(Δ_t)→Q`); Sārathi selects the actual next action under
real-world constraints (`Sārathi(Q,constraints)→a_t`) — `Lord=option generation/ranking`,
`Sārathi=action guidance`. **Delivers "much more than RAG"**: conventional RAG is
`Question→Retrieve→Generate`; KnowledgeOS is `Purpose→IdealState→Discrepancy→EvidenceValue→
AcquisitionPlan→Evidence→Assessment→KnowledgeState`.

Demonstrates the model naturally accommodates human research (`HumanResponse→Evidence`, "does not
automatically become truth"), LLM output (`LLMOutput≠GroundTruth`, `LLMOutput≠IndependentEvidence` when
derived), and genuine experimental evidence, each entering the same evidence machinery. Delivers
`ExpectedValue≠ActualValue` and a resulting feedback loop, plus a general stopping condition (no candidate
action has sufficient expected utility, rather than a scalar threshold).

**Delivers the file's most significant epistemic-discipline safeguard**: explicitly refuses to define
"Moksha=Δ=0" as a mathematical consequence of the framework, directly disciplining the corpus's earlier
philosophical Moksha-as-completion metaphor (0409/0501) — `Δ=0` is always relative to a specified
purpose/context, never global — "a very important mathematical safeguard."

**Delivers the file's central formal deliverable — the corpus's first complete, numbered KnowledgeOS
Decision Loop algorithm** (nine steps: K_t → Zero→Δ_t → GenerateCandidates→Q_t → EvaluateValue →
q*=argmax U_ρ(q) → Acquire(q*)→e_t → Assess(e_t) → Update→K_{t+1} → Repeat) — "the beginning of an active
epistemic system."

**Delivers Step 6's verdict**: THEORETICALLY RESOLVED (EDR and U_ρ remain policy-dependent; the kernel
only needs to supply the `EvidenceValueEvaluator` abstraction). **Closes opening "Step 7"**: the Knowledge
State transition function `K_{t+1}=δ(K_t,e_t)` must become "a fully specified Knowledge State transition
algebra" — new/updated/superseded assertions, contradictions, gap resolution/appearance, staleness,
retraction, provenance, temporal versioning — explicitly recommended to precede any further
implementation, "the mathematical heart of the KnowledgeOS kernel."
