## Part 2: The Critical Insight — Equality Typing

The artifact reveals a fundamental methodological principle:

\[
\boxed{
\text{A property stated without naming its equality relation is not a well-formed proposition.}
}
\]

### 2.1 The Problem

If the equality is not specified, the proposition:

\[
\delta(K, o_1) = \delta(K, o_2) \not\Rightarrow o_1 = o_2
\]

is **indeterminate**.

### 2.2 The Solution

The artifact specifies:

| Equality | Antecedent holds? | Property meaningful? |
|:---|:---|:---|
| Structural | **no** — `Π ∈ id` separates them | vacuously true, useless |
| **Semantic** | **yes** | ✅ required and load-bearing |
| Observational | yes | required |

### 2.3 The Architectural Consequence

The artifact notes:

> Collapsing operations that produce the same semantic state would make *"who asserted this, on whose authority"* unrecoverable from the state.

**This is exactly what KnowledgeOS's provenance and authority architecture is designed to prevent.**

The artifact references the `grantId` collision — "a silent loss of an authority act" — as the implementation failure that demands this property.

**This is the correct link between formal property and implementation consequence.**
