## 3 · The Constitution's responsibility

**Formalize:**

1. **Constitutional identity** — Character Definition Head 43: *"KnowledgeOS is a constitutional epistemic operating system…"*.
2. **The eleven laws — not as candidates anymore, but as constitutional articles.** Example register (HPA):

```
Article 1 — Identity

KnowledgeOS SHALL preserve knowledge identity
across representation, expression, and projection changes.

Representation SHALL NOT become meaning.
Similarity SHALL NOT become identity.
Context SHALL remain part of identity.
```

3. **Kernel boundary** — explicit separation:

```
CONSTITUTIONAL KERNEL
        |
        +-- Engine Layer
        +-- Mechanisms
        +-- Representations
        +-- Implementation
```

4. **Negative boundary** — the Constitution must explicitly state **what KnowledgeOS refuses to become** (not a repository · not an LLM · not a truth oracle · not a similarity engine · not an autonomous decision maker).
5. **Amendment discipline** — because this is a constitutional document, define: **what can change · what requires constitutional amendment · what is merely engineering evolution.**

## 4 · Standing constraints (carried from all prior phases)

- **No new concepts · no new rows · no new philosophy** — the corpus is closed; adding knowledge would violate the discipline the Constitution establishes.
- **No implementation design** — storage, APIs, classes, and databases are deliberately unconstrained here.
- **Kernel/engine boundary frozen** — engines · mechanisms · representations are referenceable, never part of the kernel.
- **The final rule** — the strongest statement never exceeds the evidence. Keep facts · rulings · engineering actions rigorously separate.
- **Character head 43 stands** — with the three clause refinements (existence · reasoning · identity) as Constitution phrasing (P4 ruling).
