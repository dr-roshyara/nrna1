## 1 · The eight lenses

### Lens 1 — Ontology: how does the tradition define what exists?

The strongest concept is the **Śiva–Śakti relationship** — Śiva as unchanging Consciousness, Śakti as changing Power/manifestation, together *Consciousness and its Power*. As a **systems ontology metaphor**, not a theology:

```
Stable invariant
        +
Dynamic transformation
        =
Living system
```

⚠️ **False mapping refused:** NOT `Śiva = Kernel · Śakti = Implementation`. The lawful extraction is the conceptual lens — *a system requires both persistence and transformation* — which resembles the KnowledgeOS separation of **identity preservation ≠ state evolution** (Articles 1 + 11).

**Classification:** Mechanism / architectural-principle **candidate**.

### Lens 2 — Transformation: how does something change without losing its source identity?

Woodroffe's description of Śakti as a series of emanations or transformations **while the underlying consciousness remains unchanged** — *creation produces an effect without change in the Producer*.

KnowledgeOS relevance:

```
Revision ≠ Deletion
Change ≠ Loss of identity
Evolution ≠ Replacement
```

**Classification:** **Strong candidate** — supports the temporal dimension, provenance, historical evolution (Article 11 History · Revisability-001 · the epistemic state model).

### Lens 3 — Relationship / System: isolated objects or relationships?

Woodroffe's Dharma — *"Dharma expresses the right relations of each part to the whole"* — an order where each part has a relation to the whole.

KnowledgeOS already rejects `knowledge = isolated object`; knowledge is object + context + relations + history + knower. Extraction: **Relational Integrity Principle** — *a knowledge element cannot be evaluated independently from its relationships.*

**Classification:** **Strong support** for an existing invariant (the relational principle · typed epistemic graph · Article 1).

### Lens 4 — Process / Practice: is knowledge stored or enacted?

The Āgamas are **practical systems (Sādhanā Śāstras)**, not merely philosophical texts — knowledge connected with practice and transformation.

KnowledgeOS distinction this reinforces:

```
Knowledge repository (document → search → answer)
   ≠
Knowledge state (evidence → process → validation → experience)
```

This is close to the established principle: *knowledge is not content; knowledge is justified state evolution* (Article 6 governed transformation).

**Classification:** Architecture-philosophy **candidate** (epistemic lifecycle · Validation/GOVERN).

### Lens 5 — Layer / Abstraction: does the book distinguish levels of reality?

A recurring structure: Transcendent principle → Manifestation → Experience → Practice.

Lawful abstraction for KnowledgeOS:

```
Constitution → Architecture → Mechanisms → Implementation
```

⚠️ **False mapping refused:** NOT `Tantric cosmology = KnowledgeOS architecture`. The useful abstraction is *complex systems need layered explanations* — which the Constitution's Ch III layering already instantiates.

**Classification:** Architectural reasoning pattern **candidate** (supports the layer architecture, adds nothing to it).

### Lens 6 — Language / Representation: symbol and meaning

The book's chapters on **Śakti as Mantra, Varnamālā, and ritual systems** — symbolic representation.

Extraction: **Representation is not the thing represented** — Symbol → Meaning → Experience. This is the same separation the study already holds as a kernel invariant: **Representation ≠ Identity · Expression ≠ Meaning** (Article 1).

**Classification:** Existing-invariant **support** (confirmation, not new content).

### Lens 7 — Evolution / Emergence: ordered transformation

Manifestation as progressive stages (the **Tattvas**).

Lawful abstraction:

```
Raw observation → Claim → Validated knowledge → Established knowledge state
```

**Classification:** Possible **lifecycle mechanism** (supports the epistemic-inquiry lifecycle stages · Article 6).

### Lens 8 — Governance: authority, transmission, interpretation

A tradition is not just information; it has authority structures, transmission, interpretation, practice. The preface's call to understand a system from within.

KnowledgeOS equivalent: knowledge requires **Origin · Authority · Context · Interpretation · Validation** — which aligns strongly with **Evidence ≠ Authority** (Article 3) and the agency requirement (Article 10).

**Classification:** **Candidate** supporting the governance model.
