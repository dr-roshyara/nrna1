## 0 · Nature — a state transformation, not a knowledge object

```
Current state → Distortion / ignorance / bondage → Transformation → Liberated state
```

## 3 · What enters / what must NOT enter

**What enters (mechanism level):**
- **Epistemic Avidyā Detection** — *wrong-model detection*: the system asks *"where could our model of reality be wrong?"* — an active reasoning capability complementing the Verification Gate (which evaluates claims) with a **frame-level check** (is the model/map itself inadequate?). Connects to the §AR upādhi/defeater distinction (*a reasoning rule can fail because the relationship is invalid, not because the evidence is wrong*). Not a kernel object. Feeds the Reasoning Engine design at Logical Architecture.
- **Pattern-discovery orientation** (Oneness) — *"knowledge requires relationship discovery"* — the opposite of a document repository; supports the typed epistemic graph's relationship-centric representation. Mechanism-level confirmation.

**What must NOT enter (HPA's five refusals):**
1. ❌ **KnowledgeOS is NOT trying to achieve human enlightenment** — the *enlightened AI* mapping is rejected.
2. ❌ **KnowledgeOS is NOT a consciousness engine** — the *awakened AI* mapping is rejected.
3. ❌ **KnowledgeOS is NOT a truth oracle** — the *Moksha state = absolute truth database* mapping is rejected.
4. ❌ **KnowledgeOS is NOT removing uncertainty** — *liberation = no unknowns* is rejected; a mature system can say **Unknown**.
5. ❌ **KnowledgeOS is NOT replacing humans** — the *system becomes the final knower* mapping is rejected.

**The governing reason:** KnowledgeOS is domain-independent and does not decide (Art 4); the §AQ ten non-identities already refuse the "truth oracle" and "autonomous decision maker" mappings. The five refusals are negative-boundary **confirmations**.
