## 1. ⛔ RESERVED MATTER ONE — the authorization names **v1**; the operative baseline is **v1.2**

**CDR §4.2 authorized consolidating *"the frozen content into single SDM-**v1**/EOP-**v1** documents."* At the time, v1 was the baseline. Since then:**

| Baseline | Added |
|---|---|
| **v1.1** *(2026-07-31)* | Assembly Fidelity Rule · Strategic/Tactical core-principle status · two-level determinism vocabulary |
| **v1.2** *(2026-07-31)* | PMR-9's verification rule · PMR-10's identifier rule |

> ### **Does an authorization granted for v1's content extend to a baseline it did not contemplate?**

| Reading A | Reading B |
|---|---|
| *The authorization is for an **act type** — administrative extraction with zero new design content — and applies to whatever baseline is current* | *The authorization named **v1** specifically; the five later adoptions require their own authorization to be consolidated* |

***Not decided here. Executing an extraction of v1.2 under a v1 authorization would be acting on an unverified premise — the pattern the AFV-F4 and repository-scope commissions were both built to prevent.***

---

## 2. ⛔ RESERVED MATTER TWO — extraction CONVERTS the baseline's architecture

**The programme has recorded two lawful baseline architectures. The baseline is currently Model B:**

| **Model B — reference-defined** *(current)* | **Model A — materialized** *(what extraction produces)* |
|---|---|
| ***ONE authoritative wording per governed statement; no copy that can drift*** | Decision → **COPY** into a baseline document → *risk of transcription, synchronization and divergence* |

> ### ⚠️ **Extraction is therefore not merely a documentation task. It CONVERTS Model B to Model A, and thereby REINTRODUCES the defect class Model B eliminates.**

**Three things bear on that, and they do not all point the same way:**

| Source | Bearing |
|---|---|
| **The Assembly Fidelity Rule — GOVERNED (v1.1)** | *"An assembly artifact shall not modify normative wording inherited from an authoritative source."* **An extraction document IS an assembly artifact, so the rule binds it directly.** ⚠️ **And PMR-5's own evidence was the eleven-site cascade: restatement creates one defect site PER SITE. Extraction creates a second site for EVERY governed statement** |
| **ES-005.4 "Never a Copy" — DEFERRED hours ago** | *"Governed knowledge references, assembles, validates, and contextualizes existing artifacts; **it never duplicates them. One rule → one home; everything else points.**"* ⚠️ ***Were ES-005.4 binding, it would arguably FORBID this act. It is deferred, so it does not bind — but the Authority should decide knowingly, not by default*** |
| **ISV-1's finding** | *A reference-defined baseline has no derived text, so classical fidelity verification does not exist for it.* **Extraction would CREATE one — but the Authority has already ruled that consolidation must NOT be undertaken to enable a verification.** ***So that is a CONSEQUENCE of extraction, never a justification for it*** |

---

## 3. The justification the act requires, and it must stand on its own

**The Authority's ruling is binding on the reason as well as the act: *do not consolidate merely to enable a verification.*** **The stated justification is **maintainability / housekeeping**, and it must be sufficient on its own merits.**

> ***Recorded for the decision: CDR §4.2 itself observes that "the record is complete and citable as it stands." So the extraction improves NAVIGATION, not COMPLETENESS — and the Authority should weigh a navigation gain against a reintroduced drift-risk class.***

---

## 4. If authorized, the constraints that bind execution

| | |
|---|---|
| **Zero new design content** | **CDR §4.2's own words. Nothing may be added, clarified, harmonized or improved** |
| **Assembly Fidelity Rule** | **Every governed statement carried VERBATIM.** *Verification before any verbatim claim — mechanical extraction and post-hoc diff, per the v1.2 issuance precedent* |
| **Supersession** | **Forward-only.** *v1 · v1.1 · v1.2 are not edited or retracted; the extraction document does not become the authority for statements it merely restates unless the Authority says so* |
| **⚠️ The drift question must be answered, not inherited** | ***Which artifact governs on conflict — the extraction document or the source records? An extraction that leaves this unstated creates two homes for one rule, which is the exact condition ES-005.4 names*** |
| **Scope** | The baseline's governed statements only. **No repository reorganization, no file movement, no promoted artifact touched** |

## 5. Out of scope

**Amending any baseline · classifying repository roots · adopting ES-005.4 · deciding its scope · reorganizing the repository · any act against a promoted artifact · raising methodology candidates.**

## 6. No recommendation offered

***Deliberately. The act is authorized by CDR §4.2, arguably forbidden by a rule deferred hours ago, binds an assembly artifact under a governed fidelity rule, and converts the baseline's architecture. A single recommendation would compress four materially different considerations into one — which is the bundling error the ES-005 adoption was just structured to avoid.***
