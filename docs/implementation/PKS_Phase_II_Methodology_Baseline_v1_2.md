## 2. What v1.2 adds to v1.1 — the two CDR-R2 adoptions, and nothing else

### 2.1 **Source verification precedes classification** *(from PMR-9 — ADOPTED)*

> **Where a finding's CLASS depends on what a governing source actually says, the source shall be verified before the finding is classified — not merely before it is asserted.**

| | |
|---|---|
| **Status** | **GOVERNED** |
| **Scope** | **Prospective.** *Not applied retroactively — the three escapes that evidenced it are remediated, and re-opening remediated work on a newly adopted rule would convert a methodology decision into an audit of completed acts* |
| **Evidence of escape** | CON-1 *(ontology error)* · M7-CF2 *(severity error)* · IBC-1 re-certification *(grading error)* — **heterogeneous rather than repetitive** |

### 2.2 **Identifier collision check precedes minting** *(from PMR-10 — ADOPTED)*

> **Before an identifier or acronym is minted, the corpus shall be searched for existing use of that token. Where the token is taken, a distinct one is chosen.**

| | |
|---|---|
| **Status** | **GOVERNED** |
| **Scope** | **Prospective** |
| **⚠️ Carried into the baseline so it cannot be lost in later citation** | ***The two collisions that evidenced this rule CANNOT be cured by it. Identifier stability forbids renaming, so `AFV-1` and `MCA-R1` are bounded, never erased. This rule prevents the third collision; it does not repair the first two.*** **Renaming any existing identifier remains FORBIDDEN, and no retroactive collision audit is authorized** |
| **Evidence of escape** | the **AFV** collision *(an Authority recommendation became unexecutable)* · the **MCA** collision *(a false claim was published and stood three days)* |
