## Part A — What Gap 7 Is

### A.1 The Gap

GovernanceState is the authoritative record of constitutional phase status for the election system. It records which phase is active, when phases transitioned, and what constitutional state the election is in. Every time-dependent constitutional function depends on it.

**What exists:**
- GovernanceState records phase transitions
- GovernanceAuthorizationCommittee authorizes transitions (ADR-2, AC-25)
- GovernanceAuthority maintains the phase record

**What does not exist:**
- Independent verification that the phase record is accurate
- A mechanism to challenge the phase record itself
- A mechanism to correct a corrupted phase record
- Protection against retroactive phase manipulation
- A deadlock-breaking mechanism when the phase clock stops
- Any constitutional actor who can verify "what time it is" without consulting GovernanceState

### A.2 Why Gap 7 Is Critical

GovernanceState is the Temporal Root — one of three trust roots identified in 38A. Unlike AC-31 (which governs evidence authenticity) and ElectionConstitution (which governs constitutional rules), GovernanceState governs constitutional time itself.

| If GovernanceState is corrupted... | ...then every time-dependent function is compromised |
|---|---|
| Phase record says "voting closed" | CA certifies based on closed voting — but voting may still be open |
| Phase record says "challenge window open" | CAB accepts challenges — but window may have constitutionally closed |
| Phase record says "certification authorized" | CA issues CO-5 — but authorization may never have occurred |
| Phase record stops advancing | Complete deadlock (TM-42) — no constitutional exit |

### A.3 Threats Generated by Gap 7

| Threat | Mechanism | Classification |
|--------|-----------|----------------|
| **TM-03** — GovernanceState Corruption | GA manipulates phase record; no independent verification; circular evidence | C-F (all conditions met) |
| **TM-10** — Phase Lock Attack | Phase acceleration, deceleration, collapse, or falsification | C-F |
| **TM-42** — Complete Deadlock | Phase clock stops; no recovery mechanism | **F (unconditional)** |
| **TM-44** — Rollback Attack | Retroactive phase manipulation; no append-only protection | C-F |
| **TM-46** — Temporal Root Capture | GA capture enables full temporal manipulation | C-F approaching F |

## Part B — What Must Be Specified

### B.1 Core Questions

1. **Who verifies the phase record?** — Is there any constitutional actor who can confirm "what time it is" without relying solely on GovernanceState?
2. **Who may challenge the phase record?** — Can the phase record itself be challenged, or only decisions based on it?
3. **Who may correct the phase record?** — If the phase record is corrupted, who can fix it?
4. **How is retroactive manipulation prevented?** — Can phases be rolled back? Is GovernanceState append-only?
5. **How is deadlock broken?** — If the phase clock stops, who can restart it?
6. **How does phase record governance relate to GovernanceAuthorizationCommittee?** — Authorization and recording are separate (AC-25). Who governs the recorder?

## Part C — Governance Model Options

### C.1 Option A — GovernanceAuthorizationCommittee as Phase Record Governor

**Description:** The GovernanceAuthorizationCommittee (ADR-2, Option B) governs the phase record as part of its authorization mandate. It authorizes transitions AND verifies that the phase record accurately reflects authorized transitions.

**Assessment:**
- Combines authorization and record governance in one body
- AC-25 requires authorization and execution to be distinguishable — but governance of the record is neither authorization nor execution; it is a third function
- Self-referential: the committee that authorizes transitions also verifies that the record of transitions is correct
- OBS-38A06-01: FAILS Q1 — validates its own authorization records

**Verdict: REJECTED.** Combines authorization with record governance, creating self-referential validation.

### C.2 Option B — Distributed Phase Verification (Multi-Party)

**Description:** No single body governs the phase record. Instead, multiple existing authorities hold independent phase verification obligations. Each authority independently records phase transitions it witnesses. GovernanceState remains the operational phase record, but discrepancies between GovernanceState and independent authority records trigger challenges.

**Assessment:**
- No new governance body — reuses existing authorities
- Each authority records phases independently as part of its own mandate
- Discrepancy between GovernanceState and any two independent records triggers phase challenge
- OBS-38A06-01: Distribution breaks self-reference — no single body validates its own phase record

**Verdict: SELECTED.** See Part D.

### C.3 Option C — CIC as Phase Record Governor

**Description:** The Constitutional Interpretation Chamber governs the phase record.

**Assessment:**
- Violates 38B01-INV-01: CIC interprets; CIC does not operationally govern
- Phase record governance is operational, not interpretive
- Same structural violation as CIC governing AC-31 (rejected in 38B-02)

**Verdict: REJECTED.** Violates 38B01-INV-01.

### C.4 Option D — New Phase Record Governance Body

**Description:** A new dedicated body governs the phase record.

**Assessment:**
- Creates a new authority aggregate — OBS-38B01-AI1 burden
- The 38B-01 and 38B-02 pattern has been to avoid new bodies where existing actors can serve
- No justification for a dedicated temporal governance body when distribution achieves the same objective

**Verdict: REJECTED.** Unnecessary governance burden. Distribution achieves the objective.

## Part D — Selected Model: Multi-Party Phase Verification

### D.1 Specification

**Phase record governance is distributed across existing constitutional actors, each holding independent phase verification obligations.**

| Actor | Phase Verification Obligation | Basis |
|-------|------------------------------|-------|
| **GovernanceAuthorizationCommittee** | Authorizes phase transitions; records authorization decisions independently | AC-25 — authorization function |
| **CertificationAuthority** | Records when it receives certification authorization; records when it issues CO-5 | CO-5 issuance depends on phase validity |
| **ChallengeAdjudicationBody** | Records when challenge window opens and closes; records phase at time of each challenge filing | Challenge timeliness depends on phase |
| **AuditExecutionAuthority** | Records phase at time of each audit finding | Audit scope depends on phase |
| **EnrollmentAuthority** | Records when enrollment phase opens and closes | Enrollment validity depends on phase |

### D.2 How Phase Verification Works

**Normal operation:**
- GovernanceAuthorizationCommittee authorizes a phase transition
- GovernanceState records the transition (operational phase record)
- Each verifying authority independently records the phase transition as witnessed
- No discrepancy → phase record is corroborated

**Challenge trigger:**
- Any verifying authority detects a discrepancy between GovernanceState and its own independent phase record
- Two or more verifying authorities report discrepancy → automatic phase challenge triggered
- Single authority discrepancy → formal review; not automatic challenge

**Challenge adjudication:**
- CAB adjudicates phase challenges
- CIC interprets constitutional phase requirements if contested
- CAB may order phase record correction (R-3) or phase record suspension (R-5)

### D.3 Deadlock Breaking

**TM-42 (Complete Deadlock) mitigation:**

If GovernanceState stops advancing (phase clock frozen), and GovernanceAuthorizationCommittee has not authorized a transition:

1. Any verifying authority may petition CAB for phase advancement
2. CAB reviews whether constitutional conditions for phase advancement are met
3. CIC interprets if phase advancement conditions are constitutionally satisfied
4. CAB may order phase advancement if conditions are met
5. GovernanceState records the CAB-ordered transition

**This breaks the deadlock:** an external constitutional actor (CAB, with CIC interpretation) can advance the phase clock when the normal authorization pathway is blocked.

### D.4 Append-Only Protection

**TM-44 (Rollback Attack) mitigation:**

- GovernanceState must be append-only: phase transitions may only be added, never deleted or modified
- Phase corrections are recorded as new corrective entries, not modifications to prior entries
- The phase record is an immutable sequence: Transition 1 → Transition 2 → Correction to Transition 2 → Transition 3
- Attempted rollback is detectable: any entry that purports to change a prior phase state without a corrective entry is constitutionally invalid

**Verification:** Verifying authorities compare their independent phase records against GovernanceState. A missing corrective entry for a phase change indicates rollback.

### D.5 Independence of Verification Records

Each verifying authority's phase records are maintained as part of that authority's constitutional mandate. They are not stored in GovernanceState. They are independent records, maintained by independent authorities, used to corroborate or challenge the operational phase record.

**This breaks the self-reference:** GovernanceState is no longer the sole evidence of constitutional time. It is the operational phase record, corroborated by independent authority records.

## Part E — Relationship to Existing Architecture

### E.1 GovernanceAuthorizationCommittee

The Committee authorizes phase transitions (AC-25). Under this specification, it also:
- Records its authorization decisions independently
- Serves as a verifying authority for phase record accuracy
- May petition CAB for phase advancement if GovernanceState is deadlocked

**The Committee's authorization function and verification function are distinct.** Authorization is the constitutional act of permitting a transition. Verification is the constitutional act of confirming the transition was correctly recorded. These are separate constitutional functions within the same body.

### E.2 CertificationAuthority

CA depends on phase validity for CO-5 issuance. Under this specification, CA:
- Records phase at time of certification authorization receipt
- Records phase at time of CO-5 issuance
- Serves as a verifying authority
- May challenge phase record if phase at certification conflicts with GovernanceState

### E.3 ChallengeAdjudicationBody

CAB depends on phase validity for challenge timeliness. Under this specification, CAB:
- Records phase at time of each challenge filing
- Serves as a verifying authority
- Adjudicates phase challenges (including deadlock-breaking petitions)
- May refer constitutional phase questions to CIC

### E.4 Constitutional Interpretation Chamber

CIC interprets constitutional phase requirements. Under this specification, CIC:
- Interprets whether phase advancement conditions are constitutionally satisfied
- Interprets phase boundary disputes
- Does NOT operationally govern the phase record (38B01-INV-01)

## Part F — OBS-38A06-01 Self-Referential Review

**Q1: Does the governance model validate its own records?**

No. GovernanceState is the operational phase record. Verifying authorities maintain independent records. Phase challenges compare GovernanceState against independent records — not against GovernanceState itself. The self-referential circularity of TM-03 (challengers must use GovernanceState to prove GovernanceState corruption) is broken: challengers use their own independent phase records.

**Q2: Does the governance model determine its own succession without external input?**

Not applicable in the same sense as AC-31. Phase record governance is distributed across existing authorities. If one verifying authority becomes unavailable, others continue. No single succession point.

**Q3: Does the governance model adjudicate challenges to its own legitimacy?**

No. Phase challenges are adjudicated by CAB with CIC interpretation. No verifying authority adjudicates challenges to its own phase records. CAB is not a verifying authority for its own adjudication records — CAB's phase records are subject to the same challenge pathway as other authorities.

**Verdict: No self-referential chain identified within the current model.**

## Part G — OBS-38B02-01 Tradeoff Tracking

**Concentration reduced:** Temporal Root concentration is reduced. GovernanceState is no longer the sole constitutional clock — it is the operational phase record corroborated by independent authority records. The self-referential property (sole record, circular evidence) is broken.

**Dependency increased:** Phase verification now depends on multiple authorities maintaining independent records. If multiple verifying authorities become unavailable simultaneously, phase verification is impaired. This is the distributed governance tradeoff: reduced single-point concentration, increased multi-party coordination dependency.

**Tracked for 38B-05 (Gap 3) and future rounds.**

### R4 — Temporal Root Observation Added

**OBS-38B03-01: Temporal governance differs fundamentally from legitimacy governance and authenticity governance.** Legitimacy disputes (Gap 4, CIC) may remain unresolved — the election proceeds under the current best interpretation while constitutional ambiguity persists. Authenticity disputes (Gap 5, AC-31) may remain unresolved — evidence authenticity questions can be preserved for post-election review. Temporal disputes cannot remain unresolved. If the constitutional clock stops (TM-42), if the phase record is contested (TM-03), or if the current phase is ambiguous (TM-10), constitutional operation cannot proceed. No one can certify. No one can challenge. No one can vote. Temporal governance therefore contains stronger liveness requirements than the other two trust roots: correctness alone is insufficient; the system must also guarantee progress. This property will become critical in technical architecture, where distributed systems theory (FLP impossibility, consensus liveness) directly constrains temporal governance design.

---

### R5 — Append-Only Language Replaced

**Original:** "GovernanceState must be append-only: phase transitions may only be added, never deleted or modified. Phase corrections are recorded as new corrective entries, not modifications to prior entries."

**Revised:** "Prior phase records must remain constitutionally reviewable. Retroactive alteration must be detectable: any modification to a previously recorded phase state must be visible as a modification, not a silent overwrite. Phase corrections must be recorded as distinct constitutional acts, preserving the original record and the correction as separate entries in the phase history. The original record of what was previously believed to be the constitutional phase must survive correction — both for constitutional transparency and for challengeability. Whether this property is realized through an append-only ledger, an event stream, a signed journal, a cryptographic chain, or another mechanism belongs to technical architecture (38C+). The constitutional requirement is detectability of retroactive alteration, not a specific implementation pattern."

---

### Additional: OBS-38B03-02 Added

**OBS-38B03-02: Temporal governance introduces liveness requirements absent from the other two trust roots.** Legitimacy governance (CIC) can operate on demand: when a constitutional question arises, CIC interprets. Authenticity governance (AC-31) can operate on demand: when verification is needed, Tier 3 parties verify. Temporal governance must operate continuously: the phase clock must advance regardless of whether any dispute exists. This liveness property — the requirement that the system make progress even in the absence of disputes — distinguishes temporal governance from the other trust roots and will impose distinct requirements on technical architecture.
