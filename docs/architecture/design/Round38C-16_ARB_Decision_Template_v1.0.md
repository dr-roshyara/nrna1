# Round 38C-16 — ARB Decision Template v1.0 (FROZEN)

**Program:** NRNA DDD Trustworthiness Research Program
**Status:** 🧊 FROZEN — mandatory structure for **all** future ARB constitutional rulings (versioned-change only). First conforming instance: 38C-15.
**Date:** 2026-06-26

> **Purpose.** A single judicial structure that (a) separates constitutional governance from software governance, (b) separates *holding* from *reasoning* from *consequences* (ratio decidendi discipline), and (c) preserves complete traceability for architecture reviewers, governance boards, and dissertation examiners.

## Mandatory sections (in order)
| # | Section | Must contain |
|---|---------|--------------|
| 0 | **Definition(s) adopted** | one-sentence precise definition of each key constitutional term the ruling turns on |
| 0 | **Standing of the ruling** | nature of the decision — value judgment vs evidence-compelled; record validation status (e.g. human n=…) |
| 1 | **Question before the Board** | the precise question, neutrally stated |
| 2 | **Alternatives Considered** | every option, with one-line essence (table) |
| 3 | **Holding (Decision)** | what is adopted/deselected — *decision only, no reasoning*; deselected ≠ refuted unless stated |
| 4 | **Ratio Decidendi** | the reasoning that compels the holding; **empirical claims bounded to evidence actually held** (e.g. "systems examined", never "universal norm") |
| 5 | **Constitutional Safeguards** | classified **constitutional / structural / procedural**; mark permanent vs transitional; **record residual risk** |
| 6 | **Scope of the Decision** | what this ruling governs and explicitly what it does **not** modify |
| 7 | **Consequences for Governance** | governance authorizations, protections, deferrals |
| 8 | **Consequences for Software Architecture** | DDD/tactical/implementation gates — *kept separate from §3* |
| 9 | **Deferred Questions** | open items, protected questions, retained reservations |
| — | **Program State block** | machine-readable status summary |

## Drafting rules (binding)
1. **Holding ≠ Ratio ≠ Consequences** — never mix; §3 states *what*, §4 states *why*, §7/§8 state *what follows*.
2. **No unsupported universal claims** — "prevailing norm", "all mature systems", "consensus" are forbidden unless a completed comparative study backs them; otherwise bound to "systems examined".
3. **Deselected, not refuted** — record retained reservations for unselected coherent options.
4. **Record residual risk** explicitly — a managed risk is named, not hidden.
5. **Define before deciding** — any term the ruling turns on gets a one-sentence definition (§0).
6. **Validation honesty** — state validation status (human n, corroboration vs proof).
7. **Constitutional vs project governance** — never place project-governance (DDD gates, dev sequencing) inside the constitutional holding.

## Evidence-grade conventions (shared with literature reviews)
- **Evidence grade:** E1 systematic-review/meta-analysis · E2 peer-reviewed empirical · E3 foundational book · E4 industrial practice · E5 expert opinion.
- **Relevance:** R1 directly-applicable · R2 adaptable · R3 background.
- **Relation:** Supports · Refines · Contradicts · Competes · Independent.
