## 🎯 Quick Reference

### The Problem We're Solving

Organizations (political parties, NGOs, diaspora groups) need a way to:
- **Capture** what members actually think and want
- **Understand** organizational problems deeply
- **Generate** and **compare** alternative solutions
- **Make decisions** transparently with explainable reasons
- **Track outcomes** to show that ideas become action
- **Preserve knowledge** so the organization learns over time

### What We're NOT Building

❌ A forum (like Reddit, Discourse, phpBB)  
❌ A voting system (simple democracy)  
❌ A project management tool  
❌ An autocratic decision engine  

### What We ARE Building

✅ A system to make **collective voice visible, traceable, and difficult to ignore**  
✅ **Parallel flows:** Problem Understanding + Solution Development  
✅ **First-class aggregates:** Problem, Idea, Alternative Proposal, Decision, Initiative  
✅ **Transparent decisions** with mandatory explanations  
✅ **Outcome tracking** through execution  
✅ **Institutional memory** that preserves alternatives and minority views

## 🏗️ Domain Architecture at a Glance

### Core Domain (Business-Critical)

```
Problem Context
├── Problem aggregate
└── Problem discovery, discussion, understanding

Solution Context
├── Idea aggregate (proposals to solve problems)
├── Alternative Proposal aggregate (competing solutions)
├── Decision aggregate (which alternative chosen)
└── Initiative aggregate (tracking execution + outcomes)
```

### Supporting Domains

```
Sentiment & Signal Detection
├── Separate sentiment (how members feel) from evidence (what evidence exists)
├── Members have equal voice on sentiment
└── Evidence quality evaluated independently

Transparency & Accountability
├── Decisions must have explainable reasons
├── Reconsideration requests (new evidence → review again)
└── Public decision records (permanent, immutable)

Execution Tracking
├── Initiative progress visible to members
└── Links to external execution systems (if applicable)

Institutional Memory
├── Archive all problems, ideas, alternatives, decisions
├── Search & discovery
└── Organizational learning
```

## 🔑 Key Design Decisions

| Decision | Choice | Why |
|----------|--------|-----|
| **Core Domain** | Problem + Solution | Organizations exist to solve problems, not discuss |
| **First-Class Concept** | Problem (aggregate root) | Without Problem, ideas become disconnected |
| **Signal Model** | Sentiment ≠ Evidence | Members should have equal voice, evidence evaluated separately |
| **Decisions** | Transparent + Explainable | Leadership visible but not overridden by software |
| **Appeal vs Reconsideration** | Reconsideration Request | "New evidence, please review" not "you were wrong, reverse" |
| **Multiple Alternatives** | Preserved forever | Organization learns from paths not taken |
| **Scope** | Configurable per organization | Political parties, NGOs, cooperatives have different hierarchies |
