# Domain Events: Complete Event Catalog

**Date:** 2026-06-05 09:40 UTC  
**Status:** Event Flows Validated  
**Revision:** 1.0

## Overview

Domain events represent **something that happened in the business domain**. They're immutable records of important facts. This document catalogs all events, their triggers, and their consequences.

---

## PROBLEM LIFECYCLE EVENTS

### ProblemIdentified
**Triggered when:** Member creates a new problem  
**Payload:**
```
{
  eventId: UUID
  eventType: "ProblemIdentified"
  timestamp: DateTime
  problemId: UUID
  memberId: UUID
  title: String
  description: String
  scope: {level: ScopeLevel, organizationUnitId: UUID}
  category: String
  tags: [String]
}
```

**Consequences:**
- Problem appears in "New" section
- Moderators notified (if moderation policy requires)
- Members in scope notified
- Archive indexed
- Search index updated

---

### ProblemDiscussionStarted
**Triggered when:** First comment on problem  
**Payload:**
```
{
  eventId: UUID
  eventType: "ProblemDiscussionStarted"
  timestamp: DateTime
  problemId: UUID
  firstCommenterId: UUID
  totalParticipantsNow: Int
}
```

**Consequences:**
- Problem status → DISCUSSED
- Discussion tracking begins
- Notification sent to subscribed members

---

### ProblemCommented
**Triggered when:** Member adds comment (signal or text)  
**Payload:**
```
{
  eventId: UUID
  eventType: "ProblemCommented"
  timestamp: DateTime
  problemId: UUID
  commenterId: UUID
  commentType: "TEXT" | "SIGNAL"
  signalType: Optional[IMPORTANT | DUPLICATE | ROOT_CAUSE | NEEDS_CLARIFICATION]
  content: String
  attachmentIds: [UUID]
  threadDepth: Int (0 = top-level, 1+ = reply)
}
```

**Consequences:**
- LastActivity updated
- Participant count incremented
- Signal aggregated (if signal type)
- Subscribers notified

---

### ProblemUnderstoodThresholdReached
**Triggered when:** Organization manually marks problem as UNDERSTOOD  
**Payload:**
```
{
  eventId: UUID
  eventType: "ProblemUnderstoodThresholdReached"
  timestamp: DateTime
  problemId: UUID
  totalComments: Int
  totalParticipants: Int
  highQualityComments: Int
  rootCausesClarified: Boolean
  decidedBy: MemberId | CommitteeId
}
```

**Consequences:**
- Problem status → UNDERSTOOD
- Solutions can now be proposed for this problem
- Notification: "This problem is well-understood, propose solutions"
- Archive records understanding decision

---

### ProblemArchived
**Triggered when:** Problem is resolved or becomes irrelevant  
**Payload:**
```
{
  eventId: UUID
  eventType: "ProblemArchived"
  timestamp: DateTime
  problemId: UUID
  reason: String (e.g., "Problem resolved via Initiative #123")
  archivedBy: MemberId | SystemId
  resolutionDetails: Optional[String]
}
```

**Consequences:**
- Problem removed from active list
- Preserved in archive forever
- Search still returns it with [ARCHIVED] tag
- No new comments allowed

## SOLUTION DEVELOPMENT EVENTS

### IdeaCreated
**Triggered when:** Member proposes an idea to solve a problem  
**Payload:**
```
{
  eventId: UUID
  eventType: "IdeaCreated"
  timestamp: DateTime
  ideaId: UUID
  problemId: UUID (which problem does it solve?)
  authorId: UUID
  title: String
  description: String
  scope: ScopeObject
}
```

**Consequences:**
- Idea appears in "Ideas for Problem X"
- Members notified (subscribed to problem)
- Search indexed
- Status → DRAFT

---

### IdeaPublished
**Triggered when:** Author moves idea from DRAFT to DISCUSSION  
**Payload:**
```
{
  eventId: UUID
  eventType: "IdeaPublished"
  timestamp: DateTime
  ideaId: UUID
  authorId: UUID
  publicAt: DateTime
}
```

**Consequences:**
- Idea now visible to all members in scope
- Members can comment, add evidence
- Status → DISCUSSION
- Notifications sent to subscribed members

---

### IdeaAmended
**Triggered when:** Author (or authorized) changes idea  
**Payload:**
```
{
  eventId: UUID
  eventType: "IdeaAmended"
  timestamp: DateTime
  ideaId: UUID
  amendedBy: UUID
  amendments: [
    {
      field: String (e.g., "description", "scope"),
      oldValue: String,
      newValue: String,
      reason: String (why changed?)
    }
  ]
  newAmendmentCount: Int
}
```

**Consequences:**
- Amendment recorded in amendment history
- Subscribers notified of changes
- Evidence might be added as consequence

---

### EvidenceAddedToIdea
**Triggered when:** Member adds research, case study, expert opinion  
**Payload:**
```
{
  eventId: UUID
  eventType: "EvidenceAddedToIdea"
  timestamp: DateTime
  ideaId: UUID
  contributorId: UUID
  evidenceType: "RESEARCH" | "EXPERT_OPINION" | "CASE_STUDY" | "DATA" | "FINANCIAL"
  attachmentId: UUID
  summary: String (what does this evidence show?)
  relevance: String (how does it strengthen/weaken idea?)
}
```

**Consequences:**
- Evidence indexed
- Search updated
- Sentiment might shift
- Notification: "New evidence added to idea you're tracking"

---

### SentimentUpdated
**Triggered when:** Aggregation logic summarizes support/concerns  
**Payload:**
```
{
  eventId: UUID
  eventType: "SentimentUpdated"
  timestamp: DateTime
  ideaId: UUID
  previousSentiment: {support: Int, concerns: Int, neutral: Int}
  currentSentiment: {support: Int, concerns: Int, neutral: Int}
  sentimentShift: "GAINING_SUPPORT" | "INCREASING_CONCERNS" | "STABLE"
  evidenceAddedThisCycle: Int
}
```

**Consequences:**
- UI shows updated counts
- If threshold reached → next event
- Trending algorithms updated

---

### IdeaReadyForProposal
**Triggered when:** Idea matures enough to become formal Alternative Proposal  
**Payload:**
```
{
  eventId: UUID
  eventType: "IdeaReadyForProposal"
  timestamp: DateTime
  ideaId: UUID
  authorId: UUID
  supportCount: Int
  evidenceCount: Int
  amendmentCount: Int
  readyDecision: "AUTHOR_DECIDED" | "COMMUNITY_THRESHOLD" | "MODERATOR_PROMOTION"
}
```

**Consequences:**
- Idea promoted to AlternativeProposal aggregate
- New ProposalId created
- Idea status → MATURE
- Notification: "Your idea became a formal proposal"
- Can now be compared with other alternatives

## ALTERNATIVE PROPOSAL EVENTS

### AlternativeProposalCreated
**Triggered when:** Mature idea becomes formal proposal  
**Payload:**
```
{
  eventId: UUID
  eventType: "AlternativeProposalCreated"
  timestamp: DateTime
  proposalId: UUID
  ideaId: UUID (from which idea?)
  problemId: UUID (solving which problem?)
  authorId: UUID
  title: String
  description: String (detailed, comprehensive)
  scope: ScopeObject
}
```

**Consequences:**
- Proposal appears in "Alternatives for Problem X"
- Members can compare with other alternatives
- Search indexed
- Status → CANDIDATE

---

### ProposalComparisonInitiated
**Triggered when:** Alternative proposals for same problem are listed together  
**Payload:**
```
{
  eventId: UUID
  eventType: "ProposalComparisonInitiated"
  timestamp: DateTime
  problemId: UUID
  proposalIds: [UUID] (all alternatives for this problem)
  comparisonFramework: String (what criteria to compare?)
}
```

**Consequences:**
- Proposals shown side-by-side
- Community helps create comparison (strengths/weaknesses)
- Notification: "Compare alternatives for Problem X"

---

### ProposalEvidenceEvaluation
**Triggered when:** Community evaluates quality of evidence  
**Payload:**
```
{
  eventId: UUID
  eventType: "ProposalEvidenceEvaluation"
  timestamp: DateTime
  proposalId: UUID
  evidenceQualityScore: STRONG | MODERATE | WEAK
  evaluatedBy: [UUID] (members who evaluated)
  evaluationConsensus: Boolean
}
```

**Consequences:**
- Evidence weight updated
- Sentiment might shift based on evidence quality
- Proposal attractiveness changes

## DECISION EVENTS

### DecisionMade
**Triggered when:** Leadership makes choice between alternatives  
**Payload:**
```
{
  eventId: UUID
  eventType: "DecisionMade"
  timestamp: DateTime
  decisionId: UUID
  problemId: UUID
  selectedProposalId: UUID (which was chosen)
  rejectedProposalIds: [UUID] (which were not chosen)
  decidedBy: CommitteeId | LeadershipGroup
  decidedDate: DateTime
}
```

**Consequences:**
- DecisionId created
- Selected proposal status → SELECTED
- Rejected proposals status → CANDIDATE (remain as alternatives)
- Waiting for reason event

---

### DecisionReasonRecorded
**Triggered when:** Decision reason is entered  
**Payload:**
```
{
  eventId: UUID
  eventType: "DecisionReasonRecorded"
  timestamp: DateTime
  decisionId: UUID
  status: "ACCEPTED" | "REJECTED"
  reasonType: String (BUDGET, DUPLICATE, LEGAL, etc.)
  reasonSummary: String (one-line)
  reasonDetails: String (full explanation)
  alternativeChosen: Optional[UUID] (if rejected, which was chosen instead)
  supportingEvidence: [UUID] (attachments supporting decision)
  reviewedBy: UUID
}
```

**Consequences:**
- Decision fully documented
- Next event: DecisionPublished

---

### DecisionPublished
**Triggered when:** Decision is made public to organization  
**Payload:**
```
{
  eventId: UUID
  eventType: "DecisionPublished"
  timestamp: DateTime
  decisionId: UUID
  problemId: UUID
  proposalId: UUID
  publicAt: DateTime
  visibility: "PUBLIC" (always)
  membersNotified: Boolean
}
```

**Consequences:**
- Decision visible to all members in scope
- Members can see reason
- Members can request reconsideration (if policy allows)
- Archive recorded
- Notification: "Decision made on Problem X"

---

### DecisionRejected
**Triggered when:** Leadership chose alternative, so this proposal rejected  
**Payload:**
```
{
  eventId: UUID
  eventType: "DecisionRejected"
  timestamp: DateTime
  decisionId: UUID
  proposalId: UUID (which was rejected)
  selectedAlternative: UUID (which was chosen instead)
  reason: String
  reasonDetails: String
}
```

**Consequences:**
- Proposal status → ARCHIVED (but preserved)
- Alternative proposal status → SELECTED
- Notification: "Proposal rejected, Alternative chosen instead"

```
  timestamp: DateTime

  description: String

  responsibleTeam: [UUID]
  budgetAllocated: Decimal
}
```

**Consequences:**
- Initiative tracking begins
- Members can follow progress
- Status → NOT_STARTED
- Notification: "Approved proposal starting execution"

---

### InitiativeProgressUpdated
**Triggered when:** Execution team reports progress  
**Payload:**
```
{
  eventId: UUID
  eventType: "InitiativeProgressUpdated"
  timestamp: DateTime
  initiativeId: UUID
  percentComplete: Int (0-100)
  completedMilestones: [String]
  inProgressMilestones: [String]
  blockers: [String] (what's preventing progress?)
  nextSteps: [String]

```

**Consequences:**
- ProgressTracking updated
- Members see: "65% complete, on track"
- If blockers: escalate to leadership
- Notification: "Initiative progress: Problem X is 65% complete"

---

### InitiativeCompleted
**Triggered when:** Initiative execution finishes  
**Payload:**
```
{
  eventId: UUID
  eventType: "InitiativeCompleted"
  timestamp: DateTime
  initiativeId: UUID
  actualCompletionDate: DateTime
  outcomeMetrics: {
    metric1: value,
    metric2: value,
    metric3: value
  }
  lessonsLearned: String
  successIndicators: [String]
}
```

**Consequences:**
- Initiative status → COMPLETED
- Outcomes recorded permanently
- Notification: "Problem X initiative completed: outcomes published"
- Archive records success
- Organization learns from completion

## RECONSIDERATION EVENTS

### ReconsiderationRequested
**Triggered when:** Member requests decision to be reviewed with new evidence  
**Payload:**
```
{
  eventId: UUID
  eventType: "ReconsiderationRequested"
  timestamp: DateTime
  reconsiderationId: UUID
  decisionId: UUID
  proposalId: UUID
  requestorId: UUID
  newEvidenceAttachmentIds: [UUID]
  explanationOfChange: String (why does this evidence change the decision?)
  whyThisMattersNow: String
}
```

**Consequences:**
- ReconsiderationRequest created
- Status → SUBMITTED
- Leadership notified
- Decision NOT reversed (stays in effect)

---

### ReconsiderationUnderReview
**Triggered when:** Leadership begins reviewing reconsideration  
**Payload:**
```
{
  eventId: UUID
  eventType: "ReconsiderationUnderReview"
  timestamp: DateTime
  reconsiderationId: UUID
  reviewedBy: UUID
  reviewStartDate: DateTime
  newEvidenceEvaluated: Boolean
}
```

**Consequences:**
- Status → UNDER_REVIEW
- Requestor notified: "Your reconsideration is being reviewed"

---

### ReconsiderationGranted
**Triggered when:** Leadership accepts new evidence and reverses decision  
**Payload:**
```
{
  eventId: UUID
  eventType: "ReconsiderationGranted"
  timestamp: DateTime
  reconsiderationId: UUID
  decisionId: UUID
  originalDecision: String (what was the original?)
  newDecision: String (what's the new decision?)
  reason: String (why did new evidence change things?)
  newInitiativeStarted: Boolean
}
```

**Consequences:**
- Original decision REVERSED
- New decision recorded
- Archive shows both decisions + reconsideration
- Notification: "Decision reversed based on new evidence"
- Status → GRANTED

---

### ReconsiderationDenied
**Triggered when:** Leadership reviews but evidence insufficient  
**Payload:**
```
{
  eventId: UUID
  eventType: "ReconsiderationDenied"
  timestamp: DateTime
  reconsiderationId: UUID
  decisionId: UUID
  reason: String (why doesn't new evidence change decision?)
  reasonDetails: String
}
```

**Consequences:**
- Original decision stands
- Requestor notified: "Reconsideration denied, decision stands"
- Explanation provided
- Status → DENIED

```
{
```

## Event Ordering Constraints

**These events must happen in order:**

1. ProblemIdentified
2. ProblemDiscussionStarted (optional, implicit)
3. ProblemCommented (0-many times)
4. ProblemUnderstoodThresholdReached
5. IdeaCreated → IdeaPublished → IdeaAmended (0-many) → IdeaReadyForProposal
6. AlternativeProposalCreated → ProposalEvidenceEvaluation (0-many)
7. DecisionMade → DecisionReasonRecorded → DecisionPublished
8. InitiativeCreated → InitiativeProgressUpdated (0-many) → InitiativeCompleted
9. (Optional) ReconsiderationRequested → ReconsiderationUnderReview → (ReconsiderationGranted OR ReconsiderationDenied)

**Invariants:**
- DecisionMade cannot happen before ProblemUnderstoodThresholdReached
- InitiativeCreated cannot happen before DecisionPublished (with ACCEPTED)
- ReconsiderationRequested only valid for REJECTED decisions

## Event Sourcing Implications

All events are:
- ✅ Immutable (created once, never changed)
- ✅ Timestamped (when did it happen?)
- ✅ Authoritative (happened in the domain, not UI)
- ✅ Complete (enough info to reconstruct state)
- ✅ Archived (permanent record)
