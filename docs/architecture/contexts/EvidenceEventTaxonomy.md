# Evidence Event Taxonomy

**Status:** DD.4 — Extracted from EvidenceScenarioCatalog.md  
**Purpose:** Inventory of domain events the Evidence Context observes, transforms, and emits.  
**Strategic Rule:** The Evidence Context is a passive downstream observer. It ingests upstream business milestones, filters them through an Anti-Corruption Layer to guarantee zero PII leakage (EVI-5), and emits unalterable preservation facts.

---

## Constitutional Timeline & Context Flow

The sequence below illustrates how data cascades across context boundaries. The Evidence Context acts as the secure, unalterable ledger of facts that subsequent evaluation and legitimacy engines depend upon.

## Section 1: Inbound Context Events (Observed — Exist Today)

These events are generated by external contexts. The Evidence Context listens to them via an Inbound Adapter (Anti-Corruption Layer) to populate its consistency boundaries without introducing tight compile-time coupling.

| Upstream Event Class (Logical Contract) | Supposed Upstream Context | Target Evidence Cluster | Purpose |
|:---|:---|:---|:---|
| `App\Domain\Election\Events\VoterAssignedToElection` | Election Administration | Cluster B: Election Window | Tracks baseline enrollment volume without storing voter identity. |
| `App\Domain\Election\Events\VotingOpened` | Election Administration | Cluster B: Election Window | Establishes lower logical bound for evidence ingestion. |
| `App\Domain\Election\Events\VotingClosed` | Election Administration | Cluster B: Election Window | Closes ingestion window; marks window data ready for final sealing. |
| `App\Domain\Election\Security\Event\ObservationRecorded` | Observation Context | Cluster A: Vote Submission | Primary entry point. Provides raw, unverified technical footprints of action. |
| `App\Domain\Election\Security\Event\LegitimacyGranted` | Legitimacy Context | Cluster C: Result Publication | Logged as correlating historical fact for integrity verification. |
| `App\Domain\Election\Security\Event\LegitimacyDenied` | Legitimacy Context | Cluster C: Result Publication | Logged to track defensive integrity and malicious pattern frequency. |
| `App\Domain\Election\Events\ResultsPublished` | Governance Context | Cluster C: Result Publication | Triggers complete immutability seal over election's evidence landscape. |

**DDD Architecture Rule:** Implementation must use an Inbound Adapter/ACL. Domain logic within Evidence Context must remain completely ignorant of `App\Domain\Election\...` namespaces to protect against structural model contamination.

## Section 3: Excluded Events (Intentionally Ignored)

To maintain explicit separation of concerns, these event types are strictly forbidden from entering the Evidence Context:

| Event Type | Reason for Exclusion | Risk if Violated |
|:---|:---|:---|
| **`VoteSubmitted` / `BallotCast`** | Votes are anonymous. Evidence tracks transaction metadata only, never vote content. | Linking vote content to evidence violates anonymity |
| **`UserCreated` / `IdentityVerified`** | User identities carry significant PII exposure. | Breaks EVI-5 anonymity invariant |
| **`VoteCounted`** | Tallying is arithmetic (Governance context). No architectural value for evidence. | Cross-context coupling without authority transfer |

## Section 4: Privacy Scrutiny & Ingestion Guardrails (EVI-5 Enforcement)

To enforce **EVI-5** (No indirect voter re-identification), the Inbound Adapter must parse and sanitize incoming payloads before writing to database.

### Strict Ingestion Filters

1. **Direct PII Stripping:** `user_id`, `email`, `mac_address`, `raw_ip_address` are discarded at outermost boundary.
2. **Deterministic Hash Verification:** `device_fingerprint_hash` must undergo cryptographically secure, one-way transformation with election-specific salt. Exact algorithm (SHA-256, BLAKE2, etc.) is a Security Architecture decision, not a domain requirement.
3. **Temporal Fuzzing (Anti-Correlation Guardrail):**
   - **Risk:** Millisecond-precision timestamps + network region easily correlate back to web server logs, identifying the voter.
   - **Mitigation:** Inbound Adapter **truncates timestamps to minute-level or uniform blocks** in low-turnout elections to eliminate side-channel correlation.

### Ingestion Schema Sanitization

| Incoming Raw Field | Sanitization Action | Normalized Internal Value | EVI-5 Rationale |
|:---|:---|:---|:---|
| `payload.ip_address` | Anonymize via Subnet Masking / Geolocation | `network_location` (Region level only) | Prevents IP-based voter lookup |
| `payload.timestamp` | Temporal Bucketing / Fuzzing (minute granularity) | `occurred_at` (Truncated minute window) | Prevents timestamp correlation with server logs |
| `payload.device_raw` | Cryptographic one-way transformation with election-specific salt | `device_fingerprint_hash` | Prevents device tracking across elections |
| `payload.user_id` | **DISCARDED — Never stored** | `<null>` | Hardest anonymity boundary |
| `payload.email` | **DISCARDED — Never stored** | `<null>` | Hardest anonymity boundary |

This taxonomy feeds the aggregate discovery:

- **Observation Cluster A** (Vote Submission) is built from: `ObservationRecorded` payloads filtered through ACL
- **Observation Cluster B** (Election Window) is built from: `VotingOpened` + `VotingClosed` events
- **Observation Cluster C** (Result Publication) is built from: `ResultsPublished` event

Events are clues about consistency boundaries, but aggregate discovery is ultimately driven by **invariants and transactional consistency requirements**, not by event shapes alone.
