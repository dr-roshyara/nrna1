# `EM-ARCH-001` — Dependency Reconciliation: D-1, D-3…D-9 against adopted `EM-GOV-069`

**Type:** Architecture reconciliation deliverable (Architecture — Session 4, bounded task) · **Date:** 2026-08-17
**Commission (PO/ARB, 2026-08-17, verbatim):** *"Reconcile D-1 and D-3…D-9 against the now-approved EM-GOV-069 and classify each as: 1. Implementation blocker — Governance decision required · 2. Implementation constraint — already sufficiently defined · 3. External dependency — intentionally unresolved · 4. No longer applicable / discharged."*
**Scope discipline:** classification only — nothing is resolved, redesigned, invented or authorized here. The approved design (`2026-08-17-EM-ARCH-001-model-a-operating-core-design.md`) is not modified; its §7 register stands as approved.

## 1 · Method — the decisive test

For each dependency: **can the approved architecture faithfully represent the matter WITHOUT the missing answer** (→ category 2 or 3), **or would implementation be forced to INVENT the missing answer** (→ category 1)? The judgment applies the design's own approved constructions — ports without adapters (B-3), placeholders (`EM-OPEN-045` marking), abstract subjects (AG-2 / §7 D-3), derived classifications (P-2/P-3, DD-1) — because the design was approved *"subject to the recorded D-1…D-9 dependencies and without resolving them by architectural assumption"* (design approval registration §1), i.e. the abstractions ARE the approved representation, not gaps in it.

**D-2 is noted only, not classified:** ✅ **DISCHARGED 2026-08-17** by adopted `EM-GOV-069` — the `EM-GOV-063` terminal state is **ELECTION DISCONTINUED**; `TerminalStatePlaceholder` acquires its governed rendering *Election Discontinued* by Governance act, exactly as the design demanded (`EM-GOV-069` adoption registration §4; `EM-OPEN-110` RESOLVED). Category 4 by the record itself.

## 3 · Conclusion

**No category-1 item remains: no governance decision currently blocks implementation of the approved `EM-ARCH-001` design.** With `EM-GOV-069` adopted (D-2 discharged — the one dependency the approval registration itself restated as *implementation-blocking*), every surviving dependency is either an implementation **constraint** the approved design already defines executably — keep the gate subject abstract (D-3), attach nothing to OPEN or to inaction (D-4), build no `C-2` classifier (D-5), consume adopted `036` without the menu (D-6), keep event names marked non-canonical (D-7), compute instants only (D-8), keep positions and the two *cancelled* levels closed and distinct (D-9) — or an **external dependency intentionally left unresolved** at a port with no adapter (D-1, `EM-OPEN-049`: organisational governance's answer, which Election-side implementation must not and need not invent). This matches the record's own registered position that `EM-OPEN-110` was *"the last vocabulary block on any future implementation authorization."* **Nothing here grants that authorization: it remains a separate PO act** (design approval registration §2; `EM-GOV-069` registration §4), and a concrete first-gate binding (D-3 residue: `EM-OPEN-054` Q3 · `055`) plus the external authority's existence (D-1) still gate any *deployed* election, as the design intends.
