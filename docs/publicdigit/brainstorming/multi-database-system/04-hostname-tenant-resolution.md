# 04 — Hostname-based tenant resolution (`<org>.publicdigit.com`)

## 1. Principle
The hostname is a **routing key that identifies the organisation**. It is **not** a database name.

```text
HTTP Host ──► organisation_domains (central) ──► organisation_id
          ──► TenantContext::set(organisation_id)
          ──► organisation_databases (central) ──► database name + status
          ──► 'tenant' connection
```

There are three separate registries, each with its own lifecycle:
- **organisations** (the domain identity);
- **organisation_domains** (routing, many hostnames per organisation possible);
- **organisation_databases** (infrastructure).

**RECOMMENDATION:** do not add `domain` or `database_name` columns to `organisations`. The `Organisation` aggregate stays free of infrastructure data. `election` puts them on `tenants`, and ended up with three registries anyway.

## 2. Current state (FACT)
- No host routing exists:
  - no `Route::domain`, `getHost`, `forceRootUrl` or `URL::defaults` (verified by grep across `app/`, `routes/`, `config/`, `bootstrap/`);
  - the organisation comes from the path, the session or headers (`02` §3).
- No `domain`, `hostname` or `subdomain` column exists anywhere.
- Organisation slugs:
  - `string('slug')->unique()` (`database/migrations/2026_03_05_000001_create_uuid_organisations_table.php:16`);
  - generated by `Str::slug($name)` with a `-N` suffix (`OrganisationController.php:312-319`);
  - no slug validation rule exists;
  - no reserved names exist.

**[I]** Slugs are lowercase ASCII with hyphens, so they are mostly DNS-safe. But:
- they can exceed the 63-character DNS label limit;
- they can be **empty** for non-Latin names (for example Nepali);
- the existence check ignores soft-deleted rows.

**Conclusion:** hostnames should be **registered explicitly** in `organisation_domains`, not derived from the slug on the fly. The slug may be used as the *default proposal*.

## 3. Resolution design (RECOMMENDATION)

### 3.1 One middleware, early
A `ResolveOrganisationFromHost` step runs at the start of the `web` and `api` groups, before `StartSession`'s consumers and before `SubstituteBindings`. It is the first step of the single `ResolveTenantDatabase` middleware proposed in the earlier assessment.

| Host | Result |
|---|---|
| `publicdigit.com`, `www.publicdigit.com` (**apex / platform host**) | No tenant from the host. Platform pages, login hub, organisation directory, `/my-organisations`, platform admin. Tenant routes on this host fall back to path / directory resolution (compatibility, §5). |
| `<label>.publicdigit.com` registered and `active` in `organisation_domains` | `TenantContext::set(org)` |
| `<label>.publicdigit.com` not registered, or the organisation is inactive or suspended | **404** (fail closed); no session write; no tenant connection |
| Any host not matching the allow-list (`^([a-z0-9-]{1,63}\.)?publicdigit\.com$` plus configured custom domains plus local dev) | **400/404** at `TrustHosts` (§6) |

### 3.2 Consistency rule (hostname is authoritative when present)
If the request also carries an organisation in the path (`/organisations/{slug}`), or a directory key (`{election}`, `{vslug}`, a token), **all must resolve to the same organisation**. Otherwise the response is **404**.

This generalises the existing `VerifyVoterSlugConsistency` / `EnsureRealVoteOrganisation` checks. It makes `nc.publicdigit.com/organisations/nrna/...` impossible.

### 3.3 Membership is still required
The hostname proves *which tenant*, not *who may enter*.
- Authenticated tenant routes keep `EnsureOrganisationMember`, which checks the central `user_organisation_roles`.
- Public routes (results pages, voter-slug links, invitations) keep their own token or slug authorisation.

### 3.4 Can existing routes stay unchanged?
**Yes (INFERENCE from the route inventory).** The host step only *adds* a resolution source in front of the existing ones:
- `/organisations/{organisation:slug}/…` keeps working on any host; on a tenant host it must match the host organisation;
- org-less URLs (`/v/{vslug}`, `/elections/{slug}`, `/invitations/{token}`) work on the apex through the central routing directory, and on the tenant host directly.

Optionally, later, a tenant host could serve **shorter URLs** (`nrna.publicdigit.com/elections`) through redirects. That is a UX decision, not a requirement.

## 5. Org-less public URLs (compatibility)
These URLs carry no organisation:
- `/v/{vslug}`, `/elections/{slug}`, `/election/{slug}/result`, `/invitations/{token}`, `/unsubscribe/{token}`;
- `/voters/{id}`, `public-demo/{id}`;
- legacy session routes: `/election`, `/vote/*`, `/voter/start`.

The central **routing directory** (`tenant_route_keys`: kind + key or token hash → organisation_id) resolves them on the apex.

**RECOMMENDATION:** on the apex, after resolving, **redirect to the tenant host** (`302 → https://nrna.publicdigit.com/v/{vslug}`). Each tenant then has exactly one origin for cookies and CSRF, and old links keep working.

## 6. Request-security settings that must change

| Setting | Today (FACT) | Target |
|---|---|---|
| Trusted hosts | `TrustHosts` exists (`allSubdomainsOfApplicationUrl()`) but is **not registered** | Register a **trusted-host allow-list** (the apex, `*.publicdigit.com`, configured custom domains, local dev). Unregistered labels are still rejected by the registry lookup. |
| Trusted proxies | `trustProxies(at: '*')` (`bootstrap/app.php:30`): any client can send `X-Forwarded-Host` | Trust only the real proxy/load-balancer addresses. Otherwise a forged `X-Forwarded-Host` **selects a tenant**. |
| Session cookie | Host-only (`SESSION_DOMAIN` null), one name | Keep **host-only** (each tenant host has its own session; the strongest isolation), or set `.publicdigit.com` for SSO. **Decision (`07`).** |
| Sanctum stateful domains | `APP_URL` host + localhost (`config/sanctum.php:16-20`) | Add a pattern covering `*.publicdigit.com` and the apex |
| CORS | Only localhost origins, `supports_credentials` true (`config/cors.php:22-36`) | `allowed_origins_patterns` for `^https://([a-z0-9-]+\.)?publicdigit\.com$`, only if cross-origin API calls are needed. With same-origin Inertia, not needed. |
| CSRF | Excludes `api/v1/*` | Unchanged; the token is per session, so it is per host with host-only cookies |
| OAuth (Google) | One callback; **no `google` config** in `config/services.php` | **One callback on the apex**, with `state` carrying the return host. Avoids registering every subdomain with Google. |

## 8. Infrastructure outside Laravel (FACT: none of this exists in either repository)

| Item | Requirement |
|---|---|
| DNS | Wildcard `*.publicdigit.com` A/AAAA (or CNAME) to the load balancer, plus the apex record |
| TLS | Wildcard certificate `*.publicdigit.com` + apex (Let's Encrypt **DNS-01** challenge; HTTP-01 cannot issue wildcards) |
| Reverse proxy | `server_name publicdigit.com *.publicdigit.com;` one vhost to one app; forward `Host` and `X-Forwarded-*`; reject unknown hosts with a default server |
| Application | **One** deployment (not one per organisation); the tenant is chosen in Laravel |
| PostgreSQL | One cluster with one central database plus N tenant databases; a pooler (PgBouncer) because workers loop over tenants; backups **per database** (plus central) |
| Monitoring / logging | Tenant id in every log record (Laravel `Context` adds it); per-tenant error rate and DB size |

## 9. Hostname registration (Q17)
1. On organisation creation, propose `<slug>.publicdigit.com`.
2. Validate the hostname:
   - DNS label 1–63 characters, `[a-z0-9-]`, no leading or trailing `-`;
   - not reserved (`www`, `api`, `admin`, `app`, `mail`, `login`, `static`, `assets`, `publicdigit`, `test`, …).
3. A **platform admin** confirms it, which closes the "slug squatting" risk.
4. Insert `organisation_domains(hostname, organisation_id, is_primary, status=active)`. With wildcard DNS and TLS, no DNS change is needed per organisation.
5. Renaming keeps the old hostname as a **redirect** entry (`status=redirect`) so existing links survive.
