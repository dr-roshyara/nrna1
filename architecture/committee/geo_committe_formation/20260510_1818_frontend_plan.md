## ❌ What Must Change (Critical)

### 1. ❌ DO NOT Load Full Tree Into Memory

**Problem:** Current plan loads entire hierarchy recursively. For 10,000+ committees, this will crash browsers.

**Fix - Lazy Expansion Architecture:**

```yaml
Initial Load:
  GET /api/v1/governance/hierarchy?depth=1 (only roots)

On Node Expansion:
  GET /api/v1/governance/committees/{id}/children (lazy load)

Store Structure:
  nodesById: Record<string, CommitteeNode>  # Normalized
  rootIds: string[]                         # Roots only
  expandedIds: Set<string>                  # Which nodes expanded
  loadedChildren: Set<string>               # Which children loaded
```

### 2. ❌ Tenant ID from localStorage is a Security Risk

**Problem:** Frontend should not self-declare tenancy. This can be exploited.

**Fix:** Tenant ID must come from JWT claims or session, not localStorage.

```ts
// ❌ UNSAFE
headers: { 'X-Tenant-Id': localStorage.getItem('tenantId') }

// ✅ SAFE - from authenticated session/backend
// Tenant ID is already in the user's JWT, backend extracts it
```

### 3. ❌ Missing HTTP Client Abstraction

**Problem:** Direct `fetch()` calls without retry, timeout, auth handling.

**Fix - Create `httpClient.ts`:**

```ts
export const httpClient = {
    get<T>(url: string, options?: RequestInit): Promise<T> {
        // Handles: auth injection, retry, timeout, 401, stale projections
    }
}
```

### 4. ❌ Missing Runtime Contract Validation

**Problem:** TypeScript types are compile-time only. Backend can drift.

**Fix - Use Zod for runtime validation:**

```ts
import { z } from 'zod';

const CommitteeHierarchySchema = z.object({
    id: z.string(),
    name: z.string(),
    // ... full schema
});

const response = CommitteeHierarchySchema.parse(apiResponse);
```

### 5. ❌ No Query Cache Layer

**Problem:** Manual caching in Pinia is error-prone.

**Fix - Use TanStack Query for Vue:**

```yaml
Benefits:
  - Built-in caching
  - Stale-while-revalidate
  - Background refetch
  - Projection generation awareness
  - Automatic retries
```

### 6. ❌ No Accessibility Strategy

**Problem:** Governance systems (public sector style) require accessibility.

**Fix - Tree must support:**

```yaml
- Keyboard navigation (arrows, enter, space)
- ARIA tree roles (role="tree", role="treeitem")
- Focus management
- Screen reader announcements
```
